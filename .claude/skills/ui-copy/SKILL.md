# 界面文案

把界面上的字改成「正式中文 App 在这个位置会写的字」。这份规则来自用户在本仓提过的要求，
真源是 `AGENTS.md` §8「UI 文案」与 §4.8；两边冲突时以 AGENTS.md 为准，并把这里改成一致。

## 一句话标准

**信**：写的是真的，和产品实际行为一致。**达**：一眼看懂该做什么。**雅**：简洁、书面、克制，像正式产品，不像聊天，也不像营销稿。

## 按位置用的规则

### 按钮

- 写成「动词 + 对象」：保存、生成视频、生成图片、取消生成、返回首页、重试、分享、编辑、删除、再次生成、暂不生成、确认生成、查看示例。两个字能说清就别用四个字。
- 不加语气词和副词：先、再、接着、就、原样、回去、一下、咱们。反例：「先存着」「不拍了」「回首页接着做」「原样再试一次」「存成第 3 版」。
- 按钮下面不挂一行去向说明（「回去接着看」）。要说明就写在按钮旁边或上方的提示里。
- 花积分的按钮要写清花多少：「生成视频 · 600 积分」。按 Token 结算的写「按实际用量结算」，**不显示冻结上限**（「最多 275 积分」这类数字用户会当成价格）。
- 不可点的按钮，就在旁边写原因（「1 处待补充，处理后可生成视频」），不做点了没反应的灰按钮。
- 同一个动作全站一个叫法。动手改名前先 `git grep` 这个词出现在哪。

### 状态

- 用这几个：生成中、排队中、已完成、失败、已取消、待补充、已保存、保存中。
- 不写：正在拍、正在出、在做、没成、没拍成、拍好了、搞定了。
- 进度只写真实的东西：所处阶段、已用时（「已用时 03:12」）、真实的排队位次。**不编倒计时、不编百分比、不写「约 2 分钟」**，除非有真实数据支撑。

### 标题和导航

- 名词，短，和导航里的叫法一致。查导航真值：`apps/web-aiavatar/src/shell/` 下的导航组件和它的测试。
- 场景、模板这类卡片的一句话描述各说各的具体事，不要清一色「让……」或清一色「不是 X，而是 Y」。
- 品牌标语和首屏标题同样要过这套规则，不因为「已定稿」就保留（2026-11-03 用户：「不好就要优化」）。不用「让……」句式和「让 A，让 B」排比，不用打造、赋能、出圈、一站式。现行标语是「一个 IP，无限可能」，副标题只写能做什么：「制作形象、图片、视频和短剧。」

### 说明、提示、空态

- 简洁的书面语：「通常需要几分钟。生成失败将全额退还积分。」「可离开此页面，完成后将通过微信通知。」
- 不写聊天口吻：「可以先去干别的」「积分够了回来点开拍就行」「说一声就补上」。
- 空态说清缺什么，给一个动作：「还没有画布」+「新建画布」。
- 选填项标「选填」，不写「不写也行」「可以不写」。
- 占位文字给例子：「例如：平放、俯拍、预留文字区域」，不重复标签。
- **只写界面上看不出来、又会影响用户决定的事。** 删掉四类：按钮和标签已经说明的、解释内部机制的、给人宽心但不影响决定的、空泛的句子。
- 费用说明只留一处。价格确定就只写价；不确定才写上限：「按实际用量结算，最多 X 积分」。要留细节放悬停提示。

### 报错

- 用户点了某个操作没做成，弹窗标题写「X 没有完成」，正文写原因和下一步，错误码和追查号放在可展开的「错误详情」里。本仓的出口是 `reportStudioError`（`src/ip/studio-errors.tsx`），别另做横幅或 toast。
- 不把供应商的内部信息给用户看：余额、配额、预扣费、费率、密钥、签名链接、堆栈。可操作的原因（素材尺寸、审核不通过）照实说。
- 不让用户去做不该他做的事（例如供应商「请清理回收站」，不能变成让用户删自己的作品）。

### 确认弹窗

- 标题写要做的事和后果（「删除这张画布？」），正文写删掉后是什么情况（能不能恢复）。
- 按钮写具体动作：「删除」「取消」，危险操作用危险色，不写「确定 / OK」。

### AI 对话

- 助手在对话里的回复照常说话，不归这份规则管按钮那一套。
- 点了会作为用户消息发出的快捷答复（如「换个风格再出一张」）用用户的口吻，不改成按钮叫法。

## 全站通用

- **真实**：不承诺做不到的功能，不编价格、时长、效果、功效、数据。没写的价格、优惠、功效不出现在示例和脚本里。
- **不暴露内部词**：字段名、枚举值、错误码原文、内部叫法（`variation_type`、「首末帧」内部称呼、「直出」）。技术细节放悬停说明里。
- **翻译腔和空话**（几乎总是错的）：打造、赋能、助力、一站式、全方位、轻松、即可、开启你的 X 之旅、无缝、极致。「点一下即可切换」→「点一下切换」。
- **开发词不进界面**：全局（→ 官方 / 平台）、实例（→ 示例）、链（→ 工作流）、目录、节点 ID。
- **标点**：界面里不用 `——`、不用「！」、不用「~」和表情；中文与英文、数字之间留一个空格（「AI 视频」「15 秒」「600 积分」）；用全角中文标点。
- **称呼**：用「你」，不用「您」（本仓现有界面全部是「你」）。
- **时间**：统一 `yyyy-MM-dd HH:mm:ss`，用 `formatDateTime()`；不写「刚刚 / 3 小时前 / 昨天」；不 `iso.slice(0, 10)`。
- **数字**：存原始值，展示层格式化（`formatCredits`、`formatCompactNumber`）。
- **不溢出**：可能变长的文字要限宽并省略或换行，完整内容放 `title`。
- **AI 产出**：生成的图和视频标「AI 生成」。

## 不动的

- 产品名（IP Studio、AiAvatar）和品牌位「IP Studio · 声量引擎旗下」。品牌标语**不在此列**，见上文「标题和导航」。
- 协议名称（《用户协议》《隐私保护指引》）。
- 行业术语：分镜、首帧、尾帧、画幅、口播、旁白、景别、运镜、BGM。第一次出现的地方要能看懂。
- 用户自己输入的内容、模型生成的正文、种子数据里的真实商品标题。
- vendored 画布（`src/canvas/`）只改 `locales/zh-CN.ts`，改了留注释。
- web-drama 另有术语表 `docs/drama-ux-copy-pass.md` §2，改 drama 先查表。

## 做法

1. **定范围**。PC 站就是 `apps/web-aiavatar` 的桌面形态（`html[data-layout="desktop"]`）。页面在 `src/app/`，Studio 业务组件在 `src/ip/`，外壳在 `src/shell/`。先列要改的页面。
2. **扫一遍**。在仓库根目录运行：
   ```bash
   python3 -I .claude/skills/ui-copy/scripts/scan_copy.py apps/web-aiavatar/src
   ```
   它按规则标出可疑文字（文件:行号、命中规则、原文）。加 `--all` 会列出全部带中文的界面文字，方便整页通读。扫描只能抓词，抓不到「信息是否真实」「语气对不对」，所以第 3 步不能省。
3. **按页面通读**。在浏览器里打开页面看实际效果，逐页列一张表：位置｜原文｜改为｜依据（引用上面哪条规则）。改动多时先把表给用户看，再动手。
4. **改**。同一个叫法全仓同步：前端、服务端报错文案（`BusinessException` 的 message）、场景目录 `ipstudio/scenes.json`、种子数据、mock、引用界面标签的文档和注释。测试如果断言的是可视文案，按 AGENTS.md §8.0.1 ⑩ 改成断言错误码或结构；文案本身就是被测行为时才保留。
5. **验证**。
   - 再跑一次扫描，确认新改的地方不再命中。
   - 跑 AGENTS.md §9「1b」那几条 `git grep` 门禁，前端应 0 命中。
   - 类型检查经统一队列：`devq run --name typecheck-aiavatar --cwd <仓库根目录绝对路径> -- pnpm --filter @ai-star-eco/web-aiavatar typecheck`。
   - 在浏览器里看改过的页面，宽度 1440 和 1280 各看一次，确认没有溢出、换行难看的地方。改了布局就再跑一轮 `/impeccable critique`。
6. **交付**。给出改动表；这次没改的存量问题记进 `TODO.md`「时间显示与文案统一」那一段，写明位置和原因。

改写前后的对照例子见 `references/examples.md`。
