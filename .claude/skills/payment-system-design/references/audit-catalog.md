# 审计目录 / Audit Catalog — 支付系统的「money-hiding」失效模式

审计现存付费 / 权益系统时逐条过。每条：**症状 → 怎么检出 → 修法**。这些 bug 在真正动到钱、或用户跨月 / 到期 / 改套餐之前，往往都不报错。

---

## 1. 永久权益（Perpetual entitlement）
- **症状**：买套餐只切换「当前套餐」标识、不记录到期时间；额度按周期无条件重置 → 付一次永久享受。
- **检出**：购买路径有没有写 `expiresAt` / `validUntil`？消费路径有没有读它？grep `expire|valid_until|到期`，若只在 session/JWT/缓存出现而权益层没有 → 命中。
- **修法**：购买时写**绝对到期时间(UTC)**；消费路径用服务端时间校验（P1）。

## 2. 自然月额度泄漏（Calendar-anchored quota leak）
- **症状**：额度按自然月 `YYYY-MM` 重置，而非订阅锚点 → 月中购买白享半月；年付每月 1 号「免费续杯」。
- **检出**：reset 周期键是 `YYYY-MM` 还是从激活日起算的子周期？
- **修法**：周期锚定订阅激活日（P3，详见 proration-playbook 的锚点段）。

## 3. live-reference 误伤已购（No grandfathering）
- **症状**：消费 / 重置时**实时读**可变的套餐定义（`plan.quota`）；运营在后台改套餐，**追溯改变所有已购用户**——尤其降额度会砍到已付费用户。
- **检出**：reset / 校验时读的是用户侧快照，还是 join 出来的 live `plan.*`？后台有没有改套餐定义的入口？
- **修法**：购买时把权益**快照**到用户 / 订阅记录；消费读快照（P2）。注意三类字段传导不同：**额度**（live→追溯）、**一次性 credits**（流水→只影响新购）、**价格**（只影响新单）。

## 4. 布尔代状态机（Boolean instead of state machine）
- **症状**：用 `isPaid` / `isActive` 单布尔表达权益，无法区分 active / 宽限 / 过期 / 锁定；欠费期还是过期态混为一谈。
- **检出**：权益判断是不是一个 bool？能不能表达「已取消但未到期」「过期只读」？
- **修法**：状态机（active / expired / grace / locked），能派生就别存（P4）。注意 Chargebee / Recurly 欠费期 status 仍 Active、靠发票驱动——别只读 status 布尔。

## 5. 信客户端 / 回调时间（Untrusted time source）
- **症状**：到期判断用客户端时间、或支付方回调时间戳，可被操纵 / 漂移。
- **检出**：到期比较用的是服务端 `now()` 对绝对时间戳，还是请求里带的时间？
- **修法**：服务端可信时间（NTP），边界加宽限秒防抖（P1）。

## 6. 非幂等发放（Non-idempotent grant）
- **症状**：支付方至少一次投递，重复 / 并发回调 → 重复发放权益 / 重复叠加时长。
- **检出**：回调处理有没有基于 event / 订单号的唯一约束 + 提交锚点？重投一次会怎样？
- **修法**：条件 update 抢占(claim) + `appliedAt` 锚点 + 唯一约束；整个发放在一个事务（§3）。

## 7. 读判写竞态（Read-judge-write race / double-spend）
- **症状**：并发消费先读到同一余额 → 双花 / 超发额度或积分。
- **检出**：扣减是「读余额 → 判断 → 写回」吗？有没有行锁 / 原子自减 / advisory lock？
- **修法**：原子自减 或 `SELECT ... FOR UPDATE` / advisory lock；或事件溯源重算（§3）。

## 8. 折算套利（Proration arbitrage）
- **症状**：套餐切换 / 升降级时折算规则可被套出钱或权益（低买高折、降级套现）。
- **检出**：折算基准用谁的单价？溢出退不退现金？降级即时还是周期末？
- **修法**：见 `references/risk-control.md`（R1–R5）。核心：基准用老套餐单价、只抵扣不退现金、降级周期末。

## 9. 退款不回收（Refund leaves entitlement）
- **症状**：退款走了，权益还在——支付方退款**不回收**会员天数 / 额度。
- **检出**：有没有监听退款回调并回收 / 缩短 `expiresAt`？还是默默没做？
- **修法**：退款回调 → 按审计流水回收权益。若本期不做，**显式记为接受的风险 + 审计**，别默默漏（R6/R7）。

## 10. 不可测支付路径（Untestable payment path）
- **症状**：验证全流程必须依赖真实支付方（真回调、真付款、真时间流逝）→ 本地 / CI 测不了。
- **检出**：有没有可注入时钟 / mock 下单 / 仿真回调端点？能不能离线跑一遍「下单→到账→到期→锁定」？
- **修法**：可测性三件套 + E2E 冒烟（SKILL §4）。

---

## 附：命名与行为不符（常见迷惑项）
「X 点/月」之类字段若实际是**购买时一次性发放**（append 到不可变流水、无月度重置），则「每月」并未兑现。审计时核对字段名宣称的语义 vs 代码真实行为，标注但区分是否本期要改。
