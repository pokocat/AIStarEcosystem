# 企业积分管理：前端设计

> 2026-10-15 · E05–E10 的完整管理、付款与财务界面；采用现有产品组件，实际验收另记。

## 页面范围

| 位置 | 本批功能 |
|---|---|
| Studio `/enterprise` | 本人两份余额、企业汇总、成员/邀请/授权、分配回收、充值、消费/操作记录、模型与在途设置、移交/退出/关闭预览 |
| 后台「财务 → 充值订单 → 企业订单」 | 登记实收金额、积分和凭据，复核后入账；退款预览、凭据登记与积分回收 |
| Studio 生成前付款框 | 每个新请求明确个人/企业、余额和费用；重试恢复原付款方，异常保留输入 |
| 后台「平台 → AI模型 → 请求日志」 | 图片/视频原任务查询、补原供应商号、明确未受理的依据确认；限平台运营 |
| 入口 | Studio 账号菜单及「我的账号」；`NEXT_PUBLIC_ENTERPRISE_ENABLED=1` 才显示 |

主账号、获授权管理员可见企业汇总；普通成员仅见本人企业积分。企业管理员没有后台财务权限。成员可看本人两份余额；企业管理者无权读取其他成员个人余额、个人充值或私人作品。

## 沿用现有设计

- Studio：沿用 `StudioPage`、品牌字体/颜色和 Ant Design Table、Modal、Input、Checkbox、Button；桌面形态遵守 `html[data-layout]`。
- 后台：沿用 `PageHeader`、Card、Table、Badge、Input、Textarea、Dialog、`useConfirm/useToast`；保留原个人订单页。
- 按用户要求结合 design-taste-frontend、gpt-taste、impeccable 的 Operate 场景原则。该页面以完成资金操作为目的，沿用系统组件、稳定定位与清晰反馈，不增加字体、营销版式或动效依赖。
- 余额使用等宽数字，四项汇总桌面一行、手机两列；长表格在容器内横向滚动，弹窗在手机内滚动，操作按钮保持可见。

## 交易交互

1. 选择成员及金额；回收支持「全部可用」，冻结积分明确排除。
2. 服务端预览人数、逐项金额、总额、操作前后余额，再由用户确认。
3. 提交时重验预览；有变化必须重新预览并再次确认。失败保留输入；同一正文重试保持请求键。
4. 财务收款表单先填写人民币、积分、凭据，再展示目标企业和待分配账户、金额、积分供复核。
5. 退款展示原收款、可退积分、成员归集、冻结/已消费和按原比例计算的人民币。页面登记人工退款事实，不调用现金支付渠道。
6. 生成付款初始个人，展示企业限制及文本冻结上限；余额不足不混扣、不自动切换。原请求重试按服务端付款快照恢复。
7. 停用、移除、退出和关闭先显示可回收额、冻结、未提交/已受理任务与阻断原因；成功后刷新真实账户。主账号移交必须接收者确认。
8. 后台核对先读取原任务，显示冻结总额和实际计价；填写依据后再次确认，只查询原任务或按明确未受理证据释放，不提供重新生成。
