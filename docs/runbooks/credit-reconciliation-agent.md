# 线上积分消耗与对账：定时 agent 任务

给定时运行的 agent 用（2026-10-26 用户要求）：盯线上用户的积分消耗，并做账本对账。agent 只读、只报告，发现问题交给人处理。

## 怎么跑

在本机仓库根目录执行（窗口小时数默认 24）：

```bash
ssh -i /Users/donis/dev/aliyun/aiartist.pem -o ServerAliveInterval=15 ecs-user@47.98.162.120 'bash -s -- 24' < scripts/ops/credit-reconcile.sh
```

`scripts/ops/credit-reconcile.sh` 固定了全部查询：会话设为只读事务，只有 SELECT；数据库凭据在服务器上从 `/etc/aistareco/server.env` 读，不打印。**agent 不自己写 SQL、不改脚本、不连库做别的事。** 需要新查询时报告给人，由人改脚本并提交。

## 输出怎么读

| 段 | 内容 | 怎么判 |
|---|---|---|
| 1 硬性对账 | A–I 九项，每项应为 0 | 任一项不为 0 = **严重**，附 1x 段明细 |
| 2 卡住的冻结 | 进行中超过 6 小时的冻结 | 有行 = **需处理**（任务可能卡死，用户积分被占着） |
| 2b 进行中冻结核对 | 冻结余额 + 赠款冻结 vs 进行中冻结剩余 | 软检查，有折扣时可能不等；有行只列出，不算异常 |
| 3 流入流出 | 窗口内按流水类型汇总 | 看总量和昨天比 |
| 4 消耗 Top 15 | 普通积分与赠款分开 | 单账户 24 小时消耗 ≥ 5000 标出来 |
| 5 单笔大额 | 单笔 ≥ 2000 | 列出来供人看是否合理 |
| 6 按模型接入点 | 任务数、成功 / 退回 / 进行中、退回比例、结算积分及来源 | 任务 ≥ 5 且退回比例 ≥ 50% = **需处理**（模型多半在报错，用户没被扣但用不了） |
| 7 按任务类型 | ip-run / 视频等 | 看结构变化 |
| 8 发出的积分 | 赠送、调整、激活码、赠款、充值、退款 | 全部列出供人核对是谁发的、发了多少 |
| 9 / 9b 赠款 | 活动发放 / 使用 / 到期；7 天内到期还有余额的赠款 | 活动发放达到总额 90% 或 7 天内到期提醒 |
| 10 余额快照 | 全平台余额与赠款合计 | 记下来，和上一份比 |

对账口径（脚本里已写死，改脚本前先读 `CreditService`）：

- 冻结（FREEZE）流水为负，同时从可用余额挪到冻结余额；结算（SPEND）流水为负，只减冻结余额，不再减总余额；退回（UNFREEZE）为正。所以「总余额 = 除 SPEND 与 SCOPED_* 之外全部流水之和」，「冻结余额 = −FREEZE − UNFREEZE + SPEND」。
- 模型赠款单独记在 `aep_credit_grants` 与 SCOPED_* 流水，不进普通余额。
- 表里时间是 UTC，脚本已转北京时间。

## 报告

- 写到 `~/dev/ops-reports/credit/YYYY-MM-DD-HHmm.md`（不进仓库），开头一行结论：「对账正常」或「发现 N 个问题」。
- 先读同目录上一份报告，消耗总量、余额快照和上一份比较，变化超过 2 倍的写出来。
- 结构：结论 → 需处理（严重 / 需处理两级，每条写清是什么、涉及谁、建议谁去看什么）→ 消耗概况（总消耗、Top 账户、按模型）→ 发出的积分 → 赠款 → 余额快照。
- **手机号一律打码**（`138****1234`），流水描述里出现的也要打码；不贴钱包 ID 之外的内部密钥或服务器配置。
- 正常时报告控制在一屏内，不要把每段原样贴出来。

## 红线

- 只读：不改钱包、不改冻结、不补扣不退款、不重跑任务、不重启服务、不发版。发现问题只报告。
- 不在命令行、报告或日志里输出服务器 env 的任何值。
- ssh 断线就重试一次，还不行报告「本次未能连上服务器」，不要换别的方式连库。
