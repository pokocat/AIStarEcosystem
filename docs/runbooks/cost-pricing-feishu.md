## 2. 填写与计算

### 2.1 采购价输入

「模型规格成本」关键列：

| 列 | 含义 | 编辑规则 |
|---|---|---|
| A–F | 规格 ID、供应商、端点、实际模型、状态、规格 | A 为稳定 ID；不能仅靠展示名称或行号匹配 |
| G/H | 预算功能类 / 业务计量单位 | 用于资源分摊和路由单位校验 |
| I/J | Token 或按单位 / 人民币或供应商点 | 不把供应商点等同于平台积分 |
| K | 每计费单位报价 | 按张、秒、次等；未知留空 |
| L/M | 输入/输出报价，每百万 Token | 分开填写，未知留空 |
| N/O | 每业务单位预算输入/输出 Token | 默认 2000/1000 是可替换假设，多轮和内部调用需合计 |
| P | 额外单价折扣 | 默认 1；净价或兑换已含的同一折扣不能再扣 |
| Q | 人民币换算率 | 自动；人民币为 1，供应商点引用结算表 |
| R | 净人民币采购成本/业务单位 | 自动，不含自有资源、损耗及免费补贴 |
| S/T/U | 资源分摊 / 完整成本 / 建议积分 | 自动，不得改成静态数 |
| V/W | 报价状态 / 能力边界 | 未绑定、停用、单位待核等须保留 |
| X/Y | 生效日期 / 报价来源或原有配置参考 | 原有估算字段仅作参考，不自动当合同价 |
| Z | 每业务单位消耗的计费数量 | 默认 1；单位换算/多次调用要说明依据 |
| AA/AB | 拟采用用户积分 / 配置流程状态 | 默认空 / 待核价；建议值不等于已发布值 |
| AC/AD | 配置目标限制 / 执行回执证据 | 供未来 AI 做配置差异及记录结果 |
| AE | 建议积分等值人民币 | 自动 = U ÷ 每元积分；2026-10-25 追加在表尾，不改原有列 |

供应商报价为点时，结算表填实际支付人民币和实际到账可消费点数（含赠送），人民币/点 = 实付金额 / 到账点数。同一供应商不同合同或余额池价格不同，要另建结算标识，不能强行共享兑换率。

价格未知用空白；**0 只代表确认零采购成本**。平台本机的 FFmpeg/分发外部模型费为 0，自有资源仍须付费。数据库中成本字段 0 通常代表未配置，不是免费。低于整数微元的采购价换入系统前须明确舍入。

按分钟采购但业务按秒时，可用 Z=1/60 归一。最低起扣、时长取整、分段阶梯不能一律用固定系数替代，应按实际任务规格/长度测算有效成本。不同缓存、上下文、音频、参考图或画幅若收费不同，应另列规格。

### 2.2 公式

```text
按单位净采购成本 R = K × Q × P × Z
Token净采购成本 R = (L × N + M × O) / 1,000,000 × Q × P × Z
完整成本 T = [R × (1 + 模型额外损耗率) + S] / (1 - 免费使用比例)
建议积分 U = ROUNDUP(T × 每元积分 × (1 + 充值赠送比例)
                    / (1 - 支付费率 - 目标技术毛利率), 0)
业务加权采购成本 = 主成本 × 主比例 + 备成本 × (1 - 主比例)
```

供应商额外损耗、免费用量补贴、充值赠送是不同因素。技术毛利已扣模型、资源、免费使用和支付费用，未扣人力、推广和税费。不要把成本加价率当成毛利率。

S 按预算功能类引用「定价建议」的资源分摊，并非逐规格实测 CPU/带宽数据。更大图、更长视频需要校准「参数与用量」的产物体积、资源权重、时延和每任务单位数。各备选模型的 S 仅作比较，**不能把所有 66 行的资源成本直接加总**；月总额通过业务分配与实际规划用量计算，避免重复分摊。

供应商 GPU 已包含在外部 API 价格中，不再加一份自有 GPU。自有机器负责应用、数据库、缓存、上传下载、FFmpeg 和媒体存储/分发。

表内每单位取整是保守预算；真实任务先合计后取整。完整作品需计入实际调用次数，但编排层不能再收一遍已计入子任务的成本。

### 2.3 快速定价（只算单价）

「快速定价」子表给“拿到一个供应商报价，想知道该定多少积分”用。黄色格只需填：报价（每计费单位）、折扣（5折填 50% 或 0.5，空 = 不打折）、计费单位；报价是供应商点时再选币种和结算供应商；想计入自有云资源就选预算功能类（不选则云资源按 0，并在备注里提示）。

结果列与「模型规格成本」R/T/U 同一套公式，参数引用「参数与用量」B6:B12：采购元 → 完整成本 → 精确积分（未取整）→ 建议积分（向上取整）→ 等值人民币（= 积分 ÷ 每元积分）→ 售价 ÷ 采购价。填「拟采用积分」可以看这个价下的技术毛利：`1 - 支付费率 - 完整成本 × 每元积分 × (1+赠送) ÷ 积分`。页面上方回显当前全局口径，每元积分不等于 100 时会写明「注意」。

例：Seedance 2.0 720p 官方 1 元/秒、5 折，功能类选「视频 768p」：采购 0.5 元/秒，完整成本约 0.591 元/秒；1 元 = 100 积分、60% 技术毛利时建议 151 积分/秒（约 1.51 元/秒，约为采购价 3 倍）。

这一页只算单价，不进入业务分配和月度预算。确认后的报价仍要填到「模型规格成本」K/L/M 并在「业务模型分配」里选上，才会影响月度损益。表中示例行是用户口述价，未核合同。

### 2.4 业务选择与缺价

在「业务模型分配」C/E 填规格 ID，D 填主模型比例；默认主占比 100%，备用占比 0 时不要求备用报价。I 自动计算加权成本，传到「参数与用量」D，再带动「定价建议」。

缺采购价、未选模型、比例错误、单位不匹配或选择已停用模型不能变成零成本。只要非零业务量存在缺价，完整总成本和利润必须显示缺采购价。音乐暂未接入且规划用量为非零，因此未补齐或明确设为零用量之前，总预算保持不完整。

## 3. AI 维护在线表的步骤

1. 读本手册和表内操作说明，再读取工作簿元数据、真实表名、目标范围的值/公式/样式。不得依据旧行号直接覆盖。
2. 保存修改前 revision 和目标单元格快照。只改用户授权的输入及必要公式依赖；不重新排列、重编号、删除旧模型或原工作表。
3. 新增模型先核对 endpointId、default_model、供应商、请求规格、计费规则与状态。复制同类公式/样式，分配新的稳定规格 ID，并扩展业务分配查找范围。
4. 批量写入后真实回读。CLI 的成功仅代表受理，不能代替结果验收。
5. 运行 `lark-cli sheets +formula-verify` 覆盖所有已用区域，必须 `status=success`、`total_errors=0`、`has_more=false`。扩表后更新范围，不能一直只扫原区域。
6. 按下述联动测试核对结果，恢复临时输入，再回读确认未知报价仍为空。记录变更范围、数量和验证结果。

当前表可用的只读检查（先 `lark-cli doctor` 检查认证；不把 Token/Key 放入表格或文档）：

```bash
lark-cli sheets +workbook-info --as user \
  --spreadsheet-token FjgmsKJSehM6Lutc8NJcGVnNnzf
lark-cli sheets +formula-verify --as user \
  --spreadsheet-token FjgmsKJSehM6Lutc8NJcGVnNnzf
```

### 4.2 采购成本映射

当前仓库 `ModelManagementService` 的 `endpointCosts` 操作调用 `AiModelEndpointAdminService.updateCosts`，字段：

| 目标字段 | 表格来源/单位换算 |
|---|---|
| supplierBillingMode | 核实后的 TOKENS / PER_CALL / PER_SECOND / AUTO |
| promptTokenPriceMicros | L × Q × P（人民币/百万Token）× 1000，转整数微元/千Token |
| completionTokenPriceMicros | M × Q × P × 1000，转整数微元/千Token |
| unitPriceMicros | 对应实际计费单位净人民币报价 × 1,000,000 |

Z 是预算业务单位转换，不应无条件乘进按供应商实际单位保存的成本字段。不要把含损耗/补贴/资源的 T 当作采购单价。请求中未使用的价格字段也须依据原配置与真实模式填妥，不能以“未知”填 0。

**一个端点目前只有一组成本字段。** 若该端点多个尺寸/模式采购价不同，不能按表格逐行循环覆盖同一个端点，造成“最后一行获胜”。须先使用系统已有的规格成本能力（如当时已实现），或扩展模型，或在用户认可的用途内采用明确标注的估算口径。
