# Studio 复用 AI 军师微信商户接入手册

Last reviewed: 2026-10-30。状态：代码已生产发布（`20261030-studio-wechat-pay`），2026-10-30 23:02 起线上启用微信扫码支付，已完成一笔真实付款、入账、退款与回调验收（见「线上验收」）。

## 选择与范围

用户确认复用 `ai-pilot` 的商户主体，不使用主理人公社商户。复用商户和安全配置；Studio 自己创建充值订单、接收通知、记自己的积分账本，不调用军师充值接口、不复制军师订单或钱包。技术参考为 `../ai-pilot/server/src/services/wechatPay.ts`；本仓继续使用现有微信 Java SDK。

本批入口是 `/studio#/membership` 的电脑扫码收银台（`WX_NATIVE`）。小程序 JSAPI 已可支付，不代表 Native 产品权限已开通。微信官方 Native 接入说明允许绑定的小程序 AppID 用于 Native 下单，前提仍是商户已开通 Native 且 AppID 与商户关联正确。

## 商户后台先完成

1. 登录用户确认的军师商户，在「产品中心」申请/开通 Native 支付，并确认原小程序 AppID 的关联状态。
2. 在「账户中心 → API 安全」获取微信支付公钥和公钥 ID（`PUB_KEY_ID_...`）。这是微信支付的公钥，与商户自己的私钥/证书序列号不同；无需为复用另行轮换军师私钥。
3. 资料通过受保护的运维配置或管理后台填写，不在聊天、日志或版本库中粘贴 API v3 密钥和私钥。

## Studio 配置对应关系

管理后台现有支付渠道页的 `wechat` 配置，默认方式选 `WX_NATIVE`。凭据继续加密存入 `payment_channel_config`，无新增表/迁移。管理页面只回显掩码；留空保留原值。

| ai-pilot 来源 | Studio 字段 | 处理 |
|---|---|---|
| `WECHAT_MINI_APPID` | `appId` | 复用军师 AppID，核对商户绑定 |
| `WECHAT_PAY_MCHID` | `mchId` | 复用用户确认的商户 |
| `WECHAT_PAY_APIV3_KEY` | `apiV3Key` | 通过安全配置搬运 |
| `WECHAT_PAY_CERT_SERIAL` | `merchantSerialNumber` | 商户证书序列号 |
| `WECHAT_PAY_PRIVATE_KEY` | `merchantPrivateKey` | 保持有效 PEM 内容 |
| 商户后台公钥 ID（军师支持 `WECHAT_PAY_PUBLIC_KEY_ID`） | `publicKeyId` | 与下面公钥成对填写 |
| 商户后台公钥 PEM（军师支持 `WECHAT_PAY_PUBLIC_KEY`） | `publicKey` | 本批新增 SDK 公钥模式支持 |
| Studio 公网 API 域名 | `notifyUrl` | `https://<Studio API origin>/api/pay/notify/wechat`，必须实际路由到本仓 server，不能复制军师通知地址 |

公钥两项齐全时选 `RSAPublicKeyConfig`；只有一项不允许启用；都没填时保留旧商户自动平台证书模式。后台的“已配置”只验证字段完整性，不验证 Native 权限或商户真实性。先完成商户操作和配置检查，再启用渠道。

## 本地实现

- 会员积分页列出后台可用的微信/支付宝，微信显示 Native 二维码；不会因为展示二维码或客户端按钮就发积分。
- 订单号留在 `rechargeOrder` 查询参数，关闭弹层不取消订单，刷新可恢复；轮询本地订单，用户可主动查渠道付款结果；收到 `paid` 后刷新余额。
- 微信下单前写入关联标识，网络异常保留原待支付单；同套餐重试复用原商户订单号，不允许把该单改为另一渠道。
- 查单和回调校验商户、AppID、订单、人民币金额及渠道流水；回调与对账仍复用条件更新 `markPaid`，积分结算只有一条路径。
- 过期微信订单仍先查单；超时关闭、用户取消、后台驳回先请求微信关单，关单失败保留本地待支付。并发取消后才返回的预下单不得把二维码交给用户。

## 上线与真实验收

2026-10-30 已合入 main：服务端支付测试（含企业充值与 Spring 上下文场景）102 个、前端钱包与计费测试 40 个、web-aiavatar / admin 类型检查、服务端编译与接口契约检查通过。同日从干净 main 构建并发布 server、admin、web-aiavatar，见 [发布记录](../releases/studio-wechat-pay-release-20261030.md)。

对现有支付宝的影响（生产当前只启用了支付宝，没有微信渠道记录，微信分支在线上不生效）：

- 会员与积分页点「立即充值」先弹出收银台选择支付方式，再跳转支付宝收银台，比原来多一步。
- 同一套餐 30 分钟内的待支付订单仍复用；查单补单多核对金额与交易号；对账不再跳过超过 30 分钟仍待支付的订单（这类订单正常会先被超时关单）。
- 本地开发的影子渠道只在演示模式（`NEXT_PUBLIC_USE_MOCK=1`）下可用，真实模式的收银台只列微信和支付宝。

商户权限与公钥齐备后，验收应记录我方订单、微信交易号、到账余额与账本条数，避免在记录中保留签名/凭据：

1. 正常充值生成二维码，真实付款；验证通知验签通过、订单 PAID、充值积分及赠送积分各按快照只发一次。
2. 同一通知重投、查单与通知重合，不重复加积分；错误金额、其他 AppID/商户、篡改报文都不入账。
3. 用户关闭后重开、刷新页面、首次下单超时后重试，仍对应原待支付单；取消和超时必须验证微信侧确已关单、旧码不可再付款。
4. 暂时收不到通知时主动查单/定时对账正确到账；支付平台无法访问时显示待核对，不能冒充未付款或成功。
5. 核对军师原小程序支付仍正常。相同商户不应改变军师回调、订单和账本。

本批不等于手机浏览器 H5 / 微信内 JSAPI 已验收：前者还需 H5 权限、域名和真实客户端 IP 传递，后者还需当前 AppID 对应的 OpenID。手机上的二维码也不等于已接手机内唤起支付。

退款继续走当前人工现金退款与账本回收流程；本批没有新增微信退款申请、回调与退款对账。支付宝是独立商户应用/签约/签名配置，微信凭据不能复用到支付宝；其真实支付/回调/退款验收仍需独立完成，可参考 [支付宝沙箱手册](alipay-sandbox.md)。

## 线上验收（2026-10-30）

用户开通 Native 支付、申请微信支付公钥后，后台「支付配置」由用户本人填写 APIv3 密钥、商户私钥、公钥 ID 与公钥，其余字段由我方填写；回调地址 `https://api.aibuzz.cn/api/pay/notify/wechat`，默认扫码支付，23:02 启用。

| 时间 | 结果 |
| --- | --- |
| 23:03–23:10 | 下单被拒：`Validate response failed, the WechatPay signature is incorrect`。SDK 未记「publicKeyId 与 serialNumber 不一致」，即公钥 ID 正确、公钥 PEM 不是这个 ID 的那把。用户重新下载公钥并重贴后恢复；失败期间只有这一笔测试单，订单保持待支付，后续重试复用同一单。 |
| 23:12 | `native prepay ok`，二维码生成，应答验签通过。 |
| 23:15:58 | 用户扫码付款 ¥99（体验包），点「我已支付，刷新结果」主动查单入账：订单 `ro-063664d9-d67` PAID、`paid_via=wechat`、交易号已记录；只有一条 `RECHARGE +10000`。角标按 15 秒轮询稍后更新。 |
| 付款后 | 微信一直没有发付款通知：nginx 无任何回调请求，TLS 与 DNS 正常。原因是商户平台「API 安全 → 解密回调」的 APIv3 密钥**未设置**（军师 `.env` 里虽有值，平台侧从未设）。没有它微信不发 APIv3 通知；查单不受影响，后台每 20 秒的对账也会兜底入账。 |
| 23:28:50 | 按用户要求在后台退款：订单 REFUNDED，`REFUND_CASH -10000`，钱包回到付款前；现金由用户在商户平台按商户订单号原路退回。 |
| 23:29:57 | 用户在商户平台设置 APIv3 密钥（与军师 `.env` 同值）后，微信从 `121.51.30.172` 补发原付款通知：验签与解密通过，识别为已退款订单的同一交易，回 200，未重复入账。 |

结论：下单、二维码、查单入账、后台退款、回调验签解密都已在生产走通。尚未覆盖：通知先于查单到达时由回调直接入账（下一笔真实付款可观察 `[pay][wechat-notify] settled`）、超时关单在微信侧确实关闭、军师小程序在设置 APIv3 密钥后的回调处理。
