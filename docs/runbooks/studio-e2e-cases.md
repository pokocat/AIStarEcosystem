# Studio 端到端测试用例

> 用途：发布前按用户的真实路径把这些场景从头点到尾。单测和结构测试只证明「挂上了」，不证明「用起来对」（AGENTS §8.0.1 ⑭）。
> 做法：浏览器面板或无头浏览器（CDP），**每一步读 DOM 状态**（焦点在哪、面板开没开、节点在不在可见区域、按钮是否可点、提示写了什么），
> 不只看最后一张截图。涉及积分的场景，开始前和结束后各记一次钱包余额与账本条数，核对差额。
>
> 环境：本地 `pnpm dev:aiavatar` + `apps/server` 起 dev profile；需要真模型的场景用受控测试身份和明确预算。
> 每条用例写清楚「前提 → 步骤 → 每步要看到什么」。测完在「记录」一列写日期、环境、结果；没测就留空，别写「通过」。

### 1.4 Codex 2026-10-19 报的六个对话 / 制作问题（本地已修，未发布）

服务端和前端都改了，要一起发 server + web-aiavatar。单测见 TODO.md 对应条目；这里是按真实路径的验收。

| # | 前提 | 步骤 | 要看到什么 | 记录 |
|---|---|---|---|---|
| 1.4.1 | 一次复刻做到制作阶段、第 1 段已出片 | 制作中打「第 3 段换个人物」 | 进度条停在「收到新指令」，助手给出新一版方案和确认卡 | |
| 1.4.2 | 同上 | 点新卡「开始制作」（或打「可以」） | 不再报「同阶段不能换计划」；还是同一次制作；第 1、2 段不重做，第 3 段及其检查重做；已花的积分不变 | |
| 1.4.3 | 第 3 段正在生成时 | 让助手出新方案并确认 | 提示「还在生成中，等它做完后再确认」，原任务照常完成 | |
| 1.4.4 | 企业付款确认的制作 | 制作中继续和助手聊几句 | 每轮对话从企业积分扣（看企业流水），个人余额不动 | |
| 1.4.5 | 把上限设得刚好不够 | 等它停在「预算不够」，点追加预算卡（或打「可以」） | 不用再点「继续制作」，执行自己接着往下做 | |
| 1.4.6 | 自己点了「暂停」后又追加预算 | 确认追加卡 | 仍是暂停，点「继续制作」才往下 | |
| 1.4.7 | 制作中有排队的任务 | 打「先停」 | 马上停下，排队的任务被取消，回复「好，停下了…」；不扣对话费 | |
| 1.4.8 | 同上 | 分别打「暂停一下」「不要停」「要停吗？」 | 第一句暂停（排队任务保留），后两句当普通消息处理 | |
| 1.4.9 | 助手模型能选（多个候选） | 切到较便宜的模型发一句 | 请求体带 `model`，服务端用的就是它（看任务记录的端点），不报「价格变化」 | 2026-10-19 本地部分：切第二项后端使用 Agnes 3.0 且结算正常；两个选项都显示“未命名模型”。见[记录](../audits/studio-local-full-e2e-20261019.md)。 |
| 1.4.10 | 断网或让保存接口返回 500 | 助手把节点放进画布后，关掉标签页再打开 | 节点被补回来，不会因为「已投影」记录而缺失 | |
