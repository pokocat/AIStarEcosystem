## 1. 本次确认的业务主线

打造数字 IP，然后用同一个 IP 衍生数字人、带货视频、短剧及其他生态应用。

LibTV 的剧本、图片、视频创作体验是对标重点。产品围绕 IP 身份与资产复用组织这些能力：

```text
创建 IP → 定稿设定与形象 → 持续衍生与创作 → 生态应用消费 → 作品回流
```

IP 可以先有人物和形象，再写故事，也可以从已有剧本提取人物设定后打造 IP。图片创作和视频创作可单独使用；写剧本不应成为所有创作任务的前置条件。

### 超长视频：2026-10-08 追加观察

### IP 档案与资产

IP 是持久身份。档案应承载名称、定位、人物设定、主形象、已选定的造型、声音和风格，并关联场景、产品及创作作品。具体资产沿用现有六类资产模型和成员关系。

创作中的候选图、试验提示词与正式选定的主形象要区分。用户主动定稿后才成为下游默认采用的资产；新尝试不应静默替换已采用的形象或声音。

| 流程 | 输入 | 产出与后续 |
|---|---|---|
| 剧本创作 | IP 设定、创作想法或已有文本，以及用途、受众、结构等要求 | 可编辑大纲、人物与场景设定、分集/场次内容；角色和场景能进入图片创作，镜头内容能进入视频创作 |
| 图片创作 | 当前 IP 的主形象或明确选中的参考素材，加一段完整指令 | 主形象候选、造型、表情、多角度、场景或分镜图；选择后加入相应 IP 资产，或继续用于视频 |
| 视频创作 | 当前 IP 资产、明确选中的参考素材、剧本/镜头内容及模型支持的参数 | 视频作品与版本；可继续迭代，或交由对应生态应用完成业务流程 |

标准创作面板把指令、素材引用、模型参数、任务状态和结果放在一起。选择 IP 后带入其已定稿资产，并清楚显示此次实际采用的素材。画布保留为进阶编排空间。

### 生态应用

- 数字人：采用 IP 指定的人物形象与声音；训练、音色、驱动能力的就绪状态分别展示。
- 带货：采用 IP 人物，组合当前产品、卖点、脚本和场景；带货业务继续由对应应用承接。
- 短剧：采用 IP 人物与世界设定，结合剧本、场景和分镜；短剧制作流程继续由对应应用承接。
- 其他应用：复用同一资产档案及允许的授权范围。

每次创作记录具体采用的资产与版本，作品回流到来源 IP。更新 IP 时保留既有作品的来源记录；下游正在制作的内容不应被自动替换。

## 4. 初始调研时的基础与衔接缺口（2026-10-07 历史记录）

以下记录初始调研时的代码事实，不作为当前未完成清单。当前 Studio 已通过 `StudioWorkflowService.adopt()` 创建/关联 IP，并接通剧本/助手任务及资产衍生；通用旧 `IpPublishService` 和旧看图分支不等于整个 Studio 的现状。当前实施及剩余差距见本文顶部与统一验证记录，仍不能据此声称已部署或全量 LibTV 对齐：

1. **已有 IP 容器。** `DapAssetIp` 与 `DapAssetService` 支持创建 IP、关联人物/场景/产品，声音随所绑定人物归入 IP。应复用这套模型。
2. **画布发布目前落成人物。** `IpPublishService.publish()` 创建 `DapAvatar`、`DapLook`，登记视频衍生物，再回写 `publishedAvatarId`；该路径没有创建或关联 `DapAssetIp`。需要把画布产物和 IP 档案接起来，并明确“创建新 IP / 加入已有 IP / 采用为主形象”的行为。
3. **画布缺少已接通的文本生成。** 文本生成分支调用的 `requestImageQuestion()` 当前明确抛出“看图对话还没开通”。完整剧本模块还需要后端生成、编辑保存、任务恢复，以及角色/场景/镜头到资产的业务映射。
4. **图片与视频有可复用底座。** 已有参考图、模型选择、云端保存、生成历史、视频版本等能力，可用于新的任务入口。
5. **视频原生模式已补齐（v0.208，本地）。** Studio 与原生节点复用 H3 模式/素材限制/定价，首尾帧与图片/视频/音频参考均携带 storage key 提交；非支持模型明确拒绝多份参考。真实厂商成片此次未新增验收，见 `ip-studio-video-modes.md`。
6. **生态衔接需逐条验收。** 本轮尚未核对带货与短剧入口能否直接采用指定 IP 及资产版本，也未验证作品完整回流。后续必须以真实业务路径确认。

## 5. 建议实施顺序与验收

1. **先完成 IP 创建与形象衍生闭环。** 新用户创建 IP、制作主形象、选定造型、保存后重新打开；档案及素材关系完整，后续生成默认采用已选资产，不要求手动连线。
2. **接入剧本创作。** 从指定 IP 开始原创或导入文本，编辑保存大纲、人物、场景和分集内容；刷新后可继续创作，后续出图明确使用所选角色和设定。
3. **完善视频创作。** 从 IP 形象或分镜图进入视频创作，素材、指令和可用参数明确；任务刷新后恢复，结果与版本可追溯。
4. **接通生态应用入口。** 同一 IP 可进入数字人、带货、短剧应用，带入指定资产；各应用按真实能力展示可用状态，完成作品能找到来源 IP 和所用素材。

实施时沿用后台模型配置、服务端积分账本、资产归属校验、异步事务派发、存储 key 和签名 URL 纪律。历史画布继续能读、能改、能查原来的产物；新增标准流程复用现有生成链。

以上为当时调研后的提案；后续实施与发布状态以各版本验证记录及生产发布记录为准。

2026-10-08 补充观察：LibTV 视频数量提供 1、2、4；运镜为输入框的命名指令标签。特效库包含作者、特效广场、收藏、最近使用与模型限制，不能用一个通用文字下拉冒充同等能力。多候选视频已按原生 Job 批次接通；运镜命名标签已按自然语言正文落地（v0.211 本地），特效继续作为独立模板资产能力推进。

### v0.217 · Studio 对话快照分享（2026-10-08，本地未发布）

助手历史旁“分享”仅在完成一轮对话后开放。先保存画布并预览服务端白名单文字快照，再明确创建链接；任何获得链接的人可匿名查看对话和创作建议。V47 新增 `ip_conversation_share` / `ip_conversation_copy`，不修改原画布、素材和积分。24字节随机 token，同内容发布幂等；更新快照撤销旧链接，撤销和源画布删除使公开读取失效。公开 GET 仅豁免精确路径，返回 no-store/noindex；复制和管理保留登录、aiavatar 开通、手机绑定及本人归属检查。

快照不含源节点、素材 key/URL、请求、模型、任务或账号字段，原参考绑定替换为重新选择提示。公开页“在 Studio 中继续创作”将文字与建议复制到本人新画布，创建新节点 ID并直接打开助手，无媒体和执行请求，未自动生成；同 owner/clientRequestId 幂等，浏览器 session 保留复制键以供失败/刷新重试。复制内容仍需显式选择本人参考素材、模型并确认费用。分享后新增消息不会自动公开，未发送草稿不进入快照。

这是 Studio 自有分享闭环；LibTV 当前可见“空对话不能分享”入口，但调研账号无历史，本轮未为探测弹窗调用模型，不能宣称其分享表单的所有行为逐项一致。公开画布与复制、社区展示仍是独立待办。验收见统一验证§28。
