# 模型赠款与折扣：收敛设计稿

状态：2026-10-25 已合入 main（`94afa651`）并生产发布 `20261025-model-grants`（server / web-aiavatar / admin / web-drama），发布记录见 `docs/releases/model-scoped-credits-production-release-20261025.md`。

## 唯一标识与价格来源

**用户已确认：以现有模型接入点记录的 ID（`endpointId`，`AiModelEndpoint` / `ai_model_providers.id`）为唯一适用标识。** 接入点已关联模型及 API 配置，直接与现有后台模型行对齐，不新增一套模型身份。

赠款与折扣仅匹配接入点 ID；同名但不同接入点分别处理。应用、对话/脚本/工作流、操作类型、规格、计量单位不决定赠款或折扣资格。模型名、API、规格和计量方式可以记录在任务快照中，用于计价与对账。

价格沿用该接入点关联的现有价格配置，不新增第二套标准售价来源。

## 规则

- 赠款绑定账户和接入点 ID，单独记录数量、剩余、冻结和到期时间，不计入普通余额。
- 同一模型用于对话、脚本、工作流或其他入口，使用同一套赠款与折扣规则。
- 模型售价先按 Token、秒、张或次换算成积分，再应用折扣；未过期的模型赠款优先抵扣，不足部分扣普通余额。
- **用户已确认**：同一笔消费命中多条折扣时，只取最优惠的一条，不叠加。
- 同一模型的赠款按最早到期优先使用；用完结束，到期的剩余额度作废。充值余额不受影响。
- 企业按接入点 ID 配置折扣，主账号、现有及新加入的子账号使用企业余额时统一生效；个人余额按个人规则处理。
- 失败按原资金来源释放，已过期赠款不恢复为可用；重复请求不重复扣费。

## 职责与配置

统一模型计费服务接收实际接入点 ID、付款账户、服务端用量/估算和请求编号，集中完成报价、冻结、结算和释放。各入口传递模型信息，不各自实现优惠规则；现有对话预算和任务流程继续复用。

后台沿用接入点及其价格配置；赠款发放和账户/企业折扣选择同一接入点。用户赠款的数量、余额、冻结与有效期单独记在赠款明细中，并引用接入点 ID，不把各用户余额塞进公共接入点记录。应用、调用方式和任务类型是查询记录，不是赠款资格条件。供应商资源池、分场景赠款和对话预算重构不纳入本次范围。

## 本次实施边界

只调整统一模型计费与赠款/折扣配置，不重做对话预算，不按产品入口分别开发赠款规则，不增加供应商资源池设计。现有入口只需向统一扣费层传递实际接入点；异步冻结、成功结算和失败释放共用一套账务实现。

验收聚焦：同一 Qwen 接入点在不同调用入口能使用同一赠款；另一个接入点不能使用；H3 赠款不抵扣 Seedance；到期作废；赠款不足余额补差；企业主账号与子账号统一折扣；不叠加折扣。

## 当前实现与运行限制

- 统一匹配、最优折扣、赠款批次、到期作废、原来源释放、个人/企业钱包隔离已接入；旧独立价格表不参与定价。
- 后台从现有接入点目录选择，模型行「赠款与折扣」进入后预选该行；新活动不配置供应商资源。
- Studio 图片、视频、配音、口型、有界文本和对话使用统一模型计费。对话追加冻结沿用首次折扣，整笔结算一次取整；现有对话预算不重做。
- 短剧写作、画布出图、角色参考图、素材起稿、音乐和视频智能优化均传实际接入点及原费用，生成沿用同一路由；不另写各入口优惠规则。
- **用户已确认拆分**：数字人组合任务的文本处理和图片/视频生成分为两笔模型消费。文本沿用原 Token 单价、按实际输入输出用量结算；媒体阶段沿用原生成价格。两笔分别匹配自身接入点的折扣与赠款；文本成功后媒体失败，仅释放媒体冻结，保留已完成文本的实际费用。两笔预冻结在同一事务内，不足时整体回滚。
- 已释放的模型视频冻结：原冻结用过赠款或折扣的需人工复核原资金来源，不能按新价格自动恢复收费；按原价、没用赠款的照旧走恢复冻结。

## 评审后修正（2026-10-25）

- 企业成员报价改用不加锁的在途任务查询：报价是只读事务，MySQL 会拒绝其中的加锁查询，企业付款的图片和视频原本无法确认费用。新增 `EnterpriseModelQuoteReadOnlyTest`，可用 `-Dmodel-scoped.jdbc` 指向 MySQL 跑。
- 视频对账恢复只拦用过赠款或折扣的任务（`ModelChargeService.usedPromotion`），原价任务恢复不受影响。
- 冻结时只锁本钱包可用且适用的赠款行，只有带资源计数的活动才锁活动行；到期清理不再锁活动行。
- 活动发出赠款后适用接入点锁定（`SCOPED_CAMPAIGN_TARGETS_LOCKED`），后台表单同步置灰。
- 赠款全额抵扣时不再写零金额的普通流水；短剧积分明细与后台流水把赠款行的余额标为「赠款余额」，短剧把「模型赠款扣除」也当作冻结结算显示。
- Studio、后台、短剧与服务端报错统一叫「模型赠款」；celebrity 按用户要求不改。
- **通用积分转模型赠款（2026-10-25）**：`ModelGrantConversionService` + `/admin/model-billing/conversions{/candidates,/preview,}`，仅 SUPER_ADMIN。只转赠送与激活码积分、保留 1000 通用积分、充值积分不动；每客户独立事务，ADJUST 扣款与赠款发放同事务，`ops_grant_conversion:<requestId>:<userId>` 幂等。规则见 `specs/BUSINESS_RULES.md`「模型折扣与模型赠款」。
- **零价接入点报错（用户 2026-10-25 拍板）**：零价一律 503 `MODEL_PRICE_NOT_CONFIGURED`，免费只能发模型赠款，免费额度因此有总量和有效期。企业零价测试改为断言拒绝且不留授权、冻结和在途占用。上线前要确认线上没有零价接入点。
- 接入点没填 `model` 时，计费记录用 `endpoint:<接入点 ID>` 作模型名，构造与比对都走 `ModelBillingTarget.providerModelOf`；后台活动也能选到这类接入点。
- **上线即坏的隐患（已修）**：V67 在 MySQL 上把流水类型列改成 VARCHAR，但启动时的 `EnumColumnWideningMigration` 会把它改回不含 SCOPED_* 的 ENUM，第一笔赠款入账就报 `Data truncated`（MySQL 全流程场景测试复现）。流水类型已从启动加宽清单移除，加宽也只处理当前确实是 ENUM 的列；守门测试改为钉住「流水类型保持 VARCHAR、不被改回 ENUM」。

初始复杂方案已移到 `docs/archive/model-scoped-credits-initial-design.md`，仅作历史追溯。实现状态以当前代码和最终核验结果为准；历史开发记录不能作为现行设计的交付证明。

## 本轮本地核验（2026-10-25）

统一计费、迁移、额度与企业接口定向回归 55 项通过；短剧、素材起稿、音乐及视频优化的相关存量回归 146 项通过；后台配置页 10 项通过，含从模型行进入后预选同一接入点。此前对话与文本的 71 项定向回归已验证追加冻结与整笔取整。工作区类型检查、后台类型检查、API 契约检查均通过。没有调用收费供应商，没有提交或部署；不能把这些本地结果当作生产验收。数字人组合计费已继续按用户确认的拆分方案收尾。

数字人拆分增量：`DapModelBilling` 只编排两笔现有模型账务，折扣和赠款仍由统一 `CreditService` 决定。文本与媒体各自固定实际接入点，客户端不可更换；付款后默认模型、地址或型号变化不会悄悄改路由或回退占位。文本使用原 Token 价格与上限，不新增标准价配置。重试使用新的尝试编号，两笔分别记账；重复结算不重复扣费。数字人账户月用量读取实际消费流水，包含媒体失败前已完成的文本费用。

最终拆分核验：文本/媒体分别扣款、Qwen 赠款不抵媒体费用、媒体失败保留已完成文本费用、同一尝试重复结算幂等、重试固定原模型与标准价、两笔冻结资金不足整体回滚均通过。最后一轮定向回归 8 项通过，完整应用启动及企业折扣用例另 1 项通过。四门检查通过；未合主线、未部署。文本回执和媒体回执均进入同一模型账本，已退款的视频仍按上文进行人工资金复核，不会换用新赠款自动补扣。
