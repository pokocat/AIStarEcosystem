### 0.2 重写的边界

重写画布渲染与交互层：由 React Flow 管理节点几何、选择、连线与视口，由一套 Studio 创作面板管理提示词、参考、参数及打开/返回。旧画布创作面板不再与新面板同时控制同一个节点。React Flow 本身不提供人物库、模板或剧本业务，这些仍需要本平台实现。

v0.222 修正此前默认右侧抽屉的交互偏差：单击节点在画布内打开无蒙层浮层，浮层以屏幕尺寸显示并跟随节点移动、画布平移与缩放；图片/视频默认依次显示参考、提示词和折叠参数，模型、报价与提交固定在底部。助手默认可拖动浮窗，只有用户点击“停靠到右侧”才停靠；任务与连续制作也使用无蒙层浮窗，普通节点选择不强制关闭它们。人物库取消/选用返回原节点，保持草稿和视口；普通文字与已完成剧本先就地编辑/预览，显式展开才进入大编辑器。

保留账号/开通、IP 资产、项目文档格式、云端保存/版本、存储 key、生成任务、幂等、积分账本、供应商接入和合成服务。旧画布数据与进行中的任务必须可恢复；换界面不得重新提交原任务。当前保留旧源码是迁移依据，不代表运行时同时维护两套创作面板。

此前冲突主要是原生画布面板与 Studio 新增面板的状态、入口及浮层定位相互竞争，以及两套样式规则的优先级问题。整仓推倒会重做已验证的资产/任务/结算能力，不能据此判断更快。交互层集中重写可减少持续兼容旧面板的工作，但仍需验证旧数据与现有工具迁移。

### 0.3 执行与验收

按四条完整动线连续交付：

1. 创建/选择人物 → 图片节点引用 → 生成与采用 → 加入人物库 → 在第二张画布复用。
2. 原创/改编 → 编辑设定与剧本 → 拆镜 → 人物/场景参考 → 图片 → 视频 → 合成与导出。
3. 套用人物/商品模板 → 填输入 → 确认实际步骤与费用 → 人工采用 → 继续视频/配音 → 重做指定步骤。
4. 成熟画布发布为个人模板 → 新项目套用 → 使用自己的输入继续，遵守模板版本、人物与素材引用规则。

开发中在完整动线结束时及时复查范围与实际可用状态，发现具体问题就定向修复；没有新改动或失败，不重复已通过的检查。完成一组动线后集中做桌面浏览器验收和必要回归，交付/提交前按仓库要求运行完整门禁。不再让每个小按钮单独经历全量构建、独立审查和文档交接，不为免费模型画质反复生成。进度按上述动线的用户可用状态报告，分别标明代码已接入、本地已验收、尚未完成、已发布，测试数量不代替功能交付。

后续先连续补齐功能，再集中验收一条动线，发现的问题一次修复并定向复验。每次进度只报告本次可操作的变化、仍未走通的部分和下一条动线；不把维护文档、审查次数或底层检查通过写成用户功能完成。不因无关历史样式提示扩大当前范围，桌面优先，不追加手机适配验收。

## 1. 决策与方案边界

本轮完成范围是上述五块可操作主线；厂商超长视频、完整社区特效媒体、Skill/插件、声音克隆及完整音轨/视频理解仍不在本地已交付能力中。新版没有以占位生成按钮冒充这些能力，也没有扩大手机验收。

### 1.1 产品定位

AI IP Studio 是围绕数字 IP 持续创作内容的工作空间。用户在画布上设计形象、编写剧本、制作图片和视频，把满意的资产定稿，再用同一 IP 创作不同作品。

统一后的主线：

```text
描述想法 / 上传素材 / 引用已有 IP
                 ↓
        画布内设计与定稿 IP
                 ↓
       剧本 ↔ 图片 ↔ 音频 ↔ 视频
                 ↓
   口播 / 单条短视频 / 带货 / 多集短剧
                 ↓
      合成、导出、作品归档与再次创作
```

剧本不强制前置：用户可以只做图片、直接图生视频，也可以先写剧本再提取角色。没有 IP 的临时创作允许先做，满意后再保存为 IP。

### 1.2 本轮明确的产品取舍

1. **画布是主要创作现场。** 标准操作由选中内容后的动作面板完成；手动连线属于可选高级操作。
2. **创作过程留在同一 Studio。** 长剧本、分镜、合成在当前项目内展开编辑器，不把用户送往另一子应用重新建项目、上传、绑定。
3. **IP 是长期资产，画布是创作项目。** 两者不一一对应；同一 IP 可参与多个项目，同一项目可引用多个 IP。
4. **复用现有能力与资产模型。** 前端承载沿用 `apps/web-aiavatar`，服务端复用 dap、ipstudio、drama 和通用视频能力；不另建同功能子应用。
5. **业务场景组合共用能力。** 数字人口播、带货、短剧通过模板、专用编辑器和必要业务规则形成差异。
6. **分阶段交付，首版必须能完成作品。** 只完成导航合并、画布换皮、按钮跳转或静态原型，不算首版完成。

## 3. 产品对象与关键业务语义

| 对象 | 定义 | 关系与边界 |
|---|---|---|
| IP | 持久的角色或品牌身份 | 复用 `DapAssetIp`；可关联人物、场景、产品等资产 |
| 人物 | IP 下的具体人物身份 | 复用 `DapAvatar`；一个品牌 IP 可以有多个人物，不能把 IP 永远等同于一张脸 |
| 造型与声音 | 可被选定的具体表现 | 明确形象版本、造型、声音；声音关联遵循现有模型 |
| 画布项目 | 本次创作的工作空间 | 复用 `IpProject`；包含素材、文本、业务卡片和引用关系 |
| 作品 | 有明确制作目标的内容 | 如一条短视频、一组带货版本、一部短剧；可引用多个 IP |
| 运行 | 一次已提交的生成或合成 | 绑定输入快照、费用与产物；复用各业务域运行记录 |
| 产物 | 某次运行得到的结果 | 候选图、音频、片段、成片；保留来源与采用关系 |

### 3.1 三种保存动作必须分清

- **保存到素材**：收藏或复用图片、文本、视频，不改变 IP 主形象。
- **加入 IP / 采用为主形象**：明确选择新 IP 或已有 IP；正式采用某个人物、造型或版本。
- **导出作品**：下载已合成的文件。与 IP 定稿、素材收藏及发布到外部平台分别处理。

不要用一个“发布”按钮同时表达上述三种行为。旧发布接口保留兼容；新行为单独定义契约，不直接删掉现有重复发布 409 的保护。

### 3.2 引用与版本

- 引用同一资产，避免让用户下载再上传；服务端按真实引用与授权规则校验。
- 新创作默认采用 IP 当前已定稿版本，提交运行时保存所用版本及素材 key 快照。
- 更新 IP 不改变旧作品和已提交任务。进行中的草稿提示可更新，由用户选择。
- 修改上游脚本或图片后，下游标记“内容已更新，可重新生成”；已有产物保留，不自动扣费重跑。
- IP、项目、人物的使用关系与资产所属关系分开；不要为了让第二个项目引用而重写资产的 `ipId`。
- 首版以本人资产为主。授权共享资产按已有授权机制处理，跨账号复用不通过放松归属检查实现。

### 3.3 数字人的含义

形象定稿不等于口播能力就绪。分别展示形象素材、声音、训练/驱动能力的状态；前置能力缺失时说明需要补什么。AI 原创与真人复刻走各自真实支持的链路，不能把任意图片默认承诺为可训练或可口播。

## 4. 信息架构与交互

### 4.1 工作空间入口

保留现有项目与资产入口，逐步将“继续创作”“新建”“我的 IP”“素材”“作品”组织为统一导航。沿用现有 `/projects`、`/projects/[id]` 等路由，不另建同 URL 的桌面/手机 route group。

新建提供空白画布和任务模板。首版模板为“IP 形象”和“IP 短视频”；数字人口播、带货、多集短剧在对应阶段接通后才提供可执行入口。

### 4.2 画布布局

```text
顶部：项目名 / 保存状态 / 历史 / 任务 / 积分
┌────────┬──────────────────────────┐
│ 可收起 │                          │
│ 的目录 │         创作画布         │
│ 与素材 │  IP、剧本、图片、视频分组 │
│        │                          │
└────────┴──────────────────────────┘
选中内容时：固定屏幕尺寸的创作面板
底部：添加 / 上传 / 模板 / 视图工具
```

- 默认突出画布；目录、素材、历史按需展开。工具条避免重复摆放相同操作。
- 创作面板集中显示指令、参考素材、模型、规格、价格、执行与停止，随选中对象变化。
- 面板不放入画布缩放层，避免缩小时输入框不可读；处理面板、底部工具和安全区遮挡。
- 简单动作自动建节点、接好引用、放到邻近空位并聚焦；不要求先造空节点再找生成入口。
- 连线表达引用或制作依赖，不自动触发付费执行。选中节点高亮其引用，复杂画布可暂时隐藏无关连线。
- 候选结果可以比较、采用和继续创作；采用第几张必须明确对应实际 storage key，重新打开保持一致。
- 沿用桌面 `.ip-surface` 视觉作用域和 `html[data-layout]` 判定，遵循 960px 默认断点及用户显式选择。
- 手机优先支持查看、选版本、改文案、查看任务和下载；继续保留进入画布的柔性提示，不新增设备硬拦截。

### 4.3 选中即继续创作

| 选中对象 | 主要动作 |
|---|---|
| 图片 | 改图、做造型、生成视频、加入 IP、设为主形象 |
| IP 卡 | 选择人物/造型、写脚本、做短视频；后续增加口播/带货/短剧 |
| 剧本卡 | 编辑、改写、提取角色与场景、生成分镜 |
| 分镜卡 | 编辑描述、指定角色/场景、出首帧、出视频、采用版本 |
| 视频 | 预览、选版本、加入成片、下载 |
| IP 与商品 | 后续阶段：卖点与脚本、商品场景图、带货视频 |

首版优先用通用节点的元数据与业务视图组合表达。确需新增业务节点时集中在 bridge/ip 层接入，不重新造第二个画布引擎，也不把 vendor 文件改造成巨型业务组件。

### 4.4 长内容与复杂制作

剧本、故事板、成片编辑器在当前项目内以大面板或专注视图打开，可拥有可恢复的 URL 状态。关闭后恢复原画布选择、位置和缩放。

多集短剧以“作品 → 分集 → 片段”的层级展开；总画布只显示摘要和必要引用，不一次渲染数百个镜头。列表、故事板与画布读取同一份业务数据，不各存一套脚本或镜头顺序。

## 5. 创作流程

### 5.1 IP 形象

描述/上传参考 → 生成候选 → 选择主形象 → 创建新 IP 或加入已有 IP → 补充人设 → 衍生造型/多角度/表情。

创建、引用和保存已存在的资产不再次收生成费；生成收费按现有定价。一次画布允许产生多个角色，不能受旧单一 `publishedAvatarId` 限制而把第二个人物挂错。

### 5.2 首版主线：单条 IP 短视频

1. 选定 IP 与形象，点“做短视频”，输入主题、画幅与目标时长。
2. 写短脚本或粘贴已有内容，编辑后确认；支持脚本单独保存。
3. 拆成有稳定 ID 的镜头，逐镜绑定角色、场景、画面描述与目标时长。
4. 生成镜头首帧，选择候选；引用素材在每次运行前清楚展示。
5. 生成视频片段，采用满意版本；失败只重做对应步骤。
6. 在成片编辑器排序、预览、合成与下载，作品归入来源 IP 和项目。

建议验收样例为单 IP、2–3 镜、约 15–30 秒的视觉短片；实际片段时长服从所选模型，不为凑样例发送不支持的规格。首版不承诺对白口型和统一角色声音；若模型输出自带音轨，成片展示明确的音轨处理方式，不冒称已配专属声音。

### 5.3 后续：数字人口播

选 IP → 选择可用形象驱动方式 → 指定声音 → 文案与试听 → 生成 → 字幕/品牌包装 → 成片。

复用前必须审计实际身份、素材要求与计费边界。`clip` 是军师 BFF 的 service token + externalOwnerId 场景，不能让浏览器直接调用、不能把 Scheme A 的零积分语义照搬到 Studio。Studio 用户到引擎身份、计价与素材授权的适配必须有明确服务端方案。

### 5.4 后续：带货

选 IP + 商品 → 确认卖点和素材 → 脚本版本 → 镜头与配音 → 视频 → 成片与多个版本比较。

自有 AI IP 带货与真人明星采购/授权保留不同规则。真人明星审批、商务签约、商家运营等继续由专业工作台管理，创作者在 Studio 内读取状态并使用获准素材；外部平台分发未真实接通前不承诺一键发布成功。

### 5.5 后续：多集短剧

IP/人物阵容 → 故事大纲 → 分集剧情与剧本 → 角色/场景 → 分集分镜与片段 → 合成。

复用现有短剧脚本和制作能力；演员可来自多个 IP。全剧设定、单集设定和单镜引用分层，避免改某一集造型影响整个 IP 的正式形象。

### 5.6 同一 IP 如何同时服务不同作品

例如用户打造“潮玩女孩”并定稿：在当前画布中点“做短视频”，生成三镜生活短片；之后仍选择这份 IP，创建口播、商品演示或短剧作品。每份作品拥有自己的脚本、镜头、运行和采用版本，共用同一份 IP 档案及明确选中的素材。

作品可以在项目内分组，长内容打开专注编辑器。用户不需要知道执行能力来自哪个子应用；IP 定稿、场景引用、声音就绪和商品信息仍各有明确状态。更新正式主形象时，系统列出正在使用旧版本的草稿，供用户逐项决定是否采用新版。

## 6. AI 助手范围

目标：理解当前选择，提出可编辑方案，把指令落实为项目里的脚本、素材与任务。

- 首版提供明确动作：写脚本、改写选中文本、拆分镜、生成选中镜头。操作对象与生成范围可见。
- 首版不以“任意一句话自动完成所有业务”的通用 Agent 为前置；先保证每个动作真实可用。
- 后续支持 `@IP`、`@商品`、`@场景` 和多方案生成；引用必须解析为稳定资产标识。
- 大批量执行前展示范围与报价；只运行用户确认的步骤，提供样片先行和分段继续。
- 聊天不是唯一数据载体。正文、镜头、采用结果、运行和费用均持久化，刷新后继续。
- 生成失败不能退回模板句、静音或占位图并冒充成功；未配置能力明确不可执行。

## 8. 技术实施原则与最小数据契约

### 8.1 组织方式

- UI 外壳与新创作入口在 `apps/web-aiavatar/src/ip/`；画布适配在 `src/canvas-bridge/`。
- vendor `src/canvas/` 只作必要扩展点与交互改动，并按仓库要求留注释；不整仓替换画布。
- 业务服务继续维护各自运行和结算真值；统一任务列表是投影，禁止复制一套可独立写状态的任务系统。
- 跨子应用复用以服务与组件边界进行；不通过 iframe 拼多个完整应用，不跨 app 源码路径随意 import 页面。

### 8.2 实现前先定契约

以下是必须表达的概念，不是已存在字段，也不预设建表名称：

| 契约概念 | 至少表达 |
|---|---|
| 项目中的 IP 引用 | IP、人物、造型/声音、采用版本、在项目中的用途 |
| 作品记录 | 来源项目、类型、参与 IP、输入修订、输出与采用版本 |
| 业务卡片 | 节点与剧本/作品对象的引用；避免在节点、作品两处存可独立修改正文 |
| 输入快照 | 原指令、实际提示词、实际送达参考、模型/规格、价格快照 |
| 运行引用 | 来源业务域、原始运行 ID、项目/节点绑定、客户端请求 ID |
| 镜头与成片 | 稳定镜头 ID、顺序、采用片段版本、合成输入快照与文件 key |

先在 `packages/types` 定义，再镜像 Java DTO，同步 OpenAPI 与业务规则。复用既有数据足够时不新建表；需迁移时检查 SQL 与 Java 两处编号，禁止改已执行迁移。

### 8.3 文档与并发

- `IpProject.doc` 仍由客户端拥有，服务端整存整取；worker 不直接修改整份画布布局。
- 运行产物另存，前端通过稳定节点/作品/运行引用恢复，采用结果通过正常版本校验写回。
- 草稿保存、采用、IP 定稿和生成前的保存闸明确处理 `failed/conflict`，不能忽略返回值。
- 新文档字段可选、带兼容读取；旧画布先加载完成再挂载，禁止空文档自动覆盖旧数据。
- 刷新与超时保留原任务 ID。上游已受理但终态未知时查原任务，不自动另建收费任务。
