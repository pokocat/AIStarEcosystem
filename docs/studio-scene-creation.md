# Studio 场景化创作：首页、AI 图片、AI 视频 · 现行设计真源

2026-10-29，本地实现，未发布。仅 `apps/web-aiavatar`，不改服务端、不加接口、不加迁移。

## 1. 为什么改

原来的 Studio 是一排「工具」：画布、出图、出视频、剧本、配音……会用的人觉得灵活，传统老板看不懂，不知道从哪下手。
参考站（茂隆掌柜 AI）好懂的地方是：首页先问「你想做什么？」，背后有两套按场景准备好的生成页，选个「口播带货」「商品白底图」，
该放什么素材、该怎么描述都已经写好，普通人一下就明白。

这次照它的布局和产品逻辑改，做了几处自己的取舍（见 §5）。原来单独一页的「灵感」（模板与案例）放到首页上。
页面细节对照的是**参考站登录后的样子**（2026-10-29 在用户已登录的 Chrome 里逐页看过：图片页、视频页、首页灵感墙和作品预览），不是访客页。

## 2. 导航

登录后的桌面从「顶栏」改为**左侧一列图标 + 文字**（`shell/desktop-top-bar.tsx` 的非公开分支，类名 `desktop-rail`）：

首页 · AI 视频 · AI 图片 · 画布 · 导演台 · 项目 · 资产 · 发行；底部是积分和账号菜单。

- 公开落地页仍用顶栏（`publicMode`）。画布页（`/projects/{id}`）照旧不挂网站导航。
- 页面让位：`body.has-desktop-bar` 改为左边让出 `--desktop-rail-w`（76px）+ 12px，`--desktop-bar-h` 在 body 上改为 12px（只剩顶部留白），
  所有用 `calc(var(--desktop-bar-h) + 12px)` 做吸顶的页面不用改。旧 SPA 的 `.app-root` 同时让出左边。样式在 `styles/studio-scenes.css` 开头。
- 「灵感」不再是一级导航：`/templates`、`/projects/demos` 归到「首页」高亮；首页「灵感」区有「更多灵感」进完整目录。
- 「场景·专项创作」（`/scenes`）并入「AI 视频」，旧链接转到 `/video`。组件 `StudioSceneWorkshop` 保留未删。
- 标签都是两三个字的业务说法，不只放图标：老板认字不认图标。

## 3. 首页（`components/landing/ip-home.tsx`，桌面登录后）

从上到下：

1. **一句话开始**：品牌标题 + 一个大对话框（`StudioConversationStart`，行为不变：先免费建画布，打开后自动发出这句话）。框下的提示改成「不想打字？直接选场景：AI 视频 / AI 图片」。
2. **常用工具**：画布（共用 `startNewCanvas()`）、短剧导演台、商品白底图、图片精修、人物真人感、人物配音、数字人口型、IP 人物库。
   每个入口一种颜色（`tone` → `data-tone`：浅色渐变底 + 同色深一档的图标与投影，悬停浮起），2026-10-30 用户嫌原来白底灰边「太平淡」后改。
   只放我们真能做的；参考站的画质增强、水印擦除、字幕擦除我们没有，不摆空入口。
3. **你想做什么？**：七张目标卡（爆款复刻、商品套图、电商带货、同城到店、品牌广告、剧情短片、IP 形象），每张落到 AI 视频 / AI 图片的某个场景（`homeGoals`）。
4. ~~继续创作~~：2026-10-30 按用户要求从首页去掉（最近的画布在「项目」里；新建空白画布用上面的「画布」入口）。
5. **灵感**：官方模板 + 精选案例，按内容分「发现 / 视频 / 图片 / 画布」（模板里有视频算视频、只有图算图片）。

   点开先是只读的画布预览，点「做同款」才复制成自己的画布并打开（2026-10-30 起全站这个按钮都叫「做同款」，原来叫「存为个人副本」）。个人模板不在这里，在「更多灵感」的完整目录里。

手机首页（`components/hub/studio-home.tsx`）在对话框下面加了同一组「你想做什么？」卡片。

## 4. 两个场景页

两页是同一个三栏骨架（`ip/scenes/scene-layout.tsx`）：左边场景列表（按分组，可收起）、中间设置、右边结果、最右「最近」。
宽度不到 1600 时「最近」挪到结果下面横排；手机上一列往下排，场景列表变成一行横滑。

场景目录只有一份，在服务端：`apps/server/src/main/resources/ipstudio/scenes.json`（见 §7）；前端 `ip/scenes/scene-catalog.ts` 只留读目录、封面地址和首页目标卡。封面在 `public/studio/scene-covers/{id}.webp`（640×640，AI 生成的示意图，不是用户作品）。

### 4.1 AI 图片（`/image?scene=…`）：一步出图

- 分组：IP 形象（设定图 / 写真 / 表情包）、人物（脸部三视图 / 人物四视图 / 模特换脸 / 人脸融合）、商品（服装上身 / 商品使用 / 白底图 / 卖点图 / 服装改款）、
  场景（人物入景 / 商品入景）、画质（人物真人感 / 图片精修），外加不选场景时的「自由出图」。
- 每个场景定义**参考图位**（第几张叫什么、必不必填，占位按人 / 商品 / 衣服 / 场景画剪影）和一段**场景描述**。描述里的「图1、图2」对应参考图位的顺序。
- **场景描述不摆给用户看**（参考站登录后也是这样）：输入框里只有一个场景标签（如「✦ 模特换脸」，悬停能看完整描述）和一个「补充要求」，
  提示写这个场景可以补什么（「可补充表情、妆容、发型细节，例如：自然微笑、淡妆、保留刘海」）。发出去的是「场景描述 + 补充要求：…」，由服务端 `POST /scenes/compose` 拼（§7）。
  需要用户决定的东西（写真风格、卖点、没放场景图时的场景）在描述里写成「按补充要求来，没写就……」，不留【…】空位，有测试守着。
  想自己改的人点「改完整描述」，改完可以「用回场景描述」。「用这段描述再做」把那次真正发出去的整段描述放回来。
- 参考图：上传（与画布同一套压缩和格式检查）或「从资产库选」。
- 「图片设置」是一个就地展开的面板：比例画成小方块、清晰度、张数；模型单独一个下拉（只有一个模型时不显示）。比例 / 尺寸 / 张数 / 报价与画布出图同一套算法（模型能力里的比例、尺寸、张数；单价 × 张数）。
- 不能生成时按钮直接写原因（「先放模特图」），能生成时写预计积分。
- 右侧两个标签：「参考示例」（选了场景先看这个场景大概做成什么样，图是示意）和「生成结果」。
- **草稿就是一张普通画布**（名字就是场景名，项目上记 `sceneId`，见 §7）：第一次生成时建，之后每次生成在这张画布上加一行（左参考图、右结果节点，连线表示引用）。
  所以「在画布中继续」打开就是同样的内容；画布自动封面取第一张有图的节点，结果节点排在参考图前面。
- 提交顺序与画布一致：**先把带 `clientRequestId` 的请求写进节点并保存，再提交** `studio-runs`。之后只读运行记录（`GET runs/{id}`）把结果写回，绝不重新提交。
  服务端没受理（4xx、没发出去）才算失败；网断等不确定的情况保留原请求，界面给「确认原任务」——同一个请求编号再交一次，服务端认得它，不会重复扣费。
  计费确认、企业付款选择、模型报价确认都走 `withStudioBilling`，和画布一样。
- 「最近」按项目上记的 `sceneId` 列出这一页建的草稿（改名也还在），点开接着看结果、接着出图；那次用的参考图会放回原位。

### 4.2 AI 视频（`/video?scene=…`）：编导写脚本，再出片（2026-10-29 改，详见 §8）

- 分组：电商带货（口播带货 / 促销转化 / 场景种草 / 痛点解决 / 功能演示）、同城到店（门店发现 / 到店实录 / 招牌体验 / 同城团购）、
  品牌广告（品牌主张 / 品牌故事 / 生活方式 / 创意概念）、剧情短片（对话 / 反转 / 悬疑 / 情感 / 剧情植入）、IP 内容（数字人口播 / IP 日常 / 爆款复刻）。运营可以在后台改（§9）。
- 照参考站：中间是「你想做一条什么视频？」和几个常用开头，底下**一个输入框**：素材位（商品图 / 门店照片…、角色、声音，爆款复刻还有参考视频）+ **一句话** +「中文 · 15 秒 · 竖屏」设置 + 发送键。
  一句话可以不写（编导先看素材）；剧情、品牌、口播、复刻这类没东西可看的场景必须写一句（`textRequired`）。不能发的原因写在发送键旁边。
- 发送后不再跳画布：编导在本页写出分镜脚本，接着说哪里要改；「用这个脚本生成」切到生成模式选模型、时长、看价格再出片。爆款复刻和更长的片子仍交给画布里的创作助手（§8）。
- 拼话规则：用户写的那句放在「我的要求」，素材按交给模型的顺序编号；交给助手和交给编导的话带同一条事实边界（`StudioSceneCatalog.FACT_RULE`）：用户没写的价格、优惠、地址、品牌年份与历史、检测或测试次数和画面、销量、排名、获奖、认证、门店数、用户数、功效数据都不出现。故事可以编，但不能写成品牌的真实经历。原因是这些最容易被模型顺手编出来当卖点，写进成片就是虚假宣传：2026-10-29 拍法写着「讲优惠」，模型编了一句优惠；2026-10-30 品牌故事首稿编了品牌年限和耐用测试次数，summary 还说没写功效。所以编导的 summary 也只许说脚本里写了什么。场景自己的拍法、思路、选项不带数字和「真实人物 / 真实评价」这类说法（`StudioSceneCatalogTest` 钉住）。
- 只有「爆款复刻」交给助手的话会命中 `studioBriefNeedsReference`（等参考视频在画布上再发）；其余场景的话一律不能命中，有测试守着。

## 5. 和参考站不一样的地方

- **草稿 = 画布**：参考站的图片 / 视频草稿是独立的；我们的草稿就是一张画布，随时可以「在画布中继续」做更复杂的编排，任务恢复、确认原任务、计费都只有一套。
- **编导写的脚本也存进画布**：参考站的编导对话和生成队列是独立的；我们每一版脚本是草稿画布上的一个文字节点，出的视频连着脚本和素材，「在画布中继续」看得到全过程。
- **长片和复刻交给创作助手**：参考站一条脚本出一条视频；超过所选模型时长的片子要分段拼接，爆款复刻要先拉片，这两种我们交给画布里的创作助手。
- **多了 IP 形象 / IP 内容两组**：本产品是 IP Studio，「一张照片做设定图、写真、表情包」「让 IP 出镜口播」是核心场景。
- **不编**：参考站有的画质增强、去水印、去字幕我们没有，首页不摆；拼给助手的话禁止编价格和优惠。

## 6. 真模型验收与没验证的

- 2026-10-29 本地真模型走通了两条链路（图片出图扣费；视频经助手出方案、确认、执行、厂商失败退款可重试），据此改了交给助手的话（要成片不只要脚本）、视频场景带上方法（`studioSkill`）、失败「重新生成」、限流说人话等 7 处，见 [`releases/studio-scene-creation-local-validation-20261029.md`](releases/studio-scene-creation-local-validation-20261029.md)。
- 场景默认描述没有在线上默认图片模型上逐个验收（本地 Agnes 限流，只真出了脸部三视图）。
- 场景封面是 AI 生成的示意图；运营要换成真实作品时直接替换同名文件。
- 左栏导航只在桌面形态；手机仍是底部 tab，没有加「AI 视频 / AI 图片」两个 tab（手机首页有入口）。

## 7. 接口与真源统一（2026-10-29）

用户要求「后端也统一一下端点，不然后续迭代容易漏问题」。原来场景数据、出图描述和交给助手的话都写在前端 TS 里，草稿靠名字后缀认，两页上传还各走一个接口。现在：

| 东西 | 以前 | 现在（唯一一处） |
|---|---|---|
| 场景目录（描述、参考图位、拍法、方法） | `scene-catalog.ts` | `apps/server/src/main/resources/ipstudio/scenes.json`，`GET /api/v1/ip-studio/scenes`；启动时校验，写错不启动 |
| 出图描述 / 交给助手的话 | 前端 `imagePrompt` / `composeVideoBrief` | `POST /api/v1/ip-studio/scenes/compose`（`StudioSceneCatalog.compose`），缺必填素材 400，话术规则只在这里（不编价格、要成片、复刻字眼只给爆款复刻） |
| 视频场景用哪种方法 | 前端写死 `video-generation` | 目录里每个视频场景的 `skill`，compose 返回 `skillKey` |
| 草稿属于哪一页 | 名字后缀 ` · AI 图片 / 视频`（改名就丢） | `ip_project.scene_id`（V72），建草稿时带 `sceneId`，服务端核对存在 |
| 视频子任务结束 → 推进制作计划 | 等 60 秒巡检（真跑看到约 90 秒还显示「生成中」） | `MaterialVideoJobEnded` 事件，提交后叫醒该用户仍在跟踪的计划 |

没动的：画布文档仍由客户端写（仓库硬规则），所以「先把带请求编号的节点存进画布、再提交 `studio-runs`」这一步还在前端；计费、报价确认、确认原任务、退款都走原来的链路。测试：拼话规则在 `StudioSceneCatalogTest`（Java）；前端测试只核首页卡片、封面和演示数据与服务端目录对得上。

## 8. AI 视频照参考站「超级编导」出片（2026-10-29）

用户确认参考站视频页「看起来是 AI 对话」之后，要我们改成同样的出片方式。参考站前端代码（只读、没发消息）显示：编导对话只负责**写脚本**（单独按条计费，失败退冻结），脚本点「应用」后填进视频描述，用户选模型 / 清晰度 / 时长 / 比例，「立即生成视频」弹确认价格，任务进右侧队列，中间预览成片。我们照这个走：

1. **对话（本页中间）**：放素材、说一句（不写就是「看素材写一版」），点发送。服务端按场景拼好写脚本的要求（`compose` 的 `video-script`），前端在草稿画布上建一个文字节点、把请求写进去再提交一个普通文字任务（`operation=text`，`textEdit.content` 是上一版正文；文字模型能看图就带 `readVisuals`，编导看得到商品图）。脚本卡片显示这一版的思路、分镜脚本、花了多少积分，按钮是「用这个脚本生成 / 改一改 / 复制」。
2. **改稿**：有了脚本后输入框变成「想改哪里，直接说」，服务端把修改意见放在最前面、原要求附后面；新一版接在上一版后面，「改一改」只挂在最新一版上。
3. **生成模式（整列换成编辑器）**：脚本可以再改；模型、清晰度、时长、画面按所选模型的合同给（时长 5 秒一档，场景默认时长放进模型范围）；素材怎么交给模型只在 `scene-video-plan.ts` 判（全能参考按编号交图和声音 / 只认首帧用第一张 / 都不行只按脚本，用不上的就地说明）。会改写描述的模型（H3）带 `rewrite: auto`。按钮写预计积分，点了照常弹确认价格。
4. **结果（右侧「生成结果」）**：一条一行，排队写位次、生成中写「一般要几分钟」、不显示假百分比；失败说人话（限流、厂商排满各有一句，厂商原话和追查号放悬停），原地「重新生成」；不确定是否受理给「确认原任务」。
5. **交给创作助手**：爆款复刻（要先拉片）发送键就是「交给创作助手」；其他场景默认时长超过模型上限时，输入框下给「交给创作助手分段做」。两者都把服务端拼好的话存成助手第一句，打开画布自动发出。

本地真跑（2026-10-29）：编导用本地聚算 Qwen 看了图，台词里认出了商品名，一版 1 积分；改稿只改了要改的两处。拍法「结尾讲优惠」与「不编优惠」冲突时模型写了句「现在下单有优惠」，已在要求里补「不说没给过的优惠」。出片走免费 Agnes 时厂商队列满，失败与重试正常。

## 9. 场景在后台可配置（2026-10-29）

用户要求「两个 AI 入口里的场景要做可配置化，后续运营可以加各种模板」。参考站的场景（它叫技能）也是服务端下发的：分类、选项默认值、素材槽位、结果示例。

- **存哪**：运营改过就存平台配置 `studio.scene-catalog`（整份 JSON），没改过用随包的 `scenes.json`。`StudioSceneCatalog` 按配置版本缓存；库里那份读不出来时用随包那份并打 ERROR。
- **后台页**：放在 Studio 自己的运营后台（`apps/web-aiavatar/studio-admin`，本地 3004，线上 `aistar.aibuzz.cn/admin`），左侧「运营配置 · 场景模板」（`/scenes`），不放系统管理后台 `apps/admin`（用户 2026-10-29 指定）。超管和平台运营都能登录编辑；经营 / 技术看板仍是只读，「只读」标记只在看板页显示。
