# Studio 对话：去掉「继续」

> 现行设计真源。替代 AGENTS.md「一轮对话尽量做完」「Studio 对话独立额度」「Studio 确认继续」三节里与此冲突的部分。
> 背景：2026-10-23 下午线上用户反复遇到对话中途停下、要说「继续」、报错（见 `docs/audits/studio-production-afternoon-evening-review-20261023.md`）。

## 1. 产品规则（用户原话的落地）

用户说一句话，助手就把事做完。**只有花钱出图 / 出视频 / 配音这类付费生成，才停下来让用户确认**（现有的方案确认卡，规则不变）。
除此之外的检查一律不停下来问用户，界面上不再出现「已暂停」「点继续接着做」，也不再给「继续」快捷答复。

对话本身按实际 Token 用量扣积分，不再要求用户逐条确认对话费用的上限。

## 2. 什么时候这一轮会结束

| 情况 | 现在 | 改成 |
|---|---|---|
| 模型做完了（不再给动作） | 结束 | 不变 |
| 用户点停止 | 结束 | 不变 |
| 要付费生成，等用户点确认卡 | 停下等用户 | 不变 |
| 模型提问（ask_question） | 停下等用户 | 不变 |
| 16 步 / 40 次模型调用 / 24 次工具 / 10 分钟 / Token 输入输出分配 | 停下，提示说「继续」 | **删掉**，不再因为这些停 |
| 这一条任务冻结的钱用完了、事情没做完 | 停下，提示说「继续」 | **服务端自动接下一条任务**（§3），用户无感 |
| 余额不够接下一条 | — | 结束，一句话：「积分不够了，已经做好的都留在画布上。充值后跟我说一声，我接着做。」 |
| 连续两步动作完全一样（死循环） | 立刻停 | 第一次：给模型一句纠正（「你刚才重复了同一个动作，换个做法，或者直接告诉用户结果」）接着跑；纠正后再重复才结束，结束语不提「继续」 |
| 动作格式错误 | 纠正两次后停 | 不变，结束语不提「继续」 |

**唯一保留的隐形保险**：同一条用户消息触发的整条任务链，模型调用累计超过 300 次或总时长超过 2 小时，按失败结束、打 ERROR 日志（带 threadId / 根 runId / 调用次数），给用户一句「这次没做完，已经做好的都留在画布上」。正常使用永远碰不到，只防程序 bug 把用户余额烧光。不给「继续」。

## 3. 自动接续（替代用户说「继续」）

- 一条任务（`ip_run`，kind=studio-dialogue）仍然只有**一笔冻结**，金额固定，结算不超过冻结额。账本、企业付款授权、充值来源全部沿用，`CreditService` 不改。
- 冻结额 = min(该端点对话额度换算的积分 `findDialogue(...).maxCost()`，钱包当前可用余额)。可用余额连一次最小调用都不够时，照旧 402。
  这样余额少的用户也能正常对话，不会因为额度变大被拒。
- 每次调模型前按「已用 + 下次预估输入 + 最小输出」算会不会超过冻结额（现有 `TurnBudget.continued` 的算法，推广到所有任务）。会超 → 这条任务按实际用量结算，**在同一个事务里**：
  1. 新建下一条任务（新 runId、新助手消息、同一 turnId 或标明同一条用户消息），`_exec.chainOf` = 链上第一条任务的 id，`_exec.chainIndex` 递增；
  2. 用同一份付款来源（个人钱包 / 企业成员授权）冻结新的一笔，冻结失败（余额不够）→ 不建新任务，按上表「余额不够」结束；
  3. 线程的 `activeRunId` 直接换成新任务，中间不出现空闲态；
  4. 派发挂 `afterCommit`。
- 新任务的上下文里写清：原始要求（链上第一条用户消息的原文）+ **整条链上每一条任务**已完成的操作（工具名、结果摘要、对象 id、子任务 id），提示「不要重复执行」。不能只列第一条（现在的 `continuationContext` 只列第一条，是 bug）。
- 旧数据里的 `_exec.continueUntilDone` / `continuationOf` 照样能读（在途任务不挂），但不再写新的；`saysContinue` / `resumedTask` 这套「用户说继续才放开」的判断删除。用户自己打「继续」就是一条普通消息。

## 4. 一轮里上下文不能无限变长

去掉步数上限后，单条任务里的消息列表会一直涨，最终超过模型窗口被厂商拒。每次调模型前裁剪：保留系统提示、本轮用户输入、最近若干轮完整交互；更早的工具结果只留一行摘要。裁剪后的估算输入用于 §3 的预算判断。

## 5. 长剧本要能读完

`DialogueCanvasDigest` 把引用文字节点截到 4000 字并标「…（已截断）」，模型没有办法读后面的部分，就反复读同一段，然后被判死循环（线上 IPP-6e051b9d 15:13）。
改成：摘要里写「全文 N 字，已给出第 1–4000 字；用 read_canvas 带 nodeId + offset 读后面」，`read_canvas` 支持对单个文字节点按 offset / length 分段读取，返回 `total`、`nextOffset`。

## 6. 子任务等待

`ChildRuns.follow` 现在等到「本轮剩余时间」，去掉时间上限后会无限等（线上图片排队最长 38 分钟，这期间对话一直显示进行中）。
改成：最多等 10 分钟；还没完成就返回「已提交，正在排队 / 生成，结果会自动放进画布」，模型据此告诉用户并正常结束这一轮（不算 limit）。结果照旧由执行器放进画布。

## 7. 冻结回收

`CreditHoldSweeper`（180 分钟）不认对话任务，正在跑的对话任务的冻结可能被释放。对话任务心跳正常（`StudioDialogueTurnWorker.STALE` 之内）时跳过。

## 8. 对话费用不再按「用户确认的上限」拦截

- 发送消息接口的 `maxCost` 保留为可选字段（老页面照发），**对话不再因为它和服务端额度不一致而回 409 `STUDIO_PRICE_CHANGED`**。线上下午那 18 次 409，很可能就是新服务端额度变大、老页面带旧额度造成的。
- 付费生成（出图 / 视频 / 配音）的 `maxCost` 校验与确认卡完全不变。

## 9. 界面

- 不再显示「已暂停 / 点继续」的系统消息，不再给「继续」快捷答复。
- 自动接续时，界面始终是一个连续的「进行中」状态，不闪成空闲；新助手消息接在后面显示。
- 「余额不够」那条给一个去充值的入口（沿用现有充值入口）。

## 10. 验收

- 一条用户消息、原来会撞 16 步 / Token 分配 / 10 分钟的长任务（写三集剧本并拆镜），一次做完，中间没有任何「继续」。
- 冻结额小于任务总花费时，自动接出第二、第三条任务，各自结算，合计扣费 = 实际用量，没有重复扣费、没有冻结泄漏；企业成员钱包同样成立。
- 接到一半余额不够：停下、提示充值、已完成内容保留、冻结全部结清。
- 第二条任务的上下文里有第一条做过的所有操作，不重复建节点。
- 死循环：第一次纠正后换了做法能接着做完；再重复才结束。
- 8000 字剧本能分段读完，不被判死循环。
- 老页面带旧 `maxCost` 发消息不再 409。
- 真模型（线上同款聚算 Qwen）至少真调一次长任务（§8.0.1 ⑦）。
