# Studio 对话：去掉「继续」

> 现行设计真源。替代 AGENTS.md「一轮对话尽量做完」「Studio 对话独立额度」「Studio 确认继续」三节里与此冲突的部分。
> 背景：2026-10-23 下午线上用户反复遇到对话中途停下、要说「继续」、报错（见 `docs/audits/studio-production-afternoon-evening-review-20261023.md`）。
> 2026-10-23 晚修订（用户原话「对话里不应该设置预算，实际对话消耗积分不会太多；积分花完了才停」）：不再「接出下一条任务」，改为**同一条回复里悄悄追加冻结**；对话费用不计入制作预算（§3、§11）。

## 1. 产品规则（用户原话的落地）

用户说一句话，助手就把事做完。**只有花钱出图 / 出视频 / 配音这类付费生成，才停下来让用户确认**（现有的方案确认卡，规则不变）。
除此之外的检查一律不停下来问用户，界面上不再出现「已暂停」「点继续接着做」，也不再给「继续」快捷答复。

对话本身按实际 Token 用量扣积分，没有自己的预算，不要求用户确认对话费用的上限；用户钱包真没钱了才停。

## 2. 什么时候这一轮会结束

| 情况 | 以前 | 现在 |
|---|---|---|
| 模型做完了（不再给动作） | 结束 | 不变 |
| 用户点停止 | 结束 | 不变 |
| 要付费生成，等用户点确认卡 | 停下等用户 | 不变 |
| 模型提问（ask_question） | 停下等用户 | 不变 |
| 16 步 / 40 次模型调用 / 24 次工具 / 10 分钟 / Token 输入输出分配 | 停下，提示说「继续」 | **删掉**，不再因为这些停 |
| 已冻结的积分不够下一次调用 | 停下，提示说「继续」 | **在同一个 run 上追加冻结**（§3），用户无感，同一条回复接着写 |
| 追加冻结因钱包余额不够被拒（402） | — | 结束，一句话：「积分不够了，已经做好的都留在画布上。充值后跟我说一声，我接着做。」+ 充值入口 |
| 追加冻结因其它业务原因被拒（企业停用成员额度、付款授权失效…） | — | 结束，直接用那条业务错误本身的中文原话说清原因，不加套话前缀，不要求用户再说什么 |
| 连续两步动作完全一样（死循环） | 立刻停 | 第一次：给模型一句纠正（「你刚才重复了同一个动作，换个做法，或者直接告诉用户结果」）接着跑；纠正后再重复才结束，结束语不提「继续」 |
| 动作格式错误 | 纠正两次后停 | 不变，结束语不提「继续」 |
| 模型只说要做没动手（「好的，我来调整第二镜。」后面没有动作，2026-10-30） | 结束，那句话就是回复 | 不算做完：给模型一句纠正（`DialogueLoop.ANNOUNCE_CORRECTION`：现在就调用工具做完，不重复那句话；在等制作或等确认就说清在等什么）接着跑。只看回复最后 40 个字，问句和「生成好了我再告诉你」「你确认后我就开始」这类等待不算。**防循环**：纠正后的下一条还是没动作就结束，不再纠正；一轮最多纠正 2 次 |

**唯一保留的隐形保险**：同一个 run（一条用户消息），模型调用累计超过 300 次或自受理起超过 2 小时，按失败结束、打 ERROR 日志（带 threadId / runId / 调用次数），仍按真实用量结算，给用户一句「这次没做完，已经做好的都留在画布上」。正常使用永远碰不到，只防程序 bug 把用户余额烧光。不给「继续」。

## 3. 同一 run 追加冻结（替代用户说「继续」）

- **一条用户消息 = 一个 run = 一条助手回复**，从头做到尾。不新建 run、不新建助手消息、不换 turn。
- **首笔冻结**：受理时冻结 `min(增量额度, 可用余额)`。增量额度 = 该端点普通文本价的上限 `AiChatTokenPricing.find(endpointId).maxCost()`（约 20 积分那档），**不用** `findDialogue` 的百万 Token 额度，避免聊天时占住一两百积分、让同时进行的出图出视频误判余额不足。余额连一次最小调用都不够 → 照旧 402。
- **追加冻结**：每次模型调用（含工具内部调用：view_images、propose_plan 的规划、历史摘要）之前，若「已用 + 本次预估」放不下当前已冻结总额，就在同一个 run 上追加一笔：引用 = `runId + "#" + n`（REF_TYPE 不变），金额 = `min(max(增量额度, 本次调用所需), 可用余额)`；可用余额付不起本次调用 → 拒绝（402 同义）。企业成员钱包照原消息的付款来源走 `EnterpriseBillingService.reserveExtension` 生成该引用的授权（同一成员、同一成员钱包、同一模型；不算新任务，不占企业在途任务上限），**绝不回退个人钱包**。追加记录写进 run 的 `_exec.holdRefs`（含每笔金额），run.cost 在结算前等于冻结总额。
- **结算**：run 结束时按实际用量从各笔冻结里依次 commit（先第一笔，用满再下一笔），其余 release；企业授权每笔都 complete。失败 / 停止 / 过期回收路径把 holdRefs 全部释放。`CreditService` 不改，dialogue 侧只有一个小的结算辅助 `DialogueHolds`；每笔结算不超过该笔冻结额、总额不超过全部冻结。
- **心跳正常期间**，`CreditHoldSweeper` 对这些引用（`runId#n` 按 `#` 前的 runId 判断）同样跳过；`IpRunReaper` 把对话 run 交给对话 worker 的 `expireIfStale`（它释放全部 holdRefs）。
- 工具内部调用不会再因为「本轮额度放不下」失败；只有钱包真没钱时，它才以「积分不够了」结束这一轮。
- 旧数据里的 `_exec.continueUntilDone` / `continuationOf` 照样能读（在途任务不挂），不再写新的；`saysContinue` / `resumedTask` 删除。用户自己打「继续」就是一条普通消息。

## 4. 一轮里上下文不能无限变长

去掉步数上限后，单个 run 里的消息列表会一直涨，最终超过模型窗口被厂商拒。每次调模型前裁剪（`DialogueContextWindow`）：保留系统提示、本轮用户输入、最近 6 轮完整交互；更早的工具结果只留一行摘要；估算仍超 80k Token 时降到 3 轮、再降到 1 轮。裁剪后的估算输入用于 §3 的冻结判断。

## 5. 长剧本要能读完

`DialogueCanvasDigest` 把引用文字节点截到 4000 字并标「…（已截断）」，模型没有办法读后面的部分，就反复读同一段，然后被判死循环（线上 IPP-6e051b9d 15:13）。
改成：摘要里写「全文 N 字，已给出第 1–4000 字；用 read_canvas 带 nodeId + offset 读后面」，`read_canvas` 支持对单个文字节点按 offset / length 分段读取，返回 `total`、`nextOffset`。

读的是用户采用的那一版（`StudioWritingContent`，2026-10-30）：编辑器保存过的剧本 → 生成的结构化剧本 → 分镜 → 文字正文；编辑器里没保存的草稿、AI 待采纳的建议都不读，保存过的字段是空的就往下找，不当成空稿。

## 6. 子任务等待

`ChildRuns.follow` 等到「本轮剩余时间」，去掉时间上限后会无限等（线上图片排队最长 38 分钟，这期间对话一直显示进行中）。
改成：最多等 10 分钟；还没完成就返回「已提交，正在排队 / 生成，结果会自动放进画布」，模型据此告诉用户并正常结束这一轮（不算 limit）。结果照旧由执行器放进画布。

## 7. 冻结回收

`CreditHoldSweeper`（180 分钟）不认对话任务，正在跑的对话任务的冻结可能被释放。对话 run 心跳正常（`StudioDialogueTurnWorker.STALE` 之内）时跳过，追加的 `runId#n` 一并跳过。

## 8. 对话费用不再按「用户确认的上限」拦截

- 发送消息接口的 `maxCost` 保留为可选字段（老页面照发），**对话不再因为它而回 409 `STUDIO_PRICE_CHANGED`，也不再用它限额**。
- 付费生成（出图 / 视频 / 配音）的 `maxCost` 校验与确认卡完全不变。

## 9. 界面

- 不再显示「已暂停 / 点继续」的系统消息，不再给「继续」快捷答复；旧数据里已有的照常显示。
- 一条用户消息只有一条助手回复，界面始终是一个连续的「进行中」状态。
- 「余额不够」那条给一个去充值的入口（个人 `/studio#/membership`，企业 `/enterprise`）。

## 10. 验收

- 一条用户消息、原来会撞 16 步 / Token 分配 / 10 分钟的长任务（写三集剧本并拆镜），一次做完，只有一个 run、一条助手回复，中间没有任何「继续」。
- 用量超过首笔冻结时，同一 run 追加多笔冻结，合计扣费 = 实际用量，没有重复扣费、没有残留冻结；企业成员钱包同样成立（每笔各自一个授权，全部完成）。
- 追加时余额不够：停下、提示充值、已完成内容保留、冻结全部结清。
- 工具内部调用触发追加时不出现失败工作记录。停止 / 过期回收释放所有追加冻结。
- 死循环：第一次纠正后换了做法能接着做完；再重复才结束。
- 8000 字剧本能分段读完，不被判死循环。
- 老页面带旧 `maxCost` 发消息不再 409。
- 确认卡上限不含对话预留；对话 turn 不再登记到制作阶段预算。
- 真模型（线上同款聚算 Qwen）至少真调一次长任务（§8.0.1 ⑦）。

## 11. 对话费用不计入制作预算

- 对话 turn 不再计入制作（execution）阶段预算：受理与追加冻结时都不登记 `attributeTurn`（方法已删除），执行器刷新阶段预算时不再统计 `dialogueRuns`，`budget.update` 与执行投影不再有 `dialogueSpent / dialogueInFlight`。
- 确认卡上限只含制作步骤：`RequestApprovalTool` 默认 `budgetCap = quoted + autoFix`，执行器的制作阶段卡同理，卡片不再带 `dialogueReserve`；`dialogueReserve()` 已删除。
- 旧数据兼容：执行行里已有的 `dialogueRuns[]`、阶段预算里的 `dialogueSpent / dialogueInFlight`、对话 run 上的 `_exec.attributedExecutionId / attributedStage` 读到不报错，执行器下一次刷新时去掉预算里的两个字段。
- 绑定了制作的线程上，对话仍由该制作确认时固定的付款人付款（D10 不变）。
