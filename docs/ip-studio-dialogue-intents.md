# Studio 对话：意图直达（agent + 技能体系）

> 现行设计真源（2026-10-20；路由规则 2026-10-21 修订：写作意图先判、平手一律不绑、只有素材不选方法）。背景：用户反馈「AI 对话里问太多」。本文定义对话助手如何识别意图、分到哪个技能、什么时候问、什么时候直接生成，以及为此改动的服务端规则。配套：提示词 `resources/prompts/material/dap.ip_studio_skill_dialogue.md` / `dap.ip_studio_skill_plan.md`，技能文件 `resources/studio/skills/*.md`。对话机制本身（线程、流式、工具、执行器）仍以 [`ip-studio-conversational-video-recreation-plan.md`](ip-studio-conversational-video-recreation-plan.md) 为真源，本文只覆盖「意图 → 技能 → 一轮确认」这一层。

## 1. 问题

改版前的对话链是为「参考视频复刻」一种任务设计的：

- 技能只有一个（复刻），消息没命中它就落进「全能创作」，模型只能聊天或建草稿，任何收费生成都做不了，于是反复追问。
- 执行必须先「分析阶段确认」再「制作阶段确认」：哪怕只生成一张图也要两张确认卡。
- 线程一旦绑定技能就不能换：画完图再想写文案，只能「从某条消息重新开始」。
- 路由平手时服务端回 400 让界面问用户「用哪种方法」，又多一次打扰。
- 提示词写的是「缺关键事实先问，一轮最多问 1–2 个」，没有说清什么算关键、什么该用默认值。

## 2. 目标行为

1. **意图精准落到技能**：出图 / 写剧本与文案 / 出视频 / 参考视频复刻 / 纯聊天。切换对用户无感，不问「要用哪种方法」。
2. **简单意图一轮确认**：「画一张国风少女海报」→ 这一轮里同时给出方案和确认卡，用户点一下（或回「可以」）就开始出图。
3. **信息丰富直接进生成**：用户贴来完整需求（主体 / 风格 / 用途 / 尺寸 / 台词 / 商品资料）时不复述、不确认理解，补几个默认值就出卡。
4. **短文字当轮写好**：剧本、口播、标题、文案 1500 字以内由对话模型自己写，`create_nodes` 放进画布，没有确认卡。
5. **问题预算**：必填缺失且推不出来才问，一轮一个，带候选和默认；可选项（画幅、张数、时长、风格、模型）一律用默认，不问也不编。

## 3. 技能目录

| 技能 | key | 阶段 | 允许操作 | 触发（关键词 ×2 / 素材 ×1） |
|---|---|---|---|---|
| 出图 | `image-generation` | 直达制作 | text, image | 出图 / 生图 / 画一 / 画张 / 出一张图 / 生成几张图 / 海报 / 封面 / 设定图 / 换背景 / 再来一张…（不收裸词「一张图」「几张图」：「用这几张图做视频」里它们是素材）；素材 image |
| 写剧本与文案 | `script-writing` | 直达制作 | text | 剧本 / 脚本 / 文案 / 口播 / 台词 / 分镜 / 标题 / 改写 / 润色…；素材 text |
| 出视频 | `video-generation` | 直达制作 | text, image, video, check, assemble | 视频 / 出片 / 动起来 / 做一条 / 短片 / 运镜…；素材 image |
| 参考视频复刻 | `reference-video-recreation` | 分析 → 制作 | analysis: recreation, text；production: text, image, video, check, assemble | 复刻 / 拉片 / 参考视频 / 照着这条 / 做同款 / 翻拍…；素材 video |

- 技能文件格式不变（YAML 头 = 服务端边界，正文 = 方法）。**直达技能 = `operations.analysis: []`**：`StudioSkill.direct()` / `StudioSkillRules.Rules.direct()`，起始阶段 `firstStage()` 为 production（与 main 上原创创作引入的 `StudioSkill.firstStage()` 是同一条规则，`direct()` 委托给它）。
- main 上同日的 `original-creation`（原创创作）与「出图」触发词重叠（画一张 / 海报 / 出图 / 设定图），合并时改为 `status: withdrawn`（文件保留，目录按文件状态把库里那一行下架；删文件不会下架），由出图 / 写剧本与文案 / 出视频替代。
- 不允许 `check` 操作的技能 `checks` 可以为空（目录校验按「是否有阶段允许 check」判断）。
- 每个技能正文固定有「必填与可选」一节：这是模型「要不要问」的唯一判据（Cursor 参数规则：必填缺且推不出 → 问；可选 → 用默认，不问不编；用户引号 / 数字原样用）。
- 关键词不用单字（「画」会命中「画布」），最短两字；目录测试钉死。
- 我们自己给的完成后建议（`StudioExecutionSummary.suggestions`）每一条都要路由到它说的那件事，或者明确不切换：`StudioSuggestionRoutingTest` 用仓库里的技能文件逐条钉住，新加一条建议就得在那里写上预期。
- 配音 / 口型 / 声音克隆 / 局部重绘不在对话里做：提示词要求说明在画布对应节点的工具里做，不冒充。

## 4. 路由（`StudioSkillRouter.decide` + `StudioDialogueService.startTurn`）

结果三种：**MATCH**（绑这个技能）、**KEEP**（不变：有当前技能就沿用，没有就不绑）、**OPEN**（平手：不绑，交给模型）。

1. **写作意图先判**（2026-10-21）：写作动词（写 / 改 / 改写 / 润色 / 扩写 / 精简 / 优化 / 拟 / 编 / 做 / 出 / 想 / 来 / 列，「起」只在数量前）在同一分句里直接带文字产物（文案 / 卖点 / 标题 / 口播 / 脚本 / 台词 / 剧本 / 简介 / 广告语 / 旁白 / 分镜 / 小传 / 人设 / 标语 / 话术 / 大纲 / 故事 / 文字…）→ 写剧本与文案，**带图片、视频素材也一样**（「用这张商品图写三条卖点文案」「做个视频脚本」）。图片素材只是写稿的材料。
   - 不算写作意图：文字是图或视频的一部分——「做一张带标题的海报」（标题后面跟「的海报」）、「做个口播视频」「卖点图」（后面紧跟图 / 视频）、「海报上的标题」、「写上 / 写在」（往东西上写字）、「特写」。
   - 这句话**先**要了图、视频或复刻（「画一张海报，上面写标题…」「做一条视频，先写个脚本」）：不算写作意图，而且写稿技能的关键词这次不计分，按其余技能打分（先点名的产物就是这件事）。「拍的 / 做好的 / 生成的」是已有素材，不算先要了别的。
   - 写成代码里的一组正则（动词 + 同一分句内 16 字以内 + 文字名词作宾语中心），不是在技能文件里堆单字关键词；写作技能键是 `StudioSkillRouter.WRITING_SKILL`，它没上架时这条规则不生效。
2. 其余按关键词命中 +2、素材类型命中 +1 打分（**词优先于素材**）；唯一最高分胜出（MATCH）。素材只在文字点名了事之后加权：「照这条做一段视频」+ 参考视频是复刻（3 比 2）。
3. **文字一个关键词都没命中 → KEEP**：沿用线程当前技能（「再来一张」接着出图；钉着做好的片段说「合成一条成片」不会因为钉的是视频就跳到复刻）；线程没有技能就不绑（全能创作，模型可用 `read_skill` 自己选）。**只有素材不选方法**（2026-10-21 起；此前素材单独计分，钉一条视频说「看看这条」就会绑成复刻、钉一段文字说「配张图」会绑成写稿）。
4. **平手 → OPEN，一律不绑**（2026-10-21 起；此前当前技能在平手里就沿用，于是刚出完图说「用这几张图做一段视频」留在了出图）：线程清掉 `skillKey / skillVersion / stage`，本轮不带技能，模型看到「还没有选定方法」和全部技能摘要，按意图表 `read_skill` 选定（提示里要求先选定、可与看图同一批、选定前不向用户提问）。日志 `[dialogue] routing tie thread=… among [...]`。**不再抛 400 `STUDIO_SKILL_REQUIRED`**；`triggers.default` 只作为给模型的提示，不做平手裁决。
5. **技能按任务绑定而不是按线程绑定**（2026-10-23 起以「不锁方法」为准：有活跃执行时也按意图换方法）：线程没有活跃执行时每条消息都重新路由，命中别的技能就换（`thread.skillKey` 改写、`stage` 改为新技能起始阶段）；有活跃执行（running / paused / needs_user）时方法不变、不路由，显式换技能 400 `STUDIO_INPUT_INVALID`。执行结束解绑时清掉线程 `stage`。
6. `read_skill` 在没有活跃执行时可以换方法（`Effects.bindSkill` 改为可覆盖）；线程没有技能时它直接绑定。

## 5. 一轮确认（直达技能）

- `propose_plan` 的 `stage` 对直达技能填 `production`（省略则按技能起始阶段），不要求先有执行；填 `analysis` 被拒。
- 校验：直达技能的制作计划可以没有 `approaches`（一张图、一段视频不需要「保留什么 / 改变什么」）；非直达仍要求。
- 执行：`StudioPlanExecutionService.create` 接受 `stage=production` 且无 `executionId` 的请求，前提是计划所属技能 direct（先 `locatePlan` 查技能，不是直达 → 400 `STUDIO_INPUT_INVALID`，与原行为一致）；执行直接以 production 阶段创建，步骤、预算、授权快照与分析阶段同一套代码。`confirmFromDialogue`（文字确认）同样放行。改方案（`replanStage`）只在计划有 `recommendedApproachId` 时核对 approachId。
- 前端确认卡：`stage=production` 的卡只在卡上带 `executionId` 时才作为阶段确认，否则是新执行的开始；去掉了「回退到面板上最近一次执行 id」的旧逻辑（它会把直达技能的开始当成已结束执行的确认）。
- 规划提示词与 `skillPlanConstraints.stageGuide` 对直达技能说明「没有分析阶段，不写 plan-compile」，并只列本技能允许的操作。

## 6. 提示词要点（抄谁的）

- 意图表 + 「纯聊天是兜底，只有非常确定用户不要产物才走」：LangChain Open Canvas 路由提示词的写法。
- 「方法切换对用户无感，不要提」：OpenAI Agents SDK handoff 前缀。
- 「说出假设就往下做；说要做就同一轮做」「必填缺且推不出才问，可选不编不问」：Cursor CLI / Agent 2.0。
- 「一轮最多一个问题」：Claude.ai 系统提示；「猜错也比留空好」：tldraw make-real。
- 技能 `summary` / 正文「什么时候用」写得 pushy、列出用户不点名也该触发的场景：anthropics/skills skill-creator。
- 出图指令：腾讯混元 PromptEnhancer（意图不变 / 总分总 / 由主到次 / 结尾点题）；视频指令：Kling 公式（主体 + 动作 + 场景 + 运镜 / 光线）+ Runway「只写变化、写清什么不动、主体与相机分开、运镜只用一种」。
- 调研原文与 URL 见本次会话调研报告（未入库）；要点已落进技能文件与两份提示词。

## 2026-10-23：出图后接着出视频

用户要的产物优先于参考素材的名称。「按第1集剧本出第一段视频，用人物设定图做首帧」明确要求视频，不会因「设定图」命中出图；写视频脚本仍按写稿，复刻仍走复刻方法。

「继续下一步」本身没有产物关键词时，`ProposePlanTool` 在调用规划模型前再次用本轮具体 brief 解析方法，并经原 `Effects.bindSkill` 写线程、父 run 快照、起始阶段和废止旧待确认卡。活跃执行不切方法，线程锁继续防止本轮刚确认的执行被换掉；不扩大任何方法的操作白名单。

新计划必须验证、服务端报价并保存成功才能发确认卡。`request_approval` 仅接受本轮产生且与当前方法/阶段一致的计划；本轮规划失败（包括参数校验失败）会阻止同批后续动作用历史图片方案发卡。它给模型返回可恢复结果，要求本轮修正并重新整理，不能以等待用户结束循环；用户不再因视频计划失败而重复执行旧图片计划。内部不匹配说明给模型纠正，用户侧显示「这份方案还没准备好，我会按你要做的内容重新整理。」。


## 2026-10-23 读取与进度纠正（本地修复，未发布）

用户明确重新钉住的正文与本轮纠正优先；目录摘要和前 4000 字不得当成全文。`read_canvas` 必须按 `nextOffset` 读完任务所需内容。询问制作进度、缺哪段、下一步时先调用 `read_production_status`，按真实任务状态回答，区分旧采用作品与正在重做/失败的新任务，不把同一对象同时列为完成和缺失。这是业务工具修复，不代表 Agent 框架已替换或真模型表现已经验证。详见 [运行时评估](audits/studio-agent-runtime-assessment-2026-10.md)。

## 2026-10-23：不锁方法（本地，未发布）

线上：出图制作在等确认时用户说「把第一段做成视频」，助手说「这段视频对象之前建好连好了线，但生成还没提交成功。我重新发确认卡给你」，随后「整理制作方案」失败，界面显示「第 1 步的操作不在当前阶段允许的范围内」。原因是线程上只要有活跃制作（running / paused / needs_user），方法就被锁死：受理处只沿用当前技能、显式换技能 400，`read_skill` 拒绝换，`propose_plan` 不再按 brief 选方法，`bindSkill` 409 `STUDIO_SKILL_LOCKED`。用户要求：agent 不绑死技能，按每句话的实际意图选。

1. **每条用户消息、每次 `read_skill` / `propose_plan` 都按意图选方法**，有活跃制作也一样；路由器「文字没命中任何技能时沿用当前的」规则保留，平手而线程上有活跃制作时也沿用当前方法（没有哪件事被说清楚）。上面四处锁全部删除，`STUDIO_SKILL_LOCKED` 不再产生。
2. **切换方法只有一处**（`StudioDialogueService.switchMethod`，线程锁内、与绑定新方法同一事务；受理、显式 `skillKey`、`read_skill`、`propose_plan` 都走它）：
   - 新方法与当前制作的方法相同 → 不动，在原制作里接着做。
   - 方法不同、旧制作没有正在生成的子任务（暂停 / 等确认 / 某步失败）→ 作废它的待确认卡，制作按停止收尾（`canceled`，已产出的留在画布，不发总结消息），线程 `activeExecutionId` 与 `stage` 清空，按新方法的起始阶段出方案。
   - 方法不同、旧制作还有正在生成的子任务 → **不取消**：制作改为暂停（不再提交新步骤，在生成的照常完成、结算），并与线程解绑（`threadId` 清空，原线程记在 `state.detachedThreadId`）；它完成的结果仍作为 `node.upsert / check.result` 发到原线程放进画布，不发卡片、总结或其它消息；不再生成时自行结束（`canceled`）。解绑的制作不占画布（新方法的方案可以照常确认执行），执行器结束时只在线程指针仍指向它时才清指针（`unbindExecution`）。
3. **方案里有当前方法不允许的操作**：`propose_plan` 在校验前按 brief 与方案里的操作选出允许全部操作的方法（优先意图路由结果，路由不出就按目录顺序选第一个能覆盖的），按第 2 条切换后再校验；只有任何方法都不允许时才失败，失败原因只给模型。
4. **内部报错不到用户界面**：`STUDIO_SKILL_OPERATION_NOT_ALLOWED / STUDIO_SKILL_LOCKED / STUDIO_PLAN_STALE` 与方案校验的「第 N 步…」在用户可见处一律换成「这份方案还没准备好，我会按你要做的内容重新整理。」（错误码换成 `STUDIO_PLAN_NOT_READY`），原文留在日志、`internalDetail` 与模型侧结果里。覆盖的路径：对话工作记录的标题 / 摘要 / 展开详情（`ProposePlanTool` 失败、工具抛出的业务错误 `StudioDialogueTurnWorker.toolFailure`、前端 `userFacingError` 兜底旧记录）、确认卡接口错误（`StudioPlanExecutionService` 计划校验）、对话子任务授权（`StudioPlanExecutionBridge.authorizeChild`）、执行器步骤原因（`StudioPlanSteps`、分析后编排制作方案的原生任务 `StudioWorkflowWorker.skillPlan`）、前端错误详情 / toast（`normalizeStudioError`）。
5. 提示词（对话提示词「先判断用户要什么」一节与技能说明里「没有进行中的制作时可以换」）改为按意图换方法；`PromptTemplateSeeder.SEED_VERSION=v26-2026-10-23-dialogue-unlocked-methods`。

## 2026-10-24：方案素材范围跨轮（已生产发布 `20261024-studio-plan-material-scope`）

**线上事故**：`PEX-fc87e85770074aa9ad51`（画布 `IPP-c2fe43a8`）。用户首轮点选「原视频」和「三视图」，要求只把中间主舞换成三视图人物；第二轮补充「脸和衣服都按三视图」，没再点选；之后某一轮才出分析方案。拉片成功（7 积分），「编排制作计划」三次失败（0 积分），日志都是「第 1 步引用了不存在的素材」，界面只说「这份方案还没准备好」。用户点了两次「继续」，撞同一个错，最后停止。

**根因**：对话里 `propose_plan` 用整张画布校验，确认后的素材名单却只取出方案那一轮点选的节点（那一轮什么都没点）加上分析步骤点名的原视频，「三视图」从确认那一刻就不在名单里。两条加载方案的路径（dialogue run 的 `output.plan`、消息里的方案块）算法还不一样。

**现在的规则**（`StudioPlanMaterials.scope`，两条路径共用）：
1. 出方案那一轮点选 / 附带的节点；
2. 方案顶层 `materialNodeIds`：分析阶段写下制作阶段才用到的素材（设定图、商品图）；
3. 方案步骤点名的画布节点；
4. 同一对话最近 200 条里用户消息点选 / 附带的节点，新的在前。

只保留当前画布上还在的，最多 16 个（请求画布上下文的上限）。不放开校验，也不把整张画布加进来。

**越界时**：校验器一次报出全部越界节点（`STUDIO_PLAN_MATERIAL_OUT_OF_SCOPE` + `details.nodeIds`）。执行停下时说清是哪个素材（用画布标题），助手顶部的进度条列出这些素材：「在画布上看」、「加入这次制作，重新编排」（`resume` 带 `addMaterialNodeIds`，只接受这一步列出的、还在画布上的）、「不用它，重新编排」（下一次编排指令里写明不要再用它）。两条路都只重跑「编排制作计划」，拉片结果保留、不再扣费。

**提示词**（`SEED_VERSION=v27-2026-10-24-plan-material-scope`）：分析方案写 `materialNodeIds`，「编排制作计划」的指令写全用户原话（换谁、换成哪张图、换哪些部分、保留什么，后来补充的也算）；替换人物时每个有这个人的步骤都绑定设定图，外观按设定图写，不写原片里这个人的外观（原片穿白西装，新提示词不能再有白西装），其他人物、场景、动作、节奏、运镜写明保留。`reference-video-recreation` 技能「提示词编写」同步一条，技能文件改动按种子规则自动生成新版本（后台改过的除外）。

**没做的**：结束这次制作后重新开一次，同一条参考视频会重新拉片、再次计费（见 TODO）。真模型未验证 `materialNodeIds` 是否会被稳定写出；跨轮点选的兜底（第 4 条）不依赖模型。
