> 2026-10-22 联合评审修订：[AI 导演台总方案 v1.1](ai-director-plan.md#10-与当前平台的接入边界) 改为 aiavatar 内独立服务端制作对象，不再共用画布镜头真值。本方案继续服务现有画布，不是导演台前置；导演台首版无双向同步，未来显式快照复制另行适配，多镜片段视频不得重复作为每镜视频导出。

## 1. 决策摘要与范围

分镜是当前项目中一组有明确归属、顺序和采用版本的镜头。画布、分镜表、AI 对话编辑同一份项目文档，成片工程消费一次明确的分镜快照。不存在“表格保存一份，再回填画布一份”的流程。

确定以下边界：

1. 项目内顶部提供 **画布｜分镜｜成片**，不是站点一级菜单，也不是“高级编辑”。
2. 剧本／分镜摘要节点提供“编辑分镜”，打开同一工作区并定位到对应序列。节点是上下文入口，不把大表格塞进可缩放的节点里。
3. 每行一个逻辑镜头；候选图、候选视频属于镜头的媒体结果，不各占一行。普通素材、参考片、试验节点不自动进入分镜。
4. 沿用图片节点作为镜头锚点、现有 `studio.shot` 作为镜头内容真值；在 doc 中增加序列关系。首版不另建镜头业务表，也不新增 CanvasNodeType。
5. 人工、画布、AI 的分镜修改统一走编辑命令层；一次操作同时更新涉及的内容与关系、形成一个撤销步骤、使用同一保存链。
6. 改稿不自动重生成，改镜头不自动重剪已有成片；已受理任务使用提交时快照，完成结果不能覆盖之后的手工修改。
7. 第一版交付范围包含手工编辑、AI 编辑、刷新恢复、旧项目适配和成片边界。只把“故事板”换成表格不算完成。

首版不做：多人实时协同／CRDT、全量素材管理重构、独立分镜站点、通用工作流引擎、自动双向改写剧本正文、多套分镜共享同一个可编辑镜头、全套专业剪辑替代品、批量导出排版系统。

## 3. 用户工作方式与页面

### 3.1 打开与范围

“分镜序列”是内部概念，用户看到作品名称和分集，如《广告 A》／第 1 集。一个项目可有多个剧本，每个剧本可有多集，每集可有明确命名的不同方案。每个序列独立保存顺序，不靠 episodeNo 推断身份。

入口规则：

- 从某剧本点“编辑分镜”：只有一组就直开；多集／多方案时在分镜侧栏选择，保留剧本上下文。
- 从某镜头点“在分镜中查看”：打开它所属序列并定位该行；未归组时提供“加入已有分镜／新建分镜”。
- 顶部“分镜”：恢复本用户本项目上次范围；无记录且只有一组则直开，多组展示目录，不把所有镜头混成一张表。
- 无分镜：显示“从剧本拆分”和“手工编排”，明确已有普通节点不会被自动转成镜头。
- URL 可恢复 view／sequenceId／shotNodeId；无效 ID 显示范围不存在，不偷偷切到另一作品。视图、滚动、选中状态是用户 UI 偏好，不进入生成内容，也不让另一标签保存时改变当前选择。

### 3.2 编辑区

桌面保留项目顶栏、保存状态与视图切换。左侧目录选择剧本／分集／方案，中间分镜表，右侧按需打开镜头详情或同一个创作助手。镜头详情与助手不能同时挤压到表格无法阅读，提供相互切换或全宽编辑。

默认列：镜号、画面预览、画面描述、台词／旁白、计划时长、视频结果／状态、操作。行内编辑，长文本可展开；模型、参考图、镜头参数、候选版本放详情。展示计划总时长与已生成视频实测总时长时分别命名，缺失时长不当零。

支持：新增／复制／移除镜头、键盘上下移动、拖动排序、选中多行、状态筛选、按镜头定位画布、单镜头生成／重试／采用、按既有上限连续制作。筛选后默认禁用拖动排序，避免局部可见顺序意外重写全序列；通过“移到某镜头前／后”进行显式定位。

输入框内部撤销仍处理当前文本；提交后的编辑使用项目级撤销。一段连续输入按一次编辑会话合并，不每个字符生成一个项目撤销项。显示保存中／保存失败／冲突，失败保留草稿。

手机沿用 `html[data-layout]`：镜头卡列表＋单镜头全屏编辑＋上一镜／下一镜，不缩小桌面表格硬塞。画布柔性设备入口保持，分镜表不新设设备拦截。

### 3.3 原故事板与节点摘要

旧故事板改为“全部节点”浏览工具，通过画布工具／分镜页次级入口打开，保留类型浏览、普通文本 AI 编辑、素材预览与定位能力，不占用另一个主视图标签。

有来源剧本时，原剧本节点提供分镜入口与派生的镜头数量／制作进度，不改写其正文。手工分镜可有一个普通 Text 摘要节点作为入口，摘要只展示序列数据。删摘要不删序列；删来源剧本保留分镜并提示“来源剧本已移除”。

## 4. 数据模型与唯一真值

### 4.1 选择节点兼容方案

采用“doc 序列关系＋现有镜头锚点”，而不是把全部镜头内容迁到新数据库或在 doc 内复制一份镜头表。

```text
IpProject.doc
  storyboards.sequences[] ──shotNodeIds 的顺序──> 镜头图片锚点 node.id
       source.nodeId ─────────────────────────> 原剧本／拆镜来源
  nodes[]
       镜头锚点.metadata.studio.shot ──────────> 标题之外的镜头内容
       镜头锚点.metadata.images/primaryImageId > 图片候选与采用版本
       镜头锚点.studio.shotMedia.videoNodeId ──> 当前采用的视频节点
       视频节点.studio.shotOwnerId ───────────> 所属镜头锚点
       视频节点.metadata.videos/primaryVideoId > 视频候选与采用版本
       成片草稿.studio.workSource ────────────> 某次序列版本与媒体快照
  connections[] ─────────────────────────────> 参考／依赖（不表示成员或顺序）
```

`shotId` 对外统一使用镜头锚点的 `node.id`，稳定、不随镜号变化。旧模型返回的 `studio.shot.id` 只保留为来源标识，不作为文档内引用键；新业务 API 不接收它来定位镜头。

### 4.2 新增字段草案

以下名称为待实施契约，不是现有字段。最终 TS／Java mirror 必须一致。

```ts
interface StudioStoryboardState {
  schemaVersion: 1;
  sequences: StudioShotSequence[];
}
interface StudioShotSequence {
  id: string;
  title: string;
  revision: number; // 成员、顺序、来源等结构变更递增
  source?: {
    nodeId: string;             // 来源剧本／拆镜草案节点，允许显示缺失
    episodeNo?: number;         // 来源标注，不是唯一键
    scriptHash: string;         // 当次拆镜读取的正文／结构指纹
    splitRunId?: string;        // 同一受理结果重放只物化一次
  };
  summaryNodeId?: string;
  shotNodeIds: string[];         // 成员与顺序的唯一真值
}
// 镜头锚点的 metadata.studio 新增：
interface StudioShotEditing {
  revision: number;            // 镜头内容、规格、引用、采用版本变更递增
  imagePromptMode: 'inherit-description' | 'custom';
}
interface StudioShotMedia {
  videoNodeId?: string;        // 选哪一个视频对象；该对象的 primaryVideoId 选具体版本
  audioNodeId?: string;
}
// 归属某镜头的视频／音频节点 studio 新增：
// shotOwnerId: string; promptMode: 'inherit-shot' | 'custom';
// doc 新增 storyboards?: StudioStoryboardState；编辑回执字段见 §8。
```

字段所有权：

| 内容 | 唯一真值 | 旧字段处理 |
|---|---|---|
| 序列归属、镜头顺序 | `doc.storyboards.sequences[].shotNodeIds` | `studio.order/episodeNo` 仅兼容投影，新路径不以它们筛全项目 |
| 镜头名称 | 锚点 `node.title` | `shot.title` 为兼容投影，所有改名入口经同一命令维护 |
| 画面描述、台词、计划时长、人物名 | 锚点 `metadata.studio.shot` | 继续复用；人物名不能代替真实参考素材绑定 |
| 图片实际生成提示词 | 锚点 `metadata.prompt` | 继承模式由描述派生；手写覆盖后转 custom，修改描述不覆盖 custom |
| 视频实际生成提示词与参数 | 当前视频节点 prompt/spec＋受控表单草稿 | 与分镜描述区分；新增解析函数统一继承与覆盖，禁止隐式优先级互相压制 |
| 图片采用版本 | 锚点 `primaryImageId`＋候选数组 | storageKey/content 保持现有派生投影；签名 URL 不作为真值 |
| 视频采用对象与版本 | `shotMedia.videoNodeId`＋该节点 `primaryVideoId` | 不在行上再存媒体 key 或整份候选列表 |
| 视频／音频归属 | 产物节点 `studio.shotOwnerId` | parentNodeId 仍表达来源，不能同时兼作唯一分镜归属 |
| 生成任务／计费 | 服务端 IpRun、执行记录及既有账本 | 镜头 revision 不改任务参数或结算状态 |
| 剪辑顺序、裁剪、字幕时间 | 成片工程／成片草稿 | 与叙事镜头顺序分开；引用来源快照用于比较 |

新命令层生成兼容投影，旧组件只读这些投影；在版本化分镜上禁止旧写入口绕过命令直接修改投影。首版兼容字段保留，后续删除另立迁移，不同时清理全部历史类型。

### 4.3 约束

- 一个镜头锚点只属于一个序列。跨方案复用时复制镜头描述与节点壳、共享不可变 storageKey，清除任务／执行绑定；不共享可编辑镜头。
- 共享人物／场景素材可被多镜头引用；修改它的当前显示版本，不静默替换已提交任务使用的版本。
- 一个视频／音频生成对象只归属一个镜头。引用其他镜头的成品时创建独立素材节点壳，不修改原对象的采用选择。
- 序列成员 ID 唯一、存在、为带 shot 的图片锚点。shotMedia 指向同镜头且类型匹配的媒体节点；未采用时可为空。
- 普通图片加进分镜时新建锚点并引用／复用其媒体 key，原素材留在画布，不将一个共享素材原地变成独占镜头。
- 全部参考仍遵循实际 storageKey、归属校验、角色和模型上限；“人物名相同”不自动绑定图片。
- 序列修订与镜头修订只因相关内容变化而递增；移动画布、缩放、URL 重签、任务进度不递增。
- revision 不随撤销回到旧数值；撤销恢复内容后产生新的 revision，避免“内容改过又改回”误接受基于旧状态的 AI 操作。
- 分镜指纹由顺序＋镜头内容修订＋采用的实际媒体版本组成，不用画布坐标和 URL 计算。

## 5. 统一编辑命令与画布同步

新增 `canvas-bridge/studio-storyboard-commands.ts` 和 selectors，将 doc 作为输入，一次返回 `{nextDoc, inverse, affectedShotIds, warnings}`。通过一次 store 更新提交 nodes、connections、storyboards，禁止分开 setter 后再补关系。现有 `projectCanvasOps` 的旧事件路径保持，新分镜批次必须原子执行。

建议命令：`createSequence`、`insertShot`、`updateShot`、`moveShot`、`duplicateShot`、`removeShotFromSequence`、`adoptShotMedia`、`updateShotGenerationSettings`、`attachReference`、`detachReference`、`applyRebreakdown`、`deleteNodeWithStoryboardImpact`。

每个命令携带稳定 commandId、目标 ID、expected revision／字段基线；新增 ID 在首次创建操作时固定，重试沿用。批次先校验所有操作，失败整批不应用；独立多行修改如允许部分采纳，先拆成用户可见的独立批次，不能静默成功一半。

例如“把第 3 镜移到第 1 镜前”传的是 `{sequenceId, shotNodeId, beforeShotNodeId, expectedSequenceRevision}`；“修改台词”传的是 `{shotNodeId, patch:{dialogue}, expectedFields:{dialogue:原文}}`。客户端显示镜号，工具执行使用稳定 ID。不得把整份旧节点对象作为 patch，也不接受模型给出的坐标去重建全画布。

| 操作 | 分镜与画布联动 | 不应发生的副作用 |
|---|---|---|
| 修改描述／台词／名称 | 同一锚点更新；继承模式的生成草稿同步更新；相关旧产物提示待更新 | 不改原剧本全文，不改已受理任务输入 |
| 改生成提示词 | 更新对应媒体节点；切为 custom；分镜详情明确显示独立提示词 | 不用提示词反向覆盖故事描述 |
| 改计划时长 | 更新 shot.durationSec；继承该时长的未提交视频设置同步、按模型合同校验 | 不篡改视频实测秒数，不擅自拉伸／裁剪 |
| 调整镜头顺序 | 更新 shotNodeIds 与镜号；兼容 order 一起派生 | 不移动画布节点；“按镜头顺序整理”是独立显式动作 |
| 新增／复制镜头 | 同时增加锚点与成员；放在来源附近可用位置；复制去掉任务身份 | 不重新生成，不复制扣费／待处理状态 |
| 从分镜移除 | 只移除成员、保留节点与产物；行有撤销入口 | 不删 OSS，不取消已受理任务，不自动清空成片 |
| 在画布删除镜头节点 | 显示受影响序列与成片；确认后移除成员，关联素材保留或解除归属 | 不留下悬空成员，不级联删除共享素材 |
| 删除采用的视频节点 | 清除该角色选择并提示缺失；保留其他候选对象；现有成片快照仍可说明来源 | 不悄悄挑另一条成片替代 |
| 选择媒体版本 | “采用”更新节点主版本及镜头所选媒体对象，两个视图一致 | 仅预览、选中节点不算采用 |
| 改参考图／断开引用 | 更新目标生成配置与实际连线，提示受影响的草稿／结果 | 不因为断线就移出分镜，不改成员和顺序 |
| 画布拖动／缩放 | 仅布局变化 | 不改镜号、时长、采用结果 |

参考连线不承担镜头排序。新建归属通过 command 明确记录；旧亲子连线保留用于理解来源。

### 5.1 保存、撤销与竞争

- 开放任何分镜编辑前，必须完成项目加载和兼容读取；沿用项目级自动保存与 `saveStudioDocument`，失败保留本地草稿。
- `project-sync.ts` 的 IpDoc、toCanvasProject、snapshot、contentChanged、remote refresh、save-copy 全部加入新字段；复用 baseDocVersion 冲突，不做静默“最后写入覆盖”。
- undo/redo 抽至共享 bridge，快照包含序列和业务字段；任务状态、已受理输入、运行结果、计费以及命令回执不随撤销倒退。撤销内容后重新计算产物是否过时。
- 正在生成时允许改下一版文案／布局；当前任务仍使用旧快照。不能删掉正在运行任务的目标实体；可以移出序列，结果到原节点待用户采用。
- AI 或另一个编辑器改到当前正在输入的字段：先完成本地输入会话，再按基线比较。相同字段变更冲突给出对比；无关字段可保留后合并，不能用整个节点替换。
- 新分镜命令只支持当前文档版本内的编辑；跨标签保存冲突仍由现有冲突弹窗处理。单条命令的字段版本检查不能代替整文档并发检查。
- 删除镜头锚点时，同一事务清除其关联媒体的 shotOwnerId／继承依赖，保留已生成素材和不可变任务快照；完成回调不能重建序列成员。显式删除的已绑定节点还需 doc 内持久删除标记供执行恢复读取，不能只靠浏览器的 projected-node 记录防复活；恢复到历史版本时由显式恢复操作重新解释这些标记。

## 6. 生成设置、版本与重拆镜

### 6.1 描述与真实请求必须一致可解释

新增 `resolveStoryboardGenerationInput(doc, sequenceId, shotNodeId, role)`，供行内生成、画布生成面板、批量制作和 AI 制作计划共同使用。输出最终提示词、模型设置、引用的精确版本、镜头 revision 与输入指纹。

继承模式从当前镜头内容构造；custom 保留用户独立提示词并展示“已单独编辑，可恢复跟随镜头”。不得同时由 shot.description、metadata.prompt、composerDraft.prompt、studio.spec 四处各自决定最终值。提交前的校验、报价和实际请求必须消费同一解析结果。

画面描述、台词不是任意拼进所有模型字段：复用既有模型合同。配音／视频台词分别按当前产品能力转换，AI 不能声称已生成声音而只写了一段文字。厂商可能优化视频提示词时继续展示现有 effectivePrompt，不把它反写为用户描述。

计划时长与供应商可生成时长不一致时明确阻断或给用户显式修正选项，禁止静默钳制。台词改变标记关联音频／口型待更新，不笼统把与台词无关的静态图也判为错误。

### 6.2 生成与采用

- 请求输入快照记录 sequenceId、shotNodeId、内容 revision、选用参考和真实生成设置；新增字段不得改变原模型协议、计费或外部任务幂等。
- 新结果进入已有媒体候选体系；已有采用版本时不因异步任务较晚返回而自动替换。无采用版本且输入仍匹配时，可采用首次成功结果；输入已变化时只入候选并提示“按旧描述生成”。
- 历史结果的输入指纹缺失时显示“未核对”，不能宣称与当前描述一致。
- 已有 externalTaskId／runId 的不明任务只查询和恢复，不重新创建收费任务。改描述后再次生成是明确的新任务，有新报价与请求 ID。
- 从画布直接生成的视频如有明确镜头来源，写 shotOwnerId；从任意素材自由生成的结果不自动归组。
- 连续制作沿用现有服务／执行机制，按 sequenceId 和选中的 shotNodeIds 编译；保留一次最多 12 镜的当前限制，超限分批明确展示。未提交步骤的来源变更后暂停并重新确认，已提交步骤继续查原任务。

### 6.3 剧本与分镜是两个创作阶段

`StudioScript.shots` 是模型拆镜输出／来源快照，已物化后不作为当前镜头内容的另一写入真值。当前镜头内容在锚点，剧本 Markdown 继续保持原有正文真值。

剧本正文变动只使 source.scriptHash 失配并提示。用户点击“根据最新剧本调整分镜”后，先产生建议：新增、修改、保留、移出。无稳定匹配的镜头不得按相同镜号自动覆盖；由用户确认映射或保留为新方案。

采用建议时保持匹配镜头稳定 ID、手工独立提示词和旧候选，更新选定字段。默认不删除旧素材、不替换采用版本。整个差异采用为一个可撤销操作；相同拆镜 run 恢复只创建一次。回写剧本是独立明确操作，首版不提供自动双向同步。

## 7. AI 上下文、工具与权限

### 7.1 同一个助手，明确当前范围

扩展 `StudioPostMessageRequest`（TS／Java DTO 同步），新增可选 `editorContext`：view、sequenceId、selectedShotNodeIds、selectedFields、发送时 docVersion。发送前先提交输入草稿并 await 保存；保存失败不发送旧内容。

服务端按本人项目已保存 doc 验证所有 ID 和当前归属。上下文只提供范围，不提供写权限或账单依据。分镜／剧本／附件文本继续是数据，不能当工具授权指令。

助手输入框显示“《广告 A》· 第 1 集 · 已选 03–05”；用户可清除或改范围。每条消息存自己的范围快照，用户发出后切到另一组不会改变在途指令目标。“把第 3 镜改掉”按发出时序列解析为稳定 ID，不按执行时屏幕上的第 3 行重新找。无范围且有歧义才问一次。

镜头很多时按序列目录、所选镜头、前后相邻镜头读取；完整内容按工具分页取，禁止只读头部后声称检查了全片。选中行不会悄悄覆盖用户显式 @ 的其他素材；两者分开表达。

### 7.2 工具设计

新增 `read_storyboard` 与 `edit_storyboard`，其余制作仍走既有 `propose_plan`、报价确认、SubmitGenerationTool／执行器。两条新工具不能变成直接写任意 doc JSON 的后门。

| 工具 | 输入／行为 | 返回与限制 |
|---|---|---|
| `read_storyboard` | sequenceId、shotNodeIds 或分页 cursor，按保存文档读取 | 稳定 ID、显示镜号、内容／结构 revision、采用版本、任务状态、缺失关系；只读 |
| `edit_storyboard` | 明确目标、白名单操作集合、字段基线；服务端补固定 commandId／新增实体 ID | 返回可应用操作或修改建议；不生成媒体、不直接写项目 doc |
| 原 `update_nodes`／`propose_text` | 普通节点保持原行为；涉及绑定镜头字段时转为同一命令或明确建议 | 禁止绕过分镜命令改 prompt/spec 后留下旧表格 |
| 原生成／计划工具 | 使用已保存分镜、选择版本与统一输入解析，绑定明确目标节点 | 返回现有 run/execution，保持预算、开通、权限与费用确认 |

首版编辑白名单覆盖：改名称／描述／台词／计划时长、插入、移动、复制、移出、采用已有候选、修改未提交生成设置／参考。永久删除素材、改已受理输入、改账本、修改其他项目、任意 JSON patch 不开放。

每次工具允许最多 20 个编辑操作，超限拆成可见分批；AI 大范围重写先提交整体建议而不是逐批悄悄覆盖。读工具默认 20 行、最多 50 行，真实上限在契约中钉住并测分页。

### 7.3 执行与建议

- 用户明确说“把这三句台词缩短”：给出并应用可撤销编辑，标出实际改动行；这些修改采用已保存基线，不扩展到其他分集。
- 用户问“这样改会不会更好”：只建议。重写整集、重拆镜、移出大量镜头、影响现有成片等动作展示差异供采纳。
- 不让模型自由填写 `approved:true` 或 `mode:apply` 就获得授权；消息意图、操作类型、范围扩大和既有确认记录共同由服务端策略限制。无法确定授权范围时降为建议。
- AI 结构化编辑不另收媒体生成费，但对话模型本身仍按现有 Token 计费；不能展示“AI 改稿完全免费”。手工编辑不收费。
- 普通编辑成功以保存回执为准；已发事件／已生成建议不能回复“已修改完成”。

## 8. AI 修改的持久化、重放与并发

现有事件序号、稳定节点 ID、未保存游标机制继续复用，但分镜的“插入＋排序＋关联”需要持久的整批操作身份。只按 nodeId 去重无法区分同一镜头的多次改稿。

### 8.1 操作记录，不是第二套分镜业务数据

计划新增 `ip_studio_edit_command` 操作记录表（名称待实现契约固定）：id、projectId、owner、threadId、turnId、toolCallId、幂等键、payloadHash、不可变命令 JSON／预期字段基线、status、committedDocVersion、错误码、创建／完成时间。索引覆盖项目待处理命令、线程及幂等键；同一逻辑工具调用重试不得新建第二条操作。

该表只记录提议／投递／确认／冲突／拒绝，不保存另一份“当前镜头”。当前业务内容仍只有项目 doc。新 Flyway 编号在实施时跨 SQL 和 Java 两目录确认，禁止修改已执行迁移。

### 8.2 保存确认流程

```text
助手读取已保存分镜
  → 校验范围／字段基线，持久化整批命令
  → 发布 storyboard.edit 事件
  → 客户端核对命令状态与基线
  → 统一 reducer 原子应用（含 commandId/payloadHash 回执）
  → 原 PUT doc 保存成功，取得 docVersion
  → 客户端提交回执，服务端核对已保存文档中的命令标记
  → 操作记录变为 applied，助手／工作记录显示已保存
```

建议接口均挂既有 `/api/v1/ip-studio/projects/{id}` 下：

| 新接口（计划） | 用途 |
|---|---|
| `GET /edit-commands?status=pending&cursor=…` | 项目级恢复待处理命令，独立于当前打开的对话；只读、不触发模型 |
| `GET /edit-commands/{commandId}` | 查询命令真实状态，防止历史 SSE 重放重复应用 |
| `POST /edit-commands/{commandId}/decision` | 显式采用／拒绝建议；幂等，批准范围不能被模型扩大 |
| `POST /edit-commands/{commandId}/receipt` | 回报 applied／conflict；applied 必须核对 doc 中相同 ID 和 payloadHash，不能相信客户端空口成功 |

事件包含 commandId、threadId、原消息范围；负载可由记录接口读。状态建议：`proposed → dispatched → applied`，也可到 `rejected/conflict`；重试查询沿用同一记录。保存失败不是新操作，也不能直接标 rejected。

状态迁移在服务端操作记录锁内完成，applied 为终态；取消／拒绝与保存回执竞争时先核对已保存标记，不能将已经落盘的改动显示为“未执行”。已生效后的取消用新的撤销命令表达。dispatched 在浏览器离线时可暂停投递，不因超时自动变成一个新的编辑请求。

沿用统一错误壳。新增错误建议区分 `STORYBOARD_SEQUENCE_NOT_FOUND`、`STORYBOARD_SHOT_NOT_IN_SEQUENCE`、`STORYBOARD_EDIT_CONFLICT`、`STORYBOARD_EDIT_ALREADY_DECIDED`、`STORYBOARD_DOC_VERSION_UNSUPPORTED`；项目级并发继续用 `IP_PROJECT_STALE`。错误 details 带稳定目标 ID 与可重试动作，不泄露签名 URL／原始模型凭据；具体命名在 S0 同步到 OpenAPI 与前端错误映射。

doc 新增小型 `studioEditReceipts` 标记集合，仅记录未获服务端确认的命令 ID／hash，随内容同一次 PUT 落库。先验证基线、再原子写内容和标记。服务端确认后可在后续正常保存中清理标记；记录表保留 applied 状态，事件重放必须先查询状态，不可因文档标记已清理而重做。

跨浏览器、事件过期、刷新恢复从项目操作记录查询；本地 cursor／localStorage 只作优化，不能作为“不重复执行”的唯一依据。回执不是安全身份认证，所有命令和节点仍验本人项目、开通与手机写权限。

### 8.3 必须解决的时序

- 应用后保存失败：保持本地修改及待保存提示，不报完成；重试原保存。
- 保存成功但回执丢失：doc 有标记，补回执，不重做编辑。
- 浏览器关闭后命令才到：保留 dispatched；再次进入项目读取并校验当前基线，已变则显示冲突，不强制覆盖。
- 两个标签同时消费同一命令：按相同基线与固定 ID 计算，项目版本检查保证只有一份过期写被拒绝；另一标签刷新后认回执。
- 一轮 AI 先改台词、再要求生成：必须等改稿保存确认后再读取新文档编译制作。超时只显示“等待编辑保存”，后续操作暂停，不用旧数据继续；恢复不另开收费任务。
- 同项目多段对话均有未决编辑：逐批排队；只回写命令所属消息，不能跟随当前 threadId 改归属。切视图不卸载命令消费者。
- 用户撤销 AI 修改：产生一次新内容变更，原命令仍为 applied，不倒退回执；历史重放不能再次把被撤销的内容加回来。
- 撤销／历史恢复不得删除尚未确认回执；已执行的 AI 命令记录不随内容快照回滚。历史恢复是新的文档版本。
- AI 同一批改三镜，第二镜被用户改过：整批 conflict，给对比并允许重新生成针对当前内容的命令，不默默跳过第二镜。

保存确认不另开后台代写镜头服务。若未来需要用户离线时由服务端直接改 doc，那是文档所有权架构变更，另行设计，不混入本次。

## 9. 成片与分镜的关系

成片草稿增加 `sequenceId` 和 `workSource` 快照，不能继续只按 episodeNo 定位。无序列的自由画布成片保留现有模式，二者不混合自动选片。

从分镜“去制作成片”时按所选序列顺序、每镜明确采用的视频、实际时长建立初始草稿；没有视频／时长未知的镜头明确提示。用户可选择“仅使用已完成镜头”，界面列出被跳过的镜头，不悄悄跳过。

workSource 记录 sequenceId、来源指纹及每个 clip 的稳定条目 ID、shotNodeId、nodeId、精确 storageKey／候选标识、当时实测时长。可在一个成片中多次使用同镜头，因此剪辑条目 ID 与镜头 ID 分开。

现有成片默认保持不变。分镜变化显示差异：改顺序、新增／移出、采用版本变化、台词变化、时长变化；用户决定应用哪些内容。基础剪辑可按选择重排／换片；高级 Twick 工程先显示影响范围和不兼容裁剪，首版对复杂时间线提供“新建一版成片”而不自动重排所有轨道。

换成更短的视频时不能沿用超出源长度的裁剪；台词变化不能假定原字幕时间轴仍正确；叙事计划时长不能覆盖真实音视频长度。合成请求从确认后的剪辑工程编译，校验源媒体归属、时长和字幕，沿用原计费链。

## 10. 旧项目、复制、模板与降级

### 10.1 旧项目识别

加载时纯函数读取旧结构，不因打开页面就写回或调用模型。只有存在 `studio.shot` 的镜头锚点才进入自动识别候选；不能仅凭 `kind:'shot'`（普通生成对象也可能带它）判定。

优先按直接拆镜父节点＋明确来源剧本＋episode 分组，保留不同拆镜结果为不同方案。只有来源证据确定时才合并同一方案；多个同名剧本不能靠标题合并。

来源缺失、父链循环、重复 order、多个视频来源都不猜：镜头进入“待归组”清单；提示用户选择归属／采用视频。order 并列时保留原节点数组顺序作为稳定暂排，并提示需确认，不按坐标推导叙事。

兼容读取生成的序列 ID 必须由项目 ID、来源节点 ID、分集和拆镜批次等确定性信息派生；不能每次 render 用 nanoid 建一套新序列。用户新建／复制时才分配新 ID。两个标签对同份旧 doc 读取须得到相同候选分组，显式整理后的归属不再被下一次兼容扫描覆盖。

已存在唯一可确定的视频归属可生成兼容绑定；多个候选没有采用证据就显示待选择，不以“最近生成”替代用户选择。第一次显式编辑／确认整理时才把升级后的结构整存，并保留原节点／旧文档历史。

### 10.2 复制与导入

- 复制单镜头：新锚点 ID、清执行／任务绑定、复制不可变媒体引用；插在原镜头后。
- 普通画布复制图片节点：默认新自由节点，不暗中加入原序列；提供显式“复制为镜头”。
- 复制完整序列／项目／模板：一次映射序列 ID、锚点 ID、媒体 owner、source、summary、workSource 等内部引用；外部来源明确断开或以来源说明保留，不留下悬空绑定。
- 模板只读不物化、不创建命令；存为本人副本后才可编辑。模板数据携带结构版本，不能把复制继承的 accepted 请求继续运行。
- 所有导入／导出路径显式支持 storyboards；未知更高版本必须只读提示，不能去掉未知字段再保存。
- 删除序列只解除编排，保留节点和产物；从序列入口做“彻底删除”必须单独说明影响。历史版本仍可查看，不自动恢复已结束任务。

### 10.3 发布兼容

先发布后端结构校验、能力声明与操作接口，再发布支持新 doc 的前端；按项目是否已有 storyboards 保持安全读取。

已存在版本化分镜的项目，旧客户端 PUT 若丢掉该字段或缺少编辑协议版本应拒绝并提示刷新；同样保护运行前附带 doc、冲突强制保存等所有写入口。未升级项目仍兼容旧读取／保存。发布前必须测旧页面长时间开着再保存。

功能关闭后，已经升级的项目仍使用兼容阅读器并保留字段；不得退回一个会丢字段的旧构建。后端迁移只新增操作记录，不破坏旧镜头 doc；保留关闭新写入口的开关和文档备份。硬删除新字段或回滚到不识别字段的前端不是安全回退方案。

## 12. 实施阶段与交付门槛

这是依赖顺序，不预估未经验证的工期。每阶段形成可单独审查的变更，但只有 S1–S6 全部达标才向用户开放完整分镜编辑。

| 阶段 | 工作项 | 完成门槛 |
|---|---|---|
| S0 契约与样本 | 固定字段与命令、错误码、操作状态；准备两个剧本各第 1 集、多版本、无归属、旧剪辑等脱敏 fixture | 同一个镜头各字段的唯一写入者明确；列出所有序列化／写入口；无悬而未决的数据所有权 |
| S1 数据与统一命令 | 类型、序列关系、旧项目适配、原子命令、撤销、保存、复制／删除、协议保护 | 新旧 doc round-trip；两个剧本互不串；保存冲突和历史恢复不丢数据；无 UI 也能验证命令语义 |
| S2 分镜工作区 | 范围目录、行内编辑、详情、快捷入口、全部节点浏览、移动布局 | 在同项目画布／分镜往返编辑、刷新、撤销均一致；无业务隐性复制；无需模型即可验收 |
| S3 生成闭环 | 输入解析、继承／覆盖、镜头产物归属、候选采用、来源变更、连续制作与恢复 | 画布／表格发出的同设置请求一致；旧任务结果不覆盖新手稿／已采用版本；先用确定性测试 |
| S4 AI 编辑 | 工具／上下文、操作记录迁移、原子投影、回执／恢复、差异建议；适配旧工具 | 明确编辑可落盘、冲突不覆盖、断线不重复、模型能读回自己刚改的内容；真模型评测通过 |
| S5 成片与旧工程 | sequenceId 隔离、选用结果编译、来源快照、更新差异、Twick 保留、旧项目升级 | 分镜调整不破坏旧成片；两个序列两份草稿；复制／模板／旧页面保护实测 |
| S6 整体验收与发布 | 用户场景测试、必要真生成、编译契约门、文档同步、灰度与回退演练 | 合入 main 后从干净 main 构建；记录提交、范围、线上验收和未验证项 |

S1 是 S2/S3/S4 的共同前置；S5 依赖确定的媒体绑定与输入规则。不能先发布 S2 并宣称“AI 分镜编辑已完成”。不以全量改写 `studio-workspace.tsx` 为前置，用领域胶水逐步替换现有入口。

|---|---|---|
| A01 | 一画布含广告 A/B，均第 1 集，另有参考片与自由图片 | 分镜和成片均按 sequenceId 隔离，参考与试验不混入 |

| A08 | AI 改当前 03–05 三镜后用户切到 B 剧本 | 原 A 范围更新，B 不动；消息仍显示原范围和结果 |
| A09 | AI 思考时用户手改同一台词／只改无关节点 | 同字段整批冲突并可对比；无关修改不被覆盖 |
| A10 | AI 插入命令重复 SSE／刷新／新浏览器／回执丢失 | 只新增一次；应用后保存失败不报已完成，恢复不依赖本地游标 |
| A11 | AI 改完台词马上生成视频，保存延迟或失败 | 保存确认后才编译新输入；否则暂停依赖制作，不拿旧稿开任务 |
| A12 | 用户撤销 AI 修改后刷新并重放历史事件 | 不重新应用旧命令，不倒退任务或账单 |

| A14 | 删除来源剧本／分镜摘要／采用视频／镜头锚点 | 各按定义处理；无悬空成员，无共享素材级联删除 |
| A15 | 改剧本后重新拆镜，用户拒绝或部分采用建议 | 原分镜仍在；匹配稳定 ID、保留候选；不按镜号盲目覆盖 |
| A16 | 旧项目 parent 缺失／order 重复／同名剧本 | 只显示可证明归属，其余待确认；打开本身不写回 |
| A17 | 复制单镜、整组、项目、模板；导出再导入 | 内部引用映射正确、任务身份清除、原项目不变、结构不丢 |
| A18 | 两标签编辑，旧客户端保存新结构项目 | 新版进入现有冲突处理；旧版写入被拦，不丢分镜字段 |
| A19 | 分镜变化时已有基础剪辑／复杂 Twick 工程 | 先展示差异，原成片保持；复杂剪辑可另建版本，不毁字幕时间线 |
| A20 | 签名 URL 过期、媒体缺失、断网保存、只读模板 | 重签／缺失状态明确；草稿保留；模板无写操作；不造占位成功 |
| A21 | 120 镜测试序列，桌面＋手机＋键盘＋中文输入 | 当前编辑不丢焦点／输入法不误提交，列表按需加载媒体，无全表视频自动播放 |
| A22 | 通用画布不含分镜，原节点浏览、助手、合成 | 原有自由创作能力保持，不强制建分镜才能使用 |

测试分层：纯命令与迁移测试负责不变量；组件测试负责输入、范围、保存失败和建议；后端测试负责 DTO、权限、命令幂等、回执和版本保护；浏览器验收负责实际往返、刷新、多标签与成片保留。

真模型触发集至少覆盖：明确改三句台词、只问建议、插一镜、重排、重拆镜、跨序列歧义、引用人物素材、改稿后制作、冲突后恢复、只看了部分却要求总结全片。记录原话、工具、目标 ID、实际保存差异、费用与恢复结果。真媒体生成另以明确测试预算执行；本次写计划不调用付费模型、不使用生产用户素材。

提交前按仓库门禁运行 `pnpm typecheck:all`、`pnpm typecheck:admin`、server 离线 compile、`pnpm check:api-contract`，另加相关单测、web-aiavatar 构建与真实浏览器检查。无关失败记录基线，不为过门禁删除测试。本轮只有文档改动，不以未运行的代码测试充当验证。

## 14. 发布与回退检查

- 功能分支完成后合 main、解决主线冲突，正式制品仅从干净 main 构建。前后端均在范围，其他服务不顺带发布。
- 先在测试项目升级 doc，再验证普通旧项目、旧客户端、模板与冲突另存；不能全库批量改写旧画布。
- 分镜写入开关、AI 工具能力开关与读取兼容分离。关闭新编辑后仍可查看／保留已有结构，不能退回会删除字段的 serializer。
- 操作记录迁移是新增；回退保留表和数据。等待应用的命令可暂停投递，不能将其当新的命令重新执行。
- 发布记录写明 main SHA、服务范围、前后端协议版本、迁移编号、样例项目、费用、线上结果。构建通过不等于产品验收完成。

## 15. 风险、取舍与实施前核对

| 风险 | 本方案决定 | 实施前需核对的事实 |
|---|---|---|
| 现有字段分散且写入口多 | 保留节点真值，新增统一命令；版本化分镜禁止旁路写 | 搜索所有 shot/prompt/spec/primary/order 写点，逐项标已接入，含原生画布与 mock |
| 旧文档根字段被序列化丢弃 | 新字段贯穿所有 round-trip，服务器拒绝老客户端降级写 | 模板、导出导入、复制、历史恢复实际入口完整性 |
| AI 发事件与落盘不是同一时刻 | 操作记录＋doc 回执＋恢复接口为首版必要工作 | 消息／事件保留策略、API 轮询成本与服务端等待方式，不能依赖事件永久存在 |
| 既有主版本自动采用行为 | 对绑定镜头执行明确采用与旧输入保护，自由节点行为保持 | 图片／视频／执行恢复三条结果投影均覆盖 |
| 来源关系不够可靠 | 保守迁移、保留待归组，不按标题或坐标猜 | 脱敏旧项目样本中的 parent 链和多次拆镜形态 |
| 方案范围失控 | 首版不引入独立镜头数据库、不改供应商协议、不做全专业剪辑 | 新迁移只承载操作可靠性，不能借机复制业务域 |

以上核对由实施者读代码与 fixture 解决，不是把已确定的产品方向重新交给用户选择。若发现当前代码不支持某个既定语义，应记录具体障碍与调整影响，不能通过悄悄改变产品行为来适配实现。
