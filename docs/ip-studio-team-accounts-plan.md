# Studio 企业主子账号与积分管理方案

> **v0.4 · 已生产发布 · 2026-10-15**
> 根据用户在 v0.1 决策表中的评论及后续 review 重写。以本版替代原月配额方案；线上代码 `f068b51d`，部署、开关与验收见 [发布记录](releases/ip-studio-enterprise-production-release.md)。

**目标：企业充值积分，管理员给成员分配积分，成员分到多少就能消费多少；支持批量操作和独立个人充值。**

## 1. 已确定的范围

| 事项 | 最新口径 |
|---|---|
| 企业与账号（D01、D06） | 主体统一叫 `Enterprise`；一个主账号、多个管理员和成员；每人同时只能属于一家企业，可退出或转企业 |
| 登录与角色（D07） | 复用现有账号中心，成员独立登录；固定主账号、管理员、成员三种角色，不做自定义角色 |
| 积分管理（D02、D08、D09） | 企业充值、成员个人充值分别记账；分配给成员的积分仍归企业，可回收；支持批量，不做月预算、周期配额或月度清零 |
| 产品开通（D05） | 沿用现有 aiavatar 产品开通逻辑；加入企业、获得积分不自动开通，不做企业席位 |
| 作品归属（D03） | 画布和成果仍归个人；企业提供积分不自动获得作品、素材、提示词的读取权 |
| 个人自费（D04） | 成员可以主动选择个人积分，不受企业积分余额限制；不自动换付款账户、不混扣 |
| 企业充值（D10、D13） | 平台财务人工确认收款金额和入账积分，不做企业套餐或自动折算；退款保留平台财务流程 |
| 模型与并发（D11） | 企业积分消费受允许模型和成员在途任务数限制，后端执行 |
| 暂不做 | 企业席位开通、自定义角色、多企业同时归属、共享画布、积分跨企业转账 |

**2026-10-15 用户补充确认**：分配积分仍属于企业，可以回收；产品开通沿用现有逻辑，暂不做企业席位。两项已确定，不再作为开发前置待决策。

D12 采用简单停用状态，防止余额清空后因任务退款恢复消费；具体处理见 §3。

## 2. 积分怎样流转

### 三种余额

| 余额 | 谁管理、怎么使用 |
|---|---|
| 企业待分配积分 | 企业充值到账后，主账号或有权限的管理员分配给成员 |
| 成员企业积分 | 成员用于画布生成；与个人积分隔离，可查看消费和分配流水 |
| 成员个人积分 | 沿用现有个人钱包；企业无权清空、回收或查看完整个人账单 |

例：企业充值 **10,000** → 分给张三 **2,000**，企业剩 **8,000** → 张三消费 **300**，剩 **1,700** → 企业回收 **1,000**，企业变为 **9,000**，张三剩 **700**。

### 操作规则

- **人工充值**：平台财务填写目标企业、实收金额、入账积分、收款凭据和备注，确认后入账。企业负责人或获授权成员可发起充值申请，但不能自行增加积分。
- **分配/回收**：企业与成员企业余额一增一减，留下关联流水；不是新充值，也不产生新积分。只操作可用积分，不动任务冻结中的积分。
- **批量分配**：勾选成员、输入每人积分，展示人数与总额后确认。首期整批成功或整批失败；余额不足时不部分发放。批量回收逐人展示可回收金额，确认后按同样规则执行。
- **生成消费**：选择“企业积分”或“个人积分”；先冻结，成功扣除，失败退回。部分成功只收成功部分，重复请求不能重复扣款。
- **企业总额**：待分配 + 成员可用 + 在途冻结。分配不计作消费，最终扣款才计作消费，报表不能重复累计。
- **退款**：平台财务按原充值凭据办理；成员已分配余额需先按授权回收，已消费或冻结部分不可直接退。原单仍有冻结时先等在途结算；之后按原订单未消费积分及原比例计算人民币，不能用其他充值顶替。财务登记人工退款凭据，系统不自动打款。充值不是给成员直接转现金。

## 3. 成员、停用与权限

### 成员生命周期

成员通过邀请加入，服务端保证每人只有一个当前企业归属，停用仍保留归属。加入和退出均不迁移个人钱包、画布及成果。

2026-10-17 更新：企业邀请改为群发分享链接，默认 90 天，可选一年；多人可通过同一链接注册/登录后加入，管理员可撤销。取消单次使用和手工粘贴口令；旧邀请记录清理，不维护旧流程。增量当前仅本地实现，见 [验收记录](releases/ip-studio-enterprise-invitation-validation.md)。

**回收积分与停用分成两个动作：**

- **回收积分**：收回成员可用企业积分，成员仍可接受新的分配。
- **停用成员**：禁止新的企业积分消费，并回收可用企业积分。仅清空余额不足以停用，因为在途任务失败后可能退回积分。

已被供应商受理的任务按原账户结算；停用或退出后释放的企业积分回到原企业。未受理的排队任务取消并释放。个人账号与个人付费能力保留。

退出/转企业时回收可用企业积分；旧任务继续绑定原企业，不将旧企业积分或冻结转到新企业。主账号退出前须先移交或关闭企业；关闭须处理完在途任务、充值和余额。

### 固定 RBAC

| 能力 | 主账号 | 管理员 | 成员 |
|---|---|---|---|
| 邀请、停用普通成员 | 是 | 是 | 否 |
| 任命管理员、移交/关闭企业 | 是 | 否 | 否 |
| 单人/批量分配与回收积分 | 是 | 经授权 | 否 |
| 查看企业积分和消费汇总 | 是 | 经授权 | 仅本人企业积分明细 |
| 发起企业充值申请 | 是 | 经授权 | 经授权 |
| 使用本人企业积分 | 是 | 是 | 是 |
| 配置企业模型与在途上限 | 是 | 否 | 否 |

管理员不能修改自己的角色/授权，不能操作主账号或其他管理员；给自己分配企业积分需由主账号处理。主账号个人创作同样先分配到自己的企业积分账户，不能直接无限使用企业余额。

企业角色不复用平台 `SUPER_ADMIN / OPERATOR / FINANCE_ADMIN`。RBAC 判定资格，余额判定可花多少；企业账单权限不包含读取成员私有作品。

## 4. 对现有代码怎么改

| 模块 | 具体处理 |
|---|---|
| 身份 | 保留 OIDC 和本地 AepUser；新增 Enterprise、EnterpriseMember、邀请记录。当前企业归属由数据库唯一约束保证，历史关系另保留 |
| 权限 | 新增集中企业权限服务，查询有效成员和角色；不把企业角色写进长效 Token。企业 ID 由服务端校验，不能伪装成主账号操作 |
| 钱包 | 在现有 Wallet/账本机制上扩展个人、企业主账户、企业成员账户；成员企业账户绑定企业和用户，不能混进个人 gift/recharge 桶 |
| 划拨 | 新增转账记录与批次，关联双方等额出入账；固定顺序锁账户、同事务记账、请求幂等，保留积分来源；划拨不记作 RECHARGE 或消费 |
| 充值 | 复用 RechargeService 的人工核准和账本入账；补充人工金额/积分及目标企业快照。不得用“赠送积分”代替实收充值 |
| 生成 | 实际操作者、作品所有者、付款账户分别保存；IpRun、工作流、配音/口型和共享视频链都要接入，不只改一个生成按钮 |
| 终态 | 复用 CreditService 的冻结/扣款/释放，补齐停用/退出后的退款归集；取消、超时、worker 和人工对账一起适配 |
| 开通/资源 | 保留现有 EnrollmentGuard，不新增企业开通来源或席位；画布和素材继续按本人归属校验，不做团队资源迁移 |

**不能直接复用旧 Tenant/Studio 作为企业**：旧 Tenant 用于激活来源归因，Studio 是一人一份经营资料。现有 Wallet.userId 也是一人一钱包，新增企业账户前必须检查所有钱包查询、财务报表及退款路径。

积分划拨需保留原来源及桶属性，避免将赠送积分转成可退款充值积分。所有余额变动继续经过不可变 LedgerEntry；新账户类型上线前完成个人业务兼容，历史账本不改写。

代码核对入口：[权限](../apps/server/src/main/java/com/aistareco/aep/config/JwtAuthenticationFilter.java)、[钱包](../apps/server/src/main/java/com/aistareco/aep/model/Wallet.java)、[积分服务](../apps/server/src/main/java/com/aistareco/aep/service/CreditService.java)、[充值](../apps/server/src/main/java/com/aistareco/aep/service/RechargeService.java)、[画布归属](../apps/server/src/main/java/com/aistareco/aep/ipstudio/service/IpProjectService.java)、[产品开通](../apps/server/src/main/java/com/aistareco/aep/enrollment/service/EnrollmentService.java)。

## 5. 页面与实施顺序

具体开发任务、依赖与完成标准见 [开发任务清单](archive/ip-studio-enterprise-development-tasks.md)。本文保留产品规则，任务执行状态统一登记在 [TODO](../TODO.md)。

**企业管理页**：企业概览、成员管理、单人/批量分配与回收、充值记录、消费流水。成员侧显示企业积分与个人积分，生成前明确本次扣哪一份。

1. **账号与权限**：企业、邀请、唯一归属、固定 RBAC、操作审计。
2. **积分管理**：企业及成员账户、财务充值、分配/回收、批量操作、个人钱包兼容。
3. **生成闭环**：全部生成入口选择付款账户，冻结/结算/退回、模型和在途限制、停用/退出。
4. **验收发布**：先确定性生成和支付测试，再受控开放；同时更新类型、API 契约和业务规则。

必须通过的验收：

- 并发消费、分配和回收不能产生负余额；批量重试不重复发积分。
- 分配前后总积分守恒；财务充值不重复到账；部分生成失败按实际结算。
- 停用后不能继续花企业积分；旧任务退回不重新激活成员余额。
- 同一个人不能并发加入两家企业；退出或转企业不带走旧企业积分。
- 企业管理者无法读取成员个人钱包及私有画布；其他产品个人消费不受影响。
- 所有新账户类型支持旧个人流程，关闭新业务入口后仍能处理已有任务与资金。

**本版删除**：月预算/月配额、周期结转、席位套餐、多来源开通迁移、多团队切换，以及对应的数据表、接口和验收任务。暂不扩展自定义角色、共享画布和复杂审批。
