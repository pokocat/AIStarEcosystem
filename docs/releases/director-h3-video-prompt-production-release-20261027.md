## 变更

用户看、改的视频提示词仍是中文；所选视频模型是 H3 时，提交前先用作品的文本模型按 MiniMax 官方 skill（`resources/director/h3-skill`，原文未改）改写成英文六段式，再交给 H3。

- **台词不经过模型**：代码从中文提示词里认出台词换成 `{{Ln}}`，模型只写画面；提交时代码按当前台词填成 `(Sx) <d>[Chinese] 原文</d>`，说话人编号按第一次开口的顺序。
- **镜头结构由代码拼**：六段标题、`[Shot N] At MM:SS.mmm` 切镜时间由代码加；模型按 `shot_1…shot_N` 骨架逐镜填。
- **校验不过不提交**：台词漏了、重复或放错镜头，模型自己写台词，缺镜头，引用不存在的参考图，超 7000 字符，漏翻汉字超过 20 个，都判失败、全额退回，自动再改写一次，仍不过才报错。零星漏翻的中文由代码删掉，漏写环境声补一句中性默认。
- **计费**：改写不报价，按实际用量另扣（界面写「另需少量积分改写提示词」）；改写完成后用用户确认过的视频价格、付款方和请求号接着提交。
- **中文模板改成 H3 结构**：【人物】【分镜参考】【画面】【声音】【配乐】无；分镜脚本提示词补了画面写法与台词量（每镜不超过「秒数 × 4」个字、一镜一人说话），片段卡片提示台词过密和同镜两人说话。
- 界面：片段视频提示词下方说明会先改写；改写完成后可展开「发给模型的英文」。
- 只对 H3 生效；只按首帧出片的模型照旧。厂商的智能优化仍关着。

无迁移、无接口变化。依据与对比实测见 `docs/audits/director-h3-video-prompt-ab-2026-10.md`。

## 评审

Codex 两轮只读评审，阻塞项全部修掉后发布（用户定：一两轮评审、无阻塞即上线）。

第一轮 6 项 P1、2 项 P2（提交 `0bfead03`）：
1. 改写完成后续提视频没核一键制作的预算 → 发改写时按「视频报价 + 改写冻结上限」核对，改写期间视频报价算占用，续提前再按实际已用核对，放不下停在预算不足。
2. 续提被拒（价格变了等）后，一键制作会换请求号按新价格重发 → 记为该片段失败项。
3. 改写期间换了分镜图、参考图或声音仍会续提 → 发改写时记下视频输入指纹（含素材 key），变了就不续提；改写缓存指纹加入镜头切换时间。
4. 台词里再套一层引号会被截成半句 → 按引号配对识别；自动生成的提示词逐句核对原文。
5. 回投时自动重试的改写不算在跑，关页后后台不再推进 → 回投时新发出的任务算在跑。
6. 删掉引用不存在素材的句子后变空的镜头仍通过 → 判缺镜头。
7.（P2）台词放错镜头只查总次数 → 记每句台词所在镜头并核对。
8.（P2）一键制作暂停后仍自动重试改写 → 不再重试。

第二轮复核（提交 `4c1db522`）：上面 6 项已修好；补修 2 项 P1：自动重试改写前核预算（文本模型可能换过、价格变了）；用户改写过的提示词里引号不成对时拒绝改写（句数对得上也可能截了半句）。可后补项一并改了：旧格式语音轨的台词按「第N镜 · 」归到各自镜头。
