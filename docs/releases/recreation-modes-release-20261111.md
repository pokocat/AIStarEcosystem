## 深度复刻的运行环境

发布后在生产机上装了深度复刻的动作提取程序，但**没有开启**：`server.env` 没加 `AEP_STUDIO_DEPTH_*`，页面上深度复刻仍显示「暂不可用」。

- 安装位置 `/opt/studio-depth`（属主 `ecs-user`）：ReShot 0.5.0、CPU 版 torch 2.15.0（阿里云 pytorch 镜像；官方源下载太慢，中途换源），venv 1.5G，没有装进 CUDA 包。Video Depth Anything Small 和 DWPose 两个权重从本机传上去，sha256 与本机一致。
- 实测：用 ffmpeg 合成的 15 秒竖屏画面（不是用户素材），按 server 的参数先转成恒定 24 帧，再依次跑骨骼和深度两遍，放在 2.5G 内存上限、禁止交换、最低 CPU 优先级的临时 scope 里。骨骼一遍 72 秒（每帧 190 毫秒），峰值 1.2G。深度一遍 10 分钟没跑完，一直顶在 2.5G 上限，整机可用内存从 2.8G 掉到 800M，于是中途停掉。测量期间线上没有 ERROR，nginx 也没有因此出现 5xx，停掉后可用内存回到 3.3G。
- 不能直接开启的原因：`aistareco-server` 自身限 2G 内存（Java 约占 1G），ReShot 由 server 启动、算在同一个 2G 里，深度一遍就会把 server 一起拖死。这台 4 核 7.4G 的机器还跑着网页、MySQL 和其他项目，根分区只剩 5.3G（97%）。
- 测量期间 nginx 记到 11 个 503，都是复刻页的报价接口：有用户在新页面选了深度复刻，服务端按预期返回 `STUDIO_DEPTH_NOT_CONFIGURED`，页面仍在反复请求。下一版前端改为深度不可用时不请求报价。
