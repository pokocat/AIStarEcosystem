## 页面与交互

| 入口 | 已接入的操作 | 关键语义 |
|---|---|---|
| Studio `/enterprise` | 创建企业、接受邀请、本人两份余额、企业汇总、成员分页、分配/回收、充值申请及记录 | 个人余额与企业积分分开；整批预览后明确确认，失败保留原请求编号 |
| 成员与邀请 | 邀请创建/撤销/状态、角色及附加授权、停用/恢复/移除、主账号移交申请 | 口令只在创建后显示一次，不写入浏览器存储；管理员不能操作自己及其他管理员 |
| 企业关系 | 主账号移交记录与接收确认、退出、关闭前核对 | 显示可用、冻结、未受理及已受理任务；阻断条件可见；不移动个人画布或资金 |
| 生成设置 | 按后台模型名称选择允许模型、每位成员任务上限 | 只影响企业付款；停用模型可明确移除；不让用户输入端点编号或密钥 |
| 划拨 / 消费 / 操作记录 | 服务端分页的划拨、实际结算与企业管理记录 | 业务记录与真实账本引用相连，不包含私人画布、提示词、素材或个人付款 |
| 所有 Studio 生成入口 | 每个新请求确认个人/企业付款、读取真实余额、显示预计费用或文本实际用量结算规则 | 初始选择个人；账户不足、企业停用或模型受限均不自动换账户；重试保留原付款 |
| 管理后台原企业充值页 | 原有人工收款/退款闭环，新增企业搜索、资金汇总、成员余额、划拨及消费报表 | 企业和个人目标区分；企业内部划拨不累计充值收入；平台财务权限仍由服务端控制 |

付款入口覆盖 `studio-runs`（文本、剧本、分镜、图片、视频、助手、改编、合成）、配音、口型、模板步骤、资产分析、资产配图，以及两套遗留画布运行/生成薄封装。没有改 vendor 画布。

原请求恢复先查询服务端的 `billing-selection`。企业请求恢复原企业，明确个人请求保留 `billing: { mode: personal }`，旧请求没有付款字段时仍不补字段。浏览器只按画布与请求编号保存付款选择，不保存口令或创作内容。重复点击共用一次确认；查询失败阻止新提交并保留错误，取消确认不会提交任务。

## 设计取舍

按本轮要求参照 design-taste-frontend、gpt-tasteskill 与 Impeccable；这是实际操作页，继承现有 `StudioPage`、Ant Design 表单/弹窗/表格，以及管理后台既有原语。保留暖灰、白纸面、深墨、既有中文排版和轻量层级，不引入新的组件依赖、视觉体系或装饰性素材。

平台原任务核对工具位于原 `/platform/ai-models` 的“请求日志”页签，支持图片/视频切换。先查我方原任务，只有受理结果未知且缺少厂商任务号时才允许补录；图片按当前未结算候选序号核对，已有厂商编号不允许替换。填写核对依据并明确确认后保存原任务证据，继续查询原任务，沿用平台管理权限。

桌面与手机继续读取 `html[data-layout]`。成员表横向滚动，主要操作可换行；长名称与表格内容允许换行，身份与计费引用放入说明或标题提示。所有财务操作先预览后确认，错误与输入同时保留。付款确认使用实际库弹窗和原生单选语义，关闭后恢复原控件焦点。

机械检查已执行一次：只有字号与颜色的 advisory，没有阻断项。字号沿用既有 Studio 工作页密度；新付款弹窗的回退颜色已统一为品牌令牌。
