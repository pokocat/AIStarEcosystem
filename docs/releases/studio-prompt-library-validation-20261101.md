## 2. 编导真模型验收（聚算 qwen38-27b，和线上写脚本、做 H3 改写是同一个模型）

本地后端（本分支，库副本，`DAP_PERSONA` 与 `DAP_VIDEO_PROMPT` 都绑聚算 qwen38-27b，不支持 response_format），场景页同样的请求（文字任务带 `scene`），15 秒竖屏。5 个场景：同城团购、口播带货、促销转化、剧情植入、数字人口播。每条约 12–20 秒、1–2 积分。

### 2.1 第一轮（编导环节第 2 版，即设计文档 §9.3 的内容）

9 条脚本（5 个场景 + 同城团购、促销转化各多跑两遍）：

| 检查项 | 结果 |
|---|---|
| 五段式齐全 | 9/9 |
| 镜头行「第N镜（起–止 秒）」、从 0 开始、首尾相接、最后一镜补到 15 秒 | 9/9 |
| 台词写成「谁说：「……」」/「谁在画外说」/「旁白说」 | 9/9 |
| 客户写的位置、价格、截止时间原样出现 | 9/9 |
| **必填信息没给时写「还缺」和【待补】**（同城团购没给「怎么买、怎么用」） | **0/3**：每次都自己编了一个办法——「入口就在主页置顶」「点击左下角链接」「打开团购平台搜店名」 |
| **素材那段照抄了模板里的尖括号占位**（「是<商品细节>参考，采用<…>」） | 6/9 |
| **画面里安排了字**（「画面中央出现醒目的文字特效『双11店铺满199减30』」「中央显示『活动到11月11日24点结束』」「浮现 6 个色块」） | 促销转化 1/3 明确要求画面出字，另有 3 条在画面描述里夹「（不生成文字，仅手势引导）」这类括号说明 |

Agnes 2.5 Flash 上次是照规则写了「还缺」的，Qwen 不照做；尖括号和画面出字也是 Qwen 上才明显。

### 2.2 H3 改写

促销转化那条（画面要求出字）真出片，改写用时 10 秒：

- 发给 H3 的英文提示词 **2188 字符**，远低于 7000 的上限。
- H3 没有负面提示词，改写时脚本第五段的「始终禁止：不生成悬浮文字」被丢掉；画面里写的字原样译了进去：`bold text reading "双11店铺满199减30" appears prominently`、`Text reading "活动到11月11日24点结束" displays in the center, with a shopping cart icon`。
- 所以「禁止」那段拦不住画面出字，得在写镜头时就不安排字。

### 2.3 改了什么（编导环节第 3 版）

只在原句旁边补具体写法，其它不动：

1. 素材那行去掉尖括号占位，改成「写清它是什么参考、采用哪些特征、不采用哪些，例如：「门店门头.jpg」是场景参考，采用招牌和门脸外观，不采用路人和杂物。」
2. 镜头规则加一句：价格、优惠、截止时间、数量这些信息放进台词说出来，画面里不安排字幕、文字特效、价签、色块和图标（写进画面的东西视频模型都会照着画出来）。
3. 镜头规则加一句：必须有的信息没给的，对应的台词和画面写【待补：……】，不要自己编一个办法或说法填上。

### 2.4 改后复测（编导环节第 3 版）

5 个场景各跑两遍，10 条：

| 检查项 | 第 2 版（9 条） | 第 3 版（10 条） |
|---|---|---|
| 五段式、镜头时间轴、台词写法 | 9/9 | 10/10 |
| 素材行抄尖括号 | 6/9 | 0/10 |
| 画面里安排字（文字特效、价签、色块、图标） | 4/9（含括号说明） | 0/10 |
| 必填没给时写「还缺」/【待补】（同城团购） | 0/3 | 0/2，仍然编「点左下角链接领券、到店出示券码」 |

改后促销转化把「满199减30、11月11日24点结束」放进旁白，画面只拍围巾和人。

**还没解决：** Qwen 对「必填信息没给就写还缺、留待补」不照做。两个办法：接受（编出来的是抖音团购通用的领券、核销流程，不涉及价格），或者让模型在输出 JSON 里单列缺的项，由代码在脚本前面补「还缺」行（比在正文里要求它写一行更可靠）。待定。
