# 成片自动字幕与编辑室增强 · 本地验证（2026-11-07，未发布）

设计真源：`docs/studio-final-cut.md`。分支 `dev/final-cut-auto-captions`，基于 `origin/main`（`edff72c03`）。

## 环境

- 后端：`devq backend` 单 JVM，端口 18181，dev profile，库副本，测试响应模式（`aep.ipstudio.fixture-enabled=true`）。
- 前端：`next dev --webpack`，端口 3143，真实后端。
- 语音识别：本机 `whisper-server`（whisper.cpp 1.9.4，`ggml-small`，`/v1/audio/transcriptions`），后台绑到 `DAP_TRANSCRIBE`。
- 素材：macOS 中文语音合成做的两段 7 秒片段，片头留 1.5 秒静音，用来判断字幕时间是否跟着真实声音走。

## 用真语音验证的结果

`StudioCaptionSpeechE2ETest`（设 `STUDIO_ASR_E2E_URL` 才跑）走整条合成链：

| 情况 | 结果 |
|---|---|
| 已知台词 | `recognized`，第一句 1.537 秒开始，第二段第一句 8.553 秒开始（7 + 1.5），字幕是台词原文 |
| 未知台词 | `recognized`，第一句 1.536 秒开始，字幕是识别出来的字 |
| 1080p + 背景音乐 | 输出 1080×1920，有声音，字幕烧进画面 |

**这次实测改掉的两处设计**：

1. 把台词当提示词传给 Whisper，两段连着交过去时第一句整句丢了（模型以为已经说过），状态掉到 `estimated`。改成只传语言说明，已知台词按片段分别识别。
2. Whisper 的段落起点粘在 0 秒（片头明明有 1.5 秒静音）。加了静音检测，把每段收缩到真正有声音的范围；整段落在静音里的按幻听去掉。

## 浏览器走查

**一键成片**

- 五步编号，默认自动字幕，什么都不改就能点「合成作品」。
- 语音识别未绑定时：成片照常出来，结果下方写「语音识别暂不可用，这次未添加字幕。」
- 绑定后选背景音乐和 1080P：写「已自动添加 3 条字幕。」，日志确认走的是 `canvas path=normalize target=1080x1920`。
- 再打开高级编辑：3 条字幕已在时间线上（片段没变时才带入）。

**编辑室**

- 改速度：1.5 倍后第一段从 7 秒变 4.667 秒，后面的片段自动前移。
- 开头淡入 + 结尾淡出：导出第 0.03 秒是黑的，第 4.5 秒接近黑，中间正常。
- 小窗：出现在右上角（一开始尺寸被 Twick 改回铺满，已修），位置和大小可在右侧调。
- 图片：工具栏「图片」添加，选左下角后预览和成片都在左下角，3 秒后消失。
- 语音识别不通时导出：成片照常出来，`captions.status=unavailable`。

**导演台**

- 视频待确认时：按钮旁写「1 个片段的视频待确认」，「查看」滚到那一段。
- 确认后点「导出整集」：对话框只问字幕、背景音乐、清晰度，都有默认值。手机 375 宽下不横向溢出。
- 导出中：「整集合成中」+「通常需要几分钟。可以离开此页面，完成后在「导出记录」中查看。」
- 完成后：「下载成片」在按钮旁边，并写「已添加 2 条字幕。时间按镜头估算，个别句子可能略有偏差。」（这轮语音识别已关，走的是估算）

- 编辑室下拉菜单被全屏层盖住（`getPopupContainer`）。
- 「画面颜色」默认显示英文 `none`。
- 工具栏提示是英文（Delete、Split 等），已换成中文。

走查：批量确认、加载屏（放慢素材请求后点「返回」和浏览器后退）、编辑室和存档页上传音乐、右侧点片段跳到那一段并打开设置、字幕开关左右同步、手动加字幕后右侧改口、拖短后提示并去掉空白、带空白导出先问、片尾停下、重新生成后的提示、音色弹窗、分镜图弹窗的按钮主次、手机宽度下的下一步提示，都在浏览器里过了一遍。第七轮查到的那条导出失败是更早本地环境的请求错误（`header parser received no bytes`），同样 3 段视频之后两次都导出成功。

修完这批又做了一次小范围核验（限 35 次操作，换了评估者），**24/40**，结论还是「不能叫非常友好，第一次用还要人带」。它查到并已修的：片段需要更新时下一步提示仍写「视频都好了」（这是上一批我引入的）；「视频已确认」没说确认的是哪一版，现在写「使用第 N 版视频」；下一步提示压住片段卡右下角的按钮，已挪到本集剧本旁边；音色弹窗「保存音色」变灰却不说原因。它说拖短片段后右侧时长不刷新，我按同样步骤操作没有复现（第一段和最后一段都试了），没有改。

八次打分是 25、21、30、27、29、28、26、24，高低主要看评估者和看多细，不是一条变化趋势，**不能用它证明「够友好」或「变差了」**。能确定的只有：查出来的具体问题修掉了，两条主路径能走完，真人第一次用还没有试过。

**测试数据注意**：这份本地库的导出比线上慢，是因为本机语音识别服务没开，要等连接超时。

## 没有验证的

- **线上主机的 ffmpeg 二进制**：没有在那台机器上跑。用更旧的 3.4.11 实跑通过（见第三轮），发布前按惯例在线上主机再跑一次。
- **线上语音识别**：还没选型，也没有绑定。中文准确率、价格和接口是否返回 `segments` 都要拿目标端点实测（AGENTS §8.0.1 ⑦）。
- **真实 AI 片段**：这轮用的是语音合成加纯色画面。AI 视频带环境声时静音检测可能不起作用，字幕时间会更依赖模型本身。
- **预览里的调色和两头淡入淡出**：导出验证过；Twick 预览的颜色和成片是否一致只按滤镜数值换算，没有逐项对比。
- **语音识别这轮是关着的**：第二轮走查没开 Whisper，导演台走的是按镜头估算，编辑室走的是 `unavailable`。真语音路径是第一轮验证的。
- **第七轮修复后的整体效果**：26/40 是修复前的分数；是否够得上「非常友好」要真实用户试用才能确认。
- **真实扣费时的路径**：全程是测试响应，没有验证过真实付款弹窗和真实等待时长。
- **浏览器真实保存**：走查时拦下了保存动作，文件字节是用接口存盘核对的；长片的等待时间和微信内置浏览器没有实测。
