# 企业积分管理：发布准备

> 本文保留发布前的准备与回退检查；2026-10-15 已获授权完成生产部署，实际 SHA、开关、迁移及线上验收见 [发布记录](ip-studio-enterprise-production-release.md)。下文的本地演练结果不代表生产交易测试。

1. **先备份、后兼容发布。** 保留数据库备份和旧个人钱包/账本基线；新代码含 V56/V57/V58。两个前后端开关默认关闭：`AEP_ENTERPRISE_ENABLED=false`、构建期 `NEXT_PUBLIC_ENTERPRISE_ENABLED=0`。启动后核对迁移记录、个人钱包与现有开通，先不开放企业入口。
2. **开启前核对。** 后台检查目标企业、成员、实际核准充值、根钱包、成员可用/冻结、消费与等额划拨。配置允许模型和成员在途上限，再开启管理/付款入口。`AEP_ENTERPRISE_ALLOWED_IDS` 可限制新付款的企业ID（逗号分隔；留空表示全局开启后全部）。先只填写已核对的试点企业。
3. **异常按原凭据恢复。** 已受理图片/视频查原供应商任务号，供应商异常期间保留冻结及容量。无任务号时由运营记录证据并补原号查询；不能为清零报表强退或重新生成。财务订单、流水和任务核对入口在新业务关闭后继续可用。
4. **关闭与回退。** 关闭新业务开关会阻止新企业关系/积分消费，不停止既有 worker、核准/退款、结算恢复。已有企业资金后，最低回退版本必须识别 accountType、空 userId、原 walletId 冻结与授权；禁止回到只有个人 userId 的旧版本，不反向删除 V56–V58 表列。必要时保留兼容后端，只回退前端并关入口。
5. **生产验收单独记录。** 实际发布需记录 SHA、镜像/构建、环境开关、迁移版本、任务与余额快照、一次受控业务闭环。当前仅交付本地测试与回退准备，不写成生产通过。

本地演练包含：已有个人数据迁移前后不变；关闭新业务后已有冻结仍可结算；重启恢复原受理任务；前端关闭不改变账本。实际已完成前端开启/后端关闭的个人生成回归（1992→1984），新企业付款403、企业查询404、平台财务查询200、纯财务恢复403、运营查询200；企业992与冻结0不变。见 [完整验收](ip-studio-enterprise-complete-validation.md)。这属于保留兼容后端和schema的关闭入口演练；该演练未操作生产或降级数据库。

受理未知而供应商明确证明原请求未受理时，运营可提交核对依据并显式确认：图片 `POST /api/admin/ip-studio/runs/{id}/release-unknown`，视频 reconcile 的 `confirmedNotAccepted=true`。仅无原供应商ID、原冻结/授权仍有效且符合未知状态时允许；审计、原任务失败、仅剩余原冻结释放/归集及授权结束同事务。已有原ID必须继续查询，不允许单凭“查不到状态”释放，也不退已成功产物的费用。
