# Studio 场景化创作 · 本地真模型验收（2026-10-29）

分支 `codex/studio-scene-home`，本地后端关掉测试响应，用库副本里配好的真实端点跑。用户确认可以花钱跑真模型，并说明「不用管生成效果，重点把链路做通顺、体验打磨好」。所以本记录只看链路和体验，不评价画面好坏。

## 环境

- 后端：本分支打的 jar，`--spring.profiles.active=dev --aep.dev-auth.enabled=true`，**不带** `--aep.ipstudio.fixture-enabled`；库是 `.studio-e2e/database.mv.db` 的副本（原库没动）。
- 出图：Agnes Image（`studio-live-agnes-image`，8 积分/张）。出视频：Agnes Video 2.5 Flash（只支持 4 秒、9:16、只认首帧）。
- 对话：库副本里加了一个聚算 `qwen38-27b` 端点（复用库里已有的聚算 Key，声明能看图、不声明 `response_format`），设成默认对话模型。Agnes 的对话端点每分钟只放一次调用，一轮对话要连着调好几次，第二次必定 429，跑不完。
- 前端：本分支 web-aiavatar 开发服务器，经 Next 代理连本地后端。

## 结果

| 路径 | 结果 |
|---|---|
| AI 图片 · 脸部三视图：上传照片 → 立即生成 → 价格确认弹窗（8 积分）→ 出图 | 通过。真图回到结果区，积分 579 → 571，「最近」的草稿封面换成了结果图，「在画布中继续」打开同一份内容 |
| AI 图片 · 商品白底图：上传 + 补充要求 → 生成 | 链路通，但 Agnes 返回 429（「请登录platform进行实名认证以获取更高rpm」），没扣积分。「重新生成」原地重交（新请求编号）同样 429 |
| AI 视频 · 口播带货：传商品图 + 一句话 → 交给创作助手 | 通过。画布打开，商品图放进画布，第一句带着 `skillKey: video-generation` 自动发出（抓包确认） |
| 助手（真 Qwen）出方案 | 看图正确描述了商品；按「不要自己编」把价格优惠留成占位；被本地视频模型的 4 秒、只认首帧两条限制驳回几次后，自己改成 5 段 4 秒，发出确认卡（20 积分，「出视频」方法） |
| 确认后生成 | 执行开始，5 段都进入生成；Agnes 视频服务返回 503 `video_queue_full`，5 个任务失败、冻结全部退回；约 90 秒后助手显示「第1段没有完成：模型提供方的视频任务队列已满…」并给「重试这一步 / 停止」，已用 0 积分 |
| 先前一版话术（「先给我分镜方案」）的确认与执行 | 助手只排了一步写脚本（21 积分上限，实际 1 积分），脚本落到画布并连着商品图；但做完给的建议都是改脚本，没有「出视频」——话术已改 |

## 这次真跑后改掉的问题

1. **交给助手的话只要「分镜方案」**：真模型只排写脚本一步，做完也不提出视频。改成「要的是做好的视频，不只是脚本：把文案、分镜和每段视频一起排进方案」，有测试守着。
2. **视频场景没指定方法**：第一句没带技能，真模型去读了「写剧本与文案」。现在开始节点带 `studioSkill`（视频场景 `video-generation`，爆款复刻 `reference-video-recreation`），助手自动发出时带上；模型之后仍可自己换方法（服务端允许）。
3. **等确认价格时，结果行写「提交结果没有确认」**：改成「正在提交」，不显示「确认原任务」。
4. **图片阶段显示百分比**：按仓库规则去掉，只说排队还是生成中。
5. **失败只能「用这段描述再做」**（两步，还要重放图）：加「重新生成」，原地用同样的输入和新请求编号重交，不堆失败行。
6. **限流原话看不懂**：429 显示「模型那边请求太多，稍等一分钟再点「重新生成」；没出来的图不扣积分」，厂商原话和记录号放悬停提示。
7. **重新打开草稿 / 用这段描述再做时参考图丢了**：现在把那一次用的参考图放回原位置。

## 没解决、记进 TODO 的

- 本地 Agnes 账号：每分钟约一次调用、免费视频队列经常满。本地验收要么给这个账号做实名认证，要么改用聚算端点。
- 助手回复里漏出内部说法：「keyframe-first」「临时 key」「真实 id」「本阶段只允许 text 和 image 操作」；写出的脚本里出现了节点编号 `[xeFx-…]`。属于现有助手提示词，不是场景页。
- 视频任务被厂商拒绝后，助手的进度要约 90 秒才从「生成中」变成失败。
- 本地视频模型只支持 4 秒，助手为凑 25 秒反复试了几轮，这一轮对话花了 55 积分。线上默认视频模型不同，没在线上环境验证。

## 统一端点后的复验（同日）

后端把场景目录和拼话统一到服务端之后（`docs/studio-scene-creation.md` §7），重新打包、重启本地后端，在页面上走一遍：

- **AI 图片 · 脸部三视图（真模型）**：抓到的请求依次是 `POST /scenes/compose`（只带场景编号、补充要求「自然微笑」、放了图的位置）→ `POST /projects`（`sceneId: face-turnaround`）→ `POST /projects/{id}/studio-runs`（`prompt` 是服务端拼的「场景描述 + 补充要求：自然微笑」）→ 真图回到结果区。
- **AI 视频 · 招牌体验**：「看看会发给助手的话」显示的是服务端拼的话；交给创作助手后，草稿 `sceneId: local-signature`、门店照片已放进画布、开始节点 `studioSkill: video-generation`（来自 compose 的 `skillKey`）、项目列表返回 `sceneId`（「最近」按它列）。
- 接口直调：缺必填参考图 → 400「先放新面孔」；建草稿带不存在的 `sceneId` → 400 `STUDIO_SCENE_INPUT_INVALID`。
- 第一句自动发出这一步，这次没等到：浏览器面板在后台，画布发送前要等两帧动画，面板隐藏时不跑——本地验收环境的现象（此前的「38 秒才发出」也是它），不是产品问题；开始节点里的方法已核对。

## 聚算 H3 真跑一条（同日）

用户同意花聚算的钱跑一条 H3。只改了库副本：H3 端点地址改成 `https://api.jusuanhub.com/v1`（原来的 `:10443` 连不上），加进 Studio 视频模型组并设为默认、补 `ai.model-access`，把「出片前改写提示词」（`DAP_VIDEO_PROMPT`）绑到本地聚算 Qwen。场景页最短 15 秒，H3 每秒 40 积分要 600，超过本地余额，所以在画布里让助手只做一段 5 秒。

| 步骤 | 结果 |
|---|---|
| 一句话：5 秒竖屏、只要这一段 | 第一次报不出价：本地没绑改写模型，助手提议「关掉智能优化按原文生成」，选了之后仍报不出价（方案里关不掉改写），白花 12 积分对话费 |
| 绑上改写模型后「再试一次」 | 确认卡：一段 5 秒视频，221 积分（视频 200 + 改写上限） |
| 开始制作 | 先调 Qwen 改写提示词（2 积分），再提交 H3（`/v1/media/generations`，`t2v`、544p、9:16、5 秒），202 受理；约 10 分钟后出片 |
| 结果 | 视频落进助手准备的那个视频节点（544×960，H.264 + AAC，5.18 秒），助手回「做好了，花了 202 积分」，余额 458 → 256 |

看到的体验问题：

- 生成的 10 分钟里，画布上那个节点一直是「上传视频 / 生成视频」的空占位，只有助手面板写着生成中；出完片才一次性换成视频。
- 改写模型没配置时，助手说「服务端提示词优化没绑上可用模型」，这句是给开发看的；而且它提议的「关掉智能优化」在方案里做不到。线上已绑改写模型，不影响线上，记 TODO。
- 做完后附一条「建议修改提示词」，修改稿是 H3 改写后的英文提示词，普通用户看不懂要不要采用。

这次真跑后改掉的：

1. 文字任务读图被第二处校验拦下（§8.0.1 ④：同一条规则写了两遍）。
2. 拍法写「结尾讲优惠」时模型会写「现在下单有优惠」：要求里补了「不说没给过的优惠，只引导下单」。
3. 生成模式的设置被出图页的样式撑成大块，对话被挤成一条缝：生成模式整列换成编辑器，设置一行一项。
4. 厂商队列满的原话（英文 + 追查号）直接显示：换成人话。
5. 长片提示「要 25 秒以上」不准确、示例文案还写「助手会先看商品图」：已改。

没验证的：新页面出片成功的那一半（H3 全能参考带商品图）没有真跑，免费 Agnes 队列满；H3 只在画布助手路径真跑过纯文字出片。记 TODO，等用户同意再花一次聚算的钱。
