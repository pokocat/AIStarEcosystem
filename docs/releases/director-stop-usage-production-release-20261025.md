# 停止创作按真实模型消耗结算：发布更正（2026-10-25）

用户明确指出模型请求提交后已经产生消耗，不能因为点击停止而退回全部积分。此前 `20261026-director-stop` 的全额释放实现错误，本次修正替换它；历史调查见[导演台排查记录](../audits/director-script-stale-and-latency-20261026.md)。

## 最终行为

- 未提交的文字任务停止时取消派发并释放冻结。新任务在认领与真正提交模型前分别记录提交跟踪状态，停止与派发在任务结算锁下协调。
- 已提交的导演请求停止后状态投影为 stopping：停止后续创作，允许用户重新确认另一笔生成，但原 HTTP 调用继续等待用量回执，不为了停止而强杀、丢掉回执。收到真实用量后按接受时费率结算，只释放未使用部分；取消后的正文不回投，新内容不被旧请求覆盖。重复回执不再结算。
- 已取得真实用量的同步文字取消不再全额退款；导演文字的截断/格式错误也先保留用量回执，取消与结果返回竞态不会丢掉已知消耗。其它原生图片、音频、视频的提交与恢复入口未改。
- 无存活线程、进程关闭或中断且没有用量回执的导演请求标为 failed / settlement.pending / STUDIO_USAGE_PENDING，输出记录 reservedCredits，账本不消费也不释放，错误日志提供追查依据；后续人工核对。不能用超时推断零消费，不能按批准上限直接消费。CreditHoldSweeper 跳过待核对冻结，不会到 TTL 后又自动退款。
- 后续真实回执若在进程关闭前抵达，可从待核对状态结算一次；无回执时没有自动对账或估算费用。发布不发模型请求，不代用户停止、确认重试或补扣历史费用。
