## 范围与环境

普通视频、分段长视频、爆款复刻在 `/video` 共用配置、制作状态、成片和最近任务。画布只在主动查看或处理问题时打开。

本次使用隔离的本地 Spring Boot 固定 JAR、H2 文件数据库、独立上传目录和 Next 预览；供应商由本机确定性测试服务替代，所有测试媒体有 `LOCAL TEST` 标记。真实受理、原生步骤推进、媒体镜像、FFmpeg 合成、计费记录与页面恢复经过本地链路；三类媒体均为 720×1280 H.264/AAC，时长分别为 15.000 / 40.023 / 15.000 秒；**不代表真实供应商生成质量或生产发布验收**。本地新库关闭 Flyway、由 Hibernate 建测试表，不改生产迁移。

重任务按 devq 串行队列执行，工作树编译门的 workspace typecheck 用 `--workspace-concurrency=1` 覆盖同一组应用；媒体操作也进入该队列。后端按固定 JAR 单 JVM 启动，未启动 Maven 常驻。打包时跳过重复测试，后端单独执行指定的业务测试，不能把打包成功当作测试结果。

## 界面与恢复

- 桌面沿用 IP Studio 的白面、深墨、细线、控件、布局形态真值；1319×801 三列，1080×800 的历史为抽屉，390×844 切换制作和作品。
- 最近任务使用原生成视频的真实缩略图，失败时保留输入图和图标回退；不把视频源当图片自动加载。
- 抽屉打开时移动焦点，Tab 在抽屉内循环，Esc 关闭并恢复触发按钮焦点。
- 原生 History API 更新去掉 Next 内部标记回传，修复“地址含任务但视图不更新”；保留同一项目的任务地址，切换项目不沿用旧任务。
- 任务切换的旧请求不能覆盖新选中；未确认提交继续使用原编号；读取不会触发新生成。历史设置只读，改一版另建草稿。
- 失败节点按原生媒体 `shot` 类型恢复，只有合成节点使用 `work`；恢复生成参数，避免视频失败被误送成片编辑器。任务返回条随停靠助手让出空间，操作不被遮挡。
