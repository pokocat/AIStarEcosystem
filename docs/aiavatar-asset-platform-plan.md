## 0. 核心诊断（一句话）

**现在的 web-aiavatar 是一个做得相当扎实的「数字人制造车间」，但离「数字资产平台」还差三层：资产的多样性、资产的权利属性、资产的流通性。**

### 0.1 现状事实

**做得好的**：

- 人物形象全生命周期：8 态状态机（draft→proofing→iterating/refining→pending→finalized→deriving→archived）、版本时间线（switch/fork）、回收站（30 天）
- 端上美颜精调（MediaPipe 478 点 + WebGL shader，确定性液化/磨皮）
- 6 类衍生物（图集/表情/场景/换装/3D 预览/运镜视频），图像类走真实生成 pipeline
- 真人授权复刻链路（6 秒三角度录制 + 身份核验 + 肖像授权凭证 LIC，可下载/续签/催签）
- 数字人广场（10 官方样板 + 运营内嵌管理 + 用户「另存为」）
- 诚实降级机制（§8.0：mock 角标 + 不扣费；生产 503 不伪造）
- 存储合规（§4.7：全走 FileStorageService，DB 存 key、出 wire 签名）

**结构性空白**（不是没做完，是**从未规划**）：

| 空白 | 事实依据 |
|---|---|
| 道具/场景/服装不是资产是消耗品 | `DerivKey` 枚举无 prop；换装/场景是一次性衍生物；场景库内置只读 |
| 声音克隆只存采样没有合成 | `DapVoice.audioKey` 存原始采样，试听 = 采样回放；DECISIONS.md 明示「TTS 排期中」 |
| 授权只是「肖像同意书」 | `DapLicense` 语义限定为真人肖像使用同意；无定价/独占/二创/分成字段 |
| 无任何交易/确权/水印/指纹/分成概念 | dap 包内搜索 order/transaction/watermark/fingerprint/copyright 零命中 |
| 应用中心三张卡全是占位 | 点击均 toast「邀约开通请联系客户经理」，无跳转无数据传递 |
| celebrity 域未接入数字人引用 | `listAvatarReferences` 硬编码 `kind==ACTOR ? "drama" : "music"`，无 celebrity 路径 |
| 3D 是图片伪装 | 多角度预览图冒充可旋转 3D，GLB「排期中」 |

**定位与兑现的落差**：PRODUCT.md 已写「可复用、带版本、带授权的资产，一键接入下游变现」——代码只兑现了「可复用、带版本」，**「带授权」和「变现」是空的**。

## 1. 定位重述：AI 时代数字资产的三个本质命题

传统素材库（视觉中国、Epidemic Sound）卖的是**文件**。AI 时代的数字资产平台，资产的本质变了——这是整个方案的立足点：

1. **资产 = 一致性锚，不是图片。** 一个数字人的真正价值不是那张定妆照，而是「在任何下游场景里都能生成出同一个人」的能力（参考图集、embedding、人设卡）。drama 线 v0.97 已在做镜间一致性（角色参考图复用），说明**下游已经在消费一致性锚了，但供给方不是 aiavatar** —— 这是当前最大的定位错位。
2. **资产 = 权利包，不是内容。** 谁的脸、谁授权的、能用在哪、分成给谁——这些元数据比像素值钱。
3. **资产 = 可调用的服务，不是可下载的文件。** 「让这个角色说这句话」「让这个角色穿这件衣服出现在这个场景」是资产的消费方式。

**终局叙事**：aiavatar 不该是五个平行子应用之一，它应该是 **music / drama / celebrity / star 四条线的供给侧**——生态的资产中枢。

## 2. 方案主体：五个方向

### 方向 1：资产类型扩展 —— 从「人」到「资产宇宙」

建立统一的一等资产抽象（现在只有 `DapAvatar` 是一等公民，其余都是它的附属物）：

| 资产类型 | 现状 | 目标形态 |
|---|---|---|
| **人物 Character** | 只有「形象」（脸 + 图集） | 升级为「角色包」：形象 + 人设卡（性格/背景/口头禅/说话风格）+ 声音 + 表演风格。人设卡可直接喂给 LLM，让角色在 drama 剧本生成、celebrity 直播话术里保持**人格一致性**（形象一致性之外，目前全生态没人做） |
| **声音 Voice** | 采样存档 + 回放（TTS 排期中） | 独立一等资产：克隆合成、情绪/语速风格参数、可**独立于形象授权**（声优只卖声音不卖脸，是真实的市场形态） |
| **道具/服装/场景 Prop·Outfit·Scene** | 换装/场景是一次性衍生物；场景库内置只读 | 可复用、可组合、可上架的独立资产库：一件「戏服」做一次可给所有角色穿；一个「场景」可被多部短剧复用。drama 的 `BoardScene.sceneRefId` 场景参考绑定已证明下游需求存在 |
| **IP 包 IP-Pack** | 无 | 打包资产：角色（可多个）+ 世界观设定 + 视觉规范 + 声音 + 授权条款，整体授权/交易。面向 B 端和专业 IP 方的 SKU 形态 |
| **动作/表演 Motion** | 只有运镜视频（无表演驱动） | 动作库、表情差分包、演绎模板（口播手势、直播动作循环），直接服务 celebrity 带货视频 |
| **3D 模型** | 图片伪装的「可旋转预览」 | 按原排期落地 GLB，但**降优先级**——它服务的场景（游戏/元宇宙）不在当前生态变现链上 |

**心智切换**：「数字人库」Tab 改名「资产库」，导航按资产类型分区。产品名字里的 Avatar 可保留，但用户心智要从「我做了几个数字人」变成「我拥有一个资产组合（portfolio）」。

### 方向 2：权利层 —— 确权、授权、分成

资产平台区别于生成工具的分水岭，最值得投入的方向：

- **生成即确权**：每个资产产出时自动登记「出生证」——内容哈希指纹、生成参数快照（引擎/prompt/参考图链）、创作者、时间戳，形成不可篡改的溯源链。有条件时接 C2PA 内容凭证标准 + 不可见水印。
  - ⚠️ product_spec.md §13.3 把「版权核验」列为冻结领域（缺工具链）。**建议解冻并收窄范围**：不做全网侵权核验，只做「平台内生成溯源」——这个工具链自己就有（DapJob 已存 payload/result 快照，差的是哈希登记 + 不可变化）。
- **授权对象化**：`DapLicense` 从「肖像同意书」升级为通用授权协议对象：适用资产、被授权方、范围（商用/非商用）、平台、期限、独占性、二创权、**分成比例**。
  - 关键是**机读化（license as data）**：下游 drama/celebrity 调用资产时后端自动校验授权有效性——过期、超范围、超平台直接 403，而非靠人看合同。现有续签/催签/凭证下载体验直接复用。
- **使用计量与分成**：资产每被下游消费一次（出图、出片、TTS 一次）记一笔使用流水 → 按授权协议分成比例给资产持有者分账。
  - 这让「真人授权复刻」路径闭环成**被动收益产品**：普通人授权自己的脸和声音 → 躺着收分成。这是真人复刻路径目前缺失的核心卖点，也是拉新故事。
  - 账本直接走现有 `LedgerEntry` 不可变账本（§4.2），基础设施现成。

### 方向 3：流通层 —— 从「广场」到「市场」

- **全资产市场**：数字人广场（只读样板 + 另存为）升级为全资产市场——人物、声音、道具、场景、IP 包统一上架。交易形态三种：
  1. **按次调用**（用一次扣一次积分，平台与资产方分成）—— AI 资产独有形态，**优先做**
  2. **订阅**（有效期内可用）
  3. **买断**（资产副本归你）
- **UGC 上架 + 创作者经济**：用户资产申请上架、运营审核，平台抽成，销量/调用量榜单。drama v0.75 创意市场的「用户自助发布 + 运营邀约精选」双通道模式可整体照搬（含 invited/declined 状态机 + 站内信授权流）。
- **B 端 SKU**：品牌数字代言人租赁（形象 + 声音 + 档期打包，按月订阅）；明星数字分身授权—— web-star 已是审核中枢，明星侧审批数字分身商用授权是其自然延伸，两条产品线在此合流。

### 方向 4：调用层 —— Asset as a Service（最大胆，也最本质）

- **资产 API 化**：每个资产暴露标准调用能力——`说这句话`（声音资产 → 音频）、`出这张图`（角色 + 场景 + 道具组合 → 图）、`演这段戏`（→ 视频）。下游子应用、未来外部开发者（开放平台 / MCP server）消费的不是文件而是调用。计费天然按调用走，与方向 2 的计量分成是同一套管道。
- **一致性锚服务**：把「角色参考图集 + 场景参考 + 风格规范」封装成下游生成时的标准输入。drama 的 factory 现在自己拼 `ref_images`，celebrity 未来做带货视频也要拼——这个能力应由资产平台统一供给：给一个 assetId，返回该角色在任意生成引擎下保持一致所需的全部锚点材料。**这是 aiavatar 在生态里最不可替代的位置。**
- **应用中心从占位变分发总线**：短期先还三件确定性欠债——
  1. celebrity 接入 `import-avatar`（现在硬编码只有 music/drama）
  2. 应用卡片真跳转（依赖 Cookie SSO，Phase 5）
  3. 引用从「只读展示」升级为「授权 + 计量 + 分成」的入口

### 方向 5：组合层 —— 资产的场景化打包

- **剧组包（Cast Bundle）**：一部短剧的全套资产——多角色 + 场景集 + 道具 + 声音——一键打包，直接注入 drama 项目立项。反向：drama 爆款项目里的角色/场景「沉淀回资产库」（同构于 drama 的 recipe 蒸馏飞轮）。
- **数字人 = 可雇佣的演员**：给角色资产加「档期 / 擅长风格 / 历史作品 / 口碑」维度，市场里按「我要一个适合演都市甜宠的女主」检索。把资产库从「文件夹」心智升级为「经纪公司」心智。

## 3. 优先级路线图

| 阶段 | 主题 | 内容 | 判断依据 |
|---|---|---|---|
| **P0 还债**（资产平台的底座资格） | 把已承诺的资产做真 | ① 声音克隆真 TTS 合成落地（否则「声音资产」是空话）② celebrity 接入数字人引用（生态变现链最粗的一条腿缺席）③ 统一资产抽象（Asset 基类：character / voice / prop / scene / outfit / ip-pack），道具/场景/服装升为一等资产 | 这三件不做，后面全是空中楼阁 |
| **P1 权利层** | 资产带上权利 | 授权对象化 + 机读校验、生成溯源/指纹登记、使用计量流水 | 差异化壁垒；LedgerEntry / 审计基础设施现成 |
| **P2 流通层** | 资产动起来 | 全资产市场（先按次调用 + 订阅）、UGC 上架双通道、分成结算 | 依赖 P1 的计量；复用 drama 创意市场模式 + FINANCE_ADMIN 结算面 |
| **P3 调用层** | 资产服务化 | Asset API / 一致性锚服务 / 剧组包 / B 端租赁（与 web-star 合流） | 生态位终局；依赖 Cookie SSO（Phase 5）和分租户（Phase 6） |

### 3.1 配套工程判断（提示，不展开）

- 现有 §4.7 的 CdnUploader / CdnUrlSigner key-only 体系和 §8.0 禁止静默降级原则，恰好是权利层和调用层需要的底座，方向不冲突。
- 统一资产抽象会触及 dap 域数据模型，**建议与 Phase 6 分租户 migration 一起规划**，避免两次大迁移。
- `SubProduct` / `PlatformSupport` 权限体系尚未纳入 aiavatar（DECISIONS.md v0.43 记录），做应用中心真打通前需先扩展。
- 所有新增外部依赖（TTS 引擎、C2PA 签名、水印服务）按 §8.0 登记门禁表：未配置 → 503 带错误码不扣费，禁止静默降级。

## 4. 一段话总结

当前产品把 80% 的力气花在「把一个数字人做得更好看」上，而资产平台的价值在「让一个资产被更多场景以更清楚的权利关系反复消费」。建议把叙事从 **Avatar Maker** 切换到 **AI 资产中枢**：人物、声音、道具、场景、IP 全部一等公民（多样性），每个资产带机读授权和溯源（权利），以按次调用 + 分成的方式被下游子应用和外部消费（流通与调用）。生态里 music / drama / celebrity / star 四条线都是它的天然需求方 —— **aiavatar 不该是五个平行子应用之一，它应该是其他四个的供给侧**。
