# AI 导演台 · 全能创作助手

> 2026-10-29 · 已生产发布（最新构建 `9ad3603b0`，AI 入口与长文见 [本次发布记录](releases/director-ai-entries-production-release-20261029.md)；正文冻结原始验收见 [前次记录](releases/director-script-freeze-production-release-20261029.md)）。现行设计真源。含写剧本前的创意对话（§7）与同日 review 修正（选区位置、撤销那一处、请求恢复、读未保存内容）。上层方案见 [ai-director-plan.md](ai-director-plan.md)。

## 1. 解决什么问题

原来写剧本只能「一句话生成整篇」，不满意只能重新生成。助手让用户在已有内容上连续讨论、局部修改：剧本、分镜镜头、分镜图与视频提示词、资产设定与出图提示词、已有的参考图和分镜图都能改。原有的生成按钮和一键制作照旧可用。

## 2. 用户看到的

- **位置**：桌面停靠在工作台右侧一列（可收起，浏览器记住开关）；手机上全屏打开，进页面不自动打开。顶栏「创作助手」按钮开关：AI 紫色（与 Studio 画布同一组 `--ai-*` 值），收起时实心紫，打开时浅紫按下状态，回复中图标转圈。
- **一部作品一份连续对话**，剧本 / 资产 / 分镜三处共用；可「新对话」，旧的进历史可切回（最多 12 段，每段最多 200 条）。
- **每条消息绑定一个对象**（输入框上方的范围胶囊，可换、可去掉回到当前页面的默认对象）。已发送的消息和建议始终针对发送时的对象，不随用户切页面变。
- **入口**（2026-10-29 统一）：内容旁只有一种入口，紫色小圆钮（`AskAI` / `AiField`，四角星图标，没有常驻文字），点了带上对象打开同一个助手、光标进输入框。名称写在悬停提示和读屏名称里（「和助手讨论{对象}」+ 一行能做什么）。有输入框的放在输入框右下角，输入框右侧留出按钮那一列，文字、滚动条和缩放手柄都不被盖住；没有输入框的对象放在容器标题行。同一对象只留一个；一键制作、重写、生成这些实际操作仍是各自的按钮。
  | 位置 | 入口 | 范围 |
  |---|---|---|
  | 剧本正文 | 选中文字后「问 AI / 润色 / 扩写」（选区工具条，保留） | 选中段落 |
  | 剧本正文 / 未拆集剧本 | 正文框右下角圆钮；没剧本时「先和助手聊聊创意」 | 某一集 / 未拆集剧本 / 创意 |
  | 分镜工具栏 / 分镜页剧本预览 | 标题行圆钮 | 本集全部片段 / 这一集剧本 |
  | 片段卡标题行 | 圆钮 | 这个片段的镜头 |
  | 视频提示词 | 输入框右下角圆钮 | 视频提示词 |
  | 分镜图弹窗 | 提示词框右下角圆钮（两个入口合成一个） | 有采用的图：分镜图；没有：分镜图提示词 |
  | 资产详情 | 描述右下角圆钮（两个入口合成一个） | 有参考图：参考图（也能改外观、提示词、音色）；没有：资产 |
- **讨论 vs 改稿**：问问题只给分析和方向，不出建议；明确要改才给建议卡。
- **建议卡**：说明改了哪个对象、改了什么（前后对比，长提示词只显示改动处，可展开全文），列出连带影响（如「已有的分镜图会标为需更新，不会自动重新生成」）。按钮：采用 / 继续调整 / 不用了；采用后可撤销。
- **剧本建议**可「预览修改」：切到剧本页那一集，正文处原文标红、建议标绿，「采用这处修改」或「保留原文」。只替换这一段，其余正文（包括之后手改的）不动。
- **分镜页剧本预览**：左栏「本集剧本 / 分集」切换（默认剧本，记住选择）。片段卡「对照剧本」后，标出这个片段对应的段落，可「只看这段 / 查看全文」。手机上是「对照第 N 集剧本」抽屉。
- **图片**：「围绕这张图修改」先改提示词（文字采用免费）；「采用并生成新版本」单独确认，弹窗写明范围和费用、不是局部精确修改、原图保留。新版本进历史，不自动替换采用中的那张。

## 3. 规则

1. **对象由服务端核对并命名**：客户端只给 kind + id，服务端校验存在后写说明文字（`scope.label`）。图片范围要求已有采用的图。
2. **每轮允许的建议类型由范围决定**（`DirectorAssistant.allowed`）：提示词范围只能改提示词，不能反改剧情；范围外的建议、引用不存在 id 的建议在校验时丢掉，回复里注明「另有 N 条建议…已略过」。
3. **剧本改动钉在具体一处，不猜**（2026-10-28 review 修正）：
   - 选中段落时，范围带 `start / end`（发送前先保存正文，服务端按保存后的正文核对，对不上 409 `DIRECTOR_SELECTION_CHANGED`）。模型给的原文必须落在选中的文字里，否则这条建议丢掉；同样的话出现两处时，改的是选中的那一处。
   - 没选段落时，原文在这一集里必须只出现一处，出现多处或找不到都丢掉（计入「已略过」），不再「多处取第一处」。
   - 回复回来时给每条剧本建议算好锚点 `anchor`（位置、确切文字、前后文），并把那一刻这一集的正文存一份快照（`assistantBase`，不出 wire；还没处理的建议出 wire 时带上 `base` 给前端预览）。采用和预览都用 `mapRange`（`DirectorAssistant` 与 `director-text.ts` 同一规则）把位置从快照按行映射到现在的正文：只有这段所在的行原样还在、顺序连着才映射过去；这几行被改过或删掉，或者是好几行一模一样的文字而数目变了（认不准用户改的是哪一行），一律 409 `DIRECTOR_PROPOSAL_STALE`，不改。不再按文字去找「那一处」：同一人物两场说同一句话、用户先改了第二场时，剩下的第一场在文字和前后文上都可能和目标一样（2026-10-28 两轮 review）。没有快照的旧建议只认「前文 + 文字 + 后文」整体还在的那一处。
4. **采用前核对，后改的不覆盖**：镜头按助手看到时的内容签名比对；用户改过的提示词 / 资产字段与助手看到的不同就拒绝。自动生成（未自定义）的提示词随镜头变，不算用户改过。片段视频生成中不改镜头。
5. **助手读的是用户眼前的内容**：发送前先保存这一轮涉及的、还没保存的修改（剧本正文 / 标题 / 摘要，分镜范围下本集全部片段的镜头与提示词，片段的镜头与提示词，资产的名称 / 外观 / 提示词），再发；保存失败（如镜头时长没填好）就不发并说明原因。保存走 `saveDrafts`：保存期间用户对这些字段的每次修改都留作草稿，包括改回旧的已存内容（撤回）；保存回来后只清掉值仍等于刚存进去那份的草稿，其余仍算未保存（2026-10-28 两轮 review：补写的台词被清掉、撤回成旧正文又变回新正文）；发送后的输入框同理，只在框里还是发出去那句时才清空（2026-10-28 review）。采用时同样先存剧本修改；片段 / 资产有没保存的修改先让用户处理。
6. **撤销**：采用时记下撤销数据（`assistantUndo`，不出 wire，只出 `undoable`），剧本建议含采用后的正文。撤销把替换后的那一段从采用后的正文按行映射到现在的正文（同 `mapRange`），只恢复实际采用的那一处；删除（替换为空）也能撤销；那几行之后又改过就不能自动撤销。撤销后建议回到「未采用」，按撤销后的正文重新记快照和锚点，可以再采用。
7. **写入效果与手动修改一致**：改正文 → 集修订号 +1、已有片段的集标 `planStale`；改镜头 → 提示词按规则重编、已有分镜图 / 视频按指纹标「需更新」；都不触发生成。
8. **文字采用永不触发收费生成**。生成新版本走原 `asset-image` / `board` 任务，`options.baseOnCurrent=true` 把当前采用的那张追加为最后一张参考图并在提示词末尾说明；候选记 `baseOn`。仍走原报价、冻结、付款、幂等。
9. **看图要真看**：只有后台声明 `supportsVision` 的文字模型才把这张图交给模型（`visualContext`）；否则只给提示词，并在回复下注明「当前文字模型不能看图」。测试响应模式一律不读图。
10. **计费与幂等**：一轮回复是一次导演台文字任务（节点 `assistant`，同一作品同时只有一条在回复），按作品所选文字模型按量结算，每轮最多冻结 `pricing.textMax`。`clientRequestId` 即消息的 `clientId`。**发送前把这次请求（编号 + 完整正文，含范围、对话段、付款方）记进本浏览器**（`director-pending.ts`，按作品存），确定的结果才删：断网 / 网关超时时先回读作品看收到没有，没收到同编号重发一次；仍不确定就保留，收起再打开助手、刷新、切换范围之后都按原请求恢复（界面给「按原请求重新发送 / 不发了」），同一句话不会另起新请求，不同的话要先处理掉那一条。业务上明确拒绝（积分不足、价格变了、正文对不上）才作废。「生成新版本」也按建议记请求，再点按原请求恢复。
11. **回复期间可以继续编辑**，不锁内容；回复回来的建议按发送时快照对比，采用时再核对当前内容。

## 4. 片段在正文里的位置

写分镜脚本时模型给每个片段一句起始原文 `sourceQuote`，服务端在本集正文里找得到才记。剧本预览按起始句定位，到下一个有起始句的片段为止（段落级）。没有起始句（旧片段、拆出来的片段）时按台词逐字匹配，标「按台词找到的大致位置」；都找不到就说没有记录，显示全文，不伪造定位。

## 6. 验证与边界

### 2026-10-28 真实模型实测（本地，库副本接聚算 `qwen38-27b`，导演台文字任务默认模型；测试脚本与日志在会话 scratchpad，不在仓库）

| 场景 | 结果 |
|---|---|
| 创意对话首轮 | 6 秒、1 积分；1–2 个问题，选项贴着故事（如「超自然/灵异」「细思极恐的后怕」） |
| 回答后 | 第 2 轮即判断信息够了、提前结束；整理的要求保留了用户原话（「包裹是自己寄的」反转），补的默认标了「（默认）」，题材 / 调性映射到固定列表 |
| 连续含糊回答 | 2 轮后收敛，没有无限追问 |
| 回「你决定吧」 | 不再调对话模型，直接写剧本，43 秒出稿 |
| 按对话写剧本 | 请求日志里带着逐条问答与整理要求；剧本是悬疑、结尾自己寄给自己的反转（28 秒） |
| 剧本讨论「哪里不够吸引人」 | 只给分析和方向，没有建议卡 |
| 选中一行「只改对白」 | 一条 `script.replace`，锚点落在选中那行；采用只改那一行，撤销恢复原样 |
| 片段「先手部特写再切反应」 / 本集「别直接揭示秘密」 | 镜头建议保留了全部原镜头 id；本集范围同时给了镜头、分镜图和视频提示词建议，`图N` 编号保留 |
| 视频提示词「缩短对白」 / 资产「更疲惫但别显老」 | 修正后（见下）正常给出建议 |
| 分镜图「第三格改近景」 | 改分镜图提示词并建议生成新版本；当前模型不能看图，回复下如实标注 |

实测发现并已修：模型在单对象范围里省略 `clipId / assetId`（改为唯一对象时补上，多个时仍丢弃）；回复带 Markdown 和内部名词（服务端转成纯文本和界面叫法）；改外观时把整份出图提示词也抄一遍（自动生成的提示词时不带，让它按新设定重编）；对话里提「只剩最后一轮」（提示词要求不提轮次）；历史里未采用的建议被说成「已改」（历史状态改用中文说明，仍偶发，见 TODO）。

未实测：写分镜脚本的 `sourceQuote` 命中率（本地库没有可用视频模型，「写分镜脚本」跑不了）；能看图的文字模型下「围绕这张图修改」交图给模型；「生成新版本」的真实出图（测试响应验过参考图编号）。另外现有「提取资产」任务在真实模型下有一次返回了缺 `{` 的 JSON 而失败，重试成功（非本次改动，记 TODO）。

- 单测：`DirectorAssistantTest`（定位、范围校验、回投、采用后用户修改不被覆盖、撤销、失败回复）、`director-text.test.ts`、`director-assistant.test.tsx`（选中发送 + 不确定结果按原编号恢复；预览采用前先存未保存修改）。
- 本地测试响应模式（零成本固定回复）在浏览器走通：选中润色 → 预览 → 采用 → 撤销；改镜头；围绕分镜图修改 → 生成新版本（服务端确认当前图作为最后一张参考）；资产入口；新对话 / 历史；手机 375 宽。
- 文字分析、局部建议及采用/撤销已通过真实模型线上补验，见发布记录；看图路径仍未在能看图的模型上实测。
- 不做：不承诺局部精确改图；不自动连带重写受影响的提示词（只列出影响，需要时让助手一起改）。

## 7. 写剧本前的创意对话（有限澄清）

还没有剧本、作品带着一句想法时，剧本页就是一段对话（`director-brief.tsx`），不再是「确认创意，生成剧本」表单：

- **进来就开始**：AI 先看想法，问 1–2 个真正影响创作的问题（目的 / 感受、题材调性、主角与冲突、结局倾向、篇幅），每个带 2–4 个贴着这个故事的选项，可点可写。用户说过的、能推断的不问；不问风格、画幅、模型这类制作参数。首轮请求编号按作品固定（`open-作品id`），刷新不会再开一轮。企业付款开着时先让用户点「开始聊」选付款方。
- **轮次上限 3**（`DirectorAssistant.MAX_BRIEF_ROUNDS`，每轮最多 2 个问题）：信息够就提前结束；到上限后服务端要求模型收敛，模型仍给问题也丢掉，按已有信息和合理默认整理要求（默认项标「（默认）」）。页面显示「已问 N 轮，最多还问 M 轮」。
- **直接写**：整句只是「你决定 / 写吧 / 开始生成 / 都行 / 不用问了」这类话，或明确以「直接 / 马上 / 开始 + 写 / 生成」开头（可带要求，如「直接写三集」）时，服务端不再调对话模型，直接用同一请求编号开始写剧本（`DirectorAssistant.saysGo`）。「写三集」「写实一点」「写成悲剧」「生成一个反派」是回答，照常进下一轮。这句话先记进对话再组装剧本请求，里面的要求（如「三集」）会进提示词（2026-10-28 review）。
- **跳过**：「跳过，直接生成剧本」（中途为「不聊了，直接生成剧本」）一直在页头，任何时候可点，按想法和已回答的内容生成，没说的由 AI 补齐。
- **可以开始了**：信息够了出现「可以开始写剧本了」卡片：整理后的要求、题材 / 调性（按对话预选，可改）、风格画幅、「生成剧本」和费用。之后还能补充，会再整理（不重新开问）。
- **写剧本带上对话**：剧本任务的 brief = 原始想法 +「写剧本前和用户确认过的内容」（逐条问答）+「整理后的创作要求」，跳过时再加「没说清的由你补齐」。对话里定下的题材 / 调性在请求没另选时沿用。
- 这只是写剧本前的澄清；有了剧本以后，右侧助手的讨论和改稿不限轮数。导入剧本、「已有剧本？改为粘贴」照旧。
- 数据：作品 JSON `brief { status: asking|ready|writing|done, rounds, maxRounds, messages[], summary, genre, tone, title }`；任务 `type=brief`（节点 `brief`，`options.message`，空串为开场）。剧本失败时状态回到写之前（`prevStatus`）。


### 2026-10-29 正文在请求期间冻结

针对剧本或选区发送消息时，从点击发送（含自动保存）起，对应草稿或分集正文、集名和摘要只读。服务端受理后以助手消息的 pending 状态为准；收起助手或刷新不会解锁。回复完成或失败后恢复编辑，发送结果不确定时保留请求并保持锁定。其他分集仍可编辑。

后端在作品行锁内拒绝修改对应正文、采用或撤销其旧建议，以及会替换正文的拆分、重新生成和一键制作，返回 409 `DIRECTOR_SCRIPT_LOCKED`。不再在选区失配时搜索其他同名文字。回复完成后用户继续编辑的场景仍沿用建议失效检查。
