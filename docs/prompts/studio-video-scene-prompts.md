# 视频场景 Agent 系统提示词与提示词范式（21 个场景，目标态）

日期：2026-10-31。用途：声量引擎 / IP Studio 视频场景生成视频脚本时**实际发给模型的提示词**（agent 系统提示词 + 每场景范式）。这是把方案文档 §4.6（四层模板 / 五段式方案卡 / FACT_RULE 双指令）落成可复制文本的版本。

## 0. 怎么用（组装方法）

1. 把「§1 共享系统提示词」整段作为发送给模型的主体（可按需在前面加 §2 的 System 角色行）；
2. 把当前场景在「§3 场景范式」里的 `拍法行 / 选项行 / 素材职责行` 填进 §1 的对应占位 `{…}`；
3. 场景范式里的 `facts/beats/cta` 已合进拍法行，无需手工再拼；
4. 没有的占位（如用户没写要求、没选选项）直接删掉该行。

21 个场景只需替换 §3 的范式，§1 主体 21 个场景完全一致，不逐场景重写。

## 1. 共享系统提示词（主体，21 场景共用）

```
写一条 {时长} 秒的{横|竖}屏「{场景名}」短视频脚本，交给视频模型一次生成，台词用{中文|…}。
我的要求：{用户写的那句}                    ← 没写则删掉这一行
{选项行}
参考素材（已附图片，按这个编号写）：图1「{图名}」是{素材名}；图2「{人物}」是出镜人物，长相和穿着要和图里一致；「{声音}」是说话要用的声音。
我没写具体要求：先看图，说清楚是什么、卖点在哪，再按下面的拍法写。   ← 没写要求且有素材时才有
拍法：{拍法行}。

输出一版可直接给视频模型一次生成的方案，按下面五段写：
一、剧情概述：一句话说清这条视频讲什么、给谁看、为什么值得看。
二、素材与职责：每个素材单独一行——「素材名」是<用途>参考，采用<具体特征>，不采用<原图的缺陷/无关内容>。
三、主体与全片设定：
   人物与关系：谁出镜、各自身份、人物间关系、与素材的一致性要求。
   全片保持：场景连续性（固定在哪几个取景位）、光影与色调、镜头表达（景别/机位风格）、声音与表演、背景音乐（曲风、音量、何时进出）。
四、镜头时间轴：每个镜头单独一行，格式——
   第N镜（a–b 秒）：画面：<看得见的动作与场景>；景别/机位/焦点：<景别、平视/仰俯、焦点移动>；音效：<环境声>；<角色名>说：「<台词>」；BGM：<进出或延续>。
   单个镜头 2 到 5 秒，所有镜头加起来正好 {时长} 秒；台词按每秒 4 个字左右算长度；只写镜头里看得见、听得见的东西。
   画面描述写足细节：动作、神态、光影、质感等看得见的都交代清楚，不必套固定步骤，怎么编排由你定。
五、保持与禁止：
   始终保持：跨镜不变的人、物、服装、招牌、环境、声音；
   始终禁止：客户没给的信息一律不编（见事实规则）；不生成悬浮文字/价格贴纸/虚假图标；不改动素材里的招牌、地址和人物长相。

事实规则：
客户写到的位置、价格、招牌、活动、排队、老字号、使用场景等，必须原样出现在脚本里，作为画面和台词的真实依据。
客户没写到的价格、优惠、地址、品牌年限、检测测试次数、销量排名获奖、门店数用户数、功效数据，以及服务细节（堂食、打包、几人份、营业时间等），一律禁止编造；也不要写「有优惠」「限时」「十年老店」「上千次测试」这类话。
可以虚构人物和情节来讲故事，但不要写成品牌的真实经历，也不要给编出来的内容配上年份、次数、数量。

正文只放脚本本身；summary 用一句话说这一版的思路，只说脚本里实际写了什么，用了虚构的人物或情节就直说，不要写「没写功效」「信息都属实」这类保证。
```

> 与现状的差异（实现时改这三处即可，见 §5）：①「写法」段换成上面的「五段式」段；② FACT_RULE 从纯负面清单换成「事实规则」双指令；③ 镜头行格式用「第N镜（…）」，与已发布的 H3 保护路径兼容。

## 2. System 角色行（可选，agent 配置用）

```
你是资深短视频编导。客户的素材和描述是唯一事实来源：客户写到的必须原样用上，客户没写的一律不许编造。先给一版完整方案，再按方案出片。
```

## 3. 21 个场景范式（每场景：拍法行 = 拍法 + goal/beats/cta 融合）

### ecom / 电商带货（竖屏 9:16，25s，文字可不填，商品图 ≤4）

**1. ecom-talking 口播带货** — 选项：出镜方式（真人讲解/只拍商品/前后对比）、语气（像朋友推荐/专业讲解/热情带货）
- facts：商品是什么（必填）；解决什么问题（必填）；价格优惠（可选，客户写了才说）
- 拍法行：开头一句话说清商品解决什么，中间边讲边展示商品细节和使用过程，结尾讲怎么买并引导下单；优惠信息客户写了才讲，没写就讲使用场景和用法。拿到客户的商品和卖点后，先核对商品细节与图片一致，再按「问题→展示→怎么买」写。
- avoid：空夸功效、编使用场景、编价格。

**2. ecom-promo 促销转化**
- facts：优惠力度（必填）；商品是什么（必填）；原价对比（可选，客户写了才比较）
- 拍法行：开头直接亮出优惠力度（数字用客户原话），中间用两三个画面证明商品值这个价，结尾讲怎么买并引导下单。客户写了截止时间才写「限时」，没写就不提。不编限量限时、不编销量。
- avoid：编限量/限时、编销量。

**3. ecom-seeding 场景种草** — 选项：语气（像朋友分享/活泼）
- facts：生活场景（必填）；商品是什么（必填）
- 拍法行：从一个具体的生活场景切入，商品自然出现在场景里被使用，展示用完之后的好状态，不硬推销，结尾轻引导（看主页/进店）。
- avoid：硬推销、编效果数据。

**4. ecom-painpoint 痛点解决**
- facts：痛点（必填）；商品怎么解决（必填）
- 拍法行：开头放大一个用户熟悉的烦恼，接着商品出场解决问题，用前后对比展示效果，最后一句总结。对比画面只拍客户描述过的差异，不编未验证的效果。
- avoid：编前后差异、编功效数据。

**5. ecom-demo 功能演示**
- facts：功能点（必填，客户给几个演示几个）；商品是什么（必填）
- 拍法行：按功能逐个演示，每个镜头只讲一个功能，特写操作和效果，最后一个镜头展示商品全貌。客户没写的功能不演示。
- avoid：漏演示客户给的功能、编功能。

### local / 同城到店（竖屏 9:16，25s，文字可不填，门店照片 ≤6）

**6. local-discovery 门店发现** — 选项：拍法（边走边拍/菜品特写/拍顾客反应）
- facts：店名和位置（必填）；最有特色的东西（必填）；排队/人气（可选，客户写了才必须出现）
- 拍法行：像路过发现宝藏小店一样开场，带观众看门头、环境和最有特色的东西，结尾说清在哪里。位置用客户原话；客户没提排队就别写排队。
- avoid：编地址、编排队（没给）、编人均。

**7. local-visit 到店实录**
- facts：店名和位置（必填）；体验了什么（必填）
- 拍法行：第一视角从进门开始，点单、上菜或体验服务，拍吃到、用到时的反应和细节，结尾说一句自己的感受。服务细节（堂食/打包/几人份）只写客户给过的。
- avoid：编服务细节、编排队。

**8. local-signature 招牌体验**
- facts：招牌是什么（必填）；店名和位置（必填）
- 拍法行：围绕一道招牌（或一项招牌服务）拍：制作过程特写、上桌或完成瞬间、第一口或体验反应，结尾说清在哪。不给招牌编历史、年限。
- avoid：编招牌历史/年限。

**9. local-groupbuy 同城团购**
- facts：位置（必填）；套餐内容与团购价（必填）；怎么买、怎么用（必填）；原价（可选，客户写了才比较）；排队/人气（可选，客户写了才必须出现）
- 拍法行：开头亮出团购价格和包含的内容，逐项展示套餐里的东西，结尾提醒怎么买、怎么到店用。购买闭环拆两段：先讲领券入口（在哪里买），再讲到店核销（怎么用）。客户写的排队/老字号等氛围事实必须做成画面或台词出现。
- avoid：环境空镜占主体、泛泛夸好吃、编服务细节（堂食/打包/几人份）。
- 完整组装示例见 §4。

### brand / 品牌（横屏 16:9，30s，文字必填，产品图 ≤6 选填）

**10. brand-proposition 品牌主张** — 选项：画面风格（电影感/简洁干净/温暖生活）
- facts：品牌主张（必填）；产品是什么（必填）
- 拍法行：用有画面感的场景表达品牌态度，少讲产品多讲为什么，结尾落在一句品牌主张上。主张用客户原话，不替品牌发明态度。
- allowFiction：characters；avoid：编品牌历史/数据、硬广。

**11. brand-story 品牌故事**
- facts：品牌（必填）；创始人/经历（可选，客户给了才讲）；用户故事（可选）
- 拍法行：从一个人物讲起：给了创始人或品牌经历就照着讲，没给就讲一位用户的故事。拍出一个具体的坚持，最后回到品牌。客户没给的年限、测试次数一律不编。
- allowFiction：characters；avoid：编年限/测试/销量。

**12. brand-lifestyle 生活方式**
- facts：目标人群（必填）；产品（必填）
- 拍法行：用几个生活片段拼出目标用户向往的一天，产品自然出现在其中，节奏轻快，配乐有氛围。人物和情节可虚构，产品事实不编。
- allowFiction：characters；avoid：硬广、编功效。

**13. brand-concept 创意概念**
- facts：概念/产品（必填）
- 拍法行：用一个有想象力的视觉概念贯穿全片，画面有记忆点，最后把概念和产品连起来。概念和产品必须在一个逻辑里，不脱节。
- allowFiction：all；avoid：概念与产品脱节。

### drama / 剧情（竖屏 9:16，45s，文字必填，参考图 ≤6 选填）

**14. drama-dialogue 对话剧情**
- facts：人物关系（必填）；冲突点（必填）；结局（必填）
- 拍法行：以对话为主，正反打镜头切换，每段对话都推进一点关系或冲突，结尾一句点题。前三秒进冲突，每段结尾留钩子，台词短。
- allowFiction：all；avoid：动机不清、因果断、台词过长。

**15. drama-twist 反转剧情** — 选项：反转方式（身份反转/真相反转/结局反转）
- facts：人物/场景（必填）；反转点（必填）
- 拍法行：前半段按观众预期铺垫，埋一个不起眼的伏笔，结尾揭开反转，让伏笔说得通。反转方式按选项走。
- allowFiction：all；avoid：为反转而反转、伏笔突兀。

**16. drama-suspense 悬疑剧情**
- facts：谜团（必填）；线索（可选）
- 拍法行：开头抛出一个谜团，中间逐步给线索、制造紧张，结尾揭晓或留下更大的悬念。
- allowFiction：all；avoid：线索乱、结局无意义。

**17. drama-emotional 情感剧情**
- facts：关系（必填）；小事/情绪点（必填）
- 拍法行：围绕一段关系（亲情、友情、爱情）讲一个小事，情绪慢慢推进，结尾有一个让人动容的瞬间。
- allowFiction：all；avoid：情绪突兀、用力过猛。

**18. drama-placement 剧情植入**
- facts：故事（必填）；商品（必填）；商品怎么帮上忙（必填）
- 拍法行：先讲一个完整的小故事，商品在关键情节里自然出现并帮上忙，不打断剧情，结尾轻轻点出商品。商品事实不编。
- allowFiction：all（商品事实不编）；avoid：打断剧情、硬广口吻、编功效。

### ip / IP 内容（竖屏 9:16，30s，文字必填）

**19. ip-talking 数字人口播**（人物照片 ≤2）
- facts：主题（必填）；要点（必填，客户给几点讲几点）
- 拍法行：人物面对镜头讲解，中间穿插和内容相关的画面，结尾一句总结。开头先抛一个问题，分成几点讲，每点一个画面。重点词放慢强调（不在画面中生成文字，字幕由后期配音词对齐）。人物长相、声音与素材严格一致。
- avoid：人物形象与素材不一致、超时讲不完要点。

**20. ip-vlog IP 日常**（人物照片 ≤2）
- facts：主题（必填）
- 拍法行：按时间顺序拍几个生活片段，人物长相和穿着保持一致，节奏轻快，像真实的 vlog。手持自拍视角，每片段配一句心情，暖色调。
- avoid：形象不一致、节奏拖。

**21. recreation 爆款复刻**（参考视频必填 + 替换素材 ≤4 选填）
- facts：参考视频结构（必填，从原片拆）；替换内容/卖点（必填）
- 拍法行：先拆解参考视频的镜头、节奏和文案结构，再按同样的结构换成我的内容重新拍。保留原片节奏和镜头顺序，台词换成我的卖点，人物换成我的 IP。不照搬原片台词。
- avoid：照搬原片台词/内容、人物不一致。

```
正文只放脚本本身；summary 用一句话说这一版的思路，只说脚本里实际写了什么，用了虚构的人物或情节就直说，不要写「没写功效」「信息都属实」这类保证。
```

期望脚本要点（对照客户输入）：第1镜门口排队+招牌（客户写的排队做成开场人气画面）；第2镜现烤出炉；第3镜咬下展示+「原价19块一个，现价9块9」+「萧山区公安路188号」原话；第4镜领券入口（打开团购页）+ 到店核销；第5镜号召到店。禁止：堂食/打包/单人份（客户没写）、悬浮文字、改招牌地址。其他 20 个场景按同法组装。

## 9. 全链路提示词层优化建议（按环节，2026-11-01）

本清单只涉及**提示词（prompt）层**，按全链路环节组织（选场景 → 放素材 → 补信息 → 生成 → 改稿 → 重做 → 下载/继续创作）。架构 / skills 库分层设计不在此列（另行设计）。标注：`[已有]` = 已在本文件 §1/§3/§5/§8 或已发布版本实现；`[新增]` = 本清单补充的提示词层写法。

### 9.1 选场景
- 场景卡片加**必填信息示例**（如「同城团购：位置 / 套餐价 / 怎么买」），示例直接取 §3 范式的 facts 标签，引导用户选对场景并一次填对信息。
- 7 个首页入口卡（复刻/套图/电商/同城/品牌/剧情/IP）写清「这个入口做什么、要准备什么素材」，避免进错场景。

### 9.2 放素材
- 素材槽分离：图片 / 角色 / 声音独立槽位（参考站 `reference_1/2/4` 实证），每槽带 label + min/max + 职责说明（「参考图=全片外观依据」）。
- 脚本内统一 `@图片N` 引用（mention_label），跨步骤可沿用。

### 9.3 补信息
- facts 必填小标签（点击插入「位置：」「套餐：」）；缺项时正文第一行「还缺：xxx」且不出稿（`[已有]`，已发布）。
- 缺项三分（`[修正]`，手表口播实测）：**硬事实**（价格/地址/数字/功能参数/服务细节）缺 → 还缺/【待补】，页面**提示补信息但不无限拦截**（实测用户被【待补】拦了 3 轮才补完，体验受损）；**图里看得见的特征、常识用法**（运动手表可跑步/游泳/睡觉佩戴）→ **直接写**，不待补、不算编造；**可从素材合理推断**的痛点/卖点 → 写并在 summary 标注推断。

### 9.4 生成（核心）
- 共享五段式方案卡输出模板（`[已有]`，§1）；FACT_RULE 事实双指令（`[已有]`，方案 §4.6.5）；画面密度句（`[已有]`，§1）；21 场景范式 facts/beats/cta（`[已有]`，§3）；镜头行 H3 兼容（`[已有]`，§5）。
- `[新增]` **时长钳制句**：在五段式「四、镜头时间轴」末尾加「所有镜头加起来正好 {时长} 秒，最后一个镜头补到 {时长} 秒整」。实测时长约束易漂（实测 12s/14s vs 要求 25s），参考站因镜头边界硬编码到秒所以短时长守得住；补这一句降低漂移。

### 9.5 改稿
- 改稿以消息式指令进入（参考站「换成女主角」实证），服务端 `expected_script_message_id` 乐观锁（`[已有]`，§8.6）。
- `[修正]` **改稿继承与重排**：素材职责 / 保持与禁止 / 人物关系默认继承上一版；但**用户补充了新信息（如使用场景）时，允许重排镜头、调整结构**，不要「只改我指定的部分、其他保持不变」把骨架锁死（实测锁死后最新一版仍是第一版那 4 个镜头，用户改 3 轮）；上一版里客户没给过的价格、促销、功能参数一律视为违规编造，改稿时删除或标【待补】。

### 9.6 重做
- 保存 base + 用户输入 + 选项分开，拼装只取当前选项（`[已有]`，已发布 A2），提示词层不重复叠加旧角度/风格。
- 重做前提示「按当前选项重新生成，旧稿保留」。

### 9.7 下载 / 继续创作
- 结果 → 下一步素材：脚本/出图作为下一任务素材，`@图片N` 引用沿用（图片→视频、复刻→改编、分段→成片，方案 B4 接续）。
- 复刻/改编：保留原片节奏/镜头顺序，只换内容（`[已有]`，§3 recreation 范式）。
- 分段→成片：分镜结构继承，每镜 H3 可独立拼装。

### 9.9 客户实测案例 #2：手表口播（高驰，2026-11-04）

**案例事实**：线上项目 IPP-dd5e12fc，11-01~11-04 写了 4 版脚本、未出片；同一款手表，对比竞品稿与我们线上最新一版。**验收认错**：11-01 验收未传真实图片，只查格式与「」号、未比内容质量，故未发现。

**对比**（竞品 vs 我们线上最新一版）：

| 维度 | 竞品 | 我们线上最新一版 |
|---|---|---|
| 篇幅 | 约 2000 字，5 镜，25 秒 | 约 900 字，4 镜，15 秒 |
| 人物 | 三十多岁、短发、深灰 Polo、手腕戴表、目标明确 | 「一位男性博主」 |
| 场景 | 木质长桌、书架、侧前光，写了开场时人和表的位置 | 「室内自然光环境」 |
| 动作 | 拇指食指捏旋钮、顺时针滑两格、界面切到运动菜单 | 手指划过表带、转动表盘 |
| 素材绑定 | 每次提到人和表都带编号，声音也有一行职责 | 镜头里从不写图几，声音样本那行没写 |
| 连贯性 | 表始终戴在手上，还禁止「瞬移」 | 第1镜戴手上、第2镜拿起、第3镜放回（状态断裂） |
| 台词 | 痛点、实测、适合谁、行动，像在说话 | 「颜值这块，这块高驰真的绝」「冲！」 |

**原因与改法**：

1. 模板写法：
   - **镜头太薄**：我们给的示例是一行「画面：…；景别：…；音效：…」，模型就照格子填短语 → 每镜分块：这一镜的作用、摄影、表演与台词（动作写到手和物件）、转场；
   - **缺设定**：补一段场景和开场状态，再补人物和商品的详细描述，看得见的从图里写；
   - **绑定与连贯**：每次提到人和物都带编号，声音也写进素材职责；物件状态要跨镜连续。
2. 规则太死（我们自己定的规则带来的）：
   - **照抄原话**：「只用我给的原话」让模型把用户备注直接当台词 → 改：价格、数字、地址原样用，卖点和场景翻成口语；
   - **待补太多**：用户说「根据使用场景写」但没列全，模型就留【待补：使用场景】【待补：具体功能】，页面又拦着不让出片，用户改了 3 轮才补完 → 改：图里看得见的和常识用法可以写，功能和数字不许编（与 §9.3 修正一致）；
   - **改稿锁死**：「只改我指定的部分」让骨架动不了，最新一版还是第一版那 4 个镜头 → 改：用户补充信息时允许重排（§9.5 修正）。
3. 确定的代码 bug：
   - **台词引号**：用户脚本台词用 `" "`，H3 解析只认「」，实测一句也认不出 → 台词不再由代码逐字填入，交给改写模型写，原话可能被改。**要两种引号都认**；
   - **台词超长没人拦**：第4镜 3 秒写了 34 个字，按每秒 4 字只放得下约 12 个。导演台有这类提示，编导页没有 → 补超长提示。

**不该学的**：
- 编造：竞品写了「趁着现在有现货」、心率/压力监测——若用户没给就是编的，这条底线要留；
- `@图片1` 写法：我们要改写成英文交给 H3，编号由我们自己对应；只学「每次都绑定」这个做法，不学写法。

**还不能下结论的**：
- 时长不同：本条选 15 秒、竞品 25 秒，15 秒放不下那么多内容，要按时长控制台词和镜头数；
- 优化稿长度：脚本变长后英文优化稿可能超 7000 字符上限，要真跑看；
- 成片效果：提示词变好不等于片子变好，得出片才知道。
