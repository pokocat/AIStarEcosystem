# AI 数字名片 · 方案真源

> 子应用落点：`apps/web-aiavatar` 下新开 `/card` 域（不新建子应用）
> 设计稿（仅视觉）：画布 artifact，见本文 §10
> last-reviewed：2026-09-06

---

## 1. 这是什么

见客户递一条链接，对方点开就能把你看明白 —— 你是谁、公司做什么、能提供什么、在找什么，还有一段你本人形象的自我介绍。

替代的不是纸名片，是「电子名片 + 一段说不清的自我介绍」。业务方原话：「大家都要给你发个电子名片或者文字，要不让你自我介绍下，介绍不明白呢。」

**名片不产生任何新资产。** 它是个人 / 企业 IP 的**对外发布面** —— 身份来自公社，内容来自 AI 军师，形象来自 AiAvatar 数字资产。三边都已存在，名片只做发布和交换。

## 2. 一期范围

只做三件事：

| # | 交付 | 说明 |
|---|---|---|
| 01 | 一个扫码就开的门面 | 短链 + 二维码。访客**无需注册登录**直接看全内容，一期不设任何门槛 |
| 02 | 一个会动、会说话的形象 | 形象分三档：静态照片 / 1–3 秒微动 / 30–60 秒口播。**从最低一档就能发出去** |
| 03 | 一键存进通讯录 | 生成 vCard 写入手机通讯录，或直接加微信。哪些联系方式放上名片由本人决定 |

**这一期只验证一件事**：30 秒内能不能把一个人说清楚。

### 二期挂起（已想清楚，但要等门面先立住）

| 项 | 为什么放后面 |
|---|---|
| 交换名片 · 互相解锁联系方式 | 要先有人愿意递出去，才谈得上互换 |
| 名片夹 · 收到的名片与会面备注 | 一期用手机通讯录即可 |
| 字段分层可见（L0/L1/L2） | 一期简化成「放 / 不放」一个开关，主人自己勾 |
| 谁看过我的名片 | 没有访问量之前，数据没有参考价值 |

## 3. 落点与开通

- 路径：`/api/v1/card/**`
- **不需要新产品码**。`ProductRouteTable` 里 `any("/api/v1/**", AIAVATAR)` 是兜底规则，名片自动归到 aiavatar 产品，跟 ipstudio 用同一条 `product_enrollment` 记录。
- 结论：**开通了数字资产平台的人，自动拥有 IP 工作台和数字名片**，不用再发一次激活码。
- 公开访问：名片正面必须让未登录访客看全，需要在 `ProductRouteTable.PUBLIC_GETS` 登记 `GET /api/v1/card/p/*`（按短链取名片），其余（编辑 / 发布 / 上传）仍走 aiavatar 开通闸。

## 4. 信息架构

### 首屏（3 秒内说清楚）

- 形象（开屏视频 / 微动 / 静态）
- 姓名 + 一句话身份
- **合作意向：能提供 / 在找** —— 商务名片的正题，必须进首屏
- 主身份（公司 · 职务），其余头衔折叠
- 操作：存到通讯录（主）/ 加微信

> 和社交向名片（Bonjour 一类）的分岔点：那类靠罗列头衔和社媒。罗列反而让人抓不住你是干嘛的。

### 往下滑

1. 我在做的事（编号条目，5 条以内）
2. 合作方向展开（能提供 3 条 / 在找 2 条）
3. 企业简介 + 三个数字 + 发展历程
4. 宣传与报道（横滑卡）
5. 成长履历（本人确认公开）
6. 联系方式 + 存通讯录
7. **关于这张名片** —— 内容来自军师诊断 / 形象是登记在册的数字人 / 开屏由 AI 生成
8. 两个出口：去 AI 军师领诊断 · 去主理人公社

§4.7 是一期唯一的转化动作，也是可信度背书。

## 5. 形象怎么来（与数字资产平台的接线）

### 核心原则：引用，不是拷贝

名片文档里存的是 **id**，不是图片。IP 工作台或数字资产平台里改了形象，名片自动跟着变。

### 直接复用 `dapDisplayRef`（v0.60 已有，不要另造格式）

`DapAvatarRefResolver` 已经为 music / drama 定义并实现了形象引用格式：

```
null            → 跟随定妆照（DapAvatar.imageKey，永远最新）
look:<id>       → 指定造型（DapLook.imageKey）
deriv:<id>      → 指定衍生图（DapDerivative.fileKey，仅图片类 kind）
variant:<idx>   → 形象变体（DapAvatar.variantKeys[idx]）
shot:<name>     → 机位照（DapAvatar.shotKeys[name]）
```

名片每一屏存一个这样的字符串即可：

| 屏 | 引用 |
|---|---|
| 首屏 | `look:<低头看手机>` |
| 我在做的事 | `look:<抱臂>` |
| 找我聊聊 | `look:<挥手>` |

**它已经处理了资产被删 / 进回收站 → 静默回退、不阻断渲染。** 名片直接复用，不用自己写降级逻辑。

### 现成可用的端点

`GET /api/v1/avatars/*/looks` 已存在，且在 `PUBLIC_GETS` 里已对 AIAVATAR / MUSIC / DRAMA 开放。名片选姿态直接用，后端零新增。

### 一个形象多个姿态

`DapLook.avatarId` 已建索引（`idx_dap_look_avatar`）。名片的「多姿态贯穿全站」不是三张随手生成的图，是同一个 `DapAvatar` 的三条 Look 记录。

## 6. 与 IP 工作台 / 数字资产平台的职责边界

两边都能生成形象，重叠是真实存在的。真实分界线不是「造 vs 管」，是**带不带 `avatarId`**：

| | 前提 | 单位 | 典型动作 |
|---|---|---|---|
| **数字资产平台（dap）** | 已经有一个形象 | 一次一个动作 | `generate` / `iterate` / `warp` / `refineApply` / `createLook` / `createDerivative`（多角度 / 表情 / 场景 / 换装 / 3D / 运镜）—— 方法签名全都带 `avatarId` |
| **AI IP 工作台（ipstudio）** | 还没有形象 | 一整组 | 画布编排「特征卡 → 主形象 → 多张形象卡」，一次跑出互相一致的一组，`IpPublishService` 落成 `DapAvatar` + `DapLook` |

**一句话：dap 管「一个形象的第 N 次」，ipstudio 管「第 0 次到第一组」。**

### 对名片的结论

名片**不该关心形象是哪边生成的**。两条路最后都汇进同一个 `DapAvatar`，名片只认这张表。

建卡时两条路径都通：

- 老用户已有形象 → 在 dap 里 `createDerivative(expr / ward)` 补个姿态，快且便宜
- 新用户 / 一致性要求高 → 走 ipstudio 一次出一组，发布后名片直接选

**ipstudio 对名片的独特价值是一致性。** 名片三个 Roll 是并排给人看的，三张图脸飘一点就露馅；ipstudio 的五层锁定（特征卡文本固定 + 主图作 i2i 锚 + 多候选择优）是专门为「看起来是同一个人」设计的。

> ⚠️ 已识别的重叠风险：dap 的 `expr`（表情图集）/ `ward`（换装变体）与 ipstudio 的「表情包六连」功能重复。长期需要产品分工声明（建议 dap 衍生只保留单张微调，成组一律进工作台），否则两边都会继续长。见 [`ip-studio-generalize-proposal.md`](ip-studio-generalize-proposal.md)。

## 7. 内容供给（AI 军师）

名片上最难写的几段，军师做诊断时已经写过：

| 名片板块 | 来源 |
|---|---|
| 一句话定位 · 能提供 · 在找 | 战略诊断报告 |
| 企业介绍与发展历程 | 战略诊断报告 |
| 宣传片 / 海报 / 手册 | 智能体工坊出活 |
| 口播文案 | 军师供稿 |

**诊断报告原文不进名片**，只公开蒸馏出的结论。

建卡主路径是「诊断里已经写过，直接引用」；公社会员资料和纸名片 OCR 只做兜底。建卡是整条链路最容易死的一步 —— 让人从零填一份个人网站，多数人填到一半就走。

## 8. 形象怎么叠进版面（视频层叠）

一段不带透明通道的视频就是个不透明矩形。巨号字标凡是落在矩形里的部分会被整块盖掉 —— 不是「被腿挡住」，是「缺了一块方的」。

**首屏采用方案 B：把层级反过来，字压在人身上**（杂志刊头压模特的老办法），视频框四周用 `mask-image` 径向羽化溶进纸里。这样任何视频格式都成立。

| 方案 | 做法 | 兼容性 | 采用 |
|---|---|---|---|
| A | 人压字 · 视频无透明通道 | ❌ 缺一块方的 | 不可用 |
| B | 字压人 + 边界羽化 | ✅ 任何格式 | **首屏采用** |
| C | 人压字 · alpha 视频（HEVC-alpha + VP9-alpha 双源） | ⚠️ 微信安卓需实测 | 有条件就升级 |

拿到 alpha 成片就把字降到视频下层，自动升级成 C —— **版面结构一个字都不用改**。

### 交付清单

**给供应商**
1. 8 秒成片，**纯白固定背景**（给具体色值）。有能力再出一版带 alpha 的
2. 同一帧导出的首帧图，跟视频**像素级对齐** —— 差几像素，视频淡入时人会「跳」
3. 彩色卷纸那几屏用 1–3 秒**透明 WebP** 微动，几百 K，全兼容
4. **05–08 秒的转体必须是连续物理旋转**。用贴图切换代替真旋转，人会「闪」一下 —— 验收只看这三秒

**给前端**
1. 首屏视频 `autoplay muted playsinline`，播一次停在末帧，不循环
2. 容器套径向 mask 羽化，**别用 `clip-path`**（硬边会露框）
3. 巨号字标 `pointer-events:none`，别挡住下面的点击
4. 首屏底色调成与渲染图棚拍白**完全同色**，图片矩形因此隐形，不靠遮罩硬遮
5. 检测到 alpha 可播就把字降到视频下层，升级方案 C

## 9. 需要新增的

少。大部分接缝是现成的。

| 项 | 说明 |
|---|---|
| `card_profile` 表 | 名片文档（wholesale JSON）+ 发布状态 + 短链 + owner。文档里存 **cdnKey 与 dapDisplayRef，不存签名 URL** |

| ipstudio 发布后加出口 | 「用这组形象做张名片」按钮 |
| `PUBLIC_GETS` 登记 | `GET /api/v1/card/p/*` 允许未登录访问 |
| 8 秒开屏视频 | 不新建，走 clip 快出片链路，产物登记成该形象的 derivative |

## 10. 三个坑

1. **引用是双刃剑。** 形象被删或授权被撤销，名片会失效。`DapAvatarRefResolver` 已有静默回退，但名片还要额外给主人发通知 —— 不能让访客看到破图而主人不知道。
2. **别去读 ipstudio 的画布文档。** `doc` 是客户端拥有、服务端整存整取的。名片只能读它**发布出来的** `DapAvatar` / `DapLook`。这条边界破了，两边就锁死了。
3. **签名 URL 不能存进名片文档。** §4.7.7 的教训：签名有 TTL，存下来一小时后全是裂图。文档只存 cdnKey，出 wire 时经 `CdnUrlSigner` 递归重签。

## 11. 设计稿

视觉稿在画布 artifact（「AI 数字名片 · 棚」），只承载视觉：桌面三屏 + 手机三屏。设计概念、机制与交付契约以本文为准，画布不再承载方案说明。

视觉方向：**棚** —— 形象本来就是纯白棚拍出来的，那就把整张名片做成一个摄影棚。每屏一卷无缝背景纸，人站在原地，背后的纸一卷一卷换。配色沿用数字资产平台的 Studio Cyan / 冷白：

| 卷 | 色 | 用在哪 |
|---|---|---|
| 01 纸白 | `#FFFFFF` | 首屏。跟渲染图棚拍白同色，图片矩形隐形 |
| 02 青雾 | `#CFE9F4` | 我在做的事。Studio Cyan 稀释成一卷纸，唯一彩色强拍 |
| 03 灰白 | `#F7F9FB` | 企业与历程。dap 地板色，回落 |
| 04 深青墨 | `#0F2836` | 联系。深色带青调，不是中性灰 |

青色只当图形用（圆点 / 强调线 / 色卡标记），正文与主按钮一律墨色 `#14202B` —— dap 的 One Ink Rule。

卷与卷之间插 82px 渐变换纸带（标 `ROLL 02 → ROLL 03`），不硬切。
