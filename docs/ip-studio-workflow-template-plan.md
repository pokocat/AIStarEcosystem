# AI IP Studio 标准画布模板方案

> 2026-10-08 用户追加产品方向：将成熟画布发布为可套用模板，把标准制作经验积累为平台核心资产。本文是模板能力的实施规格；用户同日澄清首个默认模板应一次生成一张完整人物设定图，多张资产分步生成改为可选进阶流程。
> 与 [统一方案](ip-studio-unified-canvas-plan.md) 共用工作空间、IP 资产、原生生成任务和账本。M5–M6 继续验收，模板基础兼容在本轮修正，完整产品化列为紧接其后的 M7。

## 1. 产品定义

用户选择想获得的结果，填入自己的 IP、图片或商品，按成熟流程产出可继续使用的资产。运营把已验证的创作经验组织成标准画布；作者可以保留自己的变体，经过发布验证后形成新的模板版本。

模板包含五部分：输入表单、步骤与依赖、可调参数、需要用户确认的位置、输出资产标准。画布是专业编辑方式，套用模板的用户主要完成选择输入、确认主形象、选择产出和确认费用。

平台的长期价值来自流程在不同输入上的成功率、角色一致性、完成时间和实际成本，以及可接着制作的资产包。模板数量和漂亮封面不能替代这些指标。

## 3. 首个旗舰模板：一张人物设定图

用户 2026-10-08 明确：小红书案例中的多视角、表情与细节是一次生成在同一张图里的。默认模板按这个方式做，不要求先生成八张再拼版。名称建议“IP 人物设定图 · 一次出图”。

| 阶段 | 输入或用户动作 | 输出 |
|---|---|---|
| 选择人物 | 一张参考图或本人已采用的 IP 图片版本；可补充风格和服饰要求 | 锁定本次人物参考 |
| 生成设定图 | 一段可复用的版式与一致性提示词，一次图片生成 | 一张包含主形象、正侧背视图、表情、面部/服装细节及配色的图 |
| 检查并采用 | 检查同一人物、视角、服饰、细节和标注 | 保存这张图的精确版本，作为后续创作参考 |
| 继续出镜头 | 整张设定图作参考；描述所需视角、动作、场景和构图 | 单独的一张镜头画面，不带拼版、说明文字和多个人物陈列 |
| 制作视频 | 采用单独的镜头画面作首帧，再输入运动描述 | 视频；不把整张设定图直接当作视频首帧 |

默认是一个图片步骤、一次调用、按一张图片报价。版式、风格、视角、表情、细节、配色和身份一致性规则是模板的主要资产。画布依然允许复杂依赖，模板可以很简单；平台不以节点数体现价值。

参考图可以直接供支持图像参考的模型理解，不必在前置阶段全部拆分。需要更准确地引用某个脸部细节或视角时，再裁取相应区域或按需生成一张独立图片。整图包含的信息多，细小特征可能丢失，不能承诺每个模型都能正确读懂全部区域，也不能承诺一次调用必然得到正确三视图。

[可复用提示词](prompts/ip-character-sheet.md) 是根据目标版式编写的提示词，不是恢复作者原始提示词。2026-10-08 重新打开笔记，正文只描述生成工具和效果，没有列出原词。默认先由模型生成图和短标注；中文需要精确可读时，用户可选择后加文字排版，排版不增加图片生成次数。不能把后加的可控中文排版能力说成模型文字必然正确。

“生成设定图”和“数字人可口播”是两个成果；声音、口型驱动、3D 网格与骨骼不因这张图而自动就绪。

原先主形象、视角、表情、细节逐张生成并拼板的方案保留为可选进阶模板，适合需要每张独立文件、局部版本与来源追踪的制作。其已运行的八张 + 六次限定修正属于该进阶流程实测，不是默认设定图流程，也不是一次出图能力的证据。

## 4. 作者发布模板

在成熟画布中进入“发布为模板”，依次完成：

1. 选择范围。可发布整个流程或选中的一组节点；缺失的外部依赖必须改成输入槽或明确补齐。
2. 定义输入。图片、IP 形象、商品、文本、选项；设置必填、数量、支持类型和用途。例如 `character`、`style`、`era`、`views`、`expressions`。
3. 设置步骤。为节点声明受支持操作、模型能力要求和依赖；将人物名、参考图片、商品信息等绑定到输入，不再写死作者资产。
4. 配置使用界面。选择用户可改参数、作者固定的风格和流程、主形象采用等人工确认点。用户不需要编辑整张画布才能更换人物。
5. 定义输出。每个输出明确角色，如主形象/正视图/侧视图/背视图/表情/细节/展示板，以及数量、比例和是否需采用。质量不合格时不报整个模板成功。
6. 验证并发布。发布前用不同输入试跑，检查来源引用、恢复、费用和结果标准。草稿只在作者侧；首期官方上架由运营完成。展示案例素材需有明确可公开用途，用户私有参考与对话不进入模板。

首期沿用现有超级管理员权限发布官方模板（当前接口 `requireSuperAdmin`，普通运营不能发布）；普通创作者先保存个人模板，公开投稿、审核、商业分成后续再扩展。不要首期同时建设完整社区交易市场。

## 5. 用户套用模板

模板卡展示结果示例、适用对象、必要输入、可选产出、模型要求和当前报价范围。进入后填自己的输入，点击“预览制作计划”，看到本次确切步骤、会生成多少资产、已有资产是否复用、哪些步骤需确认及费用上限。

套用创建独立项目，绑定不可变模板版本。输入与执行记录属于新用户、新项目；原模板作者后续更新不能覆盖正在制作的项目。开始只是确认范围，仍在主形象采用等明确节点停下来等待。

默认“生成一张设定图”，采用后继续出单独镜头。进阶模板可选择“先做主形象”“只做三视图”“做完整资产包”。失败时只重试确认失败的步骤；重做主形象会标记依赖资产需要更新，保留旧产物，重新报价后再执行。修改某个表情不重跑三视图和全部细节。

## 6. 版本与执行模型

沿用现有目录和项目，在其上补充以下职责：

| 对象 | 职责 |
|---|---|
| Template | 标题、分类、作者、可见范围、上下架状态与当前发布版本 |
| TemplateVersion | 不可变的画布配方、输入定义、步骤依赖、可调参数、输出标准和能力要求 |
| Project.templateVersion | 用户套用时锁定来源版本，维护自己的输入与画布 |
| ExecutionPlan | 从本次输入和模型配置编译出的确切步骤、成本上限与确认点 |
| IpRun / 原生媒体 Job | 每一步真实执行状态、输入快照、结果与计费；不另造第二份账本 |
| Output mapping | 本次产物到 IP 资产及输出位置的显式映射 |

输入槽以稳定标识引用，配方内引用模板节点或步骤输出。实例化时重建项目/node/request 标识、重连依赖，清空作者运行、任务号、计费批准、聊天历史、采用身份和私有素材。模板只声明能力要求；实际端点和价格由平台当前配置解析，不保存作者 Key 或可直接执行的外部脚本。

执行器先验依赖与输入，再编译计划；每次提交前按原生链实际价格核对批准上限。价格上涨、端点停用、输入变化、依赖失败均暂停。已受理任务只能查询恢复，不能因刷新重复提交。新增通用编排不能绕过现有 owner、enrollment、phone、账本和 afterCommit 规则。

现有 `IpDemoTemplate` 与旧模板继续可用，可转为 v1 配方；旧项目不强制迁移。公开示例与可执行模板继续分别维护：示例展示效果，模板供用户填自己的内容。正式上架版本不能直接覆盖，编辑产生新草稿/版本；下架阻止新的套用，已有项目仍保留来源记录。

## 8. 实施与验收顺序

M7.1：现有“存成模板”的 Studio 兼容清理；完成输入槽和不可变发布版本、套用绑定、目录与表单。M7.2：受控计划扩展为依赖图，支持图片生成和人工主形象采用；默认旗舰模板一次产出人物设定图，独立资产为可选进阶模板。M7.3：展示板排版、资产归档、局部更新和模板质量指标。能力不足的数字人口播模板先作为不可执行预告，不冒充已接通。

验收至少覆盖：

- 同一模板用两个不同 IP 成功套用，输出属于各自用户，没有作者的 key、任务号或身份。
- 模板更新为 v2 后，旧项目仍使用 v1；新项目使用 v2；下架后不可新建。
- 更换输入重新计算依赖；未确认主形象前不生成全部下游；费用上涨在冻结前拒绝。
- 暂停、刷新、未知提交结果均恢复原请求；终态失败才允许显式新请求。
- 默认设定图只报价一张、只产生一个生成任务；整图作为参考生成单独镜头，后者作视频首帧。
- 进阶模板的独立资产可下载、引用和打包；中文展示板文字由可控排版绘制。
- 设定图的错误先调整指令或按需补单图；不自动展开八次调用。进阶模板中一个视角失败只重做该视角；保留其他结果，部分资产包明确标识缺项。
- 官方模板有真实样例、实际成本与模型要求记录；不只验接口 200 和静态封面。

模板指标按版本记录套用量、首轮输出通过率、用户采用率、完成率、每份资产包实际积分/耗时、失败类型及后续作品使用率。先积累可重复成功的流程，再扩大目录。

## 10. M7.1 当前实现与边界（2026-10-08，未发布）

沿用 IpDemoTemplate/IpTemplateResolver，增加个人与官方可见范围、不可变 IpTemplateVersion（V44）及 Project.templateVersionId。本人在同一画布配置图片/IP、文字或选项输入、图片步骤、依赖、尺寸、输出角色和采用确认点；个人模板仅本人可见，官方发布仍需超级管理员。模板发布只按白名单重建配方与画布，作者媒体、历史候选、任务、身份、对话和批准不进入版本；旧接口不能覆盖版本模板或删除历史发布，旧模板和项目保持兼容。

用户先填自己的真实图片或精确 IP 图片版本，使用平台当前 DAP_IMAGE 配置预览逐步费用，再免费创建独立画布。每份实例重建 node/connection id、保留自己的输入并锁定来源版本；模板更新后旧画布不跟随变化，下架阻止新套用，旧画布仍可恢复创建时计划。发布与套用均不启动模型、不冻结积分；生成任务仍走原生 IpRun/账本。新增本人模板停用/启用、来源版本与创建时计划查看。商品入口同步修复仅引用旧人物图片时漏显示驱动/声音状态，多人物引用不猜默认出镜人。

M7.1 验收：两个不同人物输入分别建立独立画布，8 图片配方按当前单价报价 64 积分，v1/v2 锁定、停用阻止新建、恢复与作者私有素材清理通过，账本零变化。该段仅记录 M7.1 当时的免费验证；后续进阶配方已生成八张并限定修正六张。默认方向现按用户澄清改为一张设定图，不能以逐张生成测试证明一次成图成功。验证记录见 `ip-studio-unified-canvas-validation.md` §14。

## 11. 当前图片执行与输出边界

有限图片依赖执行、人工采用、单步确认费用/重做与原任务恢复已接入原生 IpRun；实例可调整本次图片指令，不能改变模板版本或固定引用。每次调用只生成一张；新 `sheet` 输出用于一次人物设定图。发布界面明确提示整图可供出图参考，视频先生成单独镜头。

进阶打包只收入已采用且来源仍有效的图片，原图+来源清单ZIP和中文展示板零模型积分；少选则明确部分输出。本人版本统计派生自原生任务与采用状态，终态模型成功与人工合格分开统计。进阶实测消耗112积分并通过14请求恢复，最终六张部分资产包可下载，另外两张质量未通过，不写成完整成功。

默认一次出图模板已在本地个人目录保存、实例化并返回真实结果；每实例一个原生图片任务、8积分。原始v1与提示词修正v2各一份结果保留。用户明确本轮聚焦交互与功能，不以模型画质作为通过条件，不再为效果反复生成。v2结果经浏览器采用、归档到指定人物的sheet素材，并跨画布引用；主形象与声音版本保留。进入画布即恢复模板结果，计划关闭时仍推进原任务；选中设定图提供生成镜头画面和修改设定图，生成镜头的指令与引用直接带入。

详情见验证记录§16。输入槽原地重绑、自动区域提取、跨用户运营指标及任意多模态模板执行仍未实现，不能由图片模板的闭环推定已具备。
