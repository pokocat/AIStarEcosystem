# AI 导演台 · 带货短剧方案

> 2026-11-06 · 功能分支 `feat/director-commerce-drama`，本地实现，未发布。
> 相关真源：[`ai-director-plan.md`](ai-director-plan.md)（导演台总方案）、[`ai-director-assistant.md`](ai-director-assistant.md)（创作助手）、[`studio-prompt-architecture.md`](studio-prompt-architecture.md)（提示词库）、`specs/BUSINESS_RULES.md`「导演台带货短剧」。

## 1. 用户看到什么

它还是导演台，还是拍短剧。只多一个能力：**在拍短剧时加入商品，商品被写进剧情，商品图成为分镜和视频的参考图**。比如男主角加班时拿起保温杯喝水，女主角出门前喷一下香水。

1. 新建作品（或在作品设置里）打开 **带货短剧** 开关。
2. 工作台左侧多出 **商品** 工作区。从 **商品库** 选商品，或新建商品（图片 + 名称 + 说明）。可以写一句 **植入想法**。
3. 生成剧本时，AI 把商品写进剧情。已有剧本的，点 **写进剧本**，创作助手按段给修改建议，用户逐条采用。
4. 提取资产时，商品不会被重复提取成道具；写分镜脚本时，写到商品的片段自动关联商品（模型没放进 `assetIds` 时，程序按镜头和台词里的名字、别名、简称补上）。
5. 生成分镜图和片段视频时，商品图和角色、场景图一起交给模型，提示词写明照哪张图画。

开关关闭时，导演台和现在完全一样：看不到商品入口，提示词一个字都不变。

## 2. 关键决定

| 决定 | 选择 | 为什么 |
|---|---|---|
| 开关放哪 | 每部作品一个：`settings.commerce`，默认关 | 用户说的是「决定商品库是不是出现」。一部普通短剧不该看到商品入口，一部带货短剧要能随时打开或关闭。不做后台全局开关 |
| 商品库存哪 | 个人资产库 `ip_library_record`，新增 `kind=product` | `/assets` 是现行统一个人资产入口。它已有名称、说明、多张图（版本）、主图、搜索、分页和并发保护，不用加表、不用迁移。旧的 `dap_product` 属于手机端老页面，桌面端看不到，也不支持多图上传，不再扩展 |
| 商品在作品里是什么 | `assets[]` 里的一项，`kind=product` | 片段的 `assetIds`、参考图绑定、「需更新」核对、解除关联、助手素材都已经按资产走。商品图走同一条路，不写第二套传图逻辑（§8.0.1 ④） |
| 商品资料以谁为准 | 商品库。作品里只存一份快照和本剧的植入想法 | 一份商品可以用在很多部剧；改名、改说明、加图在商品库做，点一下同步到本剧 |
| 商品图从哪来 | 只来自商品库，不用 AI 生成 | 带货要的是真实商品，AI 重画会改包装和标签 |
| 已有剧本怎么植入 | 复用创作助手的修改建议 | 已经有原文核对、逐条采用、撤销和长正文分段，不再做一条会覆盖全文的任务 |

## 3. 数据

**商品库一项**（`ip_library_record.payload_json`，`recordType=object`）：

```json
{ "kind": "product", "name": "恒温保温杯", "description": "316 不锈钢内胆，12 小时保温",
  "mainVersionId": "ILV-…", "versions": [{ "id": "ILV-…", "storageKey": "…" }] }
```

**作品里的商品**（`director_work.content_json` 的 `assets[]`）：

```json
{ "id": "as3", "kind": "product", "name": "恒温保温杯", "description": "316 不锈钢内胆，12 小时保温",
  "libraryObjectId": "ILO-…", "placement": "男主角加班到深夜，拿起保温杯喝了一口",
  "aliases": ["保温杯"], "episodeIds": ["ep1"],
  "image": { "candidates": [{ "source": "library", "key": "…" }], "adoptedId": "…", "adoptedBy": "user" } }
```

`settings.commerce` 为 `true` 才算打开。库里只存 key，出 wire 时按 §4.7 重签。无迁移。

## 4. 接口

没有新路径，只扩展现有的：

- `POST /v1/ip-studio/director/works` 多一个 `commerce: boolean`。
- `PATCH /v1/ip-studio/director/works/{id}` 的 `settings.commerce`。
- `POST /v1/ip-studio/director/works/{id}/edits`：
  - `product.add`：`data = { objectId, placement? }`。把本人商品库的一项加进作品；已经加过就同步资料和图片，保留本剧的植入想法和选中的图。开关没开时拒绝。
  - `asset.update`：多一个 `placement`（≤300 字，只有商品能写）。
  - `asset.adopt`、`asset.delete`、`clip.unlinkAsset`：照旧。
- `GET /v1/ip-studio/library/objects?kind=product`、`POST /library/objects`（`kind=product`）：照旧，只是多认一个类型。

商品不能走 `asset-image`（报 400），也不能用 `asset.create` 建（必须来自商品库）。

## 5. 提示词

全部在提示词库，后台可改。每份内容方法只在 **开关打开且作品里有商品** 时才拼进去；否则不拼，提示词逐字不变（`DirectorPromptStageParityTest` 守着）。

| 环节 | 内容方法 | 作用 |
|---|---|---|
| 写剧本 `stage-director-script` / `-script-more` | `director-commerce-script` | 每件商品都要写进剧情、对情节有用；按植入想法写；不念广告词；功效和数据只写说明里有的 |
| 写剧本前的问答 `stage-director-brief` | `director-commerce-brief` | 不再问商品是什么；要求里写明商品要写进剧情 |
| 提取资产 `stage-director-extract` | `director-commerce-extract` | 写到商品时对上商品，不提取成道具 |
| 写分镜 `stage-director-storyboard` | `director-commerce-storyboard` | 写到商品的片段 `assetIds` 带上它；至少一个镜头看清商品；不写商品外观 |
| 创作助手 `stage-director-assistant` | `director-commerce-assistant` | 把商品写进剧本时只改必要的句子，不改主线 |

输入 JSON 多一个 `products: [{ name, description, placement }]`（编剧、问答）；提取、分镜、助手的资产清单里商品带 `kind: product`。

编剧环节里「关键道具给一个可辨认的外观细节」的示例是「掉漆的蓝色铁皮饼干盒」。带货作品不给这个示例（环节变量 `commerce`），规则里也不写这个词：Agnes 实测两次，只要提示词里出现，模型就把商品写成掉漆的。

**媒体提示词**（只有片段关联了商品才多出来，其他片段逐字不变，不会被标「需更新」）：

- 分镜图 `stage-director-board`：`图N 提供商品「X」的外形、颜色、包装和标签。` 外加一句「商品和参考图保持一致，包装上原有的图案和文字照参考图保留」。
- 中文视频提示词：`商品「X」：外观、包装和标签照参考图N。`
- 英文改写的素材清单：`reference image of the product「X」; keep its shape, colors, packaging and label exactly as shown`。商品说明不进这一段：卖点文字交给视频模型可能被画成字幕。

## 6. 参考图怎么传

`DirectorService#visualAssets` 是唯一入口，分镜图和视频共用，顺序是 角色 → 场景 → 道具 → 商品。

```
片段 assetIds 含商品
   ├─ 分镜图：boundRefs → image() 的 refs → 图N
   └─ 视频：分镜图是图1，资产从图2 起 → VideoStudioReferenceInput("image", key)
```

- 一件商品一次只交一张图：用户在商品卡上选的那张（`image.adoptedId`），默认是商品库的主图。商品库有多张时可以换，换了之后已生成的分镜图和视频标「需更新」，不自动重做。
- 超过模型参考图上限时沿用现有的明确报错。
- 只按首帧出片的视频模型不收额外参考图，商品靠分镜图带过去。

## 7. 界面

风格沿用导演台现有的克制样式：白色卡片、细边、衬线标题、深色主按钮，AI 动作用紫色。商品图用浅灰底 + 完整显示（`object-fit: contain`），不裁切包装。

**开关**：新建作品弹窗和作品设置里各一行，标题「带货短剧」，说明「把商品写进剧情，商品图用作分镜和视频的参考」。

**商品工作区**（左栏 剧本 / 资产 / 商品 / 分镜）：

```
本剧商品  2                                           [从商品库添加]
剧本会把这些商品写进剧情，商品图用作分镜和视频的参考。

┌──────────┬───────────────────────────┐ ┌──────────┬────────────┐
│  商品图    │ 恒温保温杯             ⋯  │ │  商品图    │ 玫瑰香水     │
│ (完整显示)  │ 316 不锈钢内胆，12 小时…   │ │          │ …          │
│ ▫ ▫ ▫     │ 植入想法                  │ │          │            │
│ 选一张作参考 │ [男主角加班到深夜，拿起…]  │ │          │            │
│           │ ● 第 1、2 集 · 3 个片段     │ │          │            │
│           │ [写进剧本]                 │ │          │            │
└──────────┴───────────────────────────┘ └──────────┴────────────┘
```

**商品库弹窗**：搜索 + 「新建商品」；网格卡片（图、名称、说明、已添加标记）；多选后「添加到本剧（2）」。新建和编辑在同一个弹窗里切到表单：多图上传（第一张是主图，可换）、名称、说明。

**其他地方**：

- 剧本页顶部：一条商品栏，列出会写进剧本的商品和「管理」入口；开关开了但没加商品时提示一句。
- 资产页只列角色、场景、道具，商品只在商品工作区。
- 资产确认弹窗多一组「商品」，说明这些已对上商品库。
- 分镜片段的关联资产里能看到商品，能解除关联；编辑镜头时能勾选。
- 作品卡片：带货作品角上有「带货」标记。

## 8. 边界

| 情况 | 行为 |
|---|---|
| 开关关闭 | 商品入口隐藏，新写的剧本、分镜、提取不再带商品。商品数据保留，重新打开后还在。已经关联商品的片段保持不变，仍按关联资产出图，可以解除关联 |
| 开关开着但没有商品 | 不拼内容方法，提示词和普通作品一样；剧本页提示一句 |
| 只有商品、没有角色场景 | 不算「已有资产」：写分镜前仍要求先提取；一键制作照常提取 |
| 模型把商品提取成道具 | 按名称和别名对上商品（互相包含且至少 2 个字），不新建；保存时把模型的叫法记成别名，商品名和说明不变 |
| 商品从商品库删除 | 作品里的快照照常用；同步时明确提示商品库里已没有这一项 |
| 商品改名 | 同步到作品后提示词跟着变，已生成的图标「需更新」；剧本正文不自动替换 |
| 从本剧移除正在用的商品 | 409，列出用在哪些片段，先解除关联 |
| 商品说明里没写的功效、价格 | 提示词禁止编；不做服务端内容审核 |

## 9. 不做的事

- 不做商品链接、价格、下单、佣金：这里只管内容。
- 不让 AI 生成商品图或补角度。
- 不做商品出现次数或时长的硬性校验：模型不听时用户看得见，可以改。
- 不改 `/assets` 页面的分栏：商品图会进「图片」，商品对象暂时只在导演台管理（见 `TODO.md`）。

## 10. 验证

2026-11-06 本地验证（库副本。文字和出图是真实的 Agnes；视频走真实服务端链路，上游是记录请求的本地模拟聚算，没有花钱，也没有真实成片）：

| 项目 | 结果 |
|---|---|
| 新建时打开开关，落到商品工作区 | 通过 |
| 商品库新建（多图）、多选加入、已加入的不能重选 | 通过 |
| 真实写剧本 | 第一版规则：把商品写成「掉漆」，第二版：漏写香水、编了「三十多块钱」。收紧规则后：两件都写进关键情节，没有价格，没有写旧。只跑了 1 次，弱模型仍可能漏 |
| 真实问答 | 没有再问商品是什么 |
| 已有剧本「写进剧本」 | 助手给出逐字定位的修改建议，采用后状态变成「已写进第 1 集」，撤销后变回 |
| 真实提取 | 保温杯对上商品，没有变成道具，别名和出现集合并，商品说明不变 |
| 真实写分镜 | 短剧本上 Agnes 自己把商品放进了片段的 `assetIds`（程序兜底没有动用）；长剧本上它只拆出第一段，那段没写到商品，就没有关联 |
| 关联商品的片段 | 分镜图和视频提示词有对应行，图号正确 |
| 真实分镜图 | 参考图记录里有商品，画面里的杯身颜色、杯盖、标签和商品图一致 |
| 视频请求（模拟上游） | 商品图文件的哈希和原图一致；`referenceInputs` 顺序是分镜图、角色、场景、商品；提示词的「参考图4」正好是商品；成片回写到片段，记录里有图4 恒温保温杯 |
| 状态行 | 点「已写进第 1 集 · 用在 1 个片段」跳到那个片段，打开关联资产并高亮商品 |
| 关闭开关 | 入口消失，切回剧本页，商品和片段保留，重新打开后恢复 |
| 手机 375 宽 | 工作区和商品库弹窗无横向溢出 |

**没有验证（都要花钱，用户规定本地只用免费的 Agnes，需要另外批）**：真 H3 成片里商品还原得怎么样；线上默认的 Sonnet 和聚算 Qwen 的植入效果。服务端链路已经验证到把图和提示词交给厂商这一步。

评审（impeccable critique）后修掉的：离开未保存的新建表单要确认；保存不可点时写明还差什么；不再承诺「没写的不会编」，改成发布前请核对；已写进剧本的商品，「写进剧本」按钮降级；状态行能点到用它的片段；商品图可以拖入；表单弹窗高度跟内容走；手机上的小按钮放大到 40px；「已在本剧」文字对比度；工作台顶上单独一行的「查看生成原文」收进顶栏。自查另外修掉：编辑商品保存到一半失败时，重试会被当成别的页面改过。

评审里留着没动的：「去资产页修改」在关联资产抽屉里对商品也这么写，商品其实在「商品」页（全部资产共用这个按钮）。

验证清单：

1. 开关：新建打开、设置里打开和关闭；关闭后入口消失，数据保留。
2. 商品库：新建（多图）、搜索、编辑、删除、多选添加、重复添加。
3. 剧本：测试响应 + Agnes 真模型各生成一次，商品进正文；已有剧本经助手写进去、采用、撤销。
4. 提取：商品不变成道具，出现集和别名合并。
5. 分镜：片段关联商品，分镜图和视频请求的 refs 里有商品图，提示词有对应行。
6. 普通作品：提示词逐字不变（`DirectorPromptStageParityTest`），界面没有任何商品入口。
7. 手机宽度：工作区、弹窗不溢出。
