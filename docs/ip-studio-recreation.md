# 复刻创作：全片创作拆解

## 三种复刻方式（2026-11-11，本地实现，未发布；以此节为准，下面各节仍然有效）

用户定的方向（2026-11-11）：「爆款复刻」是类别名，参考茂隆，里面有三种复刻方式，都要开放，各自对应不同的视频类型和诉求；最近一直在做的复刻就是「分镜复刻」。比如大头口播这种简单场景，深度复刻就够了。

| 方式 | 每段交给视频模型什么 | 适合 |
|---|---|---|
| 分镜复刻（`recreation`） | 原片每个镜头改好的开场画面 + 用户素材，原片不交给模型（下一节） | 剪辑多、换镜频繁：带货混剪、剧情、探店 |
| 深度复刻（`depth`） | 这段原片转成的动作参考（深度图或骨骼图，ReShot）+ 用户素材 | 镜头少、动作连贯：口播、单人展示、跳舞 |
| 元素替换（`replacement`） | 这段原片本身 + 用户素材，只换点名的人或物（不拉片，见下面「元素替换不拉片」） | 原片拍得好，只想换掉其中一样 |

**元素替换不拉片、不写提示词（2026-11-12 起，已发布；用户定：元素替换直接用模型原生的编辑能力）**：分析阶段只剩一步零积分的「切分原片」（`recreation` 步骤 `mode=cuts`，`StudioWorkflowWorker#cutsStudy`：ffmpeg scdet 找切镜，按模型时长在镜头边界分段、切片，不调模型、不排模型的队）。切完由代码直接排出制作计划（`StudioPlanExecutionService#confirmReplacementProduction`）：每段一条视频（视频1 = 这段原片）、按开关检查、最后合成；所有段用提示词库 `stage-recreation-replace-edit` 的同一段话（「编辑视频：以视频1为基础，〈用户的要求〉……其余画面、镜头、动作、口型、字幕和声音保持不变」，`StudioRecreationTaskPlan#replacementAnswer`）。计划照样过 `validateSkillPlan`、报价和指纹。少了拉片和写提示词两次模型调用，报价也不再加这两笔。

- **原片能直接用就不切（2026-11-12 用户：「不是直接参考吗」）**：没截短、原片时长在每段的上下限内（Seedance 2.5 编辑 4–30 秒，2.0 / H3 参考视频 2–15 秒）、格式和大小也合这个模型参考视频的规则（MP4、≤50 MB），受理时就排出制作计划，视频1 就是用户放进来的原片（`StudioCloneVideoPlan#directSource`、`StudioRecreationTaskPlan#directReplacement`），没有「切分原片」这一步，也不合成。超过上限、要截短或要转码的才走切分。
- **时长可以自己定（三种方式都是）**：视频规格里选「跟随原片」或「自定义」，还没放参考视频也能设置。自定义可以直接输入秒数或拖动滑杆，范围是模型单段的下限（深度复刻 / 元素替换还要够参考视频或编辑的下限，`StudioCloneVideoPlan#minimumSeconds`）到原片时长。读取原片时长后按所选秒数报价，截取原片开头的对应片段（`recreationSource.limitSec`、`StudioWorkflowWorker#trimSource`）。草稿保存所选模式。
- **按模型适配参数**：模型的全能参考模式在后台规格里配 `edit`（`VideoStudioEditSpec`：原视频的最短 / 最长秒数、输出是否跟原视频的画幅和时长、编辑任务另加的请求字段）就走厂商的编辑任务，每段按编辑的时长上限切（`StudioCloneVideoPlan.clip(model, kind)`），视频步骤带 `video.edit=true`，一路传到 `VideoGenSpec.editSource`，Seedance 协议组包时发 `ratio=adaptive`、`duration=-1` 和配置的字段（`MaterialVideoModelClient`）；上传核对参考视频时长也按编辑的上下限（`StudioVideoService.editMode`）。画幅跟原片走时，计划和合成也按原片画幅（`StudioCloneVideoPlan.closestRatio`）。没配 `edit` 的模型照常用全能参考、靠提示词编辑。模型或模式没配编辑却带了编辑标记，提交时明确报错，不退回普通参考生成。
- **各模型怎么配**（火山方舟文档 2026-11-12）：Seedance 2.5 有专门的编辑任务，`omni_reference_task_type: "edit"`，画幅必须 `adaptive`、时长必须 `-1`，原视频 4–30 秒，输出的画幅和时长跟原视频一致（最多短 0.4 秒），提示词里要有「编辑视频 / 替换 / 修改」这类词；只按普通参考生成的请求（写死画幅和秒数）被模型判成编辑任务时会异步失败（`InvalidParameter.TaskTypeConstraint`），所以元素替换在 2.5 上一定要走编辑任务。配置：`"edit": {"minSourceSec": 4, "maxSourceSec": 30, "followSource": true, "requestFields": {"omni_reference_task_type": "edit"}}`。Seedance 2.0 / Fast / Mini 靠提示词编辑，官方示例照常写画幅和秒数，不配 `edit`。H3 没有编辑任务，用全能参考（1 段参考视频，2–15 秒），不配。**OneToken 转接的 2.5 现在不收编辑任务**（2026-11-12 真调：HTTP 400 `edit/extend billing is not verified for this model`），所以线上 2.5 没配 `edit`，元素替换在 2.5 上按普通全能参考提交，可能被判成编辑任务而异步失败，没真跑过；OneToken 开了编辑计费再按上面的配置加回去。2.0 已真跑通一条（15 秒原片切两段），见 `docs/releases/studio-replacement-edit-release-20261112.md`「发布后」。
- **不拉片少掉的**：认不出原作者的账号片尾，那段照做；不知道台词里有没有提到旧商品，模型照原片说，要改得在要求里写明（页面「限制」写了）。原片的字幕、水印照旧保留。
- **报价**：页面按时长均分报价，实际按切镜点分段，可能多一段（多一次检查）。首次制作报价须放进页面上限扣除已花积分后的余额，剩余预算可用于重试。段数按原片取整，合计时长允许每段差 1 秒。
- 已经受理、分析阶段带「写分镜脚本」的旧任务照原来的路走完（`stage-recreation-compile-replace` 保留）。

**三种共用一条链**（`StudioVideoTaskService` → `StudioRecreationTaskPlan`）：先拉片（看视频，写逐镜动作、台词、字幕），代码按拉片结果分段，模型只写每段的提示词，然后出片、检查、合成。工具箱分支（`codex/studio-video-clone`）原来把整条原片一次交给模型，既不按原片分段，也不知道原片里什么时候发生什么；现在深度复刻和元素替换都先拉片，补上了那个分支 TODO 里的「原片分析」。

- **分段**：深度复刻和元素替换每段原片都要作为参考视频交给模型，所以每段不超过模型单段上限和参考视频时长上限中较小的那个，也不短于参考视频的下限（`StudioCloneVideoPlan.clip`）。只开放声明了视频参考的模型。
- **深度复刻**：每段先做一步零积分的 `video-control`（`d<段号>`），把拉片切好的这段原片转成动作参考（恒定 24 帧、长边 320，全身动作用骨骼图，近景用深度图，见 `docs/studio-video-clone-toolbox.md`），视频再引用它。H3 提示词总是先优化，视频1 定义成只迁移动作（attribute_transfer）。提示词库 `stage-recreation-compile-depth`：第一行固定写「参考视频1的动作与运镜……画面里不出现灰色深度图或骨骼线条」（ReShot 给 Seedance 的写法），人、商品、场景和光线都要写出来，台词逐字照原片。原片字幕照样在合成时加回。
- **元素替换（2026-11-11 版，已被上面「不拉片」取代）**：视频直接引用拉片切好的这段原片（`StudioPlanExecutionIds.segmentNodeId`）。提示词库 `stage-recreation-compile-replace`：第一行写清以视频1为基础换什么，逐镜只写要换的东西。不再叠字幕（原片画面里已有）。2026-11-09 的真跑说明 H3 会照抄原片的商品、水印和字幕，这正是元素替换要保留的部分；原片里提到旧商品的字幕和水印也会留着，这是这种方式的限制。
- **原作者的账号片尾**：整段都是账号片尾的那段，深度复刻和元素替换不做（照着它只会再拍一遍别人的片尾），所以成片可以比页面上的时长短（`confirmVideoProduction` 只对这两种放宽）。
- **受理时冻结**原片和素材的文件（`videoTask.cloneKeys`），之后画布上改了不影响这次制作；拉片切的片段和本次产物照常按节点找。
- **报价**：制作部分按页面时长和参考视频的分段上限切段，每段一条带参考视频的视频和一次检查（`StudioCloneVideoPlan.price`），加拉片和写提示词两次文字任务。总上限是页面估价的 3 倍，首次制作报价须放进扣除已花积分后的剩余预算。
- **推荐方式**：放进参考视频后，页面按真实切镜数和平均镜头时长推荐（`GET /api/v1/ip-studio/studio/clone-advice`，ffmpeg scdet，不调模型、不扣积分）：最多 2 个镜头或平均每个镜头至少 6 秒推荐深度复刻，否则推荐分镜复刻；只加「推荐」标签和一句原因，不替用户切换。元素替换看用户想不想保留原片画面，不推荐。6 秒这个门槛是估的，要用真实素材校准。
- **动作提取单独排队**：`studioControlExecutor`（6 个线程，同一时间只做一次推理），不占出图、出视频的 `ipRunExecutor`；还没开始的每分钟替它更新心跳，免得排队久了被当成僵死。
- **写方案的模型看不到 `video-control`**（`StudioSkillRules.SYSTEM_ONLY_OPERATIONS`）：它只出现在代码拼的深度复刻方案里，模型自己写进去按方案没准备好处理。
- **入口**：工具箱的「爆款复刻」三张卡片（首页「爆款复刻」进工具箱），AI 视频页爆款复刻场景里的三张方式卡片。每张配一张示意图（`public/studio/clone-modes`，虚构人物，标「示意图」），说明写「适合」和「限制」：分镜复刻的动作和运镜与原片会有差异；深度复刻和元素替换仅部分视频模型可用（要能带参考视频）；元素替换会保留原片字幕和水印；三种都要求参考视频最长 60 秒。
- **顺手修的老问题**：AI 视频页把默认时长截到模型单段上限，爆款复刻也被截。原片长于单段上限（比如 18 秒原片配 H3 15 秒）时，页面发出的时长和拉片分段对不上，分析完就停在「分镜时长与本次设置不一致」。现在爆款复刻的时长固定跟原片走，设置面板里不能拖。

还没验证的：元素替换（不拉片版）在 2.0 上跑通了一条，成片效果还没看；2.5 的编辑配置因 OneToken 不收已撤掉，2.5 上还没跑过（见 `docs/releases/studio-replacement-edit-release-20261112.md`），生产上也还没装 ReShot 运行时，推荐门槛没校准，见 TODO.md「爆款复刻三种方式」。

### 2026-11-11 本机真跑后的修改

本机起分支版本的整套平台，模型照线上（视频 Seedance 2.5，本机库副本里给它开了参考视频；拉片 Seed 2.0 Lite；出图 GPT Image 2.5；写提示词和检查 Terra），用户给的两条视频：41 秒直播切片走深度复刻、13 秒双人手势舞走分镜复刻，素材是本地 Codex 出的虚构人物和商品。动作照搬、换人换商品都做到了，暴露的问题和改法：

- **深度复刻、元素替换检查不合格不重出**：「不合格重出一次、带上检查意见」只认分镜复刻，三种方式现在一样（`StudioSegmentedRun`）。
- **深度复刻各段场景不一致**（第三段换了个房间）：第一段开场截图换好人和商品，做一张「场景图」，每段都带上（`StudioRecreationTaskPlan`，图片步骤和开场画面同一套；报价多一张图加一次检查）。
- **字幕**：拉片把原片顶部一直挂着的标题当成了每一镜的字幕、漏了底部逐句的台词字幕，成片 42 秒都挂着那一行。拉片现在把固定标题单独写成 `screenTitle`，成片放在顶部（`Packaging.title`）；字幕只写随台词出现的那几行。模型仍把标题写成一条挂满大半条片子的字幕时，代码也把它挪成标题。
- **Seedance 自己烧字幕**（第二段，叠在平台字幕下面）：平台字幕为准，交给视频模型的提示词写明画面里不出现字幕和文字。用户定（2026-11-11）：模型还加就算了，不做检测和重出。
- **一步失败 3 次后只剩「在画布上查看」**：画布上「修改后重试」打开的是通用出图面板（显示给模型的英文说明、参考图没带上、比例变成 3:4），照着点只会出错图。用户定（能用为主）：视频页上一直能点重试，失败的积分都退了；停下来等人的任务能「停止生成」；「再次生成」被同一张画布上没结束的任务挡住时，提示改成说清要先停止它。
- **复测后再改（用户定）**：深度复刻复测时三段检查都因「背景告示还有字」「景别变了」「手势不一样」判不合格，各重出一次照样不合格，制作费从 5,094 涨到 10,268 积分。现在只有人或商品没换对（`subject-replaced` 判 fail）才重出，其它不合格只记下来；场景图的检查不看手势和构图。页面上加了「自动检查」开关（默认开，请求里 `autoCheck:false` 时方案不放检查步骤，也不会重出），开关下面一行写清开和关分别会怎样。
- 没改的：出图服务商偶尔 4 分钟不出图被断开（线上近 3 天没有超过 2 分钟的）；Seedance 13 秒要 20 分钟；成片配乐唱了原片的歌（用户说版权不用管）。

## 逐镜细读、开场画面和自动检查（2026-11-10 已发布 `20261110-keyframes-e6e2de04`；以此节为准，下一节仍然有效）

### 为什么改

2026-11-10 拿线上用户 87677a1a 的美食视频（14 秒，Insta360 拍的「手指捏住远处很小的女生，再一下冲到她面前」，PEX-66aabe7a）在线上新版重跑（PEX-b9498434）：人物、场景、节奏都比旧版好，但两处没做出来：

- **看点丢了。** 拉片只写了「比框 + 推镜」，没写「女生在远处、只有手指大小、正好被两指捏住」。单独问那 2 秒，同一个模型每秒 2 帧就答对了，说明它看得见，是整条片一起拉片时把细节概括掉了。后面写提示词和出片都照着这份粗的拉片走，成了普通推镜。
- **图3 的炒饭没被端起来。** 方案写了「人物手持图3」，但一段 14 秒 9 个镜头、4 张参考图，H3 没照做，炒饭只摆在桌上。

借位、大小关系这类空间信息，文字很难写清，画在图里视频模型就照着摆。所以加了「每个镜头先改一张开场画面」。

用户定的边界（2026-11-10）：镜头结构照原片，分几次生成只看模型能力，不为迁就模型改原片镜头数；视频页一键到底，不加确认步骤，质量靠我们自己的检查和评测集。

### 现在怎么做

1. **第二遍逐镜细读**（`StudioVideoBreakdown`「逐镜细读」，提示词库 `stage-video-shot-detail`）：第一遍拉片之后，相邻镜头凑成不超过 6 秒的小段，每秒 5 帧再看一遍。每个镜头写场景、用光、机位（含广角 / 鱼眼）、开场构图（人和物在哪、离镜头多远、占画面多大）、动作起止、视觉把戏怎么成立、后期效果，并选一个开场时刻。结果写进镜头的 `detail`，拉片文档多一节「逐镜细读」。
   - 模型回的镜号不可靠（真跑见过 5 镜的小段只回 2 镜，还把第 7、8 镜写在第 4、5 镜名下），所以要它照抄每镜的开始秒数，按时间对。
   - 用量到上限就停在已读完的小段（`detailPartial`），某个小段读不出来只记日志，镜头表照第一遍的用，不编内容。
2. **截开场画面**：每个镜头从原片截一帧（长边 1280，存 key，`filmStudy.frames`）。截图时刻先对到代码测出的真实切镜点（模型给的切镜时间常差零点几秒，真跑第 2 镜截到了上一镜），再只在切镜后 0.12 秒里取（模型常挑中段，那时推镜已经推成近景了；原先放到 0.4 秒，2026-11-10 真跑第 7 镜挑在切镜后 0.2 秒，镜头已经推到中景，出图两次都画错，逐帧看 0.1 秒内还是开场构图）。截图不上画布，用 `StudioPlanExecutionIds.frameNodeId` 编号，只给本次制作的出图步骤用。
3. **写分镜脚本**（`stage-recreation-compile` 第 4 版）：代码先定每段哪些镜头做开场画面（有截图、不是原作者账号片尾；放不下时有视觉把戏的和长镜头优先，整条片的总数受技能步数上限约束），开场画面排在这段参考图的最前面，素材接在后面。模型除了每段提示词，再给每张开场画面写一项：参照哪些素材、要改什么。规则是远处很小的人只换人、不给商品图（给了会被画大），并写明「保持很小、大小和位置不变」；看得清的人和商品一起换。提示词里这一镜写「从图N开始拍」，推近后才看得清的商品必须指向真的画着它的那张图。
4. **方案**（`StudioRecreationTaskPlan`）：每段 = 若干出图步骤（`k<镜号>`，以原片截图为图1，参照模型点名的素材，描述由提示词库 `stage-recreation-keyframe` 拼）→ 视频步骤（依赖这些出图步骤，参考图引用它们的产物）→ 检查步骤（`c<段号>`）。最后合成等所有视频和检查结束。
5. **自动检查、自动重出**（`StudioSegmentedRun.prepare`）：视频页的复刻，一段没通过检查就自动重出这一段一次，连检查一起再来；重出后还不合格、或检查本身做不了，用最后一版接着做，不停下来等人。别的视频页任务的检查照旧只作参考。重出和开场画面的钱都在视频页的上限里（上限是页面估价的 3 倍，估价本来就按分镜图算了出图的钱）。

没有截到画面、或拉片是旧的抽帧方式时，不做开场画面，照上一节的做法出片。

### 实测（2026-11-10，美食那条）

| 版本 | 怎么做的 | 积分 | 评分（满分 50） | 看点 |
|---|---|---|---|---|
| 旧版（PEX-66aabe7a） | 模型写整份方案，Seedance Fast 分 3 段 | 906 | 33 | 3 |
| 线上新版（PEX-b9498434） | 代码拼方案，H3 一段，只带素材图 | 441 | 36 | 5 |
| 手工实验 | 逐镜细读 + 8 张开场画面（Seedream 4.5）+ 人物图，H3 一段 | — | 41 | 7 |

评分由 `scripts/recreation-eval/score.py` 让 Seed 同时看原片和成片打分（看点、替换主体、前后一致、镜头结构、画面干净各 10 分），见下文「评测集」。

做开场画面时踩到的三件事，都已经写进规则：出图模型会自觉把远处的人画大（要把占画面多少写成硬性要求）；远处的镜头同时给商品图，会把菜品照片里的整张桌子搬进来；截图要截在开场、切镜之后。

线上默认出图模型 GPT Image 2.5 用同一份清单出了第 1、7、8 镜：远处的人保持很小，构图比 Seedream 4.5 更贴近原片（连动态模糊都保留了）。

**没验**：线上视频页从头到尾走一遍新流程；换真人人物、带台词的片子；手指「捏住后张开」还做不出来（张开只有约 0.15 秒，每秒 5 帧看不到，见 TODO）。

### 检查看得见东西、重出带上问题（2026-11-10 晚；2026-11-11 随 `20261111-recreation-checks-e39e8776` 发布）

独立评审读代码发现，上面第 5 条的检查基本是盲的：

- 每段成片只均匀抽 4 帧。14 秒 9 个镜头抽到的是 1.75、5.25、8.75、12.25 秒，多数镜头一帧都没有。
- 检查模型看不到素材图和开场画面，「第 3 镜端的是不是图3 的炒饭」无从对照。
- 检查模型也不知道这段该是什么样：`StudioPlanExecutor.compile` 给检查补了目标说明（被检查那一步的提示词、要换什么），但视频页任务随后由 `StudioSegmentedRun.materialize` 从原定义重编，补的内容被丢掉，只剩一句固定的话。
- 不合格时写下的问题（`fixHint`）只有长视频的分镜图会读，复刻的重出是同一份提示词原样再抽一次。
- 只重出视频、不重出开场画面；开场画面自己带进来的问题（美食那条第 6 镜戴着原片的贝雷帽）修不了。

改法（只对新受理的方案生效，方案里的检查步骤带 `sampling` / `compareReferences` 才走新路；之前受理的方案重交时请求不变）：

1. **按镜头抽帧**（`settings.sampling = "shots"` → `CheckSettings.sampling`）：受理检查时用 ffmpeg scdet 在成片上找真实切镜点（`StudioVideoBreakdown.detectCuts`），每个镜头取开头和结尾各一帧，不到 0.8 秒的镜头取中间一帧，最多 24 帧（`StudioCheckOutcome.shotTimes`）。没测到切镜按大约每 2 秒一帧。
2. **带参考图**（`settings.compareReferences` → `CheckSettings.references`）：被检查那一步交给生成模型的图（开场画面、用户素材；出图步骤还有原片截图）一起交给检查模型，编号和提示词里的「图N」一致，最多 9 张，逐张核对归属。参考图只用来对照，不能当作画面依据。是不是图片按文件内容判，不看后缀；不是图片或读不出来的那张不带、写一条 WARN，其余照常检查。
3. **目标说明接回去**：逐镜对照的检查，提示词里带上被检查那一步的提示词（上限从 1500 字放到 6000 字，14 秒 9 镜的提示词约 1800 字）。
4. **检查要点是逐镜的是非题**（提示词库 `stage-recreation-video-check`，开场画面的检查是 `stage-recreation-keyframe-check`，代码按这段的镜头和参考图填变量）：每张开场画面一条「第 N 镜开头是不是和图K 一致」，再加人和商品是不是这一镜点名的那张图、前后是不是同一个人、动作和结束画面做出来没有。
5. **重出带上问题**（`StudioSegmentedRun.recreationFix`）：出图步骤把问题整段接在描述后面（提示词库 `stage-recreation-redo-note`）。视频步骤只认「第N镜：这一镜应该是什么画面」这种句子，接到提示词里那一镜的末尾；带「建议」「请修改」的、带台词的、提示词里没有的镜头都不接，因为提示词可能原样交给视频模型、写给系统的话会被念出来。一句都用不上时就是原样重出。
6. **开场画面出完先检查**（步骤 `ck<镜号>`）：对照原片截图和素材看人换对了没有、有没有留着原片的帽子衣服、远处的人有没有被画大。不合格只重出这一张图一次，视频等检查结束再开始。每查一张多一步，步数有上限（技能的 `maxSteps`）：先保证开场画面本身，剩下的步数才给检查，有视觉把戏的镜头优先。`StudioPlanValidator` 因此允许检查更早的图片步骤。
7. **开场画面的检查放不下预算就省掉**（`settings.optionalRank`，`StudioRecreationTaskPlan.dropOptionalCheck`）。分析完成后，用首次制作方案报价与剩余任务预算比较（`StudioPlanExecutionService.confirmVideoProduction`）。放不下时按名次从后往前省掉可选的开场画面检查，日志记录省掉的步骤。视频和每段成片的检查保留。仍超出时暂停制作。重试提交前逐步核对已花费、冻结额和本步骤报价，受原批准上限约束。

同时改了两处小错：拉片和写提示词的规则写明背景音乐里的歌词不是台词（美食那条把歌词「baby」写成了「背景人声在画外说」）；方案说明里「每段带上原片这一段」那句过时的话改掉。

**第 7 张参考图起的加价不是代码漏算**：价格表本来就有 `freeRefImages` / `extraRefImagePerSecond`（`VideoStudioPricing.total`，制作计划的报价和提交都按参考图张数算），线上这两项是 0，所以没加价。要不要收、收多少在后台视频售价里配，需要定。

**没验**：没有调用任何真模型。检查模型会不会照「第N镜：……」的格式写、参考图加到二三十张后检查的用量和耗时、开场画面检查的误判率，都要线上真跑一条才知道。切镜检测在受理检查的事务里跑（14 秒的片子不到 1 秒，60 秒的片子约 1–2 秒）。

### 推到头的画面：原片里重复用的画面（2026-11-10 晚；2026-11-11 随 `20261111-recreation-checks-e39e8776` 发布）

评审指出成片第 3 镜推近后落到了第 1 镜的餐厅和沙拉上：参考图里没有一张告诉视频模型「这一镜推到头是什么画面」。逐帧看原片，每个捏合镜头是一个来回（远景两指捏着 → 冲到近景 → 再退回远景），而第 4、5、6 镜正好就是第 1、3、2 镜推到头时的近景（原片把同一段素材剪了两次）。第 4～6 镜的开场画面本来就在做，只是没告诉模型它们也是前面几镜推到头的画面。

- **认出来**（`StudioVideoBreakdown.markSameFrames`，拉片截完开场画面后跑）：整条原片按每秒 30 帧缩成 16×28 的灰度小图（推拉快的镜头里对得上的那一帧只停一瞬，每秒 10 帧会错过），每个镜头的开场画面去别的镜头里找最像的那一刻，距离（减去均值后的均方根）不超过 12 就记在那一镜上（`shots[i].sameFrames=[{at, shot}]`）。美食那条记下三处：第 1 镜 0.7 秒 = 第 4 镜开场（距离 7）、第 3 镜 4.7 秒 = 第 5 镜（6）、第 2 镜 2.9 秒 = 第 6 镜（8）；不相干的都在 22 以上。纯色、黑屏这类没有明暗变化的画面不比（标准差不到 10），整体亮度差 25 以上的不算；紧挨着的下一镜出现在这一镜最后 0.5 秒是正常接戏，不记。认不出来只是少一句提示，不挡拉片。
- **写进分镜脚本**（`stage-recreation-compile` 第 6 版）：这段里有那张开场画面的，素材列表下加一行「同一段画面：第1镜约 0.7 秒时的画面，就是第4镜的开场画面图N」，规则要求这一镜写清推到那一刻画面变成图N 的样子，两处是同一个人、同一份商品。不多出图、不多花钱。指向别的段、没做开场画面的不提。
- **检查也对照**（`stage-recreation-video-check`）：「第 1 镜（约 0.7 秒）：推到的画面是不是和图N一致」。

**没做**：退回远景（每镜结尾和开场的距离 21–24、和中间的 50–64，有差别但不够稳，没有自动写）；指向别的段的重复画面（要把那张图加进这一段的参考图）；拉片字段里的「镜内分拍、结束画面、把戏类型」（评审建议的下一步）。

## 直接看视频的拉片，代码拼制作方案（2026-11-09；2026-11-10 已发布 `20261110-recreation-197b6cfc`）

### 为什么改

线上 2026-11-07 至 11-09，AI 视频页一共受理了 12 条爆款复刻任务，只有 3 条做到了成片。其余卡在：

| 卡在哪 | 次数 | 原话 |
|---|---|---|
| 写分镜脚本 | 3 | 清晰度只能选 768p 或 544p（模型把方案写成了别的视频模型的规格） |
| 生成 | 2 | 参考视频最多 1 段，现在是 2 / 3 段（模型把几段原片塞进同一步） |
| 写分镜脚本 | 2 | 这一步的结果无法读取（模型写的整份方案解析不了） |
| 写分镜脚本 | 1 | 方案用到的素材已经不在画布上 |
| 生成 | 1 条任务 3 段 | 人像核验等待超时（Seedance Fast） |
| 分析参考视频 | 2 | 参考视频无法读取 / 用量到上限 |

做出来的 3 条也有问题：成片时长按页面默认的 15 秒出，不管原片多长；有一条没把原片当参考，只给了一张杯子图，原片的画面全丢了；素材用途靠模型猜（「请根据画面内容识别哪张是人物、哪张是咖啡」）；字幕写进视频提示词，让视频模型自己画中文。

拉片本身也有问题。它只看抽帧，不听声音：直播切片那条（41 秒一镜到底，笑点全在「抹上去三二一来 / 吸收了」的一问一答里）拉片写的是「未提供音轨，无法分析原片台词」，然后凭空编了一个 30 秒的新剧本。60 秒的片子要喂几十张图，一次 8–12 万 Token，超过额度直接失败。

### 现在怎么做

1. **拉片：整条视频交给能看视频的模型**（`StudioVideoBreakdown`，提示词库 `stage-video-breakdown`）。
   - 代码先做两件事：压一个代理视频（短边 640、10fps、单声道，60 秒约 3 MB），用 ffmpeg `scdet` 测出真实的切镜时间。
   - 模型看画面、听声音，一次写出：逐镜的景别机位、画面、逐字台词（谁说的）、烧录字幕、声音；段落结构（钩子 / 铺垫 / 反转…）；背景音乐；为什么能火（第几秒用了什么手法）；复刻时保留什么、要改什么（「原来是 X → 换成你的 Y」）、难点。格式参照茂隆给客户的拉片。
   - 真实切镜时间交给模型做参考。连续镜头超过 6 秒时，按动作和台词拆成几拍。代码把模型的镜头整理成首尾相接、覆盖全片的表，不判断写得对不对。
   - 再按所选视频模型的最长、最短时长，把相邻镜头拼成「一次生成」的段，只在镜头边界切；太短的尾段并进前一段，或从前一段挪镜头过来。每段真实裁出原片片段（沿用 `StudioFilmStudy.cut`）。
   - 输出仍是 `output.filmStudy`（多了 `breakdown`，`strategy = video-understanding-v1`），画布、视频页、对话助手都照旧读得到；`output.text` 是整份拉片文档。
2. **制作方案由代码拼**（`StudioRecreationTaskPlan`，只用于 AI 视频页的复刻任务）。
   - 分段、每段生成秒数、模型、清晰度（页面带来的这个模型没有就用合同第一档）、画幅、模式（有参考的模式优先）全由代码定。每段带哪些素材也由代码定：图 n = 用户的人物（排前面）和替换素材，音频 = 声音，都按合同的数量上限截；没有替换素材就按文字出片。**原片片段不交给视频模型**：2026-11-09 真实出片时 H3 带上原片这一段，就照着把原商品（米酒罐）、「未成年人不得饮酒」水印和原片字幕全画了出来，用户的杯子一次都没出现，提示词写了「不参考商品外观、文字和水印」也不管用。所以原片的场景、光线、景别、动作、节奏都写进逐镜提示词，片段只留在画布上给人看。
   - 模型（提示词库 `stage-recreation-compile`）只写每段的提示词和这段要加的字幕：分镜表每一行写成一镜，台词逐字写在说的那一镜，原片要换的人和物统一写成替换后的样子，画面里不许有字。原片的品牌名、商品名换成用户的，用户没给的价格、销量、功效数字删掉不编。
   - 代码拼出的方案和以前模型写的方案走同一个 `StudioPlanValidator.validateSkillPlan`、报价、指纹。少写了哪一段的提示词就整份判失败（`AI_BAD_OUTPUT`），不拿拉片原文顶替。
   - 多段时最后一步合成成片，字幕在合成时按成片时间叠上（`assemble` 的 `settings.captions` → `Packaging.captions`）。
3. **页面**：选好参考视频后，时长自动按原片长度设置（用户改过的不动）。

没有绑定视频理解模型时，拉片照旧抽帧读图；没有逐镜拆解（`breakdown`）时，「写分镜脚本」照旧让模型写整份方案。这两条都是真实的分析方式，不算降级产物（AGENTS §8.0）。

**用线上默认文字模型 Terra 写提示词（2026-11-09 晚，OneToken 充值后）**：直播、门店、美食三条，拉片用 Seed 2.0 Lite，写提示词用线上那个接入点的 `gpt-6.1-terra-official`（流式、思考强度 low，与线上配置一致），三轮都通过方案校验。写提示词每条 8–28 秒、4–13k Token。第一轮暴露的问题和改法：

- 模型这次没把 41 秒的一镜到底拆成几拍，代码均分成 3 段，每段镜头表里都是全部台词，Terra 只能猜哪句归哪段。现在拉片每句台词带开始时间（`at`），超过 6 秒的连续镜头由代码在两句台词之间切成几拍（`StudioVideoBreakdown.beats`，没写时间的按字数估），每段的镜头表只放这段里开始说的台词、时间截到段内。第二轮 41 秒切成 9 拍 3 段，台词逐段对上原片。

- 原作者的抖音号被写进字幕。规则不复刻原作者账号和平台片尾，代码再过滤一遍（`StudioRecreationTaskPlan.ORIGINAL_ACCOUNT`）；同一句字幕跨段时合成一条。

- 原片对原商品的研发背景（「法国和瑞士的抗老中心共同研发」）被安到用户商品上。规则改成产地、研发机构、成分、认证、数字这类说法用户没给就改成不带具体事实的说法或不写；第三轮已改成「这是新商品，对不对？」。

**真实出片（2026-11-09 晚，H3 768p 9:16）**：拿线上一条已出片的复刻任务做对照（`PEX-2475364dedf44a63b9a8`，24 秒米酒带货混剪，用户要「产品换成我的杯子、文案结构不变」，只传了一张木柄白杯的照片）。线上旧片 `mvj_968a42653dac` 只出了 15 秒，没带原片做参考。新流程切成 11 秒 + 13 秒两段。

| 做法 | 结果 |
|---|---|
| 每段带上原片这一段 + 杯子图 | 两段都失败：H3 照着原片画出米酒罐、玻璃杯、「未成年人不得饮酒」水印和原片字幕，用户的杯子一次都没出现。每段约 10–12 分钟 |

## 片段解析与拉片（2026-10-15本地实现）

2026-10-15重新核对用户提供的小云雀工程：示例说明明确从「素材拆解 → 拉片」进入，画布同时包含全片创作拆解、人物形象、风格参考、BGM原声和各片段。其片段1时间范围为0–3.8秒，内部镜头表又分0–1.8秒和1.8–3.8秒。因此「片段」是可包含多个镜头的叙事段落，不等于单个切镜，也不等于模型看图的分页。

本轮接通全片之后的片段解析，验收流程和真实产物，不以模型叙事是否符合恐龙范例作为通过条件。保留现有「解析」入口；「拉片」作为独立操作，复用已有全片解析上下文，已有正文保留用户编辑，不在打开文档时自动启动新任务。

- 画布组织：原片 → 全片拆解分组；原片 → 片段1、片段2……，每段一组「可播放片段视频＋镜头拆解Markdown文档」。
- 分段：基于画面变化候选及全片内容形成连续时间范围，镜头可组合成叙事片段；不固定按秒均切，不把每次闪电直接当成切镜。时间范围由真实视频时钟承载，手动调整分段留待后续。
- 每段文档：标题与原片时间范围、镜头构造表（时间/画面骨架/摄影机/调度构图焦点）、段落表达（叙事要素/视觉变化/剪辑节奏/声音）、视频生成Prompt。继续复用剧本Markdown编辑器。

- 任务：确认后关闭小面板，进度留在画布；允许失败片段重试，不重跑已完成全片；刷新不重复建节点，编辑可保存导出。

## 输入与报告

第一版支持60秒、128MiB以内的视频。服务端先校验本人项目/视频key、实际时长/画面、视觉模型、提示词和按量售价，再经原Studio链受理。当前直接调用固定版本Hypit媒体模块，以低分辨率解码全部原始视频帧，保留原始PTS，优先保留明显视觉变化前/当时/后的画面，再补齐长时间空档，最终1至64张分析帧。每页最多8张较大画面分段读取，汇总时附上未拼格的真实尾帧独立复核结尾。亮度变化单独标记，不直接视作切镜；超过预算优先保留强变化，不能保证分析覆盖每一帧。时间为近似定位，不是切镜点；不读取音轨，也不提供逐镜拉片。

| 部分 | 内容 |
|---|---|
| 创意命题 | 可见事件及显式标注的主题解读 |
| 视觉基因 | 媒介与美术风格、色彩、光线、材质与后期、构图、摄影机六项 |

| 创作骨架 | 时空/镜头组织、影像与声音边界、叙事动作三项 |
| 核心创作手法 | 画面实例、作用解读、可迁移做法 |
| 分析边界与建议词 | 身份/连续动作/声音不确定性，以及反推的可编辑创作提示词 |

报告字段由 `packages/types/src/ip-studio-workflow.ts` 定义。画面事实 `observed`、复刻规律 `rule` 与手法作用 `effect` 分开。每项视觉基因、骨架与手法须引用本次真实帧编号；服务器附加真实来源与采样时间，拒绝模型编造来源；无效帧编号隐藏并注明定位不确定，不因单条引用失败丢弃整份分析。提示词在 `prompts/material/dap.ip_studio_recreation.md`，后台Prompt管理沿用默认资源与版本管理；不把验收范例或“幼崽/复活”结论注入实际模型请求。

## 段长约束 `maxSegmentSec`（2026-10-18，本地实现，未发布）

`operation=recreation, mode=segments` 请求可带 `recreation: { maxSegmentSec: number | "model", videoModel }`。`model` 在服务端读所选视频模型合同的最长秒数（H3 为 15），显式秒数不能超过它；有效上限与合同快照写入 `_exec`。约束接在 `StudioFilmStudy` 既有的「有限段数、连续、覆盖片尾」校验处：超过上限的段按叙事边界再切或裁切后再切，重新验证覆盖与实际时长；无法同时满足段数、时长与覆盖 → 400 `STUDIO_SEGMENT_TOO_LONG`（带冲突段与上限），不冻结。旧调用不带该字段时行为不变。全能创作的 `analyze_video` 工具固定传 `maxSegmentSec: "model"`。

## 2026-10-17 · 仅显存拒绝时分批读取（2026-10-19 合入 main，未发布）

> 与线上缩图降档的关系（2026-10-19 合并时确定）：拉片调用遇到同一显存拒绝时，先用同一批画面按 1600 → 1024 → 640 缩小重试（`StudioVisualContext.BUDGET_EDGES`，2026-10-18 已上线并实测 640 通过）；只有缩到最小仍被拒，错误才交给下面的原尺寸分批读取。两者都不丢帧、不换模型；判据统一为 `AiChatHttpException.isVisualMemoryRejection`。

解析与拉片首先保持原调用：原图片、参数、模型不变。只有供应商真实响应同时满足 **HTTP 400**、`error.code=unsupported_geometry`、`error.message=visual activation/HBM headroom budget` 时才启用分批读取。判据来自结构化响应，不匹配用户提示词、通用`AI_CALL_FAILED`或日志字符串；超时、429、5xx、其他400、其他geometry原因均原样失败，不进入该路径。

降级按本次调用涉及的原片时间从原视频惰性解码，保留源画面尺寸，每批最多两帧串行读取，然后用文字观察记录完成原来的分段规划/文档输出。每批独立请求，不携带此前图片历史、不换模型、不额外缩小拼图、不丢弃本次相关帧；全局帧号与时间由程序维护。批次仍被拒绝或出现其他错误时立即停止，不递归改规格或重试。

成功调用沿用原任务的Token费率与冻结预算统一累计；每次派发前检查剩余预算，分批观察和最终汇总都计入。解析入口聚合一次降级中的各次用量后交给原结算路径，拉片逐次累计。分批观察不附加用户的全片写作要求，写作要求仍保留在原调用和最终汇总，避免观察JSON被改成报告正文。

拉片将拒绝原因、已完成批次及暂未物化的汇总写入原任务检查点。显式继续时只复用同一端点/模型、提示词、原请求图片及帧序列匹配的检查点；已完成片段仍按原逻辑跳过。父步骤物化后清除重复缓存，避免重复存储大段Markdown。全片解析保存过程检查点供取消与排障；本次未增加新的跨任务继续入口。
