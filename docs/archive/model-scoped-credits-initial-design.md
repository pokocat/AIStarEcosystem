## 产品约定

2026-10-25 按用户最新要求收敛：后台赠款和折扣优先按模型配置，例如「H3 · 全部规格」，不让运营逐一配置清晰度、画幅和参考素材组合。任务内部仍记录实际规格与渠道，防止串模型或追加扣费。先完成核心闭环，不增加复杂配置入口或重复细查。

用户以平台积分理解价格。正常价格、客户优惠、专享额度和供应商资源各自独立；专享额度不加入通用钱包余额，不能提现、退款或转账。采购折扣不等于客户折扣。现有积分面值和历史余额不迁移。

计费顺序：模型规格标准价 → 一条适用客户优惠 → 按最早到期的匹配批次抵扣 → gift / license / recharge。每次报价显示原价、优惠、专享额度和普通积分；仅用免费额度时，补差非零则拒绝受理。工作流按实际收费步骤匹配，免费图片不能抵扣文字、视频或合成费。

用途由服务端确定：appCode、action、endpointId、providerModel、specKey、unit。缺用途明确不适用，不能按用户提交的 endpoint 字符串直接赋予资格。渠道与规格不可静默替换。价格、折扣和范围在受理时快照，后续修改不影响已受理任务。

客户折扣指定个人或企业，也支持活动期间全体客户。同一收费项不叠加多条优惠，取适用的最低成交价，平价按稳定 ID 决定。未配置优惠保持标准价。折扣不改供应商资源用量。

活动单独控制发放总额、每个付款钱包累计发放额、全活动实际资源量、每人每日资源量及同时进行任务数。一个资源池只使用一种物理计量单位，不将张数、视频秒、Token 相加。每笔赠送到期不晚于活动结束。活动资源不足时不能静默补扣客户普通积分。

## 账务与并发

批次余额与冻结分配是唯一账务真值；任务只保存不可变快照和引用。普通钱包 pending 仅统计普通积分冻结，专享额度冻结单列。每条专享流水关联 grantId，balanceAfter 表示该批次可用余额，不能混成通用余额。

锁顺序沿用企业 → 钱包 → hold，再按 ID 排序锁活动、批次。发放及到期任务也遵循钱包 → 活动 → 批次。相同业务引用重放校验付款人、用途、金额；相同发放来源编号只能入账一次。失败整笔回滚。

部分成功按累计真实费用结算，再求本次差额，避免逐张/逐段取整重复收费。优先消费专享额度，普通余额的未用冻结原路释放。到期的批次释放后记过期流水，不能复活。供应商资源预占与客户结算分开：未派发可释放；已派发但供应商用量不确定则保留资源占用，不能因退款复活上游资源。

`MaterialVideoBilling` 从受理时解析的渠道、实际模型、模式、清晰度、画幅、各类参考素材数量和计量方式构造专享范围，不记录素材 key/提示词。原生视频与明确按秒的候选保留秒价，内部短剧等按条定价保留按次，按次范围额外限定请求时长。DAP 子任务仍由父 DapJob 持有原收费，不能在子视频重复收费；其他登录用户的零价视频返回 `MODEL_PRICE_NOT_CONFIGURED`，免费需由有价任务使用有限专享额度实现。

新接入的收费视频（含个人默认渠道）在受理时固定 endpoint、调用地址、视频协议规格及计费用途。派发前核对实际 endpoint/model/address/spec 未变，先在同一事务中写路由、标记供应商资源已派发再发送。已派发后用量未知时，客户退款仍按原来源退回，但供应商预占保守记为已用，不能被退款复活。成功按原冻结的累计用量与折扣快照结算，新价格不追溯。

轮询故障保留原冻结/供应商 ID，只查询原任务。尚持有原冻结的管理端恢复也沿用它，旧且没有模型快照的历史恢复保留原规则。**模型快照存在但原冻结已释放**时，当前返回 `VIDEO_MODEL_RECOVERY_REQUIRES_REVIEW`，阻止用当前优惠/新批次重新扣费；原来源恢复流程尚未实现，不能把这个保护当作恢复功能已完成。后台视频已提供按模型的全部规格选项，用户报价确认仍待接入；旧基础价为零时暂拒绝受理，新价格表启动这类入口需在统一报价时一并接入。暂不发布。详细本地数据库/服务验证见 [视频计费增量验证](releases/model-scoped-credits-video-validation-20261025.md)。

## Studio 图片报价与确认（2026-10-25，本地，未发布）
