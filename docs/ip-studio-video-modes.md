# Studio 视频模式

2026-10-08，v0.208，本地未发布。界面沿用 Studio 的纸白、群青和麦黄；功能参考 LibTV 视频节点的明确首尾帧与参考素材交互。本次没有提交收费生成，厂商成片效果未新增验收。

## 使用流程

在 Studio 视频创作面板选择支持原生模式的模型，可选文生视频、首帧、首尾帧或全能参考。首尾帧分别从画布图片选择，可以交换位置。全能参考使用画布图片、视频与音频，同类素材按选择顺序标为图1、视频1、音频1，可在提示词中描述用途。人物图片继续使用同一 IP 人物库。

清晰度、六种画幅、整数时长、随机种子与报价来自模型合同。未定价或缺少必要素材时禁用提交。切换到只支持单首帧的模型保留已有选择，多余素材需由用户明确移除。原生画布视频节点的连线缩略图显示首帧/尾帧或参考编号；参数面板只显示所选模型支持的模式。

模式切换共用当前素材选择：首尾帧 A/B 切为全能参考仍是 A/B，交换后是 B/A，人物库替换尾帧 C 后是 A/C。全能参考暂时转为帧模式时保留其他参考；再返回时，图片、视频与音频仍按原顺序显示。切到旧模型后明确删除或替换的素材，以修改后的列表为准；回到首尾帧模式若缺尾帧，保持空槽并提示补选，不恢复已删除的旧素材。

## 实现边界

- `GET /v1/ip-studio/studio/video-models` 返回已经配置且支持 H3 原生规格的模型合同和定价，复用现有 `VideoStudioModel` 类型。
- `StudioRunRequest.video` 与 `IpVideoRequest.video` 明确传模式、清晰度、种子、首尾帧和参考 storage key。没有客户端定价或原样透传 `variant_config` 的路径。
- `StudioVideoService` 校验素材归属、实际文件格式、大小及音视频可读性。帧图限 16MiB；全能参考使用既有厂商合同限制；每段参考音频 2–15 秒、合计不超过 15 秒。
- 复用 `VideoStudioService` 的模式、规格、组合限制和价格，服务端计算总价后写入原 `MaterialVideoJob(ipstudio)`。费用上限上涨先拒绝，原任务的进度、结果和结算仍是唯一真值。
- 素材运营入口继续拒绝原生规格；Agnes 等旧协议保留文字或一张首帧兼容。测试响应不冒充原生模式。
- 本地新增已有 H3 配置作为可选候选，默认 Agnes 和生产配置未改。此次没有实际请求 H3 生成。

多候选视频已在 v0.210 接通（本地未发布，详见下文）。五分钟长视频、运镜/特效预设仍待实现。模型支持的原生参数不等于已复刻 LibTV 的全部视频能力。

## v0.210 多候选视频（本地，未发布）

Studio 视频抽屉与原生画布视频参数面板均选择 1、2、4 条候选，数量与图片张数独立。提交前展示整批积分、条数和单条积分；原生模式的参考附加价与按秒模型使用同一报价规则。指定种子时第一条用原值，后续按序递增，超过上限回到 0。重新打开视频创作时，使用节点当前模型、数量、画幅、清晰度、时长及实际连接的参考顺序；断开的参考不会从旧请求恢复。手机总价与提交控件固定在同一区域，避免滚动时被遮挡。

原生节点也通过 `studio-runs` 提交：先保存包含精确请求与幂等编号的画布，未知网络结果保留该编号；刷新由 Studio 运行投影恢复，确认原任务不重复生成。旧 `generate-video` 单任务与单 Job 绑定继续兼容。

服务端整批准备规格、逐项 preflight 后，由原 `MaterialVideoJobService.submit` 一次受理。`maxCost` 是整批上限，拆到每条 Job 后再次守价；所有 worker 在事务提交后派发。Studio 运行只是不可变的 Job ID 绑定，不复制状态或创建第二份结算。停止只允许整批候选仍 queued，任一已提交时取消全部回滚。

返回 `output.videoCandidates`：固定 index、Job ID、running/done/failed、进度、key、短期 URL、时长和失败原因。任一活跃时批次仍生成中；全部结束、部分成功时标明部分完成并保留成功结果；全部失败才为失败。已采用的旧视频保留；比较窗口同时展示等待、失败和成功候选，只允许采用成功版本，切换采用后保持窗口方便比较。

原生版本箭头只在成功且有镜像 key 的候选间切换，等待与失败仍保留在比较窗口。删除采用版本时只切到另一条成功视频，最后一条可用采用禁用删除。原生和比较窗口采用共用同一状态闸，并标记下游输入已变更。就地重新生成保留采用媒体、分集、顺序和成片设置；等待或失败时旧播放器仍显示，并标明本批状态。

两处普通生成入口均由已保存的请求状态约束。活跃批次只能查看或等待原任务，受理未知改为“确认原任务”，使用原编号及原正文恢复；已知运行直接读取其状态，网络失败不解锁新编号。确认既有原请求时，本地保存失败也保留待确认状态、原编号与正文；首次提交尚未发出时保存失败，才可按未提交处理。只有明确终态失败或未受理拒绝后，才可显式修改参数发起新一批。

界面验收使用隔离本地项目和既有成片验证状态/采用，明确标记为交互样例；不是本轮新生成结果。新增收费生成 0。真实供应商多条成片效果不属于此次验收范围。详见统一验证记录 §21。

## 台词保护、厂商改写记录与首尾帧意图（2026-10-20，本地未发布）

起因（线上 2026-10-20 15:39，任务 `mvj_2ba339734773`，只读核实，未确认就是投诉那条，也没有逐帧审片）：
- **不是「没有提示词优化」，是厂商自动优化删了台词**。聚算 H3 公开契约：四种模式的生成请求**默认先改写提示词再出片**（`optimizePrompt` 缺省开启，最多四次模型调用按 token 单独计费；显式 `false` 完全跳过、不收优化费；已手动优化的提示词应传 `false`）。改写发生在付费任务**受理之后**。那条任务的改写结果是英文结构化描述，中文对白只剩开头两个字 —— 原文表情说明里又用引号引用了那两个字，改写器把它当成了全部台词。
- **首尾帧没有用上，是因为请求里本来就没有图**：描述里写了「图1」「图2定为尾帧」，但节点模式是文生视频、没有连线，前端到厂商一张图都没带。写在文字里的「图1」不会绑定图片。

本地做了什么：
- **按原文生成**（`StudioVideoSettings.optimizePrompt=false` → `VideoGenSpec.optimizePrompt` → variant_config `optimize_prompt` → 聚算请求体 `optimizePrompt:false`）。只对 `supportsPromptOptimization` 的模型（聚算 H3）显示，别的模型带着它 400 `STUDIO_VIDEO_OPTION_UNSUPPORTED`，老路径 / 非聚算协议带着它 400 `VIDEO_MODE_UNSUPPORTED`，不静默丢。默认不勾（保持厂商默认），价格不变。节点重开时从这条节点已受理的请求恢复，不从模板预设读。
- **厂商实际用的描述**：worker 每次轮询把 `promptOptimization`（状态、来源、`effectivePrompt`，没有就读 `optimizedPrompt`；记录号与版本只留库排障）写进任务 `payload_json.vendor_prompt`（只读旁路，写不进去只 WARN，不影响出片与结算；任务卡 `toCard` 不外露）。画布视频候选投影 `promptRewrite{state:off|running|done|failed, prompt?}`，解析 / 留存 / 投影只在 `VideoPromptRewrite` 一处。不用新迁移。
- **事后核对台词**：前端 `studio-video-prompt.ts` 是唯一的识别规则 —— 「名字：台词」「名字说：“台词”」「台词 / 旁白：……」算台词，「表情 / 镜头 / 切镜与声音 / 图1……」这类说明标签和带数字的标签不算；引号里的整段取全，没引号取到第一个句号。成片后拿原文台词逐个分句去比厂商描述里的 `<d>…</d>`（没有标记就比全文），漏掉的在三处说：创作面板「上次出片前，模型改写描述时没有保留台词……」+「看模型实际用的描述」、任务列表一行提示、「本次创作输入」里的实际描述与丢失清单。**这是成片之后的解释，不是生成前的拦截**，文案也这么说。
- **生成前**：面板识别到台词时提示一次「识别到 N 句台词：……要一字不差，可以勾选「按原文生成」」，不阻止生成；不默认再叠一层付费的智能优化。
- **首尾帧意图**：提交前（存文档、冻结、请求之前）如果最终提示词写了「图N / 首帧 / 尾帧」而请求带的图片不够（或首帧模式却写了尾帧），弹一次确认：「仍按文字生成」/「改用「首尾帧」选图片」/ 关闭。后者只切模式并展开参数、焦点落到首帧位，**不替用户挑图**；没有能用图的模式就只引导去选模式。「地图 / 截图2 / 构图」之类不算；同一段描述 + 同一模式答过「仍按文字生成」就不再问。
- 视频生成区（带货）：用了「智能优化」结果的生成请求带 `optimizePrompt=false`（契约要求，原来会被厂商再改写一遍并再收一次厂商优化费）；换成不会改写的模型则不带。

验证（本地，库副本 + 模拟聚算，不连真厂商、不花钱）：服务端 `VideoGenSpecTest`、`VideoPromptRewriteTest`、`MaterialVideoModelClientBodyTest` / `WireTest`（真实 HTTP 层请求体与查询响应）、`MaterialVideoWorkerSpecTest`、`MaterialVideoJobServiceStudioTest`、`StudioNativeVideoProjectionTest`、`StudioVideoPromptRewriteTest`、`VideoStudioServiceTest`；前端 `studio-video-prompt.test.ts`、`studio-video.test.ts`、`studio-video-prompt-notes.test.tsx`、`studio-video-prompt-wiring.test.ts`。浏览器走了三条路径：默认生成（先弹首尾帧确认 → 仍按文字生成 → 请求与线上同形、成片后三处显示丢失的台词）、勾选按原文生成（请求带 `optimizePrompt:false`、候选标「按原文生成」）、自己选好首尾两张图（不再弹问，请求带两个 assetId）；测试账号 3 条共扣 960，价格不变。

Codex 复审（2026-10-20，提交 47c057ea 之后）修了三处：
- **共用视频胶水也认这两件事**：`canvas-bridge/video.ts` 的 `createVideoGenerationTask` 接 `keepPrompt`（调用方用 `studioVideoKeepPrompt(node)` 从节点上次已受理的请求取，与重开面板同一条规则）和 `confirmFrames`（描述点名的图片没带上时问用户；没给回调就不提交，抛 `VideoFramesNotBound`，不保存、不扣费）。搬来的旧画布页（`canvas/pages/canvas/project.tsx`，目前没挂到任何路由）的生成与重试都经 `completeVideoNodeTask` 传入这两项，问法走 `confirmStudioFrames`（只有「仍按文字生成」才提交，关闭算返回）。Studio 面板的「重新生成」原样重发节点上保存的请求，`optimizePrompt` 跟着走。
- **记录改写结果不再整行保存**：同一事务里锁行、刷新后读当前 payload，只更新 `payload_json` 一列（`MaterialVideoJobRepository.updatePayloadJson`）。旧写法 findById 后 save，会把管理端对账同时写好的 succeeded、成片地址、完成时间盖回 generating —— `MaterialVideoPromptRewriteRaceTest` 用真 H2 和门闩复现过（旧实现失败、新实现通过）。只锁任务这一行，不碰企业账户锁，与结算的加锁顺序不成环。
- **建议的模式按首尾帧语义和容量选**（`studioFrameTarget`）：写了首帧 / 尾帧就只在带对应槽位、又放得下这些图的模式里选；只写尾帧推荐「首尾帧」并提示还要一张首帧，绝不把尾帧当首帧；没写首尾帧的「图1…图3」推荐能放下的参考模式（全能参考），不再推荐只有两个槽的首尾帧；要锁首尾帧却放不下这么多图时，改用参考模式并明说这些图只作参考；哪个模式都放不下就不推荐，说清最多几张。

还没验证的（需要真实付费）：`optimizePrompt=false` 时 H3 是否把中文台词完整说出来、口型与画面质量是否下降；把台词写进引号能否让厂商改写器保留整句。默认值是否改成按原文，要等这组付费对比之后再定。厂商改写器丢台词是厂商侧行为，需要反馈给聚算。
