# 灵感库：开箱即用的官方示例

> 现行真源（2026-11-05，2026-11-09 改画布结构）。对应代码：`scripts/inspiration/`、`apps/web-aiavatar/src/ip/studio-template-use.tsx`、`studio-template-market.tsx`。

## 用户看到的

1. 新版左侧导航有「灵感」，排在「首页」后面；旧版顶栏本来就有。手机新版在「我的」里。
2. `/templates` 默认显示案例，可以按视频、图片筛选；官方模板和我的模板还在。
3. 点开一张是一个弹窗，不占满屏幕：左边放示例效果，右边是规格和需要准备的素材。**预览不显示提示词**（用户 2026-11-06 要求），只读画布点开节点也不显示，做同款后的画布里才有。工作流模板没有成片时，左边放只读画布、右边列创作步骤；有成片的也能点「查看画布」切过去。搜索范围包括提示词。
4. 点「做同款」才复制一份到自己的画布并进入画布页。不扣积分，生成时才扣。
5. 画布原样展示这条示例的生成链，和官方模板一样（2026-11-09 起，见下「画布结构」）：参考图（有的话）连到生成节点「成片」或「成图」，生成节点里放着提示词和生成结果；旁边是创作说明。助手打开，输入框里预填要求并绑定方法，开场写「要求已填好」，发不发由用户决定。

## 内容从哪来

`scripts/inspiration/catalog.mjs` 一共 35 条，一条对应一张官方示例画布。

- **素材**是我们自己生成的 `ai_sample.*`（本机 `resources/skills/covers/by_skill_id/<skill>/`，目录未入库）。
- **文字是我们自己写的**：名称、一句话说明、做法要点、提示词。参考了 `resources/skills` 里技能的用途，但不收录原文。这些技能是从 Flova 下载的第三方内容（`scripts/flova-skill-sync.mjs`），带作者信息；原文里的分组、资产、`AGENTS.md`、指定模型在 Studio 里也没有对应物，收进来用户用不上。这和 [`releases/studio-inspiration-cases-20261103.md`](releases/studio-inspiration-cases-20261103.md) 的做法一致：参考类型，不搬运内容。

写条目时的约束（`apps/web-aiavatar/src/ip/inspiration-catalog.test.ts` 守着）：

- 提示词不写比例和时长。画布按节点设置生成，描述里写的和设置不一致会被拦下来确认。
- 提示词不写「做同款」「复刻」「原片」这些词。助手会把它当成照视频复刻，改走素材清单。
- 不出现第三方品牌和模型名。第三方技能名里的品牌（如丝巾风格那条）已改名。
- 示例里的人像用韩系风格，不要外国面孔（用户 2026-11-05 要求）。`one-take` 的示例出现了外国面孔，标了 `hold: true`，发布后保持下线，换素材后再上线。

## 灵感墙（2026-11-06）

首页的灵感区和 `/templates` 共用一个组件（`src/ip/inspiration-wall.tsx`，样式 `styles/inspiration.css`）。用户要求：Pinterest 式瀑布流、倒序、滚动继续加载、不要像管理工作台。

- **不裁图**：卡片按作品的真实比例（`templateRatio`：成品量到的尺寸 → 像素尺寸 → 设置的画幅）。写不出来的先按 4:5 占位，图到了再按图改高度。没有成图的模板是一张白纸，写着有哪些步骤。
- **摆放**：一张一张放进当前最矮的一列（`inspirationPlacement`）。结果只跟前面的卡片有关，滚动加载时已在页面上的卡不会动。
- **顺序**（`inspirationOrder`）：新发布的在前，比日期，同一天的一批按运营排序，否则一批示例会整个倒过来；有成图的排在只有步骤的模板前面；内置模板没有发布时间，排最后。
- **分页**：接口一次给全部，页面一次摆 18 张，快到底再摆下一页，不一次加载几十张大图。
- **样子**：作品不加框不加底，名字用衬线字放在图下面，像展签。指针移上去作品浮起、微微放大，视频开始播放，右下角出现「做同款」。分类和搜索吸在顶上（手机不吸）。去掉了卡片说明、数量角标、刷新按钮和「开始创作」。
- 超管的「设置封面」、本人模板的「停用 / 重新启用」不占版面，指到作品上才出现；手机常显，设置封面只留图标。

## 怎么发布

```bash
STUDIO_TOKEN=<超级管理员令牌> node scripts/inspiration/publish.mjs --base <后端地址> --skills <resources/skills 目录>
```

- 走现有接口：上传素材 → 建画布 → 保存为官方内容（`kind=example`，素材复制到 `ipstudio_demo/<demoId>/`）→ 设封面和排序 → 删中转画布。不调模型，不扣积分。
令牌从已用超管登录的 Chrome 控制台取，不写进命令历史（2026-11-06 线上就是这样发的，令牌过期或复制错会报 401）。**要在 Studio 所在的 aiavatar.aibuzz.cn 标签页里取**：登录信息按网站分开存，在别的页面执行只会复制到 `null`（2026-11-09 踩过）：

```js
copy(localStorage.getItem('aistareco.auth.token'))
```

```bash
STUDIO_TOKEN="$(pbpaste)" node scripts/inspiration/publish.mjs --base https://aiavatar.aibuzz.cn --skills <resources/skills 目录>; pbcopy </dev/null
```

Claude 桌面应用的内置浏览器不让线上页面读本机文件（`ERR_BLOCKED_BY_CLIENT`），所以不能在已登录的页面里直接发。

- 编号固定（`IPD-insp-<id>`），重复执行不会多出新条目。已发布的默认只更新名称、说明、排序和上下线。`--only a,b` 只发几条，`--dry-run` 只检查文件。
- **`--force` 才换素材和提示词，线上慎用**：服务端发布时会删掉旧版素材副本，而用户做同款得到的画布引用的正是这些文件，他们画布里的示例结果会打不开（提示词不受影响）。只是按新结构重排画布、不换素材时，用下面的 `--rebuild`。
- 排序从 100 起，排在已有官方示例后面；要调整到「官方内容管理」（`/projects/demos`）改，上线下线也在那里。
- 上传的素材会留在发布账号的资产库「灵感库示例素材」文件夹，发布后可以删掉，示例用的是复制件。

## 实现要点

- **做同款去哪**：`studioTemplateCopyHref`。画布里有 `metadata.studioStart === 'assistant'` 的节点就带 `?start=assistant`。这个节点是「创作说明」，`prompt` 是预填给助手的话，`studioSkill` 是方法（`image-generation` / `video-generation`）。
- **工作台**：多节点画布原本不响应 `?start=`（防止刷新后重新进入创建流程）。这里放开「开始节点就在画布上、且是助手」这一种；助手只在对话为空、输入框没字时才填，所以刷新不会覆盖用户的内容。
- **示例节点**标 `origin: 'example'`，不显示「你上传的」。
- **选填的素材位**：空图片节点带 `studio.templateInput.required = false`，连线留着，但 `studioLinkedNodes` 不把它算参考、也不挡生成，放了图才算。必填的空位照旧拦下。发布时只保留这种选填标记，必填约束仍由版本化模板的配方写入。
- **海报变动态、多宫格生视频**的参考图就是生成示例用的那张（同样复制进示例目录），连在生成节点上，不传也能直接出片。
- **路由修复**：`StudioSkillRouter` 把「不出现其他文字」「手写标题」读成写稿，模型复述提示词时会把出图切到写剧本与文案。现在 `出` 不含「出现」、`写` 不含「手写」。
- **服务端修复**：`publishFromProject` 发布实例时不分节点类型删 `content`，文字节点的正文也被删了。现在只删媒体节点的（§8.0.1 ⑪）。线上已有的 13 个示例不受影响，它们的文字节点此前就是空的，要补需要重新发布。
- `previewVideoUrl`、封面、悬停播放沿用 2026-11-04 的实现。视频示例额外传一张中段静帧做封面。

## 画布结构（2026-11-09）

用户反馈：做同款进画布后看不出工作流怎么走。原来的画布是「创作说明 + 我的素材 + 我的版本（空卡，提示词已填）+ 示例效果（一张不连任何东西的结果）」，海报变动态、多宫格生视频的参考图连的是空卡，结果反而孤零零放在一边。用户要的是和官方模板一样，把参考图、提示词、生成结果原样放在画布上，不做区分。

现在 `buildDoc` 出的画布：

- **创作说明**（文字，带 `studioStart: 'assistant'`），不变。
- **参考图**（`input`）：`input.sample` 是生成这条示例实际用的参考图（海报变动态、多宫格生视频两条，核对过首帧一致），标题叫「参考海报」「参考宫格图」，连到生成节点。没有 `sample` 的是给用户放素材的选填空位（「我的商品图」），同样连到生成节点，空着不挡生成。
- **生成节点**（`result`，视频叫「成片」、图片叫「成图」）：提示词、规格和生成结果在同一张卡上，版本列表和平常生成出来的一样（`images[]` / `videos[]` + `primaryImageId` / `primaryVideoId`）。多个示例是同一张卡的几个版本（开箱测评两条）。用户在这张卡上改提示词再生成，新结果是新版本，示例那版留着。
- 不再有「我的版本」和「示例效果」两张卡。

`template-facts.ts` 跟着改：规格、提示词和比例先看「提示词和结果在同一张卡上」的生成节点，参考图没有提示词，不算；首帧 → 成片这种链取视频。

**素材的来历，要和用户说清楚**：示例结果是 2026-11-05 在本地 Trae 里用它的生图 / 生视频工具按技能描述生成的，每次调用的提示词、尺寸和参考图都记在 [`scripts/inspiration/generation-log.json`](../scripts/inspiration/generation-log.json)（从 Trae 分享页导出，36 次调用，和 catalog 的 36 个素材一一对应）。只有上面两条用了参考图，其余 34 次都是纯文字生成，本来就没有参考图，画布里也就没有。生成节点里现在放的是我们按规则重写的中文提示词（不写比例、品牌），不是当初的原话；原话在这份记录里。要让这些条目也有「参考图 → 结果」，只能在线上用真实画布重新生成（2026-11-03 那批就是这么做的，见 [`releases/studio-inspiration-cases-20261103.md`](releases/studio-inspiration-cases-20261103.md)），要花积分，见 TODO。

### 按原素材重排（`--rebuild`）

```bash
STUDIO_TOKEN="$(pbpaste)" node scripts/inspiration/publish.mjs --base https://aiavatar.aibuzz.cn --rebuild --dry-run
STUDIO_TOKEN="$(pbpaste)" node scripts/inspiration/publish.mjs --base https://aiavatar.aibuzz.cn --rebuild; pbcopy </dev/null
```

- 读线上 `GET /demos/examples` 里这条示例现有的画布，取出生成结果和参考图的 key（`publishedAssets`，认重排前后两种画布），按新结构重排后经现有接口重新发布到同一个编号。**不上传、不调模型、不扣积分**，不需要 `--skills`。
- **先发服务端**：`publishFromProject` 现在把已经在这条示例目录（`ipstudio_demo/<demoId>/`）下的素材原样留用（`copyKey`），不再复制一份再删旧文件。旧版服务端会复制再删，用户做同款的画布里的结果就打不开了。脚本每发一条都核对素材 key 是否原样，有变化就停下、不再发后面的。
- 下线的条目（`one-take`）读不到线上画布，跳过；它换素材时用 `--force`。
- 用户此前做同款得到的画布不会变（复制出去的是那时的画布），新做同款的才是新结构。
