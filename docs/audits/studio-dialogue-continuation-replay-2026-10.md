## 修改

- 普通文本与单轮对话累计额度分开，默认输入 1048576 / 输出 65536；沿用同一模型单价。
- 「继续」授权由服务端根据本人同一画布、同一线程的已结束受限 run 与真实用户消息判定。请求不能直接传标记，模型文字不能授予权限；遇到新的用户任务即停止沿用。
- 确认继续的 run 保存 `_exec.continueUntilDone=true` 与 `continuationOf`，原任务和已经完成的操作加入恢复上下文。继续期间保持同一循环、同一父 run、同一助手回复与同一费用冻结，不因 Token 输入/输出分配、16 步、40 次模型调用、24 次工具、10 分钟这些单轮阈值重开任务或暂停。
- 费用仍不得超过本次实际冻结的 `rate.maxCost`，调用前根据累计真实用量、下一次预估输入和输出单价计算可支付的输出量。真实预算不足用 `limit=budget` 明确提示；用户停止、付款授权、素材归属、制作确认与重复动作保护继续生效。
- 属性式 `<studio-action … />` 归一为同一工具动作，仍经过原有校验和授权。完整回复与流式过滤共用同一识别规则；不完整、错误 JSON、重复/额外属性整批拒绝，不显示操作原文。历史残留原文只折叠，绝不补执行。

## 回归方式

- `DialogueLoopTest` 回放上面的真实四次用量与操作顺序。原输入额度在 3 步 / 4 次调用、58621 / 1254 处停下；新的独立额度与确认继续模式都能进入受控的方案、确认卡后续，准备节点只建一次。原记录没有保存下一次估算值，回放用 20000 的预估输入触发同一判断，后续方案响应为本机受控数据。
- 确认继续模式另跑 50 步 / 99 次模型调用 / 49 次工具，模拟 25 分钟，跨过全部单轮阈值仍一次完成；真实费用、停止和重复动作测试保留。
- 数据库、账本、HTTP 模拟厂商、SSE 集成：先强制小额度重现 `tokens` 暂停，再真实提交一条「继续」，连续完成 46 步 / 45 次工具，累计输入 23000 / 输出 4600 超过该测试的 20000 / 4000 分配。只有一条续接助手回复、一次续接冻结，无中间暂停提示；用户确认幂等重发不增加调用或扣费。
- 操作格式在每一种流式切分位置、逐字符输出、多个连续动作、参数中包含 `/>`、损坏和残缺 JSON 下回归；历史原文折叠同步测试。

最终验证：133 项后端回归（含真实持久化、账本与 HTTP 模拟厂商的续接集成）全部通过；80 项前端回归、全仓类型检查、后台类型检查和 API 契约检查通过。后端在独立临时构建中执行，并核对被测源文件与工作区一致。模拟厂商回放验证控制与计费规则，不代表重新生成了线上那条视频；未做真厂商新调用或生产发布。
