## 根因与改动

`JusuanImageClient.checkedSubmit` 将所有 4xx 替换为通用提示，原响应仅附在后台诊断中；异步任务失败也使用通用提示。违反 AGENTS §8.0.1 ① 的可操作 4xx 信息直出要求。

- HTTP 错误与异步失败路径共用一处解析：读取结构化 JSON 的错误消息，现已收敛至公共 `ProviderErrorMessage`，复用 `ProviderAlertText` 脱敏，最多 200 个字符。内容审核的明确错误码映射为内容审核提示，其他 JSON 拒绝保留供应商原因。
- 非 JSON、HTML 或缺少消息时回退通用提示。用户随后明确要求统一透传上游错误，因此 5xx 也展示脱敏后的具体 JSON 消息；原始响应体不直接展示。错误码保持 `STUDIO_IMAGE_PROVIDER_FAILED`，不改变既有失败结算与受理未知恢复逻辑；受理未知提示追加上游原因，不能因为有了错误信息就把不确定受理当作明确拒绝。
- 原响应、供应商请求标识与 `StudioRunErrorLog` 真实追查号链保留；资产列表直接展示已保存的失败消息，详情也展示。
- 既有 4 项 worker 测试 mock 仍调用旧的 10 参数重载，实际 worker 已调用带 providerModel 的 11 参数重载；同步修正 mock 和回调参数位置，使恢复与结算回归实际覆盖当前调用。

后续已按用户要求扩大到所有模型调用，统一规则与完整验证见 [全模型错误展示](model-error-propagation-validation-20261025.md)。
