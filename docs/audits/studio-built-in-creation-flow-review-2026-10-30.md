# 全部内置图片与视频生成流程：体验审查与优化方案

日期：2026-10-30。状态：审查与方案；未修改业务代码或线上配置，未进行新增付费生成。

## 1. 用户目标与范围纠正

用户要求所有内置图片、视频生成流程顺畅，生成内容贴合各自用途。同城团购只是说明问题的例子，不能以“先优化团购和促销”代替整个需求。

验收单位是一条完整流程：**选择用途 → 放入素材 → 补充必要信息 → 生成 → 修改 → 选定结果 → 下载或继续创作**。提示词是其中一环。所有入口都应做到少填、少猜、不中断、不丢内容，结果符合入口承诺。

本方案替代 [前一份提示词报告](studio-scene-prompt-review-2026-10-30.md) 的实施优先级。前报告中 21 个视频场景的内容矩阵、提示词与 H3 衔接证据仍然有效；团购示例仅作为一个案例。

范围包括：

- AI 图片的全部 17 个内置场景。
- AI 视频的全部 21 个内置场景，包括爆款复刻和需要分段的内容。
- 从这些入口到资产、项目、画布、配音/口型/合成的接续体验，以及首页内置模板所承诺的完整产物。

本轮完整阅读了 38 个随包场景定义，补查图片/视频共用页面、草稿与结果操作源码。源码基线仍为新版检出目录 `/Users/donis/dev/AIStarEcosystem-release-scene-home` 的 `c095ae31d`。前轮线上只读证据继续引用；本轮未逐项真实生成 38 类作品，也未遍历所有运营数据库模板。这里是全量审查范围与实施方案，不能称为全量效果验收通过。

本轮借助 product-ui-completeness 的用户意图、生命周期、空态/失败/恢复方法审查。没有进行新的几何尺寸、主题、手机或全部角色实测，不对这些维度给通过结论。保留产品现有模型选择要求，不机械套用技能参考中的“隐藏模型”建议。

## 2. 影响整批流程的共性问题

以下 G01–G05 为源码确认；影响判断与改进建议另述，未将源码推断冒称线上复现。

### G01 · P1 · 图片草稿没有恢复完整创作状态

`scene-image-studio.tsx:108–123` 打开草稿时恢复场景、参考图、比例，却清空补充要求和完整描述；没有恢复那次的模型、尺寸、数量、选项。用户点击继续，看到的条件可能已不是上次那份。尚未提交的场景输入只存在组件内 Map，刷新后无法据此恢复。

应把可编辑条件作为草稿状态保存，和已提交请求快照区分。打开草稿恢复当前编辑版本；重新采用历史结果时恢复该版本条件。不能仅恢复图片而要求用户回忆上次写了什么。

### G02 · P1 · 图片“再做”存在重复拼接和选择矛盾

`scene-image-studio.tsx:278–287` 把上次已完整组装的 `request.prompt` 放入 custom，仅恢复参考图和比例。再次生成时 `StudioSceneCatalog.imagePrompt` 仍追加本次 options 和 supplement。

如果旧请求已有角度/风格，新选项又不同，提示词会同时包含两种要求；即使不改也会重复。用户想微调，却被旧指令牵制。

应分开保存场景基础规则、用户补充、选项和最终发送文本。复用历史条件后只组装一次；用户编辑完整提示词时明确选项如何更新，不能把旧选项藏在全文里再追加新选项。

### G03 · P1 · 视频未提交改稿与切换状态缺少保护

`scene-video-studio.tsx:126–129` reset 清空输入、素材和出片稿；切换场景时已有草稿会走 reset。`:420` 采用脚本仅 setPrompt，`:569` 编辑也只 setPrompt；刷新或重开没有恢复这段尚未提交的出片修改。`:159–161` 恢复模型及脚本时长/比例，但没有完整恢复语言、清晰度、优化开关、选项和所采用版本。

没有草稿时切场景则只 pickScene，可能把同一段文字/图片继续带到另一个用途。两种情况下一个清空、一个沿用，行为不统一。

应按草稿/场景保留未提交输入和采用版本；兼容素材可建议沿用，不能按位置静默换用途。切换和刷新回来后应能从离开处继续。

### G04 · P1 · 结果到下一步的操作不足

`ImageRow:417–422` 主操作为下载第一张和复用描述；每张可打开大图再下载，但没有直接将该张作为新参考的场景操作。复用描述取的是上次输入参考，不是用户刚选中的生成结果。

`VideoRow:707–711` 成功结果只有下载，重新生成仅给失败项。用户想用某条成功视频的设置再做一版，需要回到脚本/编辑区重新对照。成功只是任务成功，并不意味着用户满意，不应把迭代入口只留给失败。

应让用户选择结果后直接“继续编辑”“生成视频”“下载”或“重新生成”；这些名称是候选产品动作，实际只展示已接通能力。新版本保留旧结果，避免用户通过重新上传来绕路。

### G05 · P2 · 不同创作模式的接续成本由用户承担

短视频在场景页完成；爆款复刻与长于模型上限的内容跳到画布创作助手。`handoff` 会保存文字及素材，已有基础值得保留。但用户从简单场景流进入画布后，需要重新理解步骤、方案和结果位置。

目标应是同一份创作持续进行：显示当前阶段、已确认的资料和下一步；需要画布时带明确上下文和返回入口。后续可以统一任务摘要与结果回显，不必要求先重写画布或执行器。

### G06 · P1 · 提示词、素材能力与成品承诺未统一

前报告 F01–F08 已记录业务字段不足、场景差异弱、H3 格式不匹配、换模型/时长后未重新校验等问题。这些需要应用到全部 38 场景。

例如：三视图要三种指定视角；换脸要保留原姿态；商品白底图要保护包装；品牌故事不能编商家经历；数字人口播要兑现人物/声音要求。每类都有自己的“保留什么、改变什么、交付什么”，不能用一份通用“生成好看的图/视频”承担。

### G07 · P2 · 结果可用性与恢复还需系统验证

场景结果 `<img>` / `<video>` 直接引用返回 URL，局部未见失效后换签恢复；是否被其他机制及时更新需要长时间停留验证。轮询错误当前多为静默下次再读，需要检查持续断网时用户是否仍被误导为正常生成。

这些列为待实测风险，不作为已线上复现。需覆盖多结果下载、长时间打开、离页返回、网络恢复与失败重试。

## 3. 17 个图片场景逐项交付定义

| 场景 | 用户应提供 | 必须保留/改变 | 完成后的自然下一步 |
|---|---|---|---|
| 自由出图 | 一句画面想法，参考图可选 | 按描述生成，少量补充即可 | 选结果、微调、下载、转视频 |
| IP 设定图 | 人物图 | 同一角色的多视角/表情/服装细节，不能变成多个人 | 保存角色参考；若需独立图，明确拆分能力 |
| IP 写真 | 人物图，风格/场景可选 | 身份保留，姿态/环境可变 | 换场景再拍、下载 |
| IP 表情包 | 人物图 | 九格身份一致，各表情不同 | 预览九格；整图/独立表情交付说明清楚 |
| 脸部三视图 | 清晰人像 | 正面/45度/90度，脸型身份一致 | 保存人物参考或继续角色创作 |
| 人物四视图 | 人物全身参考 | 正/侧/背与脸部特写，服装与比例一致 | 保存角色参考、继续视频 |
| 模特换脸 | 原模特图、新人物图 | 换指定脸/发型，保留姿势、服装、背景 | 对比原图，调整融合，下载 |
| 人脸融合 | 两个人像 | 合成新虚拟形象，不误当单纯换脸 | 采用新形象、生成设定图 |
| 服装上身 | 模特图、服装图 | 人物保留，衣服款式细节正确 | 换姿势/场景、继续商品图 |
| 商品使用 | 商品图，使用场景可选 | 商品外观与合理使用动作 | 微调使用场景、转演示视频 |
| 商品白底图 | 商品图 | 保留包装/标识/形状，背景变白 | 下载主图、继续卖点图/入景 |
| 商品卖点图 | 商品图、真实卖点 | 用画面表现卖点，按现有模板留白不生字 | 继续排版需有真实入口，不能假称完整详情页 |
| 服装改款 | 服装图、新面料图或文字要求 | 保留版型，改变指定面料/印花 | 对比、继续修改或上身 |
| 人物入景 | 人物图、场景图或描述 | 保留人物，匹配新环境透视光影 | 调整位置/比例、转视频 |
| 商品入景 | 商品图、场景图或描述 | 商品不变，摆放与环境合理 | 微调构图、转商品视频 |
| 人物真人感 | 人物图 | 增加真实纹理，身份/年龄感不漂移 | 对比原图、采用、继续写真 |
| 图片精修 | 原图 | 改清晰度/曝光/细节，内容构图不变 | 原图对比、下载、继续创作 |

图片流程应以“一步得到候选结果”为默认。已有足够素材时不强行增加脚本确认或长问卷；信息不足只询问影响结果的内容。多图槽位必须通过标签和示例明确用途。

## 4. 21 个视频场景全部纳入同一验收范围

每个场景的具体内容策略见前报告第 4 节，本轮统一补齐流程要求：

| 视频类别（全部场景） | 生成前需要确认什么 | 流程必须顺手的地方 |
|---|---|---|
| 口播带货、促销转化、场景种草、痛点解决、功能演示 | 商品、人群、真实卖点、对应目标；场景间不能只换标题 | 商品资料可沿用，能分别产出不同表达；改文案不必重传素材 |
| 门店发现、到店实录、招牌体验、同城团购 | 门店、位置、内容依据；团购才突出套餐与购买规则 | 同店素材可复用，但目的、脚本与结果互不串；明确真实记录与生成演绎 |
| 品牌主张、品牌故事、生活方式、创意概念 | 品牌立场/资料、受众、可虚构边界、视觉方向 | 先看简洁方案与脚本，风格/叙事可改，不能强套促销 |
| 对话剧情、反转剧情、悬疑剧情、情感剧情、剧情植入 | 人物关系、事件、时长、结局与商品作用（如有） | 人物素材可持续沿用；短片/分段模式自然衔接，镜头与对白不漂移 |
| 数字人口播、IP 日常 | 固定人物、声音要求、主题/当天事件 | 选人物和声音后可跨版本保留；能力不足提前说明 |
| 爆款复刻 | 参考片、想保留的结构、替换素材和本次真实信息 | 拆解、改编、生成有清晰阶段；从场景到画布回来仍找得到结果 |

视频默认“补必要信息 → 看可编辑脚本 → 确认费用并生成 → 预览/继续修改”。同一创作不应多次重复确认同一份资料。多次费用确认是否可合并需核实授权与计费边界，不能为减少点击擅自绕过用户消费确认。

## 5. 内置模板与跨入口接续

范围不能只按 `scenes.json` 的 38 项结束。还需读取实际启用的官方模板目录，逐一登记其承诺的产物和每一步。前轮线上可见个人 IP、潮玩 IP、数字人形象视频、IP 商品视频、剧情带货、原声视频复刻等模板；运营目录可能继续变化，数量不写死。

统一检查：

1. 点“做同款”后明确替换哪些素材，哪些现成说明可删，哪些参数必填。
2. 上一步已生成的图片/文字能够直接进入下一步，不要求下载再上传。
3. 每一步当前采用版本明确；换了人物、商品或脚本，依赖结果提示需要更新，不自动烧积分重做。
4. 模板写的“生成整套”“保留原声”“完整成片”要有真实执行能力与交付路径。
5. 局部失败只处理对应步骤，已成功产物不无故重做；受理未知继续查原任务。
6. 从项目恢复能回原流程；普通用户可以完成任务，画布编辑作为进阶能力。

本轮未完成全部官方模板逐项执行，上述是下一阶段必须纳入的清单，不宣称已经验收。

## 6. 正确的优化顺序

### 第一批：先修共用流程，同时惠及图片与视频

- 完整草稿保存与恢复：素材、输入、选项、采用版本、模型规格及未提交改稿。
- 正确“再做一版”：不重复拼选项，不错用旧素材，不覆盖旧结果。
- 结果直接继续：明确选中哪张图/哪条视频，提供对应后续能力。
- 模型能力、素材、时长与稿件一致；修复场景稿与 H3 的格式衔接。
- 报价、生成中、失败、受理未知和恢复的表达保持一致。

### 第二批：38 个内置场景全部完善内容规则

逐条补用途、最低输入、可默认项、保持/改变项、内容结构、示例和验收标准。不同场景按需要适配，不能全部加长表单，也不能全部塞同一套营销话术。

原提示词报告的团购样例保留为其中一条；不以完成团购/促销作为本轮需求完成标志。

### 第三批：跨步骤与模板闭环

让图片到视频、复刻到改编、分段到成片、项目到继续编辑都能承接上一步状态。优先复用现有服务和画布能力；缺能力的动作不显示成已可用。

### 第四批：全量走查、代表性效果验证

- **38/38 场景**：入口、必要素材、参数、输入保护、返回恢复、结果后续动作逐项记录。
- **全部当前启用官方模板**：替换素材到交付的每个步骤均有记录。
- **共用状态**：空/加载/成功/失败/取消/受理未知/网络恢复；批量结果、长文本、缺素材。
- **共用形态**：桌面与手机、新旧 UI 可达入口；只抽一个宽桌面空态不能算通过。
- **生成效果**：固定资料比对新旧方案，每类至少有可评审的样本；所有付费实测按明确预算开展。不能凭代码或提示词检查断言成片质量已提升。

## 7. 最终完成标准

用户不学习提示词语法、不理解画布内部结构，也能从任一内置用途进入，使用自己的资料得到符合该用途的结果；改一次、换素材、退出回来、失败恢复、再用结果继续做下一步，都不需要重新开始。

“顺畅”以每条流程的实际完成、重复操作次数、输入保留、结果可用性判断。提示词变长、页面能打开、接口成功都不能代替这个标准。
