**三、共性故障与责任**

1. 供应商资源配额耗尽。

截至本次查询，20:12–20:25 共 6 笔视频、4 笔配音明确被聚算 personal_asset_quota_exceeded 拒绝；比前次诊断新增视频 mvj_de6e881e811d。原 9 笔已核验全部释放，本次新增笔同样 RELEASED、remaining=0，只有 FREEZE -320 / UNFREEZE 320，无 SPEND。它们未扣失败生成积分，但不等于相关对话费用全部退还。视频均无 external_task_id，属于明确拒绝。

其中同一画布三笔配音在 20:13:48、20:13:59、20:14:06 连续失败；这说明同一不可恢复条件下重复受理没有被有效阻断。不能仅凭任务间隔判断是人工点击还是客户端触发。

资源空间属于我们使用的供应商账号，提示用户清空本平台回收站会误导。应按供应商账号维度标记不可用，覆盖共用配额的视频和配音入口；展示受影响能力及替代选项，保留原参数。恢复配额后允许明确继续原制作，不能未经确认补投全部历史失败任务。

当前没有配额恢复成功证据。本轮没有供应商用量、资产依赖或扩容报价；清理和扩容仍需先准备可核对的范围。

2. 图片规格及结果解析。

7 笔图片失败中，4 笔来自端点 ai-abadd123-a06：选择 768×1024，返回 1448×1086。即竖向 3:4 变成横向 4:3，并非只是像素多一点。现有严格输出校验因此失败；不能通过放开校验把横图当成功。

另外 3 笔为 STUDIO_IMAGE_SUBMISSION_UNKNOWN，其中 1 笔结果缺少配置的输出字段、2 笔显示 UpstreamCallException。后者尚缺底层响应证据，不能把三笔全部归到供应商容量。现有文案统一鼓励重新生成，缺少受理/产物状态区分。

建议：修正并验收端点参数映射，做画幅/参考图/输出字段矩阵；只对可证明无损的同画幅缩放归一，构图变化须用户选择。保留已有厂商任务或资源 ID，优先找回原结果；将“明确未受理”“已受理待恢复”“有结果但校验失败”分别处理。原错误码仍保留给运维，用户文案解释当前处理和下一步。

3. 发布可用性。

Nginx 当日下午至晚间共有 520 条 502：

| 时间（北京时间） | 502 条数 | 本次可确认内容 |
|---|---:|---|
| 15:14:39–15:14:57 | 33 | 与当日下午发布时段相邻；单独列出，不并入晚间 50 秒事件 |
| 19:39:28–19:40:17 | 475 | 已确认本次单实例后端重启导致连接拒绝；344 GET、131 PUT |
| 21:05:32–21:05:50 | 12 | 新发现窗口，与当前 systemd 服务激活时间重合；具体发布责任需查对应操作记录 |

19:39 这次发布是本对话中的修复发布。保护在途生成、等 worker 完成，没有保证在线接口可用，这是发布方案的缺口。该窗口受影响的 12 个保存路径后来都有 PUT 200，但不能据此证明每次失败保存的全部内容已恢复。

建议：预热新实例、就绪后切流、旧实例排空；切换全过程探测读取、保存与 SSE，明确多实例调度租约及去重。前端本地待保存草稿与服务器修订号结合，断线显式显示“正在重新连接/待保存”，恢复后核对版本并补存，不能用旧文档覆盖新版本。上线成功条件应包括发布过程无新增 5xx，而非仅上线后健康检查通过。

4. 性能、任务状态和计费感知。

排队比生成本身占据更多时间；用户看不到当前步骤，就会重复点击、问进度和重新生成。另一方面，studio-video 父记录 28 条都为 done，实际视频只有 21 条 succeeded；对话 17 条全 done，也包括协议失败和读文循环。当前底层运行完成、已受理、目标达成三种语义不能直接混用。

建议：统一用户侧状态为待确认/排队/生成/恢复中/完成/需处理/失败，并指向原始任务真值；明确排队位置、等待估计区间及可继续做的工作。提供整个作品的制作清单。对确定的系统错误方向费用、格式自修复成本制定补偿或平台承担政策，避免用户为系统纠错反复付费。普通内容质量不满意与系统执行错误需要不同策略。

**四、建议排序与验收条件**

| 优先级 | 工作 | 具体通过标准 |
|---|---|---|
| P0 | 供应商配额恢复与账号级阻断 | 确认不可重试故障后，同账号受影响入口不再反复冻结/提交；保留用户方案，可查恢复状态 |
| P0 | 图片画幅/输出契约修复 | 支持的画幅、参考图组合逐项验证；返回不符能定位配置及保留可恢复产物；不冒充成功 |
| P0 | 追清 18 次持续 409 | 每次有业务错误码与关联请求；用户无需反复改写即可恢复原请求或得到明确所需动作 |
| P0 | 发布及断线保存保护 | 发布期间持续读、存、对话；无新增 502，无重复生成/扣费；断线草稿和新服务版本正确合并 |
| P1 | 作品进度真值 | 对话、节点、列表、工作流显示一致；“已有五段又缺两段”回归样例不再出现 |
| P1 | 当前剧本与镜头版本 | 指定新剧本后所有新规划使用新版本，旧产物可复用/需更新可见，不靠标题猜测 |
| P1 | 跨图片/视频/配音续接 | 单轮能到正确方案或必要输入入口；同一次失败规划绝不出现旧报价 |
| P1 | 排队体验与容量治理 | 区分排队/供应商/镜像耗时，展示可信估计；先验证供应商容量再调并发；不会让一个项目长期占满队列 |
