## 设备形态：默认按宽度，但用户说了算

真值在 `<html data-layout>`，CSS 与 JS 读同一个（`src/shell/layout-mode.ts`）：

| 来源 | 规则 |
|---|---|
| 用户显式选过 | 以他为准（「我的 → 切换到桌面版」、桌面账号菜单的「切换到手机版」） |
| 没选过 | `matchMedia(min-width: 960px)` |

**为什么是 960 而不是 1024**：手机浏览器的「请求桌面版网站」会忽略 viewport meta、
改用约 **980px** 的布局视口。断点卡 1024 的话，用户明明在 Chrome 里选了桌面版，
看到的还是那条 480 的窄列 —— 这是真实反馈。960 恰好接住 980，
又不会误伤横屏手机（iPhone 16 Pro Max 横屏 956，多数安卓旗舰横屏 < 940）。

**画布的设备提示是柔性的**，不是拦路：手机上先给一屏说明（它确实挤），但主按钮就是
「仍然在手机上打开」。理由很实在 —— 出门在外想看看昨天那条链出了什么效果、
临时改一句提示词重跑一次，都是真需求，不该被一个断点判死。画布核心用 PointerEvent，
拖拽 / 平移在触屏上是通的，缩放有左下角按钮；够「看一眼、改一点」，
只是不适合从头搭一条链。选择记在 sessionStorage，本次使用内不再拦。

代价没有丢：`CanvasHost` 仍走 `dynamic({ ssr:false })`，那 15k 行 + antd 的 chunk
**只有真的要进画布时才下载**（实测：进提示屏 antd style 0 个 / 点了继续之后 6 个）。

**新增桌面样式时**：写 `html[data-layout="desktop"] xxx`，不要写 `@media (min-width: …)`
—— 媒体查询绕过用户的选择。真正的宽度约束（例如某块内容两侧各要 260px 才放得下）
仍然写媒体查询，那不是形态问题。

**属性是谁写的**：`<body>` 第一个子节点那段裸 `<script>`（首帧之前）+ 挂在根布局的
`AppChrome` 订阅的那个全局监听（视口变化时跟着改，且**顺手兜一次底** ——
内联脚本被 CSP 拦掉时它是第二道保险）。
不要用 `next/script` 的 `beforeInteractive`：实测它要等 app bootstrap 才真正插进
head，那时 `document.readyState` 已是 `interactive`、应用标记全解析完了，
也就是很可能已经按手机版画过一帧。

**代价**：JS 完全不跑（禁用 / CSP 全拦）时桌面用户会看到 480 窄列。这是**有意的**
fail-safe —— 窄列在宽屏上只是不好看，反过来把桌面版塞进 375px 才是真没法用。

## 页面归属：看在新路由，做在 /studio

企业成员邀请（2026-10-17，本地未发布）：企业管理内创建可群发的 90 天/一年链接，品牌页 `/enterprise/invite` 直接短信注册或登录后加入；当前已登录者显式确认。链接可多人使用、可撤销，产品开通沿用原规则；企业积分不自动分配，个人钱包和作品保持个人归属。这与账号级邀请注册推荐关系是不同功能，见 [群发邀请验收](../../docs/releases/ip-studio-enterprise-invitation-validation.md)。

账号注册邀请的后端真值属于统一账号中心，Studio 也提供完整的本人管理视图：“我的账号 → 邀请朋友 → `/invitations`”，覆盖链接生成/复制/预览、邀请人、直接邀请记录、分页和刷新；桌面与手机都有入口。所有操作直连 ID 本人 API，权限与关系绑定由 ID 负责，邀请不等同产品开通或分佣资格。2026-10-17 已配套上线 Studio 品牌 `/invite/{code}` 直接短信注册，真实注册、ID 绑定、进入 Studio 和双方邀请视图已完成线上验证，详见 [前端设计](../../docs/unified-account-referral-frontend.md)。

并入之后本 app 有两层页面，**边界是「看」还是「做」**，不是「新」还是「旧」：

| | 在哪 | 形态 |
|---|---|---|
| **看**：主页 / IP 管理 / 发现 / 资产 / 资产详情 / 名片 / 授权 / 我的 / 自由画布 | App Router 路由 | 响应式，桌面铺开 |
| **做**：声音工作室 / 真人素材 / 任务中心 / 会员算力 / 存储 / 回收站 / 设置 / 创建链路 / 合成 | `/studio`（老 SPA，26 屏） | 分步流程，固定 480 宽 |

这不是「有一半没做完」，是刻意的：**分步表单本来就该窄**，一行输入拉到 1100px
反而难填。所以桌面上 `/studio` 有自己的取景（两侧深一档底色 + 描边投影 + 左侧
一句说明），读起来是「一个专注的流程面板」而不是「这页没做响应式」。

判断新页面该放哪：**它是让人浏览和挑选的，还是让人一步步填完的？**
前者进 App Router 并做响应式；后者进 /studio（或按双轨迁出时也保持窄列）。

真正的重复只有一处：`/licenses` 列授权、`#/licenses` 出证书 —— 证书视图尚未迁，
所以列表页要跳过去。迁完之后那条外链就该删掉。

## IP Studio · 声量引擎旗下：首页与 IP 管理

公开 `/` 与登录后的桌面 `/dashboard` 共用首页：人物主图、两行中文衬线标题与「开始创作」，四张创作方向卡和三张灵感示意卡。登录后「继续创作」读取真实近期三张个人画布；没有画布或读取失败时明确提示。首页图片是创作示意，不是客户的实际 IP 产物。移动 `/dashboard` 继续使用 HubHome。

首页「开始创作」进入 `/create`，不自动创建画布；匿名用户登录后返回创作页。图片、视频与短剧等明确功能入口仍先免费进入对应画布，模型生成与积分在节点里确认。原根 hash 转发和真人授权回调恢复保留。桌面主导航为「首页 / 项目 / 画布·自由创作 / 场景·专项创作 / 灵感 / 资产 / 发行」；自由画布保留 `/create`，灵感保留 `/templates`，账号菜单保留账号、授权、名片、发现、设备切换与退出，余额使用真实钱包组件。

Studio 登录由统一账号中心处理，登录后回到原页面并保留查询参数与锚点；退出也走统一账号中心。
画布直达链接在完成登录和数字资产开通检查后才加载本人画布，未开通时展示激活码入口。

`/assets` 默认分类“我的 IP”承接现有个人 Avatar 与形象库，不新增 IP 容器模型；旧 `/ips` 保留查询参数并转到 `/assets?tab=ips`。它提供真实统计、搜索、状态/标签筛选、排序和网格/列表视图；选择人物后在列表右侧显示相邻档案，包含「人物设定 / 形象版本 / 关联声音 / 相关作品」。已定稿不表示已发布；缺失表情、设定图、声音和作品不补造，读取局部失败与未知统计均明示。

设定编辑保存同步更新同一实体的列表和详情，失败保留草稿；具体视图与历史版本可选，素材类别和声音试听沿用现有 API。导出设定为 Markdown。「生成形象」免费打开带精确 `storageKey/avatarId/version/lookId` 参考的画布，引用保存失败时复用已创建项目；收费生成仍由用户在节点内确认。

## IP Studio · 声量引擎旗下：创作与模板市场

画布默认使用「拖动画布」，在工具栏排第一；拖动空白处平移画布，节点标题栏在两种工具下均可拖动。「选择工具」用于框选，按住空格临时平移整张画布后恢复原工具。工具栏新增文字、图片、视频时，优先放在当前可见区域的空位，保持视口与缩放；当前区域已满时仍留在视野中，不推到整张画布最右侧。右键添加沿用点击位置并限制在当前视野内。

可编辑节点的标题支持双击原地改名，回车或离开输入框保存，Esc 取消，空白名称保留原值；只读模板不开放改名。普通文字的正文、提取资产及展开编辑共用一个浮层，收起展开编辑返回原浮层。连线端口平时显示 8px 小圆点，鼠标进入隐形操作区或拖线时放大为 28px 圆形加号，离开后收回；缩小时仍保持 44px 的命中区域，连线锚定原节点边缘。

画布封面统一（2026-10-17，已发布 a4092626）：项目页和灵感页使用同一套规则与组件：人工设置的封面优先，其次自动选择已有图片（节点采用图优先），没有可用图片则显示真实画布缩略图。允许上传独立 JPG/PNG 封面、从画布选图、恢复自动封面；失败保留原封面并可重试。图片加载失败继续尝试其他图片，最后回落画布。封面仅更新服务端 coverKey，读时重签，不向画布添加节点、不改 doc 或模板版本。个人项目与个人模板由属主管理，官方模板由 SUPER_ADMIN 管理。保留搜索、筛选、排序、分页、网格/列表、真实媒体数量与查看流程入口。

`/create` 使用 `StudioCreateHome`，只承载新创作；`/projects` 是独立「项目」页，使用 `StudioProjects` 管理个人画布，不再重定向到创作页。已有 `/projects/{id}` 地址继续使用。两页沿用现有浅色顶栏与暖灰、白色、深墨工作面，无侧栏；一级导航的「项目」紧跟「首页」，进入列表；项目页「新建创作」直接新建一张画布并打开（2026-10-20 起，见下「2026-10-20 · 新建就是一张新画布、空画布有入口、助手能开新对话、卡片只说要紧的」）。

（2026-10-21 起桌面和手机都是这一页，进来不建画布。）创作页从上到下是：一张「新建画布」卡片（点了才新建空白画布并打开，助手一起打开）、九项平铺能力卡片、一行推荐模板（最多四份）；没有想法输入框，也没有方式切换，不混入个人画布列表。图片、视频、剧本、解析视频、导演、成片、配音、口型、人物库均配有 AI 生成的功能示意图；「新建画布」卡片用画布加助手的示意。卡片显示用途说明，均通过原 `StudioEntry` 免费打开画布，不自动生成或扣点；不再将后六项收为「更多工具」。推荐模板的「更多模板」进入灵感 `/templates`，模板仍先只读预览、显式存副本。

模板预览与个人画布统一占满浏览器内容区。个人画布只保留画布自己的返回、名称和操作栏，返回入口回到 `/projects`；桌面积分余额沿用真实钱包组件，读取失败可重试。模板的只读预览和显式「存为个人副本」流程保持不变；官方内容管理 `/projects/demos` 继续使用网站导航。

「项目」页的我的画布支持名称搜索、全部/草稿/已发布筛选、最近编辑/最近创建/名称排序、网格/列表与分页。状态和数量使用保存的真实数据；封面沿用统一规则，个人预览只加载当前页文档，最多并发两份，签名媒体地址仅在内存中缓存。列表、模板与预览失败各有重试，创建与删除防重复提交，删除须显式确认。

项目成为独立页面后，网格恢复原来的大预览卡片：上方 4:3 画布缩略图，下方名称、状态和时间，更多操作位于卡片页脚；不再沿用创作页中紧凑的横向小卡片。列数随内容宽度自动排布，列表视图继续用于密集浏览。

创作页推荐官方模板通过「更多模板」进入 `/templates`。灵感分官方模板、我的模板、精选案例；个人模板继续只供本人保存复用，可停用/启用，不能视为公开社区发布。现有官方精选画布与运营管理入口保留。所有模板沿用只读画布预览，只有「存为个人副本」才免费创建可编辑项目，原模板不变。

具体页面意图与本轮验证边界见 [.impeccable/ip-create.md](.impeccable/ip-create.md) 和 [.impeccable/ip-template-market.md](.impeccable/ip-template-market.md)。本轮扩展以桌面为目标；当前路由统一使用该画廊，手机专项设计及 1536/1280 渲染截图验收仍待完成。

## Users

**主要用户**：内容创作者与数字 IP 运营者（音乐人、短剧团队、带货商家）。使用语境是**手机上、碎片时间**，形态为移动端 H5 / 微信小程序的全屏沉浸式 SPA。

**要做的事（job-to-be-done）**：把创作要用到的**全部素材**沉淀成可复用、带版本、带授权的资产，再把它们**组合**成成片，然后一键接入下游子应用（音乐 / 短剧 / 带货）去变现。

**六类资产（v0.104 起）**：数字人不再是唯一的资产种类，而是六类之一 ——

| 类型 | 前缀 | 来源 | 授权 |
|---|---|---|---|
| 人物 | `DH-` | 真人授权复刻 / AI 原创 | 真人复刻需 LIC |
| IP | `IP-` | 新建容器 / 导入 | 需 LIC |
| 场景 | `SC-` | 实拍上传 / AI 生成 | 只记来源 |
| 产品 | `PD-` | 实拍上传 / AI 生成 | 只记来源 + 品牌方授权备注 |
| 声音 | `VO-` | 克隆录制 / 挑选内置 | 随人物 |
| 风格 | `ST-` | 从作品提炼 / 手动新建 | 只记来源 |

**两条人物素材路径**：
- **真人授权素材库** —— 上传图片 / 视频或倒计时录制 → **确认平台授权说明** → 首次由**七牛云本人刷脸**建立真人组 → 素材逐条审核 → 审核通过后成为视频生成可选素材。授权流程到入库即结束，不自动生成数字人、不消耗生成算力。
- **纯 AI 原创** —— 上传照片 或 文字描述 → 四宫格挑选 → 推荐音色 → 保存。

**真人授权确认（v0.106）**：授权由两份不同性质的证据共同成立。第一份是用户在平台内明确确认的
《真人数字形象授权及个人信息处理告知》快照（版本、正文摘要、范围、期限、确认时间与终端信息留痕）；
第二份是七牛云 Modelink 返回的 **liveness_face active**，只证明活体与同人一致性的技术核验结果，
**不表述为居民身份证实名认证、公证，也不自动扩张成全平台授权**。只有两份证据齐全，服务端才登记
生效 LIC；凭证显示平台确认记录与七牛 qgroupid 引用。历史 liveness 授权缺协议快照时降为「待补确认」。

移动端在当前页面进入七牛云 H5，完成后回调页自动跳回 `#/real-auth/{sessionId}`；该路由可在刷新、
微信 WebView 回流或重新登录后继续轮询并完成登记。七牛 `h5_link` 约 120 秒有效，过期必须重建分组，
不能通过重复 GET 伪装成“换新链接”。浏览器回跳仍然只代表已提交，最终结果只认服务端拉取的上游状态。
真人形象**没有完整授权证据就不能出片**，并保证没有建单、没有扣算力。

**真人主体与素材的粒度（v0.107）**：七牛 `liveness_face` 分组按真人主体建立，不是账户一次授权，
也不是每条素材都重新刷脸。同一真人继续上传素材时复用已 active 的 `qgroupid`；每条图片 / 视频仍独立
送审并取得自己的 `qassetid`。生成视频只允许引用 `approved` 素材的 `qasset://...`，不能仅凭 LIC 生效
就绕过素材审核。换另一个真人必须新建真人组。平台协议按真人主体、范围和期限确认；协议升级可补确认，
已有 active 技术证据可复用，不强制重复刷脸。

**素材平台审核（v0.105 起）**：资产可以提交**内容安全审核**，审核状态在界面上如实展示
（待审核 / 审核中 / 已通过 / 未通过，未通过给出可读原因并允许重新提交）。两条来源：
真人素材在授权证据登记后**随核验自动送审**（送审失败不影响已经成立的授权）；
AI 原创人物的形象主图由用户在资产详情里主动「提交平台审核」。审核与授权一样**不消耗算力**。

**IP 是容器**：一个 IP 下挂人物 / 场景 / 产品 / 声音，整体授权、整体调用。
**合成工作台**把 人物 × 场景 × 产品 变成成片，产物回流登记为该 IP 的衍生物，并给每个用到的资产双向记一条「已用于」。

资产一旦定稿，形象 / 声音 / 衍生物（图集 · 表情 · 场景 · 换装 · 3D · 运镜视频）与跨资产成片一站式沉淀，可被下游 app 反复复用而无需重新生成。

## Product Purpose

**是什么**：移动端「数字资产平台」—— 把分散的 AI 生成能力（形象生成、声音克隆、场景 / 产品入库、衍生物产出、跨资产合成）收敛成一个「资产沉淀 + 组合 + 复用」的中枢。

**为什么存在**：下游子应用都需要「可信、可复用、带授权」的数字人形象。与其每个 app 各自生成、各自管理，不如有一个统一的资产中枢：一次创建、处处复用、版本可追、授权可查。

**成功长什么样**：创作者能在手机上几分钟内创建一个数字人、定稿形象、生成所需衍生物，并把它授权接入某个下游 app；同一资产被反复复用而零重复生成；每个产物都诚实标注（真产物 vs 占位）。

## Brand Personality

**三词**：清爽（clean / airy）· 档案感（archival / precise）· 可信（trustworthy）。

**声音与语气**：去黑话、口语化中文、不画大饼。文案诚实（状态用「已就绪」而非技术黑话；占位产物明示 mock，绝不假装成功）。

**情绪目标**：当前首页与 IP 管理是「角色与世界的创作空间」：暖色人物、中文衬线标题、白色工作面与明确操作，让用户看见内容并继续创作，见 DESIGN.md。旧移动 H5 的「The Atelier Ledger」（工坊台账）继续记录在 DESIGN-mobile.md；版本和授权仍按真实资产语义展示。

## Anti-references

明确**不要**做成：

- **不是深色 SaaS 仪表盘**。不靠 dark-mode 炫技；主入口是浅色工作面，旧移动 H5 保留纸白工具形态。
- **不是彩虹分类**。衍生物 / 六类资产**不**各配一色；分类靠**登记前缀与图标**区分（`DH-` / `IP-` / `SC-` / `PD-` / `VO-` / `ST-`），V4「清爽」皮肤已把分类收敛为单一墨灰 + 图标（见 DESIGN-mobile.md 的 The Sanctioned Palette Rule）。
- **不是「什么都要授权」**。授权登记只发给真人肖像人物与 IP；场景 / 产品 / 风格是轻资产，只记来源（实拍上传 or AI 生成）。授权徽标因此仍然稀有，一眼可信。
- **不是套壳演示预览**。已删除 iPhone 外壳 / 伪微信胶囊 / 伪状态栏 / 伪 home 指示条；用真实安全区，是能投产的 H5，不是手机模型截图（DECISIONS §F）。
- **不套用共享 shadcn 设计系统**。强行套用 `@ai-star-eco/ui` 会摧毁 HeyGen 风视觉语言；本 app 自带 `src/proto/*` 设计层（DECISIONS §A）。
  - **v0.190 仍然成立，而且更彻底了**：AI IP 工作台并入时把它原来那一个 `@ai-star-eco/ui` 依赖（一个 AlertDialog）
    改成了 antd Modal，`@ai-star-eco/ui` 现在**完全不在本 app 的依赖里**。
  - 当前视觉按页面作用域分开：首页、IP 管理与共享浅色顶栏使用暖灰 / 白 / 深墨（`DESIGN.md`），
    限定在 `.ip-brand-surface` / `.ip-management-editor`；画布与现有桌面工具内容保留群青 / 麦黄
    （`DESIGN-desktop.md`），限定在 `.ip-surface`；旧青色 HeyGen 风移动 H5 见 `DESIGN-mobile.md`。
    共名变量依然靠作用域隔离（见 `src/styles/ip-desktop.css` 头注释）。**新增页面前先明确适用范围**，
    不按设备宽度把新首页令牌覆盖到整个应用。
- **不用浏览器原生 `confirm` / `alert` / `prompt`**。二次确认走 `Confirm` 弹窗，提示走 toast / inline error（仓库 CLAUDE.md §8 强制）。
- **不伪装能力**。未配引擎 / 调用失败 → 占位产物 + `mock=true` 角标 + 不扣费；绝不假装成功、绝不返回假内容（CLAUDE.md §8.0）。

## Design Principles

1. **资产即档案（Asset as dossier）**。六类资产**共用一套登记语言**：衬线资产名 + REG 编号 + 版本 + 更新时间。登记处的仪式感（登记号 · 衬线资产名 · 字段标签 · 归档钢印）是产品骨架，不是装饰。

1b. **组合优于重复生成（Compose, don't regenerate）**。同一个人物在不同场景、拿不同产品的成片，靠**槽位组合**出，而不是每次从头生成。每次组合都留下双向引用，资产的价值随复用次数累积。

2. **诚实优先，绝不伪装（Honesty over illusion）**。降级必须可见（mock 角标）、不扣费、不造假内容。能力没接通就明说「去后台哪里配什么」，不端上假产物冒充真产物。

3. **Mock 是一等公民（Mock is first-class）**。所有流程离线可演示。唯一数据出入口是 `src/proto/api.ts`；从 mock 切真后端只改 `NEXT_PUBLIC_USE_MOCK`，屏幕层零改动。

4. **真实可投产，而非演示（Ship a product, not a preview）**。真安全区、真永久链接（hash 路由随导航写回 URL）、真返回栈、真下拉刷新。去掉一切「演示壳」与原型残留。

5. **忠实还原优于过早抽象（Fidelity before abstraction）**。忠实移植上传规格 + Figma 原型；用松类型的 `createElement` 屏幕层换取最大设计还原度与最低回归风险，类型契约集中在 `data.ts` / `api.ts`。

6. **确定性保身份（Deterministic, identity-preserving）**。涉及人脸 / 身份的编辑优先端上确定性算法（MediaPipe 关键点 + WebGL 实时美颜，像素级可复算、保身份），而非不可控、会漂移身份的扩散重绘。

## Accessibility & Inclusion

**现状为 de-facto 姿态，尚无正式 WCAG 等级承诺**；以下含已落地项与候选改进。

- **触控优先**：输入控件高 44px；可点元素 `user-select:none` + 禁长按菜单。⚠️ viewport 禁缩放（`maximumScale:1, userScalable:false`）对低视力用户是 trade-off，列为已知点待复评。
- **动效健壮 + 可关**：入场动画只动 `transform`（被节流 / 截图 / 打印时不会消失）；动画由 `html.anim` 类整体门控，具备「一键关闭」基础。⚠️ 候选：显式接 `prefers-reduced-motion` 自动摘除 `html.anim`。
- **不靠颜色单独传意**：分类靠**图标**区分而非颜色（对色盲友好）；语义状态（成功 / 警告 / 错误）均带图标 + 文案。正文深石板墨（#14202B）on 纸白，对比充足。
- **语言**：中文单语（符合仓库约定）。
- **安全区**：刘海屏 / home 指示条用真实 `env(safe-area-inset-*)`，加入主屏后接近原生 app。

### 2026-10-21 · 新对话的四个快捷入口

### 2026-10-20 · 原创出图有了自己的方法、助手真的看图、规格写到节点上、失败节点说清楚

- **原创创作**：没有参考视频的出图出片（原创人物三视图、设定图、海报、原创短片）用新的「原创创作」方法，直接出制作方案、报价、确认后制作，不再被「参考视频复刻」的「先分析、分析阶段不许出图」卡住。对话已经挂错方法、又没有在制作时，助手会换过来，旧方法的待确认卡作废。
- **看图**：助手要说图里是谁、长什么样、哪个视角，先调用「看图」真的看画面（用对话模型的看图能力，按本轮对话用量计费，一次最多 4 个对象）；没看过只说名称，不按文件名猜，不编名字。对话模型没有看图能力时如实说看不到。
- **规格写到节点上**：用户在对话里说的画幅、时长、数量和要用的人物图 / 场景图，助手写到图片 / 视频节点上（参考素材同时连线），生成面板按它打开。面板不再悄悄把时长改成模型的最小值：做不到就在发送按钮旁说明并给「改成 N 秒」；描述里写的画幅 / 时长和设置不一致时，付费前先问「按描述改设置 / 按当前设置生成」。
- **助手的操作不再漏成正文**：模型把操作写成 `<studio-actions>…</studio-actions>` 时照样执行，界面不显示原文；写得不完整就不执行、要求重发；模仿工作记录假装做过事按格式错误处理。历史回复里残留的原文折叠为「这一轮没有执行的操作原文」。
- **失败节点**：没生成出来的图片 / 视频节点显示「没有生成出来」+ 一行原因 +「修改后重试」（保留提示词和参考）/「改为上传」，不再显示空节点的「上传图片或使用 AI 创作」。工具条只留一个恢复动作：模型临时不可用是「重新生成」，模型已下架是「换模型重试」（面板不再预选那个模型，并说明这次改用哪个）。服务端对已下架的视频模型在冻结积分前直接拒绝。

### 2026-10-18 · 全能创作：连续线程、技能与制作计划（本地实现，未发布）

全能创作改成**每张画布一条连续对话**（2026-10-20 起助手头部恢复「新对话 / 历史对话」，见下「2026-10-20 · 新建就是一张新画布、空画布有入口、助手能开新对话、卡片只说要紧的」）：没有模式页签，旧的四模式对话收进折叠的「之前的对话」，原来的采用、分享、「确认原对话任务」都还在。输入框始终可用：AI 正在说话、调工具或后台制作时都能继续发消息，新消息显示「已收到 / 排队中，下一步应用 / 已应用」，在下一个工具边界被应用；「停止」走优先控制。要换方向时在任一条消息上「从这里重新开始」分叉，原线程只读保留。

AI 的回复是**真实流式**正文（只有供应商真的流式返回时才逐字出现；不支持流式的模型一次给出，不假装打字）。它调工具的过程以一行「工作记录」嵌在同一条消息里（读取画布、拉片……），左侧细线串成过程，进行中转圈并写已用时间，失败直接写原因；点右边的小箭头才展开真实状态、耗时与已结算积分（运行中显示「待结算」）。回合进行中，回复下方有一行带动效的阶段提示（「正在思考 / 正在回复」，阶段来自真实事件，不编思考内容），回合结束、失败或停止即消失。问题选项和后续建议点一下就作为你的消息直接发出，不往输入框里堆，也不动你写到一半的草稿。每条回复的「放进画布 / 从这里重新开始」是右下角的小图标，最新一条常显，旧的悬停时出现。模型回复里不再出现整包 JSON 或内部名词。

AI 按仓内**技能**「参考视频复刻」工作（看片要点、方案推导、分段 ≤ 模型最长秒数、提示词骨架、检查清单、修正优先级）；方法固定、方案现场定：分析之后给推荐方案和必要的替代（保留什么、改变什么、取舍、报价），用户用对话或卡片确认。计划分析、制作两阶段，每阶段一张**确认卡**（范围、报价、可改的总上限与重做上限、付款账户），点「开始分析 / 开始制作」或直接回复确认都行；预先授权范围内不再弹卡。

确认后由**服务端执行器**按依赖推进（拉片 → 逐段出片 → 检查 → 合成），关掉页面也继续；每步提交前核对「已消费 + 在途 + 本步报价 ≤ 上限」，不够就停下来说差多少；暂停只查不提，停止取消排队中的任务，已交厂商的照旧结算。产物按稳定编号增量落到画布，用户手改过的文字不会被覆盖。检查结论以「AI 判断」节点呈现（逐项 通过 / 未通过 / 无法判断 + 依据），首版只建议不自动重做，用户可「就用这版」或「重做这一段」。完成后一条总结（实际积分、重做过的段、没过的检查项）和 2–3 条后续建议。

模型能力由后台「AI 模型与 Key」声明（是否支持工具调用、是否支持流式），不按模型名猜。设计真源 [`docs/ip-studio-conversational-video-recreation-plan.md`](../../docs/ip-studio-conversational-video-recreation-plan.md)；S0 付费实测与技能后台（S3）尚未进行。

**技能管理与多技能（S3，同日本地实现）**：技能从仓内文件改为**库里带不可变版本**（文件只是第一版种子，运营改过之后以库为准）；后台「平台 → Studio 技能」可以看、改、发新版本、回滚、停用（最后一个启用的不能停）、试跑（给一段分析和需求，看它会怎么排计划）。启用的技能多于一个时，助手按素材类型与关键词自动挑，挑不出就在对话里让你选；一段对话一旦绑定技能就不再换，要换从某条消息「从这里重新开始」。运营在一次制作完成后可以「把这次制作整理成技能草稿」：AI 只看方案、步骤结果、检查结论与采用情况，不看提示词、原话和素材，产出的草稿要运营在后台审阅后才会发布生效。

### 2026-10-23 · 对话不再停下来让你说「继续」（本地，未发布）

上面「对话额度独立」「确认继续后保持执行」两节里「点「继续」接着做」的做法以本节为准。你说一句话，助手就把事做完：读剧本、写稿、建对象、整理方案都在这一条回复里接着做，界面一直是「进行中」，中间不再出现「已暂停」「点继续接着做」，也不再给「继续」快捷答复。只有要花钱生成（出图、出视频、配音）时才发确认卡等你确认，必填信息缺了才问一句。

对话没有自己的预算，按实际用量扣积分。开始回复时只先冻结一小笔（普通文本那一档），不够了在同一条回复里悄悄再冻一笔，不会占住大笔积分影响同时在做的出图出视频；结束时按实际用量结算，多冻的退回。钱包真没钱了才停，提示「积分不够了，已经做好的都留在画布上。充值后跟我说一声，我接着做。」，下面有「去充值」（企业积分是「去申请企业充值」）。企业停用了你的额度这类原因，就直接告诉你是什么原因。

对话花的积分不算进制作预算，确认卡上的上限只包含出图出视频这些步骤本身。长剧本会分段读完，不会反复读开头那一段。等出图、出视频最多等 10 分钟，还没好就告诉你已经提交、结果会自动放进画布。旧对话里已经有的「已暂停」提示照常显示。设计见 `docs/ip-studio-dialogue-no-continue.md`。
