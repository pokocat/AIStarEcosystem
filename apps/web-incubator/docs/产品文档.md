# 明星端工作台 · 产品文档

> 版本：v3.0  · 文档日期：2026-06-10
> 模块定位：AI 艺人孵化平台 · 明星 IP 端
> 对应代码：`src/app/components/celebrity/CelebrityWorkbench.tsx` 及子模块

---

## 一、产品概述

### 1.1 模块定位

明星端工作台是 AI 艺人孵化平台面向**明星本人 / 经纪团队**的核心审核与运营中枢，承担从 IP 资产托管、授权审核、内容把关、商品准入到收益结算的全链路管控。其核心价值在于：

- **资产侧**：把明星的肖像、声纹、切片素材、数字人模型等 IP 资产以可控、可审、可撤销的方式接入平台技术底座（火山引擎等）。
- **风控侧**：为来自 MCN、生态创业者、品牌方的所有商业化请求提供分级审核入口，保证明星人设、合规与法律边界。
- **结算侧**：对授权产生的 GMV / 分成进行透明可追溯的核算。

### 1.2 三方协同关系

明星端处于平台铁三角的顶点之一：

```
              ┌──────────────┐
              │   明星端      │  ← 本文档
              │ (本人/团队)   │
              └──────┬───────┘
                     │ 授权 / 审核 / 分成
        ┌────────────┼────────────┐
        ▼                         ▼
┌──────────────┐          ┌──────────────┐
│ 生态创业者端  │ ── 内容 → │   粉丝端      │
│ (MCN工作台)  │          │ (星海粉丝)    │
└──────────────┘          └──────────────┘
```

明星端**不直接产出内容**，但所有内容、账号、商品、品牌合作必须通过明星端的相应审批阀门，方可在生态创业者端流转。

### 2.2 资产分级（绿/黄/橙/红区）

风险分级是贯穿数字人、AI 形象、内容审核三个模块的统一语言：

- **绿区**：日常推广、无敏感行业、低改造度，自动放行或快速审。
- **黄区**：需人工审看，限定平台与场景。
- **橙区**：高敏（医美、金融、政务），需补充资质材料。
- **红区**：禁止使用（涉政、博彩、违禁品、人格混淆）。

颜色与代码定义：见 `ZONE_COLORS` / `ZONE_LABELS`。

## 三、核心业务流程

### 3.1 IP 授权中心（4 类资产）

`IPAuthType = 'portrait' | 'clip' | 'digitalHuman' | 'documents'`

每类资产经历 6 状态机：

```
notStarted → preparing → uploaded → techReceived → volcanoSync → active
   未启动      准备中      已上传     技术方接收     火山同步    已激活
```

| 资产类型 | 含义 | 必备文件 | 下游能力 |
|---|---|---|---|
| `portrait` | 肖像 / AI 形象底素材 | 多角度高清照、3D 扫描 | AI 形象授权、数字人面部 |
| `clip` | 影视/综艺切片素材库 | 原始视频、版权说明 | 切片授权、二创 |
| `digitalHuman` | 数字人模型 | 训练视频、声纹样本 | 直播 / 短视频数字人 |
| `documents` | 法务底档 | 身份证明、工商资料、签字授权书 | 合同生成 |

**关键交互**：
- 上传后由对接的技术公司（默认火山引擎）回执 `volcanoProjectId`；
- `active` 后才会在下游模块（数字人审核 / AI 形象 / 内容审核）出现可授权选项。

### 3.2 账号报白 5 步流程

`WhitelistStep`：

```
received → contacting → sms → processing → authorized
受理      → 联络中    → 短信验证 → 平台处理 → 授权完成
```

**字段要点**（`WhitelistRequest`）：
- 准入维度：粉丝量、账号年龄、MCN 等级、近 30 天视频数、平均播放、信用分；
- 平台：抖音 / 视频号 / 快手 / 小红书；
- 结果四态：`pending / approved / rejected / info_required`。

**业务规则建议**：
- 信用分 < 60 默认进入 `info_required`；
- 同一手机号 + UID 60 天内禁止二次提交（防刷）。

### 3.3 数字人 / AI 形象授权

两条独立但结构相似的审批管道：

- **DigitalHumanRequest**：用途三选（live / shortVideo / ads）+ 平台白名单 + 时长。
- **AILikenessRequest**：模型粒度三选（voice / face / fullBody）+ `riskLevel` 分级 + AI 厂商记录。

**分级处理**：
- `low` → 自动通过（仅记录）；
- `medium` → 经纪团队人工审；
- `high` → 必须明星本人确认 + 合同补签。

### 3.4 内容审核

进入审核池的内容来源：

- 切片二创（来自切片授权账号）；
- 数字人产出（直播录屏 / 短视频）；
- AI 形象生成视频。

四态：`pending / approved / revision / rejected`。`revision` 携带具体修改意见，回流到 MCN 端的"驳回返工"列表。

### 3.5 商品入库（6 步流程）

`ProductOnboardItem.step` 取值 0~6：

```
0 已提交 → 1 平台初审 → 2 明星审核 → 3 寄样中 → 4 样品确认 → 5 入库
                                                          ↘ 6 驳回
```

**双重寄样机制**（`platformSample` / `celebSample`）：

```
notSent → shipping → delivered → approved
                              ↘ rejected
```

- 平台寄样 = 平台合规中心物理验收；
- 明星寄样 = 明星本人/团队体验确认。
- 两路寄样均为 `approved` 才允许进入 `step=5 入库`。

**三种商品来源**（`ProductSource`）：
- `platform`：平台严选采购；
- `creator`：创作者自荐（带货导向）；
- `brand`：品牌方直供。

### 3.6 品牌授权

`BrandAuthRequest` 状态机：

```
pending → platformReview → celebReview → sampleStage → approved
                                                     ↘ rejected
```

授权类型多选（肖像、声音、AI 形象、数字人代言、影视植入），合同金额、时长、平台白名单全部可配。沿用与商品入库相同的双向寄样校验。

### 3.7 收益分成

- KPI 卡：累计 GMV、本月 GMV、待结算、已结算；
- 趋势图：按月 GMV 折线（`GMV_DATA`，使用 Recharts AreaChart）；
- 明细：按 MCN / 商品 / 渠道下钻；
- 结算周期建议：T+1 月 15 日打款。

### 3.8 内容规则配置

`ContentRule` 支持启停 + 分区（绿/黄/橙/红），是上述所有审核动作的策略来源。规则改动会写入审计日志，并影响下一时刻进入审核池的内容判定（已审项不回溯）。

### 3.9 子模块

- **侵权巡查**（`InfringementPatrol.tsx`）：全网监测仿冒账号、盗用素材、非授权数字人，一键发函/取证。
- **合同中心**（`ContractCenter.tsx`）：三类授权合同（切片 / AI 形象 / AI 数字人）的电子签、续约、撤销。

## 四、技术说明书

### 4.1 技术栈

| 层 | 技术 |
|---|---|
| 框架 | React 18 + TypeScript |
| 样式 | Tailwind CSS v4（白底 light 主题为默认） |
| 动效 | `motion/react` |
| 图表 | `recharts` |
| 图标 | `lucide-react`（已全局替换 emoji） |
| i18n | 自研 `Lang` 枚举 + 组件级 `zh/en` 字段 |
| 主题 | `ThemeProvider`（5 色赛博朋克，默认 `light`） |

### 4.2 组件结构

```
celebrity/
├─ CelebrityWorkbench.tsx   # 主容器：左导航 + 右内容区
├─ ContractCenter.tsx       # 合同中心子页
└─ InfringementPatrol.tsx   # 侵权巡查子页
```

`CelebrityWorkbench` props：

```ts
{ lang: Lang; onBack: () => void }
```

子模块按 `NavSection` 切换，状态全部在主容器内 `useState`，未引入全局 store —— 当前规模可控，未来若新增"跨页面任务流"建议引入 Zustand。

### 4.3 数据模型（核心 interface）

参见文件顶部 type/interface 区：
- `WhitelistRequest`、`DigitalHumanRequest`、`AILikenessRequest`
- `ContentReviewItem`、`IPAuthRecord`
- `ProductOnboardItem`、`BrandAuthRequest`、`ProductLibItem`
- `ContentRule`

所有列表当前以 `MOCK_*` / `INIT_*` 常量注入，后端联调时替换为 API 即可（建议 REST：`/api/celebrity/*`，分页 + 状态过滤）。

### 4.4 状态机原则

凡涉及"流程"的实体（IP 授权 / 报白 / 商品入库 / 品牌授权 / 寄样）均采用**只前进不回退**的有向状态机；驳回 (`rejected`) 与回改 (`revision`) 是终态分支，需重新发起单据，不在原单上回滚——保证审计链完整。

### 4.5 风险分级实现

`zone: 'green' | 'yellow' | 'orange' | 'red'` 在 UI 层通过 `ZONE_COLORS` 直出色值；建议后端落库时再加一层 `zoneVersion` 以追溯规则变更对历史单据的影响。

### 4.6 与其他端的接口边界

| 触发点 | 上游 | 下游 |
|---|---|---|
| 报白审批通过 | MCN 工作台账号管理 | 创作者发布中心解锁该账号 |
| IP 资产 active | 明星端上传 | 创作者制作工坊出现可选模型 |
| 内容驳回 | 明星端审核 | MCN 任务列表"返工" |
| 商品入库 | 三源任一 | 商品库 → 创作者带货组件 |
| 侵权处置 | 明星端巡查 | 平台合规中心法务工单 |

### 4.7 UI 设计约束

- **颜色**：白底浅色为默认，文本 `text-gray-900`；强调色继续使用红黑灰主题色（`--theme-primary` 等）以保持系列感。
- **卡片**：圆角 `rounded-2xl`，阴影 `shadow-sm`，hover 上浮 + 边框由 gray-200 → primary。
- **表格**：横向滚动 + 粘性表头，状态徽章用 `<Badge>`（lucide 图标 + 文案）。
- **动效**：`motion.div` 进出场用 `initial/animate/exit`，统一 `duration: 0.2`。
- **图标**：禁用 emoji，全部 lucide。
- **响应式**：≥1280 推荐桌面排版（侧边导航 240px），<1024 折叠为顶部 Tab。

## 五、术语表

| 术语 | 解释 |
|---|---|
| IP 授权 | 明星把可被技术处理的资产（肖像/切片/模型/法务文件）授权给平台 |
| 报白 | 短视频平台对账号开启商业化挂载权限的过程 |
| 数字人 | 由真人训练得到的可被驱动的虚拟形象 |
| AI 形象 | 不必动态化的静态/半动态 AI 生成形象（声纹/面部/全身贴图） |
| 切片 | 截取自影视/综艺的二创可用片段 |
| 寄样 | 商品准入流程中的物理样品验收环节 |
| 火山引擎 | 当前默认对接的技术承接方（可替换） |
