# 第1章 门户与全局框架

> 适用范围：AI艺人孵化 + 明星IP授权平台（产品名 **AI Star Eco**）React 原型。
> 事实来源：`/workspaces/default/code/src/app` 下源码。原型中的所有数据都是前端 Mock，所有异步行为都由 `setTimeout` 模拟。
> 本章覆盖的模块：全局路由（App.tsx）、新版首页 NewLandingPage 及其 AuthModal、原版首页 HomePage、三端门户 Portal、创业者登录 LoginPage、制作人引导页 ProducerIntro、MCN 控制台外壳 MCNConsole（侧边栏、顶栏、工作台总览）、角色切换 RoleSwitcherFAB、命令面板 CommandPalette、通知面板 NotificationPanel、悬浮快捷操作 FloatingActions、动态流 ActivityFeed、设置页 SettingsPage、主题系统 ThemeProvider/ThemeSwitcher、国际化 translations.ts、新手引导 OnboardingGuide，以及骨架屏 SkeletonLoader。
> 文档约定：
> - “现状”指当前代码已经实现的行为。
> - “目标”指 PRD 要求的正式版行为。
> - “现状差距”逐条列出两者之间的不一致和缺陷。
> - 行号（如 `App.tsx:491`）只用于定位，可能随代码修改而偏移。

### 1.0.3 全局技术约束（现状）

1. 不使用路由库。页面切换完全依靠 `App` 的 `useState<page>`，因此：
   - 刷新浏览器会回到首页；
   - URL 不变化，无法分享深链；
   - 浏览器“后退”不起作用。
2. 没有真实鉴权，也没有 Token / Session。任何“登录成功”都是定时器回调。
3. 语言 `lang`、主题 `theme`、控制台 `activePage` 都不持久化，刷新即丢失。
4. 动画统一使用 `motion/react`（`AnimatePresence`、`motion.div`），样式使用 Tailwind，图标使用 lucide-react，图表使用 recharts。
5. 所有数据都来自组件内的常量或 `MOCK_ARTISTS` 等 Mock 数组。

## 1.1 全局路由与应用壳（App.tsx）

### 1.1.1 页面目标
- 作为整个原型的唯一入口，负责维护“当前页面”“语言”和“首页版本”三个全局状态，并根据它们渲染对应的一级页面。
- 为一级页面提供统一的跳转回调：`onEnter`、`onBack`、`onLoginSuccess`、`onEnterApp` 和 `onLogout`。

### 1.1.2 入口与跳转
- 入口：应用启动后默认 `page='home'`、`landingVersion='new'`，即渲染新版首页（`App.tsx:491-493`）。
- 跳转矩阵：

| 当前 page | 渲染组件 | 触发 | 目标 page |
|---|---|---|---|
| home（new） | NewLandingPage | onEnter（AuthModal 成功 / 直接体验） | portal |
| home（new） | 右下固定按钮“查看原版首页” | 点击 | 保持 home，landingVersion=original |
| home（original） | HomePage | onEnter（进入平台 / CTA） | portal |
| home（original） | 右下固定按钮“查看新版首页” | 点击 | 保持 home，landingVersion=new |
| portal | Portal | 点击“生态创业者”列 | producer_login |
| portal | Portal | 点击“星海粉丝”列 | fan |
| portal | Portal | 点击“明星IP端”列 | celebrity_ip |
| portal | Portal | 创业者小程序 | miniapp_entrepreneur |
| portal | Portal | 切片专用小程序 | miniapp_clip |
| fan | FanAppFull | onBack | portal |
| producer_login | LoginPage | onBack | portal |
| producer_login | LoginPage | onLoginSuccess | producer_intro |
| producer_intro | ProducerIntro | onEnterApp | producer_app |
| producer_app | MCNConsole | onLogout | home |
| celebrity_ip | MCNConsole（initialRole=celebrity） | onLogout | home |
| miniapp_entrepreneur | EntrepreneurMiniApp | onBack | portal |
| miniapp_clip | ClipMiniApp | onBack | portal |

### 1.1.3 页面布局分区
App 本身没有可视布局，只做条件渲染：
1. 外层是 ThemeProvider（主题 Context）。
2. 内层用 `page` 选择一级组件。
3. 在 page=home 时，右下角额外渲染 fixed 的“首页版本切换”按钮（`bottom-6 right-6`）。

### 1.1.4 字段/元素清单

| 字段名 | 类型 | 来源/示例值 | 规则 |
|---|---|---|---|
| page | 联合字符串 | 'home' \| 'portal' \| 'fan' \| 'producer_login' \| 'producer_intro' \| 'producer_app' \| 'celebrity_ip' \| 'miniapp_entrepreneur' \| 'miniapp_clip' | 默认 'home'；只能通过子组件回调修改 |
| lang | 'zh' \| 'en' | 默认 'zh' | 作为 props 下发给 Portal、HomePage、NewLandingPage、LoginPage、MCNConsole 等；setLang 一并下发 |
| landingVersion | 'original' \| 'new' | 默认 'new' | 只在 page=home 时生效 |
| 版本切换按钮 | button | 文案“查看原版首页”/“查看新版首页” | fixed，层级在首页之上 |

### 1.1.5 交互说明

| 触发 | 结果 |
|---|---|
| 点击“查看原版首页” | landingVersion 切到 original，渲染 HomePage；滚动位置不重置 |
| 点击“查看新版首页” | landingVersion 切到 new |
| 子组件回调 | setPage(目标)，立即替换整个页面，没有过渡动画 |

### 1.1.6 状态与状态流转
- page 的状态机见 1.0.4 节。
- 没有任何守卫：例如直接 setPage('producer_app') 不会校验登录态（原型中无法从 URL 直达，但目标版本必须加守卫）。

### 1.1.7 业务规则与校验
1. 目标：进入 producer_app / celebrity_ip 前必须已登录，且账号拥有对应身份；否则重定向到登录页。
2. 目标：语言选择应全局持久化（建议用 localStorage 的 `lang` 键），刷新后保持。
3. 目标：引入 URL 路由（例如 `/`、`/portal`、`/login`、`/console/:page`），支持浏览器后退和深链分享。

### 1.1.8 空态/加载/异常
- 现状：没有全局加载态，没有错误边界（ErrorBoundary），也没有 404 页面。page 取到未知值时什么都不渲染（白屏）。
- 目标：增加全局 ErrorBoundary（展示“页面出错了，返回首页”）、路由级 Suspense 骨架，以及 404 页面。

### 1.1.9 验收标准
1. 首次打开应用时展示新版首页，右下角出现“查看原版首页”按钮。
2. 点击“查看原版首页”后展示原版首页，按钮文案变为“查看新版首页”；再次点击可以切回。
3. 在门户依次点击三列和两个小程序按钮，都能进入 1.1.2 表中对应的页面。
4. 粉丝端、登录页和两个小程序的返回操作都回到门户。
5. 登录成功后进入 ProducerIntro；点击“进入制作人控制台”后进入 MCNConsole，并且默认是工作台页。
6. 在控制台点击“返回首页”后回到首页（新版或原版取决于当前 landingVersion）。
7. 在任一页面切换语言后，再跳转到其他页面，语言保持一致（会话内）。

## 1.2 新版首页（NewLandingPage）

### 1.2.1 页面目标
- 面向 B 端（MCN 机构、独立运营者、明星方、品牌方）介绍平台的两大业务支柱：“AI艺人孵化”和“明星切片授权矩阵”。

- 入口：应用默认首页；控制台“返回首页”（landingVersion=new 时）；原版首页的“查看新版首页”。

  - AuthModal 任一流程成功 → handleSuccess：关闭弹窗，调用 onEnter，进入 portal。

## 1.14 动态流（ActivityFeed）

### 1.14.1 页面目标
在工作台底部实时展示旗下艺人的发布、里程碑、交易和合作动态。

### 1.14.2 入口与跳转
嵌在工作台中，条目没有跳转。

### 1.14.3 页面布局分区
1. 头部：标题、LIVE 徽标（脉冲效果）、“8 条动态”。
2. 列表：默认 5 条。
3. 底部：“查看全部 8 条”或“收起”。

### 1.14.4 字段/元素清单
| 字段 | 说明 |
|---|---|
| type | release / milestone / nft / collab / fan / revenue / award / content |
| artist | 艺人名称 |
| artistIcon | 现状是字符串（如 "MIC"），直接以文本渲染 |
| text | 动态内容 |
| time | 相对时间 |
| highlight | id 1、2 为 true，带高亮边框 |

示例：
- Neon V 新单曲发布（5分钟前）
- PRISM 7 粉丝突破 300K
- Luna Soft 收益 ¥12,800
- Crystal Flow 收到 NEXON 合作邀约
- MC Thunder 发布 EP.12
- 等，共 8 条

### 1.14.5 交互说明
点击“查看全部”后展开到 8 条，文字变为“收起”；条目以 stagger 动画进入。

### 1.14.6 状态与状态流转
expanded: false ⇄ true。

### 1.14.7 业务规则与校验
目标：实时推送，按时间倒序，最多保留 50 条，超出后分页加载；只展示当前账号旗下艺人的动态。

### 1.14.8 空态/加载/异常
没有空态（目标文案：“暂无动态”）。

### 1.14.9 验收标准
1. 默认显示 5 条，底部显示“查看全部 8 条”。
2. 点击后显示 8 条，按钮变为“收起”。
3. 前 2 条带高亮样式。
4. 艺人图标以图形显示，不出现 “MIC” 等文本（现状不通过）。
5. 组件风格与工作台浅色主题一致（现状为深色，不通过）。

### 1.14.10 现状差距
- G1.14-1：artistIcon 字面渲染。
- G1.14-2：深色样式与浅色页面冲突。
- G1.14-3：条目不可点击。
- G1.14-4：“LIVE”名不副实，数据是静态的。
