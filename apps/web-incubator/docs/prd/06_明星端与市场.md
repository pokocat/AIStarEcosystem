### 6.1.1 页面目标

为明星本人或经纪团队提供统一的 IP 资产托管和商业化审批中枢。所有涉及明星 IP 的请求（账号报白、数字人使用、AI 形象/声音、内容、商品、品牌合作）都必须在此审批，同时提供收益查看、商业化规则配置、侵权巡查和合同管理。

### 6.1.7 IP授权（section = ipAuth）

#### 页面目标
明星方把四类 IP 资产（肖像、切片素材、数字人模型、法务文件）按「录入 → 技术公司接收 → 火山引擎部署 → AI 系统激活」的链路授权给平台，并能追踪每类的进度和文件清单。

#### 布局分区
1. 页头：标题和链路说明
2. 四张授权卡（网格），每张包含：类型名、状态标签、6 段进度条、文件数 filesCount/requiredFiles、操作按钮
3. 详情面板（展开）：说明 note、文件清单、技术公司接收状态、火山项目 ID 与同步状态、上传日期和激活日期

#### 字段表：IPAuthItem

| 字段名 | 类型 | 可选值 / 示例 | 必填 | 校验 |
|---|---|---|---|---|
| type | enum | portrait / clip / digitalHuman / documents | 是 | 唯一 |
| status | enum | notStarted / preparing / uploaded / techReceived / volcanoSync / active | 是 | 只能单向前进 |
| filesCount | number | 35 | 是 | ≥0 |
| requiredFiles | number | 32 | 是 | >0；filesCount ≥ requiredFiles 才允许进入 uploaded（建议） |
| techCompany | string | 灵镜AI Lab / 法务合规中心 | 否 | — |
| volcanoProjectId | string | VK-PRT-2024-001 | 否 | 格式 VK-XXX-YYYY-NNN（建议） |
| uploadedAt | date | 2024-xx-xx | 否 | 首次推进时自动写入 |
| activatedAt | date | — | 否 | 进入 active 时写入（建议） |
| note | string | 说明文本 | 否 | — |

#### 文件清单 IP_AUTH_META

| 类型 | 中文 | 必需文件清单 |
|---|---|---|
| portrait | 肖像授权 | 7 项（正面、侧面、多角度、表情集、全身、授权书等） |
| clip | 切片授权 | 切片使用协议、视频素材包×50+ |
| digitalHuman | 数字人模型 | 4 项（建模扫描、动作捕捉、声纹样本、使用协议等） |
| documents | 法务文件 | 4 份 PDF（肖像权授权书、身份证明、经纪合同、合规承诺） |

#### 初始数据

| 类型 | status | files | 技术方 / 项目 |
|---|---|---|---|
| portrait | active | 35/32 | VK-PRT-2024-001 |
| clip | active | 120/50 | — |
| digitalHuman | volcanoSync | 8/10 | 灵镜AI Lab |
| documents | techReceived | 4/4 | 法务合规中心 |

#### 状态机：IPAuthStatus

| # | 当前状态 | 按钮文案 | 触发函数 | 下一状态 | 副作用 |
|---|---|---|---|---|---|
| T1 | notStarted | 开始准备文件 | simulateIPUpload(type) | preparing | uploadedAt 为空时写入今天 |
| T2 | preparing | 上传授权文件 | simulateIPUpload(type) | uploaded | 同上 |
| T3 | uploaded | 通知技术公司 | simulateIPUpload(type) | techReceived | — |
| T4 | techReceived | 推送至火山引擎 | simulateIPUpload(type) | volcanoSync | — |
| T5 | volcanoSync | 确认部署完成 | simulateIPUpload(type) | active | — |
| T6 | active | （无按钮） | — | 终态 | — |

```
notStarted → preparing → uploaded → techReceived → volcanoSync → active
```

**【现状差距 G-1-5】** 推进时不校验文件数：digitalHuman 只有 8/10 也能「确认部署完成」。**【建议】** 只有 filesCount ≥ requiredFiles 才允许 preparing→uploaded；不满足时按钮置灰，并提示「还缺 N 份文件」。
**【现状差距 G-1-6】** 没有真实的上传控件，文件清单的圆点颜色按 index < filesCount 着色，与实际文件无关。
**【现状差距 G-1-7】** 没有撤销或回退路径，也没有「暂停授权」或「撤回授权」。《产品文档.md》强调授权「可控、可审、可撤销」，**【差异】** 源码不支持撤销。
**【现状差距 G-1-8】** 推进到 active 时没有写 activatedAt，详情中激活日期依赖 mock 初值。
**【现状差距 G-1-9】** T3–T5 本应由技术公司和火山引擎回调触发，原型由明星方手动点击，角色错位。

#### 交互
| 触发 | 结果 |
|---|---|
| 点击卡片主体 | 切换 expandedIPType（同一张卡再点一次则收起；点另一张则切换过去） |
| 点击推进按钮 | 调用 simulateIPUpload，状态 +1，进度条 +1 格；需要阻止冒泡，避免触发展开（建议） |
| 状态到达 active | 按钮消失，状态标签变绿 |

#### 业务规则
1. R-IP-1：四类授权互相独立推进。
2. R-IP-2：只有 active 的资产可以被创作者端制作工坊调用（《产品文档.md》联动表：「IP 资产 active → 创作者制作工坊出现可选模型」）；原型中没有这种跨模块联动。
3. R-IP-3：进度条 6 段，对应 6 个状态，当前状态及之前的段全部点亮。

#### 空态 / 加载 / 异常
- 空态：不适用（固定 4 类）。
- 加载：原型无。正式版推进时需要 loading，按钮防重复点击。
- 异常：正式版中火山同步失败要显示「同步失败，重试」，状态保持 volcanoSync。

#### 交易状态机 A：一口价（txState）

| # | 当前 | 触发 | 函数 | 下一状态 | 规则 |
|---|---|---|---|---|---|
| X1 | idle | 点击「立即签约」 | handleBuy | confirm | balance < price 时按钮 disabled，显示余额不足 |
| X2 | confirm | 点击「确认签约」 | handleBuy | processing | 提示「确认签约后不可撤销」 |
| X3 | confirm | 点击取消 | setTxState('idle') | idle | — |
| X4 | processing | 1.8 秒后 | setTimeout | success | 父组件 `setBalance(b => b - price)`，listing.acquired=true |
| X5 | success | 关闭抽屉 | onClose | — | 卡片显示「已签约」 |

**【BUG B-4-1】** 父组件用函数式写法 `setBalance(b => b - price)`。当外部传入的 setBalance 不是 React setState（例如普通的 `(n:number)=>void`）时会出错。**【建议】** 统一为 `setBalance(balance - price)` 或明确类型为 Dispatch<SetStateAction<number>>。
**【现状差距 G-4-3】** 联合孵化 price=0，「申请合作」直接走买断流程并扣 0 元，没有申请审核流程。

#### 交易状态机 B：拍卖

| # | 当前 | 触发 | 函数 | 结果 | 校验 |
|---|---|---|---|---|---|
| A1 | idle | 输入金额并点击出价 | handleBid(amt) | processing（1.4 秒） | amt > currentBid，否则提示 |
| A2 | processing | 1.4 秒后 | onBid(id, amt) | currentBid=amt，bidCount+1，回到 idle | — |

**【BUG B-4-2】** 占位符提示「≥ 当前价 + 5000」，但实际只校验 amt > currentBid，加价幅度没有强制。
**【BUG B-4-3】** 拍卖到期（endsAt 已过）后仍可出价，没有截拍逻辑和成交结算。
**【BUG B-4-4】** 出价不校验余额，也不冻结保证金。
**【BUG B-4-5】** 抽屉持有的是打开时的 listing 快照，出价后抽屉内的当前价不刷新（数据陈旧）。**【建议】** 抽屉按 id 从 listings 中实时读取。

#### 交易状态机 C：议价（negState）

| # | 当前 | 触发 | 结果 |
|---|---|---|---|
| N1 | idle | 输入报价并发送 | sent |
| N2 | sent | 2 秒后 | countered，卖方还价 = price × 0.88 |
| N3 | countered | 点击「接受成交」 | 调用 handleBuy：txState 从 idle 变为 confirm，但议价区不渲染 confirm 界面，需要再点一次 |
| N4 | countered | 再次点击 | processing → success |

**【BUG B-4-6】** 接受成交需要点两次，第一次没有任何可见反馈。
**【BUG B-4-7】** 成交扣款使用原价 price，而不是还价 price×0.88。
**【现状差距 G-4-4】** 还价与用户报价无关，固定为 0.88 倍；用户报价高于 0.88×price 时仍会被「还价」到更低价，逻辑矛盾。**【建议】** counter = max(用户报价, 卖方底价)，用户报价 ≥ 底价时直接成交。

#### 自有上架（isOwn）
**【现状差距 G-4-5】** 按钮显示「管理」，但打开的是购买界面，可能出现自己买自己的情况。**【建议】** 打开管理视图：查看报价 offers（接受 / 拒绝）、修改价格、撤回（48 小时内）。
