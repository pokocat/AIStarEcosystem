# 出图

用户要的是**一张或几张能直接用的图**。这是最常见、也最该快的事：把用户给的信息变成一条写清楚的出图指令，报价，确认，出图。
下面是方法，不是脚本。

## 什么时候用这个方法
- 用户说「画 / 出图 / 做张图 / 来张海报 / 封面 / 商品图 / 人物设定图 / 换个背景」；描述了一个画面；贴了一张参考图说「照这个风格再来一张」；把一段文案钉进来说「配张图」。用户没说「出图」两个字也算。
- 不用这个方法：要把图动起来、做成视频（→ 出视频）；要照着一条视频做（→ 参考视频复刻）；只是讨论构图、问意见、改文字（直接回答或改文字，不出图）。

## 必填与可选：这是「要不要问」的唯一判据
- **必填**：画什么（主体 + 场景或用途）。用户的一句话、钉住的文字、参考图都算来源；从这些里推得出就不问。
- **可选，一律用默认，不问也不编**：张数（默认 1；用户说「几张」「多来几版」默认 2）、画幅（海报 / 封面 / 手机壁纸 9:16，横幅 16:9，头像 / 商品主图 / 没说用途 1:1）、风格（跟参考图；没有参考图就按用途选一种常见风格并在方案里写明）、模型（省略，用默认）。
- 用户用引号或明确数字给的值（「1080x1920」「要 4 张」「赛博朋克」）原样用。
- 真正要问的情况只有一种：必填缺失且推不出来（例如整句只有「画张图」）。这时问一个问题，附 2–4 个候选并标出默认。一轮只问一个。

## 一轮确认：方案和确认卡同一轮发出
- 读取本方法后，用 propose_plan 直接整理制作方案（本方法没有分析阶段，stage 填 production），接着 request_approval 发确认卡。**不要先发方案等用户说「好」再发卡**，那是第二轮。
- 正文一两句：按什么画、几张、什么画幅、哪些是你补的默认。报价只说卡上的数字。
- 用户贴了完整需求（主体、风格、用途、尺寸、文字都齐）时，正文更短：一句「按你写的做」+ 补的默认，直接出卡。

## 参考图怎么用
- 用户钉住或连进来的图就是参考，不要再问「用哪张」。
- 角色图 → referenceBindings role=character；商品图 → product；场景图 → scene；只借风格或构图的图 → reference-image。
- 同一个人物的多张图取最清楚的正面那张做第一顺位；旧版本、带文字标注的图不要混进去。

## 出图指令怎么写（给模型的 prompt）
- 意图不变：主体、动作、数量、风格、布局、关系、属性、文字，都必须和用户说的一致，扩写只补细节不改意图。
- 总-分-总，由主到次：先一句说清整体（什么图、什么风格），再从主体写到场景、光线、材质、色彩，最后一句点题（整体风格或类型）。
- 具体到可核对：「右手握着图1 的蓝色保温杯，杯口朝上」优于「拿着我的杯子」。
- 有参考图时写清每张图提供什么（「图1 定人物长相与发型，图2 定服装」）；没提供给模型的东西不要写成事实。
- 画面上要出现的文字用引号原文写出并说明位置；没要文字就写「无文字」。
- 禁止项放最后：多余人物、水印、变形手部、与参考不符的服饰道具。
- 人物设定图 / 三视图 / 表情表这类拼版图：明确「同一人物，身份、画风、服装、比例一致」，并写明分几格、每格什么。

## 多张图与变体
- 「多来几版」= 一步 count=2 或 4，不是多个步骤。
- 「分别画 A、B、C」= 几个步骤，各自一步，互不依赖。
- 「先定人物再画场景」= 两步：第一步出人物，第二步 dependsOn 第一步并用 referenceBindings stepId 引用它。

## 不做什么
- 不替用户决定做视频；不把出图方案写成多阶段大工程。
- 不承诺像素级还原参考图；不声称已生成；报价数字只来自服务端。
- 局部重绘、裁剪、拆图是画布上图片节点自己的工具，对话里说明在哪做即可，不冒充能做。

## 对用户怎么说
- 像一个熟手设计师复述需求：一句话说清要画什么、补了什么默认，然后出卡。
- 做完由服务端放进画布；用户要改，改指令再出一版，不重新问一遍需求。
