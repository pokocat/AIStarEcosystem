# 出视频

用户要的是**一段或几段能直接用的视频**：把一张图动起来、商品展示、一个人说一段话、按剧本出几段再合成。没有参考视频要拆解，就用这个方法；要照着一条视频做，走「参考视频复刻」。
下面是方法，不是脚本。

## 什么时候用这个方法
- 用户说「做一条视频 / 出片 / 把这张图动起来 / 来一段商品展示 / 按这个剧本出片」；钉住了图片或剧本说「做成视频」。
- 不用这个方法：有参考视频要照着做（→ 参考视频复刻）；只要图（→ 出图）；只要文字（→ 写剧本与文案）；要配音、口型同步、声音克隆（画布上对应节点自己的工具做，对话里说明在哪做，不冒充能做）。

## 必填与可选
- **必填**：拍什么（主体 + 动作或内容）。来源可以是一句话、钉住的剧本或文案、画布上的图。从这些里推得出就不问。
- **可选，一律用默认，不问也不编**：时长（单段默认 5 秒；口播或展示段默认 8–10 秒；受所选模型最短 / 最长秒数约束，整数秒）、画幅（手机短视频 9:16；用户说横屏或桌面 16:9；商品主图动起来 1:1）、清晰度（模型默认档）、张数 / 段数（默认 1 段；剧本有几段就几段，超过 8 段先合并）、模型（省略，用默认）。
- 用户给的明确数字（「10 秒」「16:9」）原样用。
- 只有必填缺失且推不出来才问，一轮一个，附候选并标默认。

## 一轮确认：方案和确认卡同一轮发出
- 读取本方法后，用 propose_plan 直接整理制作方案（本方法没有分析阶段，stage 填 production），接着 request_approval 发卡。不要先发方案等用户说「好」再发卡。
- 正文一两句：几段、每段多长、什么画幅、哪些是你补的默认；报价只说卡上的数字。
- 用户贴了完整剧本或分镜时，直接按它分段，不复述内容，补的默认说一句就出卡。

## 怎么分段
- 一段 = 一个连续的动作或一个镜头意图，不是一句台词一段；3 秒以内的碎段合并。
- 每段时长在所选模型的最短 / 最长秒数之间；超了按动作边界再切，不截断。
- 多段要合成时最后加一步 assemble，按段序列出 clipOrder；用户只要单段就不加。
- 用户在意人物或商品一致时，先出一张关键画面（image 步骤），后面的视频步骤用它做 frame 或 character 参考（keyframe-first）。

## 参考怎么用
- 用户钉住或连进来的图就是参考，不要再问「用哪张」。
- 要把图「动起来」：这张图做 frame（首帧），提示词只写变化，不复述画面。
- 人物图 role=character，商品图 role=product，场景图 role=scene；每段只绑这一段需要的，不把无关的图都绑上。
- 模式按模型合同选：有首帧用首帧模式，有多张参考用全能参考模式，只有文字用文生视频；合同里没有的模式不写。

## 视频指令怎么写（给模型的 prompt）
- 结构：主体 + 主体在做什么 + 场景；然后可选的运镜、光线、氛围。自然语言，2–4 个主要意思，不堆关键词。
- 主体动作和相机动作分开写，各一句；运镜只用一种（推进 / 拉远 / 平移 / 环绕 / 升降），不叠加。
- **写清什么不动**：首帧出发时，没说不动的东西模型会自己加动作。例如「人物保持原位，只有头发和衣角随风动」。
- 有参考图时按编号说明用途（「图1 定人物，图2 定商品外观」），没提供给模型的东西不写成事实。
- 对白 / 字幕要出现时用引号写原文；不要求就写「无字幕」。
- 光线只用一套，不混「黄昏」和「影棚灯」。

## 检查与合成
- 多段制作建议在每段视频后接一个 check（subject-consistency / scene-and-action / duration-and-order 里选用），单段短片可以不检查。
- 检查没通过只给建议，不自动重做（autoFixChecks 为空）。
- 合成：assemble 按段序，audioStrategy 默认 generated；用户要配自己的音乐或原声，说明在成片页做。

## 不做什么
- 不把出视频写成「先分析再制作」的两阶段工程；不为单段视频提多个方案。
- 不承诺逐帧可控；不声称已生成；报价数字只来自服务端。

## 对用户怎么说
- 像一个熟手剪辑：一句话复述要拍什么、分几段、补了什么默认，然后出卡。
- 做完由服务端放进画布；要改某一段，只改那一段再出，不重新问需求。
